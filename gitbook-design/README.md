# はじめに：何をするゲームか

> **この文書について。** Wylls の設計書です（2026-10-23 版）。ゲームの全体を理解し、設計を判断し、それを基準に開発するために使います。プレイヤー向けの操作説明や宣伝資料ではありません。
>
> 主張には状態の印を付けます。決まったことは【決定済み】、試作で確かめる案は【検証する候補】、まだ決まっていないことは【未決定】、実装を確かめたことは【実装あり：S1】などです。印の意味は [読み方と状態の表し方](00-how-to-read.md) にあります。

## 何をするゲームか

**文明を育て、国どうしで戦いながら、文明の機能そのものも住人が増やしていくゲームです。**【決定済み】

- 土台は、文明シミュレーションと戦略バトルです。畑、鉱山、工房、軍、砦があります。
- 参加者を **住人** と呼びます。住人は人間と AI で、それぞれ世界に村を持ちます。
- 住人は 6 つの国のどれかに属し、村を育て、兵を訓練し、砦を取り合います。
- その上で、住人は自分の施設を他人に使わせます。他人の施設や仕組みを組み合わせて、新しい仕組みも作ります。完成した仕組みは、次の人の部品になります。
- 世界は終わらずに続きます。戦争の勝ち負けだけを、2 週間ごとの **戦期** で区切ります。

## 何が面白いのか

確かめたい面白さは、**他の住人に頼ることが、戦略と駆け引きを生むこと** です。物流の管理を増やすことが狙いではありません。

たとえば、次のような場面です。

> A が工房の生産枠を公開する。B は、A の工房と自分の輸送・倉を組み合わせ、砦に兵器を届ける補給サービスを公開する。C は、それを自分の軍の運用に組み込む。
>
> 敵が近道を封じたら、どうするか。迂回するか、別の工房を探すか、備蓄で耐えるか、護衛を出すか、作戦を変えるか。

生産枠とは、他人が動かす工房の、実際に使える生産の能力です。倉は物を預かる建物で、村の外にも建てられます。

この例では、誰に頼り、誰を守り、誰の補給を断つかが、戦争の判断になります。この遊びを **補給網** と呼びます。補給網は、この面白さを確かめるための【検証する候補】の一つで、採用は決まっていません。普通の交易より面白いかを小さな試作で確かめてから決めます（[第11章](11-verification-and-plan.md)）。

## 最上位の原則

まず面白いゲームを作ります。Eternum との違いは要りますが、違いを出すためだけに機能を増やしません。

判断の順は次の ①〜⑤ です。再設計の文書に、2026-10-23 のあなたの発言として記録されています。

- ① 面白い判断と、結果の手応えがあるか。
- ② Eternum と違う戦略、対人の関わり、展開を生むか。
- ③ その判断を直感的に選べ、結果の因果が分かる UI/UX か。
- ④ 世界観とビジュアル。
- ⑤ EVE Frontier の拡張性や Solana の接続性が、その体験を支えるか。

## 何が決まっていて、何を検討中か

ここでは主なものだけを挙げます。決定の一覧は [読み方と状態の表し方](00-how-to-read.md) に、未決定の問いは [第12章](12-open-questions.md) にあります。

### 決まっていること【決定済み】

- 核の一文（上の「何をするゲームか」の太字）。
- 文明と戦争の土台を残す。
- 任意のコードを渡さない。資源は無から増えず、許可なく他人の施設に触れない。
- 世界は続き、戦争だけを戦期で区切る。
- 土地と国の形。
- 段階 1〜4 の各段階で採用した規則。段階 1〜4 は、再設計が示した作る順番です（順番と中身は【提案】。各段階で採用した規則は【決定済み】）。詳しくは [第3章](03-facilities-and-offers.md)。
- AI の 4 つの役割と、AI も人と同じ規則に従うこと。
- お金の流れの形。
- 賞金を、使われた回数や売った量では数えないこと。

### 試作で確かめる案【検証する候補】

- 補給網（他人の生産枠を使う補給サービス）。
- 他人を使う理由（立地、建設時間、設備容量）。
- Solana の CPI と PDA を使った、公開の入口。

### 検討中の案【提案】

- 「生きた文明の地図」の画面。
- hex（六角形のマス）を内部のルールに残すこと。
- 部品の細部、画面の細部、この文書の推奨。

### まだ決まっていないこと【未決定】

- 数字とトークン。
- 賞金と補給網の会計のつなぎ方。
- 施設が奪われたときの、使用権の札と預かり品の扱い。
- 「AI ステーキング」の意味。
- ほか（[第12章](12-open-questions.md)）。

### 作ってあるもの【実装あり：S1】

段階 1 の一部が、作業ブランチ（main に未統合）にあります。

- 兵器と工房
- 倉と荷車
- 荷車の襲撃
- 見張り塔
- 柵と砦の建物、国の構え（他国を「戦い」「通す」「味方」のどれとして扱うか）

S1 は、段階 1 を入れたルールの版です。実装の詳しい状態は [第10章](10-gap.md) にあります。

## 3 つの遊びを分ける

この設計では、似て見える次の 3 つを、別の遊びとして扱います。

| | 何をするか | 終わったあとに残るもの |
|---|---|---|
| **① 資源の売買** | 物と物（または金）を 1 回交換する | 何も残らない |
| **② 施設の利用条件** | 施設の持ち主が、使う権利を出す。使う人は材料を持ち込み、できた物を受け取る | 札と施設の設定 |
| **③ 他人の機能を再利用した新しい仕組み** | 他人の倉・札・施設をつなぎ、名前を付けて公開する | 仕組みとその札。さらに別の仕組みの部品になる |

ここで **札** とは、持ち主に何かを許す、売り買いできる権利です。ゲームの外のトークンではありません。それぞれの例は次のとおりです。例の数値は仮です。

- **① の例。** アオイが兵器 10 を、木材 40 と引き換えにベンへ渡します。交換が済めば、何も残りません。
- **② の例。** アオイが、自分の工房の使用権の札「1 日 3 回まで動かせる」を出します。ベンは自分の鉱石と木材を運び込み、兵器を受け取ります。施設の持ち主が「誰が、いくらで、どう使えるか」を決めます。施設はアオイの物、材料と兵器はベンの物のままです。
- **③ の例。** カイが「前線補給」を作ります。部品は、鉱山の倉の受け取りの札、アオイの工房の使用権の札、毎日の送りの **決まり** です。決まりとは「合図 → すること」の自動の指示です。兵器が砦の倉に毎日届きます。エマは札を買って加わります。③ は「受け取る → 実行する → 渡す」の形につなぐことです。

**③ ではないもの。** 公開された仕組みの設定を写して自分の施設で動かすのは、テンプレートの共有です。「在庫が減ったら自動で買う」設定は、① を繰り返すだけです。③ は、**いま動いている他人の施設の能力** を使って、別の人が使える働きを作ることです（[第3章](03-facilities-and-offers.md)）。

## 破れないルール【決定済み】

- 任意のコードは渡しません。運営が、基本の法則と組み合わせの文法を用意します。
- 資源は無から増えません。許可なく他人の施設に触れられません。
- 運ぶには時間がかかり、運んでいる荷は襲われえます。
- 失敗したら止まって、記録に残ります。

## Wylls の違いをどこに置くか

次のものには、EVE Frontier や Eternum にも先行例があります。コードを書かない組み立て、施設どうしの接続、AI、交易、外部のクライアントや拡張です。**だから、それだけを「世界初」「独自」とは言いません。**

逆に、他の作品でできるから Wylls に価値がない、とも結論しません。違いは **体験の全体** で評価します。文明戦略としての遊び、UI/UX、世界観、対象のユーザー、チェーンを含めた全体です（[第8章](08-comparison-eternum-eve.md)、[第9章](09-chain.md)）。
