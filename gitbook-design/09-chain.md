# 第9章 チェーンの位置づけ

この章は、Wylls がどのチェーンの上にあり、それが遊びと入口に何を足しうるかを、ゲームの比較（第8章）とは別の軸として整理します。最上位の判断基準では、チェーンの接続性は 5 番目です。チェーンは面白さを支えるもので、面白さの代わりにはなりません。

## 9.1 この章の根拠

ゲームの遊びとは別に、どのチェーンの上にあるかで、作り方、つなげる相手、入口が変わります。ここは 17a（`5090501`）の整理を元にし、17a が引く公開資料をこの文書の執筆者は再取得していません。17a 自身も、live の環境、利用量、継続の稼働は確かめていないとしています。

## 9.2 Wylls が今チェーンでしていること【main で確認】

| していること | 中身 |
|---|---|
| ゲームの判定 | 戦いの結果は、Solana のプログラムが決める。ブラウザは報告を計算し直せる |
| 行き先を隠す移動 | 軍の行き先は、時間ロックの封（指定した時刻まで誰も開けない暗号）で隠す。将来は zk |
| 検証 | シーズンの取引の記録を、検証ツールで再生できる（自前の検証ツールで、第三者の監査ではない） |
| お金 | ローカルのテスト用 USDC の参加費と賞金の道。本物のお金は使っていない |

出典は main の README と、第10章の照合です。S1 の段階 1 の命令と検証も、同じ形で足されています【実装あり：S1】。

## 9.3 配置の段階を混ぜない

| 作品 | 今の配置（資料の範囲） | 混ぜてはいけないこと |
|---|---|---|
| EVE Frontier | Sui。稼働中のサーバー（Stillness）は Sui の **テストネット**（確認：付録B）。17a も、移行先は Sui Testnet としている | Sui の本番ネットワークの資産と、EVE の操作が同じ処理でつながっているとは言えない。本番での公開日は見つからない |
| Eternum | Starknet 系。固定 SHA の README は、shard ごとの Starknet のアプリチェーン（native Cairo／Madara）と、価値を扱う Starknet の本番の層を分けている（17a） | すべての操作が本番の同じ状態の上で組み合わさる、と単純化しない。live の配置の全経路は未検証 |
| Wylls | Solana と互換のチェーン。最初の版は devnet で 1 シーズン動いた（ブランチ `codex/magicblock-playable`）。作り直した今の版は、ローカルのテストチェーンとテスト用 USDC だけで動かしている。本番ネットワークと本物の USDC は、法的な確認を条件にした **計画**【main で確認：README】 | ローカル／devnet で確かめたことと、将来の本番の資産への接続を分ける |

## 9.4 4 つの面で分ける

| 面 | EVE Frontier／Sui | Eternum／Starknet 系 | Wylls／Solana |
|---|---|---|---|
| 技術的な実現のしかた | 所有者と版を持つオブジェクトが中心。PTB（Programmable Transaction Blocks）は、Move の呼び出しの結果を同じ処理の後ろに渡し、全体を原子的に成功・失敗させられる | Cairo のアプリチェーンと本番の価値の層の分離 | CPI（プログラムからプログラムを呼ぶ）と PDA（プログラムが管理するアドレス）。原子性は 1 つの処理の中だけ。CPI の深さ、計算の予算、同じ書き込み先の取り合いは、設計と実測の課題 |
| つなげるサービス | Sui の上のサービス（接続済みかは個別に確かめる） | Starknet の上のサービス。ゲームの外の売買所（Agora）など | Solana の上のサービス。ただし **つなげられる（可能性）** と **つないだ（実装）** は別。今の版で動いているのは、ローカルのテスト用 USDC の参加費と賞金の道まで。最初の devnet の版は MagicBlock の ephemeral rollup と x402 を使った【main で確認：README】 |
| 既存のウォレットと資産 | Sui のウォレット。本番の USDC は Sui にもある（Circle の一覧、17a） | Starknet のウォレット。本番の USDC は Starknet にもある（同） | Solana のウォレット。本番の USDC は Solana にもある（同）。手数料を別の人が払う設計もできるが、実費と濫用の負担は残る |
| ユーザーと開発者の入口 | Move。施設の拡張と、コードを書かない外部の道具（第8章の教訓 3） | Cairo／Dojo の歴史。AI の実行部品、拡張のひな形 | Rust のプログラム。すでに Solana を使う人が、別のチェーンへ移らずに参加できる入口。これは **獲得の仮説** で、利用者が増える証拠ではない |

## 9.5 言ってはいけないこと

- 「原子的な組み合わせは Solana だけ」：誤り。Sui の PTB も 1 つの処理の中で原子的です。
- 「USDC は Solana 専用」：誤り。Sui と Starknet の本番にも Circle の USDC があります。
- 「他のチェーンでは技術的に不可能」：言えません。違いは、利用と外部の開発が成り立つかを測ってから評価します。
- 複数ターンにまたがる補給の履行は、どのチェーンでも 1 つの処理の原子性では守れません。各段の事実を別々に記録する必要があります（27a）。

## 9.6 Wylls で試せること【検証する候補】

17a の提案で、どれも検証する候補です。実装の実績ではありません。

1. 工場・輸送・予約の公開の入口を、Solana の上の他の開発者が自分の道具に組み込めるようにする。CPI で呼べる公開の機能と、PDA で管理する限定の権限（対象の機能、期限、予算）を候補にする。注文ごとの権限と予算の検査は Wylls 側で作る必要がある。
2. 別ブランチの AI 予算（agent-wallet）とつなぎ、人間と AI が同じ検査の入口から、絞った権限で注文する。推論の費用と処理の手数料を分け、停止、撤権、重複の防止を設計する（[第6章](06-humans-and-ai.md)）。
3. すでに Solana を使う人が、別のチェーンへ移らずに参加できる入口を作る。

17a の説明の候補「Solana の共有経済基盤の上で、プレイヤーが作った機能を他者や AI が再利用する文明戦略ゲーム」も検証する候補で、採用していません。
