# 第9章 チェーンの位置づけ

この章で分かること：

- Wylls が今チェーンの上で何をしているか
- 3 つの作品の配置（試験用か本番か、どの層で動くか）を混ぜてはいけない理由
- チェーンの違いを 4 つの面で分けた比較と、言ってはいけないこと
- Solana の上で試せること（どれも検証する候補）

この章は、Wylls がどのチェーンの上にあり、それが遊びと入口に何を足しうるかを整理します。ゲームの比較（第8章）とは別の軸です。最上位の判断基準では、チェーンの接続性は 5 番目です。チェーンは面白さを支えるもので、面白さの代わりにはなりません。

## 9.1 この章の根拠

どのチェーンの上にあるかで、作り方、つなげる相手、入口が変わります。これはゲームの遊びとは別の話です。

この章は、比較の根拠と留保の文書（17a）の整理を元にしています。

- 17a が引く公開資料を、この文書の執筆者は取り直していません。
- 17a 自身も、live の環境、利用量、継続の稼働は確かめていないとしています。

## 9.2 Wylls が今チェーンでしていること【main で確認】

| していること | 中身 |
|---|---|
| ゲームの判定 | 戦いの結果は、Solana のプログラムが決める。ブラウザは報告を計算し直せる |
| 行き先を隠す移動 | 軍の行き先は、時間ロックの封（指定した時刻まで誰も開けない暗号）で隠す。将来は zk |
| 検証 | シーズンの取引の記録を、検証ツールで再生できる（自前の検証ツールで、第三者の監査ではない） |
| お金 | ローカルのテスト用 USDC の参加費と賞金の道。本物のお金は使っていない |

出典は main の README と、第10章の照合です。S1（段階 1 を入れたルールの版）の命令と検証も、同じ形で足されています【実装あり：S1】。

## 9.3 配置の段階を混ぜない

配置には、試験用か本番かの違いと、どの層で動くかの違いがあります。Eternum は、アプリチェーンと、価値を扱う本番の層を分けています。作品ごとに、今どこで動いているかを分けて読む必要があります。

### EVE Frontier

- 今の配置：Sui です。稼働中のサーバー（Stillness）は、Sui の **テストネット** です（確認：付録B）。17a も、移行先は Sui Testnet としています。
- 混ぜてはいけないこと：Sui の本番ネットワークの資産と、EVE の操作が同じ処理でつながっているとは言えません。本番での公開日は見つかりません。

### Eternum

- 今の配置：Starknet 系です。固定 SHA の README は、次の 2 つを分けています（17a）。
  - shard ごとの Starknet のアプリチェーン（native Cairo／Madara）
  - 価値を扱う Starknet の本番の層
- 混ぜてはいけないこと：すべての操作が本番の同じ状態の上で組み合わさる、と単純化しないこと。live の配置の全経路は未検証です。

### Wylls

Solana と互換のチェーンです。段階は 3 つに分かれます【main で確認：README】。

| 段階 | 状態 |
|---|---|
| devnet | 最初の版が、devnet で 1 シーズン動いた（注） |
| ローカル | 作り直した今の版は、ローカルのテストチェーンとテスト用 USDC だけで動かしている |
| 本番 | 本番ネットワークと本物の USDC は、法的な確認を条件にした **計画** |

混ぜてはいけないこと：ローカル／devnet で確かめたことと、将来の本番の資産への接続を分けます。

注：最初の devnet の版は、ブランチ `codex/magicblock-playable` にあります。

## 9.4 4 つの面で分ける

### 技術的な実現のしかた

- EVE Frontier／Sui：所有者と版を持つオブジェクトが中心です。PTB（Programmable Transaction Blocks）は、Move の呼び出しの結果を同じ処理の後ろに渡し、全体を原子的に成功・失敗させられます。
- Eternum／Starknet 系：Cairo のアプリチェーンと、本番の価値の層を分けています。
- Wylls／Solana：CPI（プログラムからプログラムを呼ぶ）と PDA（プログラムが管理するアドレス）です。原子性は 1 つの処理の中だけです。CPI の深さ、計算の予算、同じ書き込み先の取り合いは、設計と実測の課題です。

### つなげるサービス

- EVE Frontier／Sui：Sui の上のサービス（接続済みかは個別に確かめる）。
- Eternum／Starknet 系：Starknet の上のサービス。ゲームの外の売買所（Agora）など。
- Wylls／Solana：Solana の上のサービスです。ただし、**つなげられる（可能性）** と、つないだ（実装）は別です。

Wylls の「つないだ」と「つなげられる」は、次のように分かれます。

| 区別 | 中身 |
|---|---|
| つないだ（実装） | 今の版で動いているのは、ローカルのテスト用 USDC の参加費と賞金の道まで。最初の devnet の版は、MagicBlock の ephemeral rollup と x402 を使った【main で確認：README】 |
| つなげられる（可能性） | Solana の上のサービス。つないだことにはならない |

### 既存のウォレットと資産

- EVE Frontier／Sui：Sui のウォレット。本番の USDC は Sui にもあります（Circle の一覧、17a）。
- Eternum／Starknet 系：Starknet のウォレット。本番の USDC は Starknet にもあります（同）。
- Wylls／Solana：Solana のウォレット。本番の USDC は Solana にもあります（同）。手数料を別の人が払う設計もできますが、実費と濫用の負担は残ります。

### ユーザーと開発者の入口

- EVE Frontier／Sui：Move。施設の拡張と、コードを書かない外部の道具（第8章の教訓 3）。
- Eternum／Starknet 系：Cairo／Dojo の歴史。AI の実行プログラム、拡張のひな形。
- Wylls／Solana：Rust のプログラム。すでに Solana を使う人が、別のチェーンへ移らずに参加できる入口です。これは **獲得の仮説** で、利用者が増える証拠ではありません。

## 9.5 言ってはいけないこと

> 次の言い方は、Wylls の説明に使いません。あわせて、原子性の限界も書きます。

- 「原子的な組み合わせは Solana だけ」：誤りです。Sui の PTB も、1 つの処理の中で原子的です。
- 「USDC は Solana 専用」：誤りです。Sui と Starknet の本番にも、Circle の USDC があります。
- 「他のチェーンでは技術的に不可能」：言えません。違いは、利用と外部の開発が成り立つかを測ってから評価します。
- 複数ターンにまたがる補給の履行は、どのチェーンでも 1 つの処理の原子性では守れません。各段の事実を、別々に記録する必要があります（27a）。

## 9.6 Wylls で試せること【検証する候補】

どれも 17a の提案で、検証する候補です。実装の実績ではありません。

1. 工場・輸送・予約の公開の入口を、Solana の上の他の開発者が自分の道具に組み込めるようにする。
   - 候補は、CPI で呼べる公開の機能と、PDA で管理する限定の権限（対象の機能、期限、予算）。
   - 注文ごとの権限と予算の検査は、Wylls 側で作る必要がある。
2. 別ブランチの AI 予算（agent-wallet）とつなぎ、人間と AI が同じ検査の入口から、絞った権限で注文する。
   - 推論の費用と処理の手数料を分ける。
   - 停止、撤権、重複の防止を設計する（[第6章](06-humans-and-ai.md)）。
3. すでに Solana を使う人が、別のチェーンへ移らずに参加できる入口を作る。

17a の説明の候補「Solana の共有経済基盤の上で、プレイヤーが作った機能を他者や AI が再利用する文明戦略ゲーム」も検証する候補で、採用していません。
