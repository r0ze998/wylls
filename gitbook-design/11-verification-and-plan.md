# 第11章 試作と検証、開発順序

この章で分かること：

- 補給網が、なぜ「決まった機能」ではなく「確かめる候補」なのか
- 試作で答える 6 つの問いと、合格・見直しの兆し
- 最小の試作の形と、その中で起こす場面
- 開発の順序と、試作の結果による分かれ道（合格なら 3a、退けたら 3b）

この章は、「他人の能力を組み合わせる」遊びが **普通の交易より面白いか** を小さな試作で確かめ、その結果で開発の順序を決める計画です。

補給網（再設計の文書 27a の案）は、その体験を確かめる候補の一つです。【検証する候補】であり、採用は決まっていません。チェーン、バックエンド、画面の詳細は [付録C](appendix/c-developer-spec.md) にあります。

- 補給網は、次の場合にだけ採用を考えます。他者への依存が新しい戦略や対人の関わりを生み、直感的に選べて、因果が分かる場合です。退屈な管理作業、クリックの短縮、合成を見せるだけの機能は、合格にしません。
- 27a の「比べて判定する」やり方を採るかは、試作を始める前に決めます（Q-A1）。

## 11.2 何を確かめるか

27a の体験の仮説は、次のとおりです。

> 他人が作った仕組みを使って、さらに別の人が使える仕組みを作る。その依存関係が戦争の判断を変える。

ここで **合成** とは、他人の工房と自分の倉・輸送をつなぎ、第三者が注文できるサービスとして公開することです。合成したサービスをさらに部品にすることを **再合成** と呼びます（[付録A](appendix/a-glossary.md)）。

これを 4 つの役で表します。例の人物は [第4章](04-scenarios.md) と同じです。

| 役 | すること | 例 |
|---|---|---|
| A | 工場の生産枠を公開する | アオイの工房 |
| B | A の **実際の生産枠** と自分の倉・運搬を組み合わせ、「指定の砦に兵器を届ける」補給サービスを公開する | カイ |
| C | B のサービスを、自分の軍の運用に組み込む | エマ |
| 敵 | 道を封じる | フジ |

注：

- A が公開する生産枠には、受け取る材料、料金、使える枠、引き渡しの予定時刻が含まれます。
- B が兵器を買って並べ直すだけでは、確かめになりません。A の生産の能力そのものを使うことが条件です。
- A の工場が止まると、B の履行と C の補給に響きます。
- 敵が道を封じたら、B と C は、迂回、別の工場、備蓄、護衛、作戦の変更のどれを選ぶかを考えます。

狙いは物流の管理を増やすことではありません。**他者への依存が戦略と駆け引きを生むこと** です。

## 11.3 試作で答える問い

あなたが示した 6 つの問いを、最上位の判断基準（①〜⑤）と 27a の判定の表に対応させます。数値の目標ではありません。試作を見て判断するための問いです。

### 問い 1：運営の指示なしに、他人の能力を使う分業が生まれるか（基準 ②）

- 合格の兆し：A の設備 → B のサービス → C の利用が、自然に起こる。
- 見直しの兆し：チュートリアルの再演や、報酬目当ての自己利用だけになる。

### 問い 2：補給や依存先の変化で、戦い方が変わるか（基準 ①②）

- 合格の兆し：工場の停止や道の封鎖で、迂回、別の工場、備蓄、護衛、作戦の変更に判断が分かれる。補給網を断つ戦い、守る戦いが起こる。
- 見直しの兆し：依存が、ただの待ち時間になる。

### 問い 3：新しく来た人にも、他人から選ばれる役割があるか（基準 ②）

- 合格の兆し：不足を見つけ、小さなサービスを作って選ばれる。
- 見直しの兆し：自前で作るか、古参に従うしかない。

### 問い 4：自前で全部作ることが、いつも最適にならないか（基準 ①）

- 合格の兆し：価格・時間・危険・容量・相手との関係で、選択が分かれる。
- 見直しの兆し：いつも自前になる。または、いつも同じ最安値だけが選ばれる。

### 問い 5：AI なしの手動のプレイでも面白いか（基準 ①）

- 合格の兆し：手で遊んで、交易だけの版より判断が増える。
- 見直しの兆し：手では面白くなく、AI に任せて眺めるだけになる。

### 問い 6：待ち時間や設定作業が増えただけになっていないか（基準 ③）

- 合格の兆し：失敗の理由（どこで、誰の何が止まったか）を、参加者が画面から答えられる。
- 見直しの兆し：設定画面が主役になる。合成が、クリック数を減らすだけになる。

世界観とビジュアル（④）と、チェーンの接続性（⑤）は、この試作では扱いません。

### 数え方の注意（27a）

- 運営の Bot の注文、自己取引、同じ人の複数アカウントは、独立した第三者の採用と分けて数えます。
- 第三者の再利用の率は、試作で見る値です。**賞金の条件ではありません。**
- 使われた回数や売った量を賞金で数えないことは【決定済み】です（[第7章](07-economy-and-continuity.md)）。利用回数や取引額を賞金に結び付ける案は、自己取引による水増しを検討しないまま採りません。

## 11.4 試作の形【提案】

27a の最小試作を元にします。

| 項目 | 中身 |
|---|---|
| 世界 | 小さな地図、2 つの供給の拠点、1 つの前線。材料 1 種、補給品 1 種。工場・倉・輸送。危険な近道と安全な遠回り |
| 他人を使う理由 | 立地、建設時間、設備容量を基本の制約にする（[第3章](03-facilities-and-offers.md)）。値は試作の中だけの仮の値 |
| 範囲 | 27a の 4 段階のうち、3（他者の能力の利用）と 4（合成）を **一段だけ**。再合成は合格の条件に含めない |
| 入れないもの | 任意のコード、無限の再合成、新しいトークン、融資、保険、汎用の裁判、何十種類もの建物、AI |
| 比べ方 | 同じ補給の課題を、**手の交易だけの版** と **合成ありの版** で遊ぶ |
| 作り方 | チェーンなしで作る（ブラウザだけの小さな世界） |
| 画面 | 判定のための仮のもの。製品の画面とは分ける（[第5章](05-ui-map.md)） |

注：チェーンなしで作るのは、一番の不確かさが技術ではなく「面白いか」だからです。計算量や検証に費用をかける前に、安く早く確かめます。

### 試作の場面

| 場面 | 起こすこと | 見ること（問いの番号） |
|---|---|---|
| 始まり | 前線の砦（エマ）で兵器が足りない。アオイの工房に空きの枠がある。カイは施設を持たない | カイが組み合わせたサービスを、エマ以外の人も使うか（1） |
| 手の交易との比較 | 同じ課題を、合成なし（物の売買だけ）で遊ぶ | 合成した版で、新しい戦略が出るか（4、6） |
| 工場を止める | アオイの工房を止める（燃料切れ、奪取） | 待つ以外の手が出るか（2） |
| 道を封じる | フジが近道に柵を建て、塔で削る | 迂回、護衛、作戦の変更に判断が分かれるか（2） |
| 新しい人を入れる | 新しい参加者を途中から入れる | 小さなサービスを作り、選ばれるか（3） |
| AI なしで遊ぶ | 全員が手で遊ぶ | 面白いか（5） |

## 11.6 開発の順序【提案】

試作の判定で道が分かれます。全体の流れは次のとおりです。

```
順 0 記録をそろえる
  ↓
順 1 段階 1 を仕上げる  ─┐（並行してよい）
順 2 手で遊ぶ最小試作  ─┘
  ↓ 11.3 の 6 つの問いで判定
  ├─ 合格 → 順 3a 生産枠と注文を S1 の世界へ
  │            ↓
  │          順 4 AI を加える
  │            ↓
  │          順 5 広げる
  └─ 退ける → 順 3b 別の道へ（その後の順は、選んだ道によって決め直す）
```

### 順 0：記録をそろえる

- 作るもの：段階 1 の実装の承認（Q-P1）と、試作の判定のやり方（Q-A1）を決定ログに書く。分かれたブランチ（比較・補給網の候補、この原稿）を main と合わせる（Q-P5）。
- 状態（2026-10-27）：未着手。段階 1 は main に入ったが、承認の行はまだない。

### 順 1：段階 1 を仕上げる

- 作るもの：段階 1e の手順 2〜5 と、段階 1f の画面。
- 理由：前線と封鎖の遊びは、補給網を採るかどうかに関わらず要ります。
- 状態（2026-10-27）：作るものは main に入った【実装あり：S1】。S1 のシーズンを、人・ボット・AI で最後まで遊んだ【実地で確認】。残りは次のとおり。
  - 画面に出していないもの：国内の襲撃、他人宛ての送り。
  - 実地で通していないもの：砦、続く包囲、略奪で奪って家へ運ぶ、戻す提案、AI の S1 の候補。
  - 新参の守りの「育ったら切れる」（11.8）。
  - オーナーの判断：砦が戦う相手（Q-F10）。

### 順 2：手で遊ぶ最小試作

- 作るもの：11.4 の試作。
- 順 1 と並行してよい：チェーンを使わないためです。
- 次へ進む条件：11.3 の判定。
- 状態（2026-10-27）：未着手。

### 順 3a：合格なら、生産枠と注文を S1 の世界へ

- 作るもの：
  - 生産枠を持つ施設（1 回ごとの作業を予約できる）
  - 注文の状態（受付 → 材料・能力の確保 → 加工 → 輸送 → 到着／失敗）
  - 二重予約を防ぐ容量の会計
  - サービスの公開と注文
- 先にすること：11.7 の 5 項目を決め、採用を決定ログに記録する。
- 次へ進む条件：段階 1 の世界で、手の試作と同じ遊びが出るか。計算量と検証が収まるか。

### 順 3b：退けられたら

- 次のどれかに進みます。
  - 決まった段階 2〜4 の順番のまま進める。
  - 27a の B 案（都市の共同生産）か C 案（利用権の束ね）に戻る。
  - 別の体験の仮説に戻る。

### 順 4：AI を加える

- 作るもの：27a の 2 つの役割。
  - 設計の提案：人が採用前に確かめる。
  - 限定の運用：予算・権限・期限の中で、予約や代わりの調達をする。撤権、予算切れ、所有者の停止、モデルの障害を区別して記録する。
- 始める時期：AI なしの循環が面白いと確かめた後。
- 次へ進む条件：AI が全部組んで、人が眺めるだけになっていないか。

### 順 5：広げる

- 作るもの：再合成、テンプレート、写す、地図と検索、持ち主の札、戦期。
- 次へ進む条件：二段の再合成が自然に起こるか。

### 補給網を採用する場合の、決まった段階 1〜4 との関係

段階 1〜4 は、再設計が示した作る順番です（1：兵器・倉・荷車・襲撃・塔／2：札と交換／3：決まり／4：まとめて公開・検索・写す）。

| 補給網で要るもの | 決まった段階での位置 | 扱い【提案】 |
|---|---|---|
| 他人の工場の生産枠を使う | 段階 2 の使用権の札（1 日○回） | 生産枠の予約として先に作る。使用権の札の決定（条件の変更は新しい札だけ、など）を引き継ぐ |
| A の枠と B の倉・運搬をつなぐ | 段階 3 の決まり（合図 → すること） | 「材料が届いたら加工、できたら送る」に要る合図だけを先に作る |
| B のサービスを第三者に公開し、C が注文する | 段階 4 のまとめる・公開 | 公開と注文だけを先に作る。検索、テンプレート、写す、持ち主の札は後 |

段階の順番と中身、この表のように段階の一部を先に作ることは【提案】です。入れ替えるかは、決定ログに記録して決めます（Q-A3）。

## 11.7 採用する場合に先に決めること（27a の 5 項目）

27a は、採用する場合にだけ、次の 5 項目を決定ログへ移して仕様にするとしています。この文書の推奨を添えます【提案】。既存の決定と照らし、決まっていないところは埋めずに残します。

### 1. 誰の資産と能力を、いつ確保するか

- 対象：材料、工場の枠、倉の枠、輸送の枠、期限、キューの上限、価格の版、解放の条件。
- 推奨：
  - 工場の枠は、材料が工場の倉に届いてから確保する。届く前は「予約の見込み」として表示だけする。
  - 注文の時点で、料金・条件・使うサービスの版を固定する。
  - 1 人が同時に持てる予約に上限を置く。
- 既存の決定との関係：条件の変更は新しく出す札にだけ効く【決定済み】と合います。

### 2. 途中で壊れたとき、誰が何を失うか

- 推奨：
  - 事実を別々に記録する。
  - 加工済みの品は、注文者の物として工場の倉に残す。
  - 輸送中の品は、襲撃の規則（奪う・焼く）に従う。
  - 返すのは、まだ実行していない段階の料金だけ。
  - 保険や保証で失敗を隠さない。
- 既存の決定との関係：施設が奪われたときの使用権の札は【未決定】です（Q-F5）。返金と、占領時の預かり品は、27a も未決定としています。

### 3. 権限が変わったとき、どうなるか

- 推奨：
  - 停止は新しい注文にだけ効く。受注済みの注文は、物理的にできる限り履行する。
  - 工場が奪われたら、受注済みの注文は「履行不能」として記録する。
- 既存の決定との関係：倉が奪われたら札は無効、中身は奪った側【決定済み】。施設の場合は Q-F5 と合わせて決めます。

### 4. 参加者に何を見せるか

- 推奨：仕組みの説明書に、生産枠の空き、道の危険、依存先、失敗の理由、代わりの工場を加える。
- 既存の決定との関係：仕組みの説明書は、システムが自動で書き、作者の説明とは分けて表示します【決定済み：段階 4】。

### 5. 遊びとして合格か

- 推奨：11.3 の 6 つの問いで判定する。

### 27a も決めていないこと

賞金への接続（注文を、戦争の消費の記録にどうつなぐか）と、AI の予算・停止・権限は、27a も未決定としています。この章でも埋めません（Q-M3、Q-M1、Q-H1〜H3）。

## 11.9 技術の危険

- **複数ターンにまたがる履行。** 受付から到着までを、一回の成功として扱えません。各段の事実を別々に記録する必要があります（27a）。どのチェーンでも、1 つの処理の原子性では守れません（[第9章](09-chain.md) 9.5）。
- **容量の会計。** 同じ枠の二重予約を防ぐ会計が要ります。荷車には、積載の容量と分割がまだありません。
- **他人宛ての送り。** S1 は、他人の村や倉への送りに財布の署名を求めます。サービスが他人の砦へ自動で送るには、署名の扱いを決める必要があります（Q-F8）。
- **計算量。** 戦いの処理の余裕は約 3% です。行き先を明かす処理（コードでは Reveal）は、S1 の上限 28,000 に対し、建物の判定を入れた最悪値が 27,586 です（段階 1e のメモ）。S1 の村の清算（兵器、鉱石、休眠）で、収穫・建設・訓練が以前の上限を超えたため、清算する 14 の命令に 20,000 の余裕を足しました（最悪値 32,371、2026-10-26）。
- **検証ツールの作業量。** 命令 1 つあたり、12〜15 か所の作業が要ります（段階 1 の実装計画）。
- **AI。** モデルを使った AI 市民は、96 ターンで 16〜18 回、自分から行軍しました【実地で確認】。ただし、S1 の候補（隊商、待ち伏せ、護衛）は条件がそろわず出ていません。限定の運用が働くかは、順 4 で確かめます。

## 11.10 最初の一歩【提案】

1. **段階 1 の実装の承認と、試作の判定のやり方を決定ログに記録する**（Q-P1、Q-A1）。あわせて、砦が戦う相手（Q-F10）と、工房と鉱石の釣り合いを当面今のままにすること（Q-B1）も記録する。
2. **段階 1 の残りを仕上げる。** 1e と 1f は main に入りました。残りは、国内の襲撃と他人宛ての送りの画面、実地でまだ通していない遊び（砦、続く包囲、奪って運ぶ、戻す提案、AI の S1 の候補）、新参の守りの切れる条件です。
3. **並行して、手で遊ぶ最小試作を作る。** ブラウザだけの小さな世界で、手の交易の版と合成の版を比べます。
4. **11.3 の 6 つの問いで判定し、補給網を採るかを決める。** 採るなら、11.7 の 5 項目を決めてから S1 の世界へ移します。
