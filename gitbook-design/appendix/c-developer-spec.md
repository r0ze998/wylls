### 部品ごとの詳細

**ルールの版。** M1 と MC のシーズンは S1 のプログラムでは拒否し、それぞれ元のプログラムのまま動きます。プリセットは `S1_LOCAL_7D`、`S1_LOCAL_14D`、`S1_TEST` です。

**工房。** 持ち主の村の中で、材料を連続して変換します。材料が尽きる時刻を計算し、その後は、足りない材料の生産で支えられる割合（切り捨て）まで落ちます（経路に依らない精算）。兵器が上限でも、材料は使われます。

**地形の鉱石。** 基本 4/時に、同じ州の半径 2 の丘 1 マスごとに 2、山 3、鉄 4 を足します。地形の分の上限は 30/時で、合計で最大 34/時です。村の作成時（前哨と自由都市の奪取を含む）に計算し、村のデータに保存します。

**倉。** 置けるのは通れるマスで、村の場所・砦・野営地でないところです。1 マスに 1 つまで。生産も劣化もしません。

**荷車。** 移動には、行き先を隠した進軍の 1.5 倍の時間がかかります（潮の国は 0.8 倍）。1 州に 5 台、1 州に 8 ターンまでです。

**命令（倉と荷車）。** 0xB0 BuildVault、0xB1 SendCaravan、0xB2 SettleCaravan（誰でも）、0xB3 RaidCaravan、0xB4 SeizeVault、0xB5 CloseVault（空のときだけ、財布）、0xB6 DefaultRaid（誰でも）。

**他人宛ての送り。** 行き先が自分の村や倉でなければ、財布の署名が要ります。ゲーム用の一時的な鍵は拒否します。

**届け。** 倉には上限まで入り、超えた分は失われます。行き先がなくなっていれば、荷は全部失われます。手数料は決着させた人へ払われます。

**戦いへの参加。**

- 荷車は、ターンの始まりに立っているマスで、0 人の守備として、州の守備が 12 未満のときだけ戦いに加わります。
- 同じマスの味方が護衛になります。
- 村の場所・野営地・砦・先の荷車のマスでは、戦いに加わりません（守られる）。
- 同じ国の荷車は、戦いでは味方として扱うので襲われません。国内の襲撃は、段階 1e の手順 3 の命令（RaidDomestic）で起こします（下）。

**襲撃。**

- 奪う：荷車ごと持ち主と国が移り、襲った側の場所へ道を変えます（J2）。
- 焼く：荷を空にして、そのまま進みます。
- 決める猶予は 6 ターンです。猶予の後は DefaultRaid で、襲った側の村へ持ち帰ります。
- 襲った側の村がなくなっていれば、すぐに焼きます。帰る道がなければ、猶予の 144 ターン後に焼けます。

**見張り塔。**

- 命令は 0xB7 BuildTower、0xB8 SeizeTower、0xB9 CloseTower です。
- 同じ州の半径 2 を見ます。
- 国の構えが「戦い」の国を削ります。構えは国の投票で変えられます（初めは全部「戦い」）。「通す」の構えの塔は削りません。
- 敵の範囲を歩いた 1 分ごとに 1%（最大 30%）削ります。
- 判定は、進軍では行き先を明かす処理（Reveal）のとき、荷車では道が決まったときです。待っている軍は削りません（J4）。
- 塔の燃料と維持費は、まだありません。知らせる相手の設定（持ち主だけか、国全体か）で、読み取りのサーバーが知らせの宛先を分けます。

**建物（段階 1e の手順 1）。**

- 見張り塔を「建物」の 3 種（塔 1、柵 2、砦 3）に広げました。上限は 1 人あたり塔 2・柵 4・砦 1 です。
- 砦は州の砦の記録を 1 つ使い、兵がいなくなった砦だけを奪えます。
- シーズンに国の構えの表（全部 0 は全部「戦い」）を、村に追放の印を持ちます。
- 止める規則は 1 つです。国 N の建物は、構えが「戦い」の相手と、N から追放された村を止めます。
- 止める塔は削り、止める柵はそのマスをふさぎます。軍は行き先を明かす処理の時点で、荷車は送る時点で断ります。
- 砦は歩みに影響しません。

**国の投票（段階 1e の手順 2）。**

- 命令は Propose、Vote、SettleProposal です。提案は 3 種（他の国への構え、追放、戻す）。国ごとに 4 つの枠があります。
- 1 村 1 票。国に入って 288 ターンで投票権、144 ターンで締め切り、賛成 3 票以上かつ反対より多ければ可決です。1 人が同時に出せる提案は 1 つです。
- 追放された村は、432 ターンたつと戻す提案ができます。

**国内の襲撃（手順 3）。** RaidDomestic は、同じ国の荷車が立っていたマスに、襲う側の軍が立っていたことを示して襲撃を開きます。決着は RaidCaravan か DefaultRaid です。

**砦攻めの兵器（手順 4）。** DeclareSiege は、預けの金に加えて兵器 50 を使い切ります。

**砦（手順 5）。** FortGarrison で、控えの槍兵を砦に入れます（最大 2,000）。守備隊のいる砦は、戦いに村の守備と同じ形で加わり、そのマスにいる他の国すべてと戦います（構えの止める相手だけと戦う契約の案は、オーナーの判断に戻されている）。兵が 0 になった砦は奪えます。

**画面と AI の候補（段階 1f）。** 画面は、タイルのカード（貯蔵庫、塔、柵、砦、奪う、包囲、追放）、村の画面（隊商、要塞の守備隊、国の議会）、地図の印（倉、建物、荷車とその到着、襲撃で止まった荷車）です。AI の頭脳は、隊商、待ち伏せ、護衛の候補を出します。

**計算量。** 塔は戦いの処理を変えません。S1 の行き先を明かす処理（Reveal）の上限は 28,000 です。村を清算する 14 の命令には、S1 の清算のために 20,000 の余裕を足しています（2026-10-26）。

**読み取りのサーバー。** 倉、荷車、建物、国の流れ（`h/caravans.json`、`h/structures.json`、`h/nations.json`）があります。開いている襲撃は、流れでは決着してから示されます。画面は、州の記録から読んで示します。

## C.3 段階 2 以降のデータの形【提案】

再設計の組み込みの章の考え方（札はゲームのプログラムの中の記録として持ち、汎用のトークンにしない）に沿った、論理的な形です。

```
Ticket（札）
  id, kind(share|receipt|use|proxy|owner), issuer(倉 or 施設 or 仕組み), holder
  terms{ amount, period, per_day, expires_at, refund_on_stop? }
  issued_at, valid(倉や施設が奪われたら false)
  acc_per_share（持ち分の札：受け渡しのたびに配分を清算するための累計）

Escrow（引き換えの預かり）
  id, side_a{owner, items[]}, side_b{owner, items[]}, deadline
  state(open|settled|returned)

StandingOffer（出しっぱなしの申し出）
  id, vault, give{kind, qty}, take{kind, qty}, audience(all|nation|list)

Rule（決まり）
  id, owner, vault, trigger(time|amount|arrival|public_fact|own_tower)
  action(send{to, kind, qty, fixed_path} | operate{facility, ticket, times})
  prepaid_fee, state(active|stopped|failed), last_failure

Mechanism（仕組み）
  id, name, parts[](倉・札・決まりの id), owner_ticket, copied_from?
  sheet（仕組みの説明書：自動生成）, author_note（作者の説明：別）
  record{ sent, failed, raided }
```

## C.4 決定を検査に直す【提案】

検証ツールに足す検査の案です。命令を 1 つ足すたびに検証と AI の候補も足す、という再設計の方針に合わせます。

| 決定 | 検査 |
|---|---|
| 無から増えない | 各ターンで、すべての置き場の資源の合計の変化 ＝ 生産 ＋ 工房の出力 − 工房の入力 − 消費 − 失われた分 |
| 許可なく触れない | 倉や施設を動かした命令の署名者が、持ち主か、それを許す札の持ち主 |
| 札は裏付けがないと働かない | 受け取りの札の支払いの合計 ≤ その期間の倉の中身。足りなければ割合で減っている |
| 奪われた倉の札は無効 | 奪取の後に、その倉の札で物が出ていない |
| 条件の変更は新しい札だけ | 札の支払いと動かしが、その札の発行時の条件と一致する |
| 受け渡しのたびに清算 | 持ち分の札の配分が、受け渡しの順番に依らない |
| ターンの始めにまとめて判定 | 同じターンの決まりの実行結果が、実行の順番に依らない（順番を入れ替えた再計算で同じ状態になる） |
| 前払い | 実行の手数料が前払いから払われ、尽きた決まりは動いていない |
| 失敗は止まって記録 | 実行できなかった決まりに、失敗の記録がある |
| 取り分の 5 項目 | 消費された物の出どころ（最後に出た倉）を、消費まで追える |

## C.7 組み込みの危険

出典は、再設計のまとめと独自性の文書（17 の 3-5）と、段階 1 の実装計画です。挙がっている危険は次のとおりです。

持ち分の配当の清算、実行役の順番の力、小さな送りの嫌がらせ、空の倉の乱立、奪われた倉の札、国を移る人の札、札と賞金とお金の規制、検証ツールの手間、遅延計算との相性（自動の流れの両端を同じ時刻で計算する）、計算量の余裕。
