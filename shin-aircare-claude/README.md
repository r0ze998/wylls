# 真 −SHIN− エアコンクリーニング｜Claude版サイト

店舗・オフィスなど法人向けのエアコンクリーニング会社「真 −SHIN−」のウェブサイト案です。
別のAIで作られた案（比較対象）とは独立に、構成・デザイン・文章を一から起こしています。
他のディレクトリ（Rust / Solana のプロジェクト）には触れていません。

- 比較・検証・参考サイト分析の詳細: [docs/REVIEW.md](docs/REVIEW.md)
- スクリーンショット: [docs/screenshots/](docs/screenshots/)

## 起動手順

ビルド不要の静的サイトです。任意の静的サーバーで `shin-aircare-claude/` を配信してください。

```bash
cd shin-aircare-claude
python3 -m http.server 8080
# → http://localhost:8080/index.html
```

Node を使う場合: `npx serve .` でも同じです。`file://` で直接開いても表示はできますが、
Google Fonts の読み込みとクリップボード API はサーバー経由（http/https）で確認してください。

### 表示検証スクリプト（任意）

Playwright がインストールされた環境で、PC（1440px）／スマホ（390px）／中間幅（768・1024・1200px）の
スクリーンショット撮影と、横はみ出し・文字サイズ・タップ領域・リンク・フォームの流れ・キーボード操作の自動チェックを行います。

```bash
node scripts/verify.cjs http://localhost:8080 docs/screenshots
```

結果は `docs/screenshots/verify-results.json` に保存されます（最終実行: 71/71 通過）。

## デザインの意図

**方向性: 「炭と紙」。** 黒一色ではなく、チャコール（#15171a）の帯と生成りの紙色（#f5f2ec）を交互に重ね、
ページを下るごとに明暗が切り替わるようにしました。参考サイトの Procoat（青・白・写真多用、B2C の明るさ）、
BEPPO（茶・緑・オーガニック、価格訴求）はいずれも個人向けのトーンだったため、法人担当者が社内で見せても
違和感のない、落ち着いた・専門性のある方向に振っています。

- **書体**: 見出しは明朝（Noto Serif JP）、本文はゴシック（Noto Sans JP）、英字のラベルは Inter。
  「真」という一字の社名に合わせ、明朝の見出しで誠実さ・手仕事感を出しています。本文は 16〜16.5px、行間 1.9。
- **色**: 差し色は「空気」を表す淡い水色（暗い背景上 #8fd0e2 ／ 明るい背景上 #1e6b82）。朱（#bf3b2c）は
  ブランドマークの落款と「必須」表示にだけ使い、安売り感の出る赤ボタンは使っていません。
- **写真の代わりに線画**: 施工写真・社員写真と誤認されないよう、ファーストビューは天井カセット形エアコンを
  見上げた SVG イラスト、対象設備は統一した線画アイコンにしました。「イメージ図（イラスト）」と明記しています。
  実写が用意できた段階で `hero-cassette.svg` を差し替えられます。
- **構成（上から）**: ファーストビュー → 01 担当者の困りごと → 02 対象設備と作業内容 → 03 仕事の姿勢（暗）
  → 04 ご相談から作業までの流れ → 05 見積もりに必要な情報（チェックリスト） → 06 対応エリア（暗）
  → 07 FAQ → 08 会社概要 → CTA → フッター。
  見出しのスタイル・カードの形・背景色をセクションごとに変え、「同じカードが並ぶだけ」にならないようにしました。
- **法人担当者向けの仕掛け**: 05 のチェックリストは実際にチェックでき、「チェックリストをコピー」で
  社内チャットやメールに貼れるテキストになります。「このページを印刷」は印刷用 CSS で
  ヘッダー・ヒーロー・CTA を省き、FAQ の回答も展開して出力します（稟議・社内相談用）。
- **問い合わせ導線**: ヘッダー CTA、ヒーローの主ボタン、各セクション末尾、CTA 帯、スマホでは画面下の固定ボタン。
  フォームは別ページ（contact.html）にして、入力に集中できるようにしています。

## フォーム（デモ）の仕様と本番化

現在は **送信先未設定のデモ** として動作します。

- 入力 → 確認 → 送信 の 3 段階。確認画面から「修正する」で入力値を保持したまま戻れます。
- 未入力・形式不備（メール、電話、相談内容 10 文字未満、同意チェック）は、各項目の直下と上部のエラー要約に表示し、
  要約のリンクで該当項目にフォーカスします（`aria-invalid` / `role="alert"`）。
- 送信ボタンは押下直後に無効化し（`disabled` + `aria-busy`）、二重送信を防ぎます。
- デモ時の結果画面は **「送信は行われていません。」** と表示し、「受付完了」とは表示しません。
- 入力値はページ内のメモリにだけ保持し、localStorage・Cookie・外部サービスには保存／送信しません。
- ハニーポット（非表示の `website` 欄）を備えています。

### 本番のメール送信に切り替える箇所

1. `assets/js/site-config.js` の `form.endpoint` に送信先 URL を設定します。
   空でなくなると `contact.js` はデモ動作をやめ、確認画面の「この内容で送信する」で
   入力内容を JSON（`{company, person, division, email, tel, pref, building, units, timing, message, consent, page, submittedAt}`）として `POST` します。
2. 送信先は次のいずれかを想定しています。
   - **自前のサーバーレス関数**（Cloudflare Pages Functions、Vercel、AWS Lambda など）で JSON を受け取り、
     Resend / SendGrid / Amazon SES などのメール API で担当者宛てに送る（必要なら自動返信も）。
     スパム対策として `website` 欄が空であることのチェックと、レート制限を関数側に入れてください。
   - **フォーム受信サービス**（Formspree、Web3Forms など）。サービスの受け口が `application/json` を受け付けない場合や
     フィールド名に規約がある場合は、`contact.js` の `payload` 生成部分を合わせて変更してください。
3. `contact.js` は **2xx 応答のときだけ**「送信しました。」を表示し、それ以外は確認画面にとどまりエラー文を出します。
   15 秒で時間切れとして扱います。
4. 本番公開前に `contact.html` の `<meta name="robots" content="noindex">`（デモ用）を外すか判断してください。
5. 「入力内容の取り扱い」の同意文は、プライバシーポリシー公開後にリンクを追加してください。

## 自分で弱いと思う点

- **写真がない。** 法人担当者が最後に見たいのは「実際の現場での仕事ぶり」で、線画では伝えきれません。
  実写（養生の様子、分解した部品、作業後の確認）が 3〜4 枚入るだけで説得力は大きく変わります。
- **暗い背景の割合が高く、印刷やスクリーンショットでの社内共有に向かない箇所がある。**
  印刷用 CSS で白地に変換していますが、Web 上の見た目をそのまま共有したい場面では不利です。
- **スマホのページが長い**（約 17,000px）。チェックリストと設備一覧が主因です。内容を削らずに畳む
  （アコーディオン化）選択肢もありますが、「一覧で見渡せる」利点を優先しました。
- **文章量が多め。** 確約を避けるため「ご相談時に確認します」が繰り返し登場し、ややくどい箇所があります。
  条件が確定すれば短く言い切れます。
- **ファーストビューの情報量が多い。** 見出し・説明・特徴チップ・ボタン 2 つ・注記が入っており、
  もう一段そぎ落とす余地があります。
- **検証はヘッドレス Chromium のみ。** Safari / Firefox、実機のスマホでは未確認です。

- 自動チェック 71 項目すべて通過（横はみ出しなし、本文 12px 未満なし、操作要素の高さ 32px 以上、
  ページ内リンク先の存在、画像 alt、モバイルメニューの開閉と `inert`、フォームの検証／確認／修正／二重送信防止／
  デモ結果、外部通信なし、Tab 順・スキップリンク・FAQ のキーボード操作、チェックリストのコピー）。
- 目視で確認して直した点: ヒーロー見出しの不自然な改行、暗い背景でのボタンの視認性、スマホでのイラストの順序と大きさ、

  スマホでの設備カードの縦長化（図を左に置く横長カードに変更）、10〜11px の小さな英字ラベル（12px 以上に）。
