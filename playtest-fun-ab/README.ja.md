# Wylls 比較試作：まずここから

「Wylls はゲームとして本当に面白いか」を確かめるための、遊べる比較試作と、人間のプレイテストの一式です。チェーン、財布、お金、外部の AI は使いません。インターネットも要りません。

## 1. 開くもの

| したいこと | 開くもの |
|---|---|
| **遊ぶ** | `proto/index.html` をダブルクリック（Chrome か Edge を勧めます） |
| 遊んだ記録を振り返る | `proto/replay.html` を開き、保存した JSON を選ぶ。試しに `logs/example-script-A.json`（台本で動かした例。人間の記録ではない）を開けます |
| 結論と根拠を読む | この README の 4〜7 節 → `docs/` |
| テスターに遊んでもらう | `playtest/PROTOCOL.ja.md`（進行役向け）と `sheets/` |

## 2. 遊び方（あなたが自分で比べる場合、約 45 分）

1. `proto/index.html` を開き、「何回目か」で **練習** を選んで「はじめる」。6 ラウンドで操作に慣れます。
2. 最初の画面に戻り、**1 回目・版 K・条件番号 101** で 36 ラウンド遊ぶ。終わったら 5 つの質問に答え、「答えを記録して保存」。
3. **2 回目・版 M・条件番号 202** で同じように遊ぶ（条件番号を同じにすると、相手の動きも同じになります）。
4. `proto/replay.html` で 2 つの記録を開き、ラウンドごとの自分の手と結果を見比べる。

版 K はいまのルール、版 M は「砦の数が食料・鉱石・金の基本生産を決める」ルールです（テスターには、どちらが何かを言いません）。

**操作の流れ**：「村」で建てる → 「兵」で訓練し、「軍勢を作る」 → 「軍勢」で「出発…」、行き先（地図を押しても選べる）と着く時を選んで「出発する」 → 「次のラウンドへ」。結果は「報告」に出ます。他国の出発は見えますが、行き先は着くまで分かりません。砦は、守り手のいない状態で 72 ターン（6 ラウンド）居続けると奪えます。

途中で閉じても「続きから」で戻れます。「同じ条件でやり直す」で、同じ相手・同じ揺れで最初から遊べます。

## 3. 何を見れば判断できるか

- **自分で遊ぶとき**：2 つの版で、「相手の動きを見て、予定を変えた場面」と「自分の判断が結果を変えたと感じた場面」が、どちらでどれだけあったか。振り返りの画面の「自分の場所が脅かされた次のラウンド」に軍勢を動かした割合と、それ以外のときの割合の差（反応の大きさ）も見ます。ただし、あなたは違いを知っているので、あなたの感想はテスターの結果とは分けて扱ってください。
- **判断の材料にするとき**：4〜8 人に `playtest/PROTOCOL.ja.md` のとおり遊んでもらい、`sheets/summary-template.ja.md` を埋めて、先に決めた決まり（同じ文書の「判定の決まり」）に当てはめます。

| 結果 | 意味 | 次にすること |
|---|---|---|
| 支持（3 分の 2 以上で、版 M の方が「判断が効いた場面」か「脅かされたときの反応」が多く、どちらも少なくはない。分かりにくさ・退屈・早く決まる感じが増えない） | 「砦が途中で何も払わない」ことが、面白さを削っている | 本体で「砦の保持が国の生産に効く」形（未決の OD-14 の一案）を検討。量はフェーズ 6。実時間で確かめ直す |
| 否定 | 途中の実入りは、ここでの面白さの鍵ではない | 待ち時間（H2）を実時間で調べる方へ |
| 分からない | 人数が足りない、差が小さい、など | 理由を書き、試作か人数を直してもう一度 |

## 4. 現行ゲームの評価（要約）

詳しくは [docs/02-EVALUATION.ja.md](docs/02-EVALUATION.ja.md)。

- 人間がこのゲームを遊んだ記録は、まだ一つもありません（設計の診断の文書 C6）。以下はルールとボットからの見立てです。
- **残す価値がある芯**：行き先を封じた進軍と、砦の取り合い。見えるもの（出発・数・着く時刻）と隠れるもの（行き先）の分け方がはっきりしていて、戦いの計算も説明できます。
- **弱めているもの**：
  1. 戦いに勝っても、砦を取っても、途中で何も得ない。結果が次の手に返らない（征服の契約 R-10「止める級」、未決の OD-14）。
  2. 待つ時間が判断よりずっと長い（出発の体力 74、占拠 12 時間、格上げ 6〜24 時間）。
  3. 解散すると兵がどこからでも次のターンに村へ戻り、作り直した軍勢は体力満タン。体力の待ちを飛ばせ、守りがいつでも間に合う（コードで確認）。
  4. 維持費がなく、兵をためるのが常に正解。途中参加者に意味のある役割がない。
  5. 交易と協力（S1 の荷車・襲撃）は、画面がなく誰も遊べない。

## 5. 検証した仮説と、A/B の違い

仮説は 3 つに絞り、試作で確かめられる 1 つを選びました（[docs/01-HYPOTHESES.ja.md](docs/01-HYPOTHESES.ja.md)。試作の前に書き、変更は理由つきで記録）。

- **H1（選んだ）戦果が次の手に返ってこない** → 版 M で、砦の数が食料・鉱石・金の基本生産を決める（3 つでいまと同じ量。世界全体の量は変えない）。
- H2 待ちが判断より長い → 時間を縮める試作では確かめられない。実時間のテストで。
- H3 他人への依存が判断を生む → 複数の人間が要る。補給網もここに入る。

A/B で **変えたのは 1 点だけ** で、地図・初期資源・相手・画面・戦いの計算は同じです。砦が 1 つも動かない試合は、A と B で最後まで同じ結果になることを自動テストで確かめました。再現していないこと（時間を縮めた、規模、S1 の荷車など）と比較の限界は [docs/03-AB-DESIGN.ja.md](docs/03-AB-DESIGN.ja.md)。

## 6. 実行したテスト（すべて再現できます）

[docs/04-TESTS.ja.md](docs/04-TESTS.ja.md)。`node --test tests/` で 13 件、すべて合格。

- 試作の戦いの計算は、ゲームのコード（`combat::resolve_engagement`）と 400 件で一致。
- 120 試合のランダムな操作で、資源・兵の総数の保存・体力・進行不能のなさを確認。作る途中で 2 つの誤りを見つけて直した。
- 測った値は、相手の手を台本で決めた試合で、手で数えた値と一致。
- ボットどうしの総当たり（版ごとに 1,280 試合）：一つの方針がいつも勝つことはない（攻めの方針が混合の試合の約 6 割）。最初に砦を奪った国が勝つ割合は A 68%・B 71% で、事前に決めた否定の線 80% より下。人間の席では、守るだけ・ゆっくり育てるだけの方針はほぼ勝てず、攻め続ける・守ってから取り返す、の 2 つが 23〜32% 勝つ（3 か国なので互角なら 33%）。
- 解散して作り直す抜け道（F2）を使うボットも試したが、解散を使う場面が 1 度も生まれず、**抜け道は試せていない**。
- **ボットの結果は、人間にとって面白いかの証拠ではありません。** 人間の結果はまだありません。遊ぶ時間（10〜20 分）も、人ではまだ測っていません。

## 7. 分かったこと・まだ分からないこと・次の判断事項

**分かったこと**

- いまのルールの戦いの計算は、そのまま小さな試作に移せ、説明できる。
- 「砦が途中で何も払わない」「解散で兵が瞬時に戻る」「維持費なし」は、コードで確認した事実。
- 縮めた試作でも、攻める・守ってから取り返す、の複数の方針が戦え、後半にも砦が動く（ボットの範囲で）。

**まだ分からないこと**

- 人間が、封じた進軍の読み合いを楽しむか。版 M で判断が増えるか（プレイテストが要る）。
- 実時間の待ちがどれだけ苦痛か（H2）。
- 人どうしの依存が判断を生むか（H3）。

**あなたが決めること**

1. このプレイテストを、誰に、いつ行うか（連絡はしていません）。
2. 解散で兵がどこからでも瞬時に戻り、作り直すと体力満タンになるのは、意図した仕様か。
3. 維持費 0 は意図か（ルールの核には 2 乗の維持費がある）。
4. H2 を実時間で確かめるか（既存の core-playtest の手順を使えます）。
5. H3 のために、S1 の画面を先に作るか、複数人で遊ぶ別の小さな試作を作るか。
