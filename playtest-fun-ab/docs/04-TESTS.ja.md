# 自動の検証：何を確かめ、何は確かめていないか

**自動の検証は、ルールの整合、進行不能、一つの正解の有無、単純な悪用、測り方の正しさを見るものです。人間にとって面白いかは、ここからは何も言えません。** ボットの成績がよくても、それは面白さの証拠ではありません。

## 実行のしかた

Node.js 20 以上で、`playtest-fun-ab/` の中から：

```bash
node --test tests/
```

```bash
node tools/tournament.js 20
```

```bash
node tools/resource-check.js
```

```bash
node tools/example-logs.js
```

総当たり（約 80 秒）、資源の確認、例の記録は、`logs/` の同じ名前のファイルを上書きします。同じコマンドなら同じ数字が出ます。

戦いの計算の突き合わせの元データ（`tests/fixtures-combat-oracle.jsonl`）を作り直すには Rust 1.89 が要ります（`tools/combat-oracle/`。ゲームの `permutation-rules` をそのまま使います）：

```bash
cd tools/combat-oracle && cargo run --release --quiet -- 400 > ../../tests/fixtures-combat-oracle.jsonl
```

## ボットどうしの総当たり（`logs/TOURNAMENT.ja.md`、生データ `logs/tournament.json`）

版ごとに 4 方針の 64 通りの並び × 条件番号 20 ＝ 1,280 試合、人間の席に 5 方針を置いた 300 試合、席の偏りの確認 400 試合。

| 見たこと | A 版 | B 版 | 読み方 |
|---|---|---|---|
| 一つの方針がいつも勝つか（混合の試合の勝ち分） | 攻め重視 60.6%、取り返し 42.0%、釣り合い 24.0%、守り重視 6.7% | 63.1%、41.3%、22.1%、6.8% | 攻めの方針が強い。どちらの版でも「いつも勝つ」ほどではない。守るだけでは勝てない（勝ち負けが砦の数なので、意図どおり） |
| 席の有利（同じ方針どうし：青・赤・黄） | 29.2 / 37.3 / 33.5%（80 試合）、34.2 / 29.0 / 36.8%（別の 400 試合） | 26.7 / 40.4 / 32.9%、32.5 / 30.2 / 37.3% | 80 試合では 33% から ±10 ポイントは偶然でも出る。400 試合では赤の有利は消え、どの席もいつも有利ではない。最初の版の 44/11/44% はボットの同点の決め方の偏りで、直した。人間はいつも青の席なので、残る偏りは A と B に同じように効く |
| 雪だるま：最初に砦を奪った国が勝つ | 67.8% | 71.3% | 事前に決めた否定の線（80%）より下。B でやや強まる |
| 雪だるま：ラウンド 18 の首位が勝つ | 60.2% | 64.8% | 後半にも逆転がある |
| 1 試合の砦の奪取 | 6.18（後半 3.57） | 6.47（後半 3.78） | 後半まで動きがある |
| 人間の席で、各方針の勝ち分（相手は試作と同じ赤＝取り返し、黄＝攻め重視） | 守り重視 0.6%、釣り合い 3.3%、攻め重視 23.3%、取り返し 31.7% | 0%、3.3%、30.0%、31.7% | 守るだけ・ゆっくり育てるだけでは勝てず、攻め続ける・守ってから取り返す、の 2 つは勝てるが 3 割前後。一つの方針で勝ち続けられる相手ではない（3 か国なので、互角なら 33%） |
| 抜け道（F2）を使うボットを人間の席に | 23.3%（解散の使用 0 回） | 30.0%（0 回） | このボットの動き方では解散を使う場面が生まれず、攻め重視と同じ結果。**抜け道は試せていない** |

**ボットの B は A とほとんど同じ。** これは予想どおりです。ボットは B の「砦が実入りになる」に合わせて動きを変えないので、変わるのは砦の得失による国力の差だけです。B の効果があるかは、人間が判断を変えるかどうかにかかっていて、それを見るのがプレイテストです。

## 資源の縛り（`logs/RESOURCE-CHECK.ja.md`）

ボットの国で、ラウンドの終わりにたまっている量 ÷ そのラウンドの収入：食料 1.4〜2.5 倍、鉱石 2.8〜6.5 倍、金 5.3〜15 倍、木材と石はさらに多い。方針ごとに見ると、攻め重視（1.2 倍）と取り返し（1.7 倍）は食料が一番少なく、工房を建てる釣り合い（balanced）は鉱石が一番少ない（1.7 倍）。金はどの方針でも余っている。B 版の対象を食料まで広げた理由です（[01-HYPOTHESES](01-HYPOTHESES.ja.md) の変更の記録）。

## 画面の確認（ブラウザ）

ローカルのサーバーで開き、次を確かめました。

- 36 ラウンドを最後まで画面の操作で進め、終わりの質問の画面が出る。誤りの出力なし。
- 練習（6 ラウンド）で、版ごとの規則の行が出ない。終わると「練習はここまで」。
- 途中で再読み込みしても「続きから」で同じ状態に戻る。そのラウンドの操作と考えた時間も引き継ぐ。
- 終わりの質問の画面を閉じても「終わりの質問を開く」で戻れ、「記録を保存」でも書いた答えが記録に入る。
- 記録の見返しの画面で、計算し直した結果が記録と一致し、ラウンドごとに操作・報告・ボットの手・測った値が見える。
- 幅 375px（スマートフォン）で横にはみ出さない。遊ぶのはパソコンを勧めます。

## 確かめていないこと

- 人間が面白いと感じるか（プレイテストの役目）。
- 遊ぶ時間（36 ラウンドが 10〜20 分か）。
- ボットにない戦い方（だまし、ためてから一気に、F2 の悪用）で一方の版が壊れないか。プレイテストの記録で見ます。
- 1 つの戦いより大きな単位（1 ターンの中の複数の軍勢の組み合わせ、場所の押さえ方）を、ゲームのコードと突き合わせてはいません。組み立ては `frontier/clash.rs` を読んで再現しました。到着の枠、面の軍勢の数の上限、隣のマスへの退却は省いています。
- Safari、Firefox での表示（Chrome 系のブラウザでだけ確認）。
