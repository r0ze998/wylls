状態は、次の5つのタグで示します。

- 【動いている】 コードがあり、実際に実行した。別ブランチにあるものは「ブランチ上で」と書く。

## 1. Wylls とは何か

Wylls は、AI がプレイヤーのように振る舞うゲームです。完成形は、6つの国が一つの世界を共有し、人と AI市民が並んで遊ぶ、シヴィライゼーション風のゲームです【設計のみ】。

いま動いているのは M1 です【動いている】。M1 は、最初に遊べる基本ゲームです。国を選び、村をもらい、建て、訓練し、行き先を封印した軍を出し、10分ごとの鐘で戦うところまでです。限界が4つあります。

- 動かしたのは試験用チェーン（Solana の本物のネットワークではない、ローカルの環境）だけです。
- M1 の通し走行で遊んだのはスクリプトBot（決めたルールで動く試験用のプレイヤー）だけです。プロジェクトの外の人は、まだ誰も遊んでいません。
- 通し走行は過去の乱数の値を再生したので、封印の秘密が守られるかは試していません。
- AI の走行は運営の試験用の鍵の乱数で動くので、「公開の乱数」とは言えません。

AI市民は、運営があなたの Mac 上のモデル（Gemma）で動かす AI のプレイヤーです。有料の API は使いません。別ブランチ（本体とは別に作業しているコードの置き場）で作成中で、動いたのは6体の小規模な確認走行までです【作成中】。記憶（コードが公開記録から作る出来事の記録）が AI市民の核で、ハッカソン版に入れます（決定 X1）【作成中】。ただし「覚えている」とは書かず、「引用した」と書きます。

用語。シーズン: 1回のゲームの期間。征服: 他の国の領土を奪うしくみ。評議会: 国ごとの話し合いの場で、採用された目標が「攻撃命令」になる。仕様書: AI市民の仕様書（設計書では「契約」）。

詳細: 設計書 第0章、第1章

## 3. 実行したものの数字

- M1【動いている】。ゲーム内7日（1,008鐘）を、試験用チェーン上でスクリプトBot 1,000体が最後まで遊びました。実時間は8時間39分です。記録を再生して確かめるプログラム（検証器）が144,300件の取引を通し、わざと入れた改ざん30種をすべて見つけました。検証器は自分たちのもので、外部の再生記録はありません。
- AI市民の小規模確認 smoke-b3（ブランチ上）【動いている】。AI 6体で、完了した鐘は86回です。モデルが呼ばれた判断52回がすべて有効で、検証に合格しました。ただし回数が少なく、仕様書が定める下限の300回に届きません。この合格は、後で修正した検証器では再確認していません。AI が送った操作171件のうち、モデルの判断の中で送られたものは51件（29.8%。上限値）です。大半（約64%）は、モデルの代わりに経済と日課だけを進める「自動運転」でした。
- 征服（cq-integ 上）【動いている】。プログラムの試験とシミュレータまでです。人も AI も遊んでいません。
- AI市民の統合と本番の走行【作成中】。コードは別ブランチ（ai-integ）にあり、提出するコードには未統合です。10-12 朝に統合する予定です。smoke-b4 は 10-04 夜に開始し、現在の状況は未確認です。
- AI 自身の進軍【作成中】。AI が選んだ軍が実際の衝突になった数（Y）は、本番の走行で数えるまで分かりません。smoke-b3 の 9 は、公開記録から数えた代用値です。
- 国の評議会と攻撃命令【作成中】。smoke-b3 では評議会が9回開かれ、9回とも必要な票数に届かず成立しませんでした。攻撃命令が採用された例はありません。
- 共有の文明、統治、外交、市場【設計のみ】。大枠だけを書いてあり、技術、時代、エンジンの中身は未設計です。ハッカソン後に着手する予定で、征服との順序は未決です（Q13）。
- お金（参加費、賭け金、賞金）【設計のみ】。計算のコードはありますが、ゲーム本体に入っていません。

## 4. 提出するものと日程

提出するのは、ピッチ（2分、あなたの声と顔）、デモ動画（3分以内、英語）、README（英・日）、リポジトリ、SUBMISSION.md です【作成中】。作ったものは作ったものとして出し、決めた目標は設計として出します。README は両者を分けて書きます。デモ動画の AI の場面は、AI市民を録画できた場合だけ使います。できなければ「AI市民: 設計のみ」のバナーを使います。

日程は JST の予定で、いずれも未実施です【作成中】。

- 10-08 まで: 残りの修正。AI に不正な指示を混ぜて試す試験。A/B の予行。
- 10-09 13:00〜20:30: A/B テスト（条件を変えた2通りの比較。AI 12体）。
- 10-09 21:00〜10-10 05:00: 本番の走行（AI 18体、ゲーム内3日、10倍速、約7.2時間）。
- 10-10: 報告と検証。10-11: あなたと録画。評議会の場面で、あなたが国0の席で投票します。
- 10-12 朝: AI市民のブランチを提出するコードに統合（ローカルのみ、GitHub へ送らない）。10-12 23:59 に凍結。
- 10-13 15:59 まで: 提出（あなた）。

走行が間に合わない場合は、次のとおりです。

- Y が 0 のときは、「AI が自分で軍を出して戦闘になった」という主張を外し、評議会の場面を中心にします。
- 日程が遅れたときは、決めた順に機能を削ります（反省と自己要約、A/B の2回目、人格の差の測定の順）。それでも足りず社会の層まで削る場合も、ラベル、安全策、AI の進軍、記憶、検証は残します。
- 走行が凍結までに終わらないとき、または必須の検査（引用の正しさ、判断の再生の一致）に落ちたときは、すべての文書の AI市民の節を「AI市民: この提出では未実装。設計のみ。」に置き換えます。

## 5. 書き方の規則

動いていないものを、動いているとは書きません。測っていないものを、測ったとは書きません。

- どの項目にも、5つのタグのどれかを付けます。別ブランチで動いたものは「ブランチ上で」と書き、実行した範囲を添えます。
- AI の数字には規模を添えます（6体、判断52回、少ない回数）。「AIが決めた」と書くときは、同じ文に4つを付けます。モデルが選んだ割合、判断数、実行の名前と commit、進軍の話なら衝突に至った数 Y です。
- 「人と同じルール」は、安全枠を添えるときだけ使います。安全枠は、候補は12個まで、1回の判断で兵の60%まで、本拠に40%を残す、モデルの進軍は1日4回まで、自動運転は自分から進軍しない、です。
- 書かない言い方があります。「AI は必ず表示される」「AI は鍵を持たない」（書けるのは「モデルは鍵を見ない」）、「不正は不可能」、「覚えている」「恨みを持つ」（書けるのは「引用した」）、「地図が動く」「AI が征服した」、「公開の乱数で配った」、「誰も払わず稼がない」です。
- 記録のない出来事は書きません。ゲーム会社と話したこと、人が遊んだことが該当します。

詳細: 設計書 第9章

## 6. あなたの返事が要る点

設計書の付録A に34件あります。重要な9件を挙げます。「既定」は、返事がない間の扱いです。

**README とピッチを書き直す前に要る点**

1. **AI の印を残すか（Q2）。** D2 で、地図画面は印なしと決まりました。ここで尋ねるのは、評議会・監査ページと公開名簿に今ある印（AI、スクリプトBot、運営の席の区別）だけです。返事の例: 「残す」または「外す」。外す場合は、仕様書の「常にラベルを付ける」の条項を直します。既定: 残す。返事がなければ既定で進み、「AI は必ず表示される」とは書きません。法的確認（EU の AI 法50条など）は未実施です（Q34）。
2. **事業計画をピッチで言うか（Q18）。** 賞金、USDC の参加費、運営の取り分、ゲーム会社への提供を、ピッチの動画とスライドで言うかです。返事の例: 「言う」または「言わない」。既定: 文書には状態をつけて書き（数字なし）、動画とスライドでは言わない。
3. **ハッカソン後の順序（Q13）。** 共有の文明と征服のどちらを先にするかです。記録は、10-01 の「領土の争奪が核」と、決定 W8「共有の文明が最優先」で、順序を述べたものはありません。返事の例: 「文明が先」「征服が先」「並行」。既定: 仮置きとして、文明の中身の設計を先にし、征服を並行にする。決まるまで「未決」と書きます。

**あなただけが確認できる点**

4. **SUBMISSION の空欄（Q32）。** 次の3点です。0xCiv と 0xARK という別のプロジェクトからコードを持ち込んでいないこと。「AIのコーディング支援のもとで作った」の書き方。ハッカソンの開始日（あなたのメモは 9/14、リポジトリの最初のコミットは 2026-09-21）。返事の例: 3点それぞれの事実。既定: 確かめていない主張は書かず、空欄にする。
5. **LICENSE（Q33）。** リポジトリの直下に置くか、置くならどのライセンスにするかです。今は直下になく、各部品が MIT を宣言しています。返事の例: 「MIT で置く」または「置かない」。既定で進みます。README は現状のままです。
6. **GitHub への公開（Q24）。** GitHub 上の公開用の最新版（origin/main）は、旧試作の README のままです。提出するコード（frontier/unify）、AI 側、征服側のブランチは、GitHub に送っていません。返事の例: 「公開してよい。時期は10-○○」または「まだ送らない」。既定: 送らない。許可があるまで行いません。設計書は、提出に公開が必要かを確かめていません。提出規則で確認してください。必要な場合は、提出の締切（10-13 15:59）の前に決める必要があります。

**AI の走行（10-09）の前に要る点**

7. **仕様書の設計者の既定（Q10）。** 仕様書にある既定6件です。攻撃命令を封印する、評議会は8ゲーム時間ごと（試験用の設定）、人のいる国は人の1票が要る、A/B が1組しか成立しなくても弱めた主張を出す、録画は評議会ページのみ、Mac の予約。返事の例: 「異議なし」または異議のある件名。既定: そのまま進む。
