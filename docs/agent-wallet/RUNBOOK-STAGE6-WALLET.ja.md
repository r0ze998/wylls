# 段階6 手順書：実ウォレット拡張での署名（人が操作して確認する）

目的：開発用ウォレットの代わりにブラウザ拡張のウォレット（Phantom、Backpack、Solflare など）を使い、所有者の署名が必要な操作を、人が承認ウィンドウを操作しながら確かめる。確かめる操作は、メッセージ署名・取引署名と、その拒否。

この確認は自動化しない。承認ウィンドウは拡張機能のもので、スクリプトからは操作できないため。

## 0. 守ること

- **テスト専用のウォレットアカウントを新しく作って使う。** 実資金のあるアカウントや、普段使いの復元フレーズは使わない。
- 使うのはローカルのテスト用チェーンとテスト USDC だけ。承認ウィンドウに表示されるサイトが `http://127.0.0.1:<port>` で、額がテスト USDC（ページの「接続用トークン」欄ではなく、`/gw/f/agent/terms` の `mint`）であることを、毎回確かめてから承認する。
- 承認ウィンドウにメインネットの資産の移動が表示されたら、承認しない（この手順にそのような取引はない）。
- 記録にスクリーンショットを使うときは、復元フレーズや秘密鍵の画面を写さない。アドレス（公開鍵）は写ってよい。
- **ページのウォレットの安全チェックは緩めない。別のネットワーク（devnet など）にもデプロイしない。**（所有者の判断、2026-10-24）拡張が `solana:localnet` を名乗らず使えない場合は、そのまま「使えない」と理由つきで記録して、段階 6 を終える。

## 2. 使えるウォレットかの事前確認（最初に必ず行う）

**先に知っておくこと（2026-10-23 時点・未確認）**：ページが使えると判定するのは、`solana:localnet` を名乗るウォレットだけです。Phantom の開発者向けドキュメントは、拡張で使えるネットワークを Mainnet・Devnet・Testnet としています。localnet は挙げていません。そのため Phantom は「このネットワーク（solana:localnet）に対応していません」と表示される見込みが高いです。Backpack と Solflare についても、localnet を名乗るという情報は見つかっていません。実物の拡張では確かめていないので、この節の手順で確かめて、その結果を記録してください。どれも使えない場合は、安全チェックを緩めたり別のネットワークに移ったりせず、「対応する拡張がない」という結果として記録します（所有者の判断、2026-10-24）。

1. 拡張を入れたブラウザで `http://127.0.0.1:41640/frontier/frontier/agent.html` を開く。
2. ウォレットの一覧に、拡張の名前の「〇〇でつなぐ」が出るかを見る。
   - 押せる状態なら使える。
   - 押せない（灰色。2026-10-23 の修正までは、見た目が押せるボタンと同じだった）なら、横に理由が出る。理由は次のどれか：
     - 「このネットワーク（solana:localnet）に対応していません」
     - 「従来形式（legacy）の取引に対応していません」
     - 「メッセージの署名に対応していません」
     - 「接続に対応していません」
     - 「取引の署名に対応していません」
   - 理由をそのまま記録して、別の拡張を試す。どの拡張も使えなければ、段階6は「対応する拡張がない」として終える（それ自体が結果）。
3. 一覧に何も出ないときは、拡張が Wallet Standard に登録されていない。拡張を有効にしてから、ページを再読み込みする。

ページが使えると判定するのは、Wallet Standard の `chains` に `solana:localnet` があり、`solana:signTransaction`（対応する取引形式に legacy を含む）、`solana:signMessage`、`standard:connect` に対応しているウォレットだけ（`permutation-server/web/wallet.mjs` の `unsupported`）。

### 人が試す前のリハーサル（自動）

`permutation-gateway/screens/live/agent-extension.live.mjs` は、拡張と同じ手順（Wallet Standard の登録）で読み込まれる「テスト用の拡張」を使います。このテストの承認ウィンドウはスクリプトで、承認するか拒否するかをスクリプトが選び、届いた依頼の内容を記録します。これで、§2 の一覧と、§3a〜3c の操作・拒否（R1〜R4）をひととおり通します。

```sh
cd permutation-gateway/screens && LIVE_HERALD=http://127.0.0.1:41640 LIVE_OUT=<出力先> node --test live/agent-extension.live.mjs
```

このリハーサルの記録は、本物のウォレットでの結果とは分けて残す（下の §4）。これまでの結果：

2026-10-23 に、このリハーサルで次の 3 つの不具合を見つけて直しました。
- agent ページが拡張を探していなかった（開発用ウォレットしか一覧に出なかった）。

## 3. 確認する操作

**3a. プレイ画面で参加する**（まだ Citizen がなければ）

1. `/frontier/frontier/index.html` を開き、拡張のウォレットでつなぐ。
2. 国を選んで参加する。
   - ゲーム内の鍵を作るためのメッセージ署名と、参加のための署名を、それぞれ承認する。
   - テスト USDC が足りなければ、ページが先に受け取る。
3. 村ができたら、手動で収穫を 1 回行う（S1 では、前提 2 のプレイ画面の修正が要る）。

**3b. agent ページ**

| # | 操作 | 拡張に出る署名 | 期待する結果 |
|---|---|---|---|
| 1 | 拡張でつなぐ | 接続の承認 | 「ウォレット 〇〇…」が表示される |
| 2 | 代理人を作る（村 p,q,site を入れて作成） | メッセージ署名（文頭が `Wylls agent wallet command v1`） | 接続用トークンが一度だけ表示される |
| 3 | 預け入れる（1） | 取引署名（手数料は relay が払う。テスト USDC の TransferChecked） | 「預け入れました（1）」、残高の預け入れ合計が 1 |
| 4 | 予算と行動を保存 | メッセージ署名 | 「保存しました（版 2）」 |
| 5 | 鍵を代理人に渡す | 取引署名（SetSession） | 「鍵を代理人に渡しました」、チェーン上の委任が代理人 |
| 6 | 自動にする | メッセージ署名 | 「自動にしました」、しばらくして「行動 Harvest：送信」 |
| 7 | 手動に戻す | メッセージ署名 | 「止めました（サーバー側）」、状態の行が「停止中：あなたが手動に戻しました。…」 |
| 8 | 鍵を取り戻す | 取引署名（SetSession） | 「鍵を取り戻しました。代理人はもう村に署名できません。」、委任が「あなた」 |
| 9 | 全額引き出す | メッセージ署名 | 「引き出しを送りました（額）。代理人は手動に戻りました。」、確定後にウォレットのテスト USDC が戻る |

**3c. 拒否の確認**：承認ウィンドウで「拒否」を押す。

| # | どこで拒否するか | 期待する結果 |
|---|---|---|
| R1 | 2（作成）のメッセージ署名 | ページに「ウォレットで取り消されました」。代理人は作られない（再読み込みしても一覧にない）。入力した村と上限はフォームに残る |
| R2 | 3（預け入れ）の取引署名 | 何も送られない。預け入れ合計も、ウォレットのテスト USDC も変わらない |
| R3 | 5（鍵を渡す）の取引署名 | チェーン上の委任は変わらない（「あなた」のまま） |
| R4 | 7（手動に戻す）のメッセージ署名 | 自動のまま。代理人は動き続ける |

**拒否のたびに、残高と権限が変わっていないことをページの外でも確かめる**（拒否の直前と直後に 1 回ずつ）：

```sh
curl -s "http://127.0.0.1:41640/gw/f/agent?id=<agentId>" | python3 -c "import json,sys; v=json.load(sys.stdin); print(v['balance'], v['mode'], v['policy']['version'], v['delegation'])"
```

`balance`（預け入れ・使える額・予約・支出）、`mode`、ポリシーの版、`delegation` が、拒否の前後で同じであること。最後に、全額出金のあとで帳簿が合うこと（`deposited = withdrawn + spent の合計 + reserved`）も確かめる。

各行で、拡張が表示した内容（サイト、署名の種類、取引の説明や警告）を記録する。拡張が「この取引は失敗するかもしれません」などの警告を出すことがある（拡張自身のネットワークで取引を試算するため）。警告の文言をそのまま記録し、承認して結果がどうなるかを見る。

**3d. 委任中のプレイ画面**（この案内は `agent-wallet/integrate` に入っている）

- 5 のあとにプレイ画面を開く。村の行動バーに「代理人に任せています（自動）。この端末の鍵では送れません。」と、「鍵を取り戻す」ボタン、「代理人のページ」リンクが出ることを確かめる。
- 手動で収穫を押すと送られずに拒否され、拒否の表示に理由と「代理人のページを開く」リンクが出る。
- 「鍵を取り戻す」を押すと、拡張に SetSession の取引署名が出る。承認すると「鍵を取り戻しました。代理人はサーバー上ではまだ自動です…」と表示される。
