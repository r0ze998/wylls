## 統合を妨げる問題

**ブロッカーはない。** 根拠: 全テスト 2414 / 2414 と 37 / 37、実ブラウザ 18 / 18、ライブ 18 / 18 チェック、ベンチは文書の数値と一致、期限ルールのシナリオは 16 / 16 チェックで文書どおり（解放まで 3,603 s、deposited = withdrawn = 10,000,000）、トークンは状態ファイルにもログにも現れない。

ブロッカーではないが記録する食い違い・注意点:

1. **トランスクリプトの `window.breakdown` は鎖での拒否を「休み」に数える。** review-2 では `Build → refused (QueueFull)` が 1 回あった（リレーのログ）が、台帳の履歴（`relay/agent-wallet.json` の `history`）にはその呼び出しの `spend`（i=31, ok: true）だけがあり、`status != 'sent'` の `action` 行がない。`scripts/agent-wallet-e2e.mjs` の breakdown は `rests = calls − sent − refusedOnChain − failed` で導くため、`modelActionsRefusedOnChain: 0, rests: 4` となる（実際は拒否 1、休み 3）。金額には影響しない（各呼び出しは一度だけ課金、合計 100,000）。DESIGN.md §12.2 の run 9 の行は「Refused on chain 1 (Build, QueueFull)」を載せており、その列の出所は本レビューのトランスクリプトからは再現できない。この列を読むときはリレーのログを見るべき。
2. **DESIGN.md がレビュー中に変わった。** 16:27 の初読では §12.2 の表に `RUN10C_ROW` というプレースホルダが残っていた。16:28:36 のコミット `ad9f20f1` で 10c の行（`9 (+1) | 0.09 | 4 | 0 | 0 | 5 | 0 Harvests | 43 (gap 16, no change 12, back-off 15)`）に置き換えられている。本レビューは `ad9f20f1` を対象とする。
3. VERIFY §1 の表はテストファイル 8 本だが、実際は 9 本（`agent-wallet-regression.test.mjs`）。文書の小さなずれ。
4. `scripts/agent-page-browser.mjs` の DevTools ポート既定値 41697 は 416xx 帯で、他のスタックと並走するときは `AGENT_PAGE_DEVTOOLS_PORT` の指定が要る。VERIFY §5 に記載がない。
5. `frontier-stack down` は「stopping the supervisor (pid …)」の後に「down: stopped nothing (already down)」と出すが、実際にはすべて止まりポートは解放されていた（3 回とも lsof で確認）。表示が紛らわしいだけ。
