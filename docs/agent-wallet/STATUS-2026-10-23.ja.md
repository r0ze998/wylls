## 7. 公開前に所有者が決めること（推奨案つき）

| 事項 | 推奨 | 理由 |
|---|---|---|
| 資金の保管 | 運営カストディをやめ、エージェントごとのオンチェーン vault（PDA）にする。入金は所有者が直接、出金は所有者の署名、推論費の引き落としは vault 上の予算の範囲で relay が署名 | 今は運営鍵が全額を動かせ、単一プロセスの台帳が唯一の記録。vault なら上限と出金先がチェーンで強制される（DESIGN.md §9） |
| 推論の料金 | 実際の原価（モデルと基盤）を計測してから、1 回あたりの固定価格を決める。「休み」も課金する現行ルールは維持し、所有者の判断回数上限を既定で表示 | 0.01 はテスト価格。休みの課金は原価に合うが、上限がないと時間に比例して費用がかかる（DESIGN.md §12） |
| 未確定の推論の扱い | 1 時間で自動解放（運営が負担） | 所有者が理由なく資金を拘束されない。運営の負担は回数上限で抑えられる（DESIGN.md §6.5） |
| 出金の制限 | 待機期間なし、`available` のみ（現行どおり） | 予約中の分は出せない設計で、二重支出は防げている |
| 対応ネットワーク | 最初は devnet でテスト USDC、mainnet は vault と監査の後 | 現在の構成は localnet 前提（`--agent-wallet` は localnet 以外を拒否） |
| SOL 手数料 | 運営負担のまま記録だけにする。換算するなら、レートの出所と有効期限を公開してから | 暗黙の換算は所有者に見えない課金になる（DESIGN.md §6.3） |
| 厳密スキーマ | Gemma 4 26B で on と off を比べてから既定値を決める | 小型モデルでは不正な答えを大きく減らしたが、測定済みの条件を変えるため |
