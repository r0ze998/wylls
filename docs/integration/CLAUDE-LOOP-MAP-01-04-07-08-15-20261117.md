## The loop as the code has it

| Step | Where (adopted code) | State in the code |
|---|---|---|
| **1. A village** | the game (`permutation-server/web/frontier`): the village card, the holding drawer, the hand; reads from the herald | implemented. Build and train numbers match the program (checked in the earlier rounds). |
| **2. To the request board** | `hud/coopboard.mjs` + `hud/coopentry.mjs`: the village card's slot opens ①'s board (`/coop/config` on the same origin, then `BOARD_PAGE?to=p,q,site,gen`) | implemented. Offered only when the board's `season.seasonId` (and its `programId`, when given) is the page's (`FS.season.seasonId`, decoded from the Season, `herald.mjs:461`). Another world's board is said as such; with no board on the server the slot is hidden. |
| **3. Request, answer, caravan prepared** | ① `coop/board.mjs` (server), `coop/record.mjs`, `coop/store.mjs`, `coop/coop-ui.mjs`, `coop/send.mjs` (`planSend`, built with the game's `fplay.buildShape`) | implemented (①'s docs 21–23). The wallet is the game's Wallet Standard wallet; the Dev Wallet only on localnet when chosen. |
| **4. Send status** | ① `coop/send.mjs` / `coop/pending.mjs`: sending, landed, result unknown, conflict | implemented. A sending record left by a restart offers "結び付ける" for the caravan that landed, never a second send (①'s U5). |
| **5. Result (arrival)** | ① `coop/arrival.mjs`, `coop/ws04.mjs`, `coop/fulfil-bounds.mjs` | implemented, with ④'s quantity contract: credited only when recorded; a vault delivery without credited is `Unverifiable`; amounts are lower or upper bounds, per resource, never summed. A settle at another village is "cause being checked", not counted. |
| **6. Cooperation outcome** | ① `coop/goal.mjs` + `joint-count.mjs` (the joint goal: "達成（記録だけ）" only from verified lower bounds); ⑮ `src/evaluate.mjs` with `adapters/ws01.mjs`, `s1-chain.mjs` and `ws04.mjs` (aligned with ①'s `ws01-board v1` at `2a3a0c94`: caravan context, request destination, zero settles) | ①'s own outcome: implemented, a record and no reward. **⑮'s rulesets (A/B/C) are not adopted** (⑮ README; ⑮ docs 06 Q1–Q8, 07 M1–M8). The game shows no ⑮ verdict, and must not until one is adopted. |
| **7. After a restart** | ① `coop/store.mjs` (the board's records), `pending.mjs` (unfinished sends); the game re-reads the herald; ④ runexec's store (when used) | implemented: the board re-folds its signed records, and an unfinished send is linked, not re-sent. |

**The quantity rule is kept everywhere the loop counts:**
- **The caravan's cargo** is what was sent.
- **The settle's credited** is what the village kept, and only when recorded.
- **The request's fulfilment** is computed from bounds, and is never the arrived amount itself.
- ⑮ adds nothing to these numbers. ①'s lower bound and ⑮'s `lowerBound` were equal in ①'s scenario (①'s doc 23-2).
