## 実際の欠落

1. 三つのフィードの読み込みが失敗しても、カードは何も言いませんでした。`FS.s1.error` は、書かれるだけでした。
2. フィードをまだ読めていないとき、カードは「貯蔵庫や物見櫓…は、地図でマスを選ぶと建てられます」「隊商を送れる行き先がまだありません」と出しました。読めていないことと、ないことが、同じ表示でした。
3. 隊商の送信の結果が未確認のとき、通知が消えると、カードには何も残りませんでした。同じ荷を、もう一度送れました。
4. 一覧を本人が読み直す入口は、領土の再取得（`cq-refresh`、ほかの読み込みも行う）しかありませんでした。

## 変更

### `controller.mjs`

- **`refreshS1`**（前に世界の照合を入れた関数）：
  - フィードごとの最新の読み込みの結果を `s1.read` に記録します（`'ok'`、`'missing'`、`'failed'`）。
  - 要求の番号 `s1Ask` を足しました。あとから始めた読み込みだけが書きます。通常の読み込みどうしは、もともと `refreshConquest` の要求番号で同じ扱いでした。変わるのは、本人の読み直しと重なったときだけです。
  - 入れ替わった `FS.s1`（世界が変わった）には書きません。
- **新規 `rereadS1()`**：`refreshS1` だけを呼びます。押したときの要求・herald・世界を控え、違えば書きません。読んでいる間の二度目は、何も始めません。例外は「読み直せなかった」とします。
- **`ACTIONS['s1-reread']`**、`useHerald` と `adoptPinnedWorld` の `FS.s1Reread = null`。
- `refreshConquest` の本体、`s1Caravan`、要塞の送信は、変えていません。

### `screens/s1.mjs`

- **`renderS1Village`**：カードの頭の下に、読み込みの注記と、命令の結果を出します。「ない」の二つの文は、一覧が読めているときだけ出します。

## 場合ごとの結果（静的な逆レビュー）

| 場合 | 結果 |
|---|---|
| フィードを一度も読めていない | 「まだ読めていません。ないという意味ではありません」。「地図で建てられます」は出さない |
| 読み込みに失敗し、前の一覧がある | 「最新の読み込みに失敗しています。下は最後に読めたもの」 |
| herald にファイルがない（`NotFound`） | 空の一覧として読めた扱い（これまでどおり）。注記なし |
| 読み直しを押す | 三つのフィードだけを読む。読んでいる間は、ボタンを出さない |
| 読み直しの間に、通常の読み込みが始まる | あとから始めた通常の読み込みが書く。読み直しの答えは書かない |
| 通常の読み込みの間に、読み直しを押す | 読み直しが書く。先の通常の読み込みの S1 の答えは書かない（その読み込みの残りは続く） |
| 読み直しの間に、世界か herald が変わる | 何も書かない |
| 隊商の送信の結果が未確認 | 「送信済み・この命令の結果は未確認。もう一度命じると二重になることがある」。一覧の読み直しを出す（注記に同じボタンがあれば、出さない） |
| 隊商を送る前に断られた | 「送られていません」と理由 |
