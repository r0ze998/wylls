## 完成させた導線

広い地図の描画 → 読めていない・順番待ち・届かなかったことを、その場で知る → 州を選ぶ → 既存の「もう一度読み込む」→ 正しい地図に戻る、という一続きです。

実際の経路は、次の順です：

1. 読み込み側が、州の読み込みの結果（`FS.provinceReads`）を記します。
2. `app.mjs` の `readMarksNow` が、地図に渡す一覧を作ります。
3. `map/fmap.mjs` の `topPass` が、地図の上に文を描きます。
4. 州を押して選びます（これまでどおり）。
5. `hud/inspect.mjs` の札が、読み込みの結果を言います。
6. `province-reread` が、`retryProvince` と `loadOverviews` を呼びます。

## 実際の欠陥

前の束で、州の読み込みの結果は記すようになりました。しかし、それが出るのは、選んだ州の札の中だけでした。地図の上では、次のものの区別がつきませんでした：

- 記録を読めなかった州
- 村の一覧が届かなかった環
- 本当に何もない土地

どこを選べば読み直せるかも、わかりませんでした。また、環の一覧の読み込みが失敗したことは、どこにも記されていませんでした。記されていたのは、「まだ持っていない」ことだけです。

## 変えていないこと（逆レビュー）

- **読み込みの決まり**：同時に 12 件（実際に進んでいる要求の数）、一つだけの待つ場所、前の世界の答えを捨てることは、そのままです。印は、何も頼みません。
- **視界**：地図が州を頼むのは、これまでどおり、測量済み以上の州だけです。印は、その結果だけを言います。知らない領土や敵は、描きません。
- **本人の操作**：続けての選択・取り消し・読み直し・拡大・移動は、これまでどおりです。印は、選択もカメラも動かしません。
- **A → B → A**：州の状態は、世界が変わると忘れます（`adoptPinnedWorld`）。環の「届かなかった」は、世界（世代を含む）が違えば、出しません。
- **描く負担**：
  - 一覧は、州の状態（少数）と、届かなかった環（少数）だけです。
  - 環の文を出す州は、記すときに一度だけ求めます。
- **主・D の範囲**：`controller.mjs`・協力の部分・ターンの一覧・状態・MCP には触れていません。
