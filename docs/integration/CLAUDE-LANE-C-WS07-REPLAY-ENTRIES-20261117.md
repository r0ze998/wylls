## 実際の欠陥

`battle-play` は、次の場所から送られます：

- 報告
- お知らせ（`hud/feed.mjs` の「見る」）
- 追跡の一覧（`screens/tracker.mjs`）
- 調べる画面（`hud/inspect.mjs`）

報告の中から押したときは、前の束で、報告の行に「読み込み中」「読めませんでした」を出すようにしました。しかし、**報告の外から押したとき（`rep` がないとき）、`playAsked` は何も記さず、何も出しませんでした。** 衝突を読めなくても画面は何も変わらず、読めなかったことも、戦いがなかったのかどうかも、わかりませんでした。

## 変更（`app.mjs` と、英語の辞書の末尾だけ）

- **`playAsked`**
  - 報告が開いていない押下では、`FS.replayAsk = { p, q, bell, state: 'loading', req }` を置き、すぐに描きます。報告の中の押下では `null` にします（報告の行が出します）。
  - 待ったあとは、その押下自身の表示（`req` が同じ）だけを変えます：
    - **true**（場面を見せた）：消します。
    - **false または例外**で、その間に何も変わっていない（`asked()`）：`state: 'failed'` にします。
    - **null**（取り消し）：消します（何も言いません）。
  - 最後に押したものでなければ、何もしません（これまでどおり）。
- **`replayNotice`**（新しい小さな関数）：その表示の中身です。失敗のときだけ、同じ要求を出すボタン（`battle-play`）を付けます。閉じるボタン（`replay-dismiss`）は、いつも付けます。
- **`renderFeed`**：地図のお知らせの積み重ねに、状態の表示とお知らせの間に、一つだけ入れます。
- **`HUD_ACTIONS['replay-dismiss']`**：表示を消します。読む間に閉じたら、押した番号を進めて、その要求を取り消します。場面は見せず、カメラも動かしません。
- **`syncBattleWorld`**：世界が変わったら、表示を消します。
- **英語**：一文を、辞書の末尾に加えました。「読み込み中」と「もう一度読み込む」は、すでにある文を使います。

## 変えていないこと（逆レビュー）

- **記録と既読**：お知らせの一覧（`FS.feed`）・閉じた印（`feedDismissed`）・留守の確認の位置には、触れていません。
- **送信の状態**：`FS.notice`・`FS.lastAct`・「もう一度」（`notice-retry`）は使っていません。「もう一度」は、最後の**送信**をやり直すボタンです。再生の失敗をここに載せると、前の送信をやり直してしまいます。
- **再生の成功と、ただの地点の移動**：成功のときだけ、場面とカメラの移動があります（`playBattle`）。失敗のときは、カメラは動きません。「地図で見る」（`goto`）は、変えていません。
- **本人のカメラと、閉じる操作**：失敗の表示は、何も動かしません。読む間に閉じた要求は、取り消します。
- **報告の中の押下**：前の束のとおりです（報告の行に出し、報告は残します）。
- **主の範囲**：`hud/status.mjs`・`hud/turnlist.mjs`・協力の部分・`controller.mjs` には触れていません。`hud/feed.mjs`・`screens/tracker.mjs`・`hud/inspect.mjs` も変えていません（ボタンは、そのまま同じ動作を送ります）。
