## 変更（`app.mjs` と、英語の辞書の末尾だけ）

- **`playAsked`**
  - 報告が開いていない押下では、`FS.replayAsk = { p, q, bell, state: 'loading', req }` を置き、すぐに描きます。報告の中の押下では `null` にします（報告の行が出します）。
  - 待ったあとは、その押下自身の表示（`req` が同じ）だけを変えます：
    - **true**（場面を見せた）：消します。
    - **false または例外**で、その間に何も変わっていない（`asked()`）：`state: 'failed'` にします。

## 訂正（2026-11-17、同じ日、ブランチ `claude/lane-c-ws07-replay-world-20261117`。起点 `ff1a823e`。`ff1a823e` は集約保留）

**残っていた穴**：`ff1a823e` の `syncBattleWorld` は、世界の変化を見ると、`FS.replayAsk` を無条件に消していました。次の順で起こります：

1. 世界が B に変わる。
2. 地図の次の同期（`peopleSource` など）より前に、本人が B で「見る」を押す。「読み込み中」の表示が出る。
3. `playBattle` が答えを待つ間に、同期が来る。**B の正当な表示が消える。**
4. 衝突を読めない（false）。`req` が合う表示がもうないので、**また何も出ない。**

「読み込みの結果を必ず言う」は、この場合、成り立っていませんでした。

**直したこと**（`app.mjs` だけ）

- **表示が、頼んだ世界を持ちます**：`FS.replayAsk = { …, req, world }`。`world` は、押したときの `reportWorld()` です。失敗の状態に変えるときも、同じ `world` を持たせます。
- **`syncBattleWorld`**：`FS.replayAsk.world !== world` のときだけ消します。新しい世界で押した表示は、同期のあとも残り、あとから届く失敗が、その表示を見つけます。
- **比べている二つの文字列**：表示の `world`（`reportWorld`）と、同期の `world`（`momentWorld`）は、コードの上で同じ式です（固定と、その世代）。回帰（X7）で、式が同じであることを確かめます。別の形の文字列を比べてはいません。

**それぞれの場合の期待**（回帰 `web-frontier-ws07-replay-world-text.test.mjs` の X1–X7。書いただけで、実行していません）

- **B に変わり、同期の前に B で押す**：表示は残ります。読めなければ、同じ表示が「読めませんでした」になり、ボタンが出ます。
- **A で押したあと、B に変わる**：同期が、その表示を消します。要求そのものは、`playBattle` が取り消します。
- **A → B → A**：世代が違うので、最初の A の表示は、最後の A のものではありません。
- **同じ世界で、遅れて来た同期**：`syncBattleWorld` は、表示を見る前に戻ります。
- **続けて二度押す**：前の答えは、何にも触れません（`req` が違います）。
- **読む間に閉じる**：取り消しです。場面も、表示もありません。

**守れることの範囲（訂正後）**

- 報告の外から押した再生は、次のどれかになります：
  - 場面が出る
  - 「読めませんでした」とボタンが出る
  - 本人または世界の変化による取り消しで、何も言わずに消える
- 実行で確かめたことはありません。
