## Original player page

The existing expedition inspection card now describes the supported return
sequence in player terms: disband in the wide region, wait for turn resolution,
then return troops to the original village's reserve. Each phase is an observed
state, never a claim that this browser executed an earlier step. A return-stage
observation shows the proposed troop credit and resulting reserve, explicitly
stating that no credit or send occurred.

`fexpedition-return.mjs::originalReturnModel` checks the complete inspection
request/report binding and additional state/next-step/arrival arithmetic before
constructing a local immutable proposal. The selected inspection retains its
accepted request separately from the response scope. Existing reconciliation,
input edits, new reads, source changes and closing the card discard both. The
model does not accept raw proposed bytes as an input.

Only observed Dissolve and Return stages produce the existing private 60-byte
command and ordered account roles. Leave resolution has no invented command.
The proposal binds program, Season, full original host, exact standing key,
roles/privileges, request digest, snapshot digest, Clock and context slot. The
independent content digest includes standing and payer, which are absent from
the command bytes. All execution/admission/signature/queue/completion flags
remain false; report content and freshness are not authenticated by this model.

The Rust `wide_resident_draft::Draft::content_digest()` uses the same explicit
encoding. Four independent fixed vectors cover native role snapshots,
actor=payer, and standing coordinates above JavaScript Number precision. Their
[provenance and encoding](../../frontier-node/crates/fclient/tests/fixtures/original_resident_draft_v1.md)
distinguish existing native evidence from public contract variants. Expected
values were not generated by either implementation under test.

The mobile experimental action row now scrolls horizontally, retaining legible
button labels. While the return card is open it retains the selected host's
identity and close control and hides unrelated orders, as the boundary card
already does. Existing nonexperimental action bars are unchanged.
