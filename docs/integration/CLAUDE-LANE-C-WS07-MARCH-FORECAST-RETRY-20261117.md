## 実際の欠陥（親の指摘どおり）

1. **失敗した見込みが、そのまま残りました。** `updateForecast` は、`c.forecast.key` が今の鍵と同じなら、すぐ戻ります。規則を読めなかった（`NoWasm`）見込みも同じ鍵で残るので、二度と計算されませんでした。計算し直す入口もありませんでした。
2. **行き先の州の記録を持っていないと、`NoInput` のまま直りませんでした。** 近くの行き先や座標で選んだ州は、地図を押したときと違って、読み込みを頼まれません。記録がなければ `forecast()` は `NoInput` を返し、札は「見込みはまだ出せません」のままでした。
3. **失敗の処理（`catch`）が見ていたのは、下書きが同じかどうかだけでした。** 鍵も世界も見ていませんでした。古い要求の失敗が、同じ下書きの新しい鍵の見込みを、「規則がない」に書き換えることがありました。
4. **後片付け（`finally`）は、いつも `fcBusy = null` にしていました。** 別の要求の「計算中」の印まで消すことがありました。
5. **計算の途中の例外が、決まりによる断りと同じ形で残りました**（`why: Error`）。
6. **地図を押したあとの断りの表示**（`dest-from-map` のあとの処理）は、`FS.compose === c` だけを確かめていました。同じ下書きで、あとから選んだ別の行き先の `routeError` を出すことがありました。

## 変更

- **`app.mjs` の `updateForecast`**
  - **`fcRun`**（要求そのもの）：`{ c, key, dest, world }` を持ちます。`mine()` は、次のすべてが成り立つかを確かめます：
    - `fcRun === run`
    - 下書きが同じ
    - 行き先がそのもの
    - 鍵が同じ
    - 世界（世代を含む）が同じ

    答えの反映と失敗の処理は、`mine()` のときだけ書きます。後片付けは、`fcRun === run` のときだけ空けます。鍵だけの `fcBusy` は、なくしました。
  - **`unread`**：次のときに付けます：
    - 規則のモジュールを読めなかったとき
    - 行き先の州の記録を持っていないとき（`NoRecord`）
    - 計算の途中の例外

    見えていない土地（`OutOfSight`）と、決まりによる断りには付けません。`OutOfSight` の確認は、これまでどおり、最初に行います。
  - **`NoRecord`**：
    - 通常の読み込みを頼みます（`wantProvince`）。本人が押したときは `retryProvince` を使います。同時の件数と待ちの決まりは、そのままです。
    - 記録が届いたら、自動で計算し直します。
  - **計算中のまま残った見込み**：前の要求が残した「計算中」は、計算し直します。
- **`HUD_ACTIONS['forecast-retry']`**（新しい一行）：読めなかった見込みだけを、同じ下書きから計算し直します。送信中は、何もしません。
- **地図を押したあとの断り**：`draftAims(c, aim, world)` で確かめます（その押下が渡した行き先そのもの・同じ下書き・同じ世界）。
- **`hud/marchcard.mjs`**：
  - 見通しの「予測」の欄に、「見込みはまだわかりません」と、その理由を出します。
  - その下に、「下書きはそのままです」の文と、「見込みをもう一度計算する」のボタンを出します。守り手の数がわかっていなくても出します。
- **英語**：六つの文を、辞書の末尾に加えました。
