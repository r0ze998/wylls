## 訂正（2026-11-17、同じ日、ブランチ `claude/lane-c-ws07-report-play-fix-20261117`。起点 `e37bf5fc`。`e37bf5fc` は保留）

**残っていた穴**：`playAsked` が確かめていたのは `req !== playAskSeq` と `FS.report === rep` で、どちらも `await playBattle` の**あと**でした。そのころには、前の要求でも、場面を置き・効果を送り・カメラを動かし終えていました。「最後に押したものだけが答える」「本人の画面の操作を尊重する」は、言い過ぎでした。一方で、追従の `still` をそのまま使うと、`(auto || still)` の「新しいターンを優先」が明示の再生に効いてしまい、過去の戦いを見る正常な操作を止めてしまいます。

**直したこと**

- **`playBattle` に `asked` を加えました**：明示の要求そのものが、まだ有効かを答えるものです。`still` と同じ位置、つまり待ちのすぐあとで、場面・`FS.battles`・カメラ・効果のどれより前に確かめます。偽なら null です。
  - `asked` は、「新しいターンを優先」の決まり（`auto || still`）には入れません。そのため、本人が名前で頼んだ過去の戦いは、同じ州でもっと新しい場面が流れていても見せます。
- **`playAsked` の `asked`**：次のすべてが成り立つときだけ有効です：
  - まだ最後に押したものである
  - 今開いている報告が、押したときの報告である（押したときに報告がなければ、今もない）
  - 世界が同じである
- **あとの扱い**：これまでどおりです。
  - 最後に押したものでなければ、何もしません。新しい要求の「読み込み中」や失敗の印を、消したり残したりしません。
  - true：その報告だけを閉じます。
  - false または例外：報告を残し、印を付けます。もう一度押せば読み直します。
  - null：何も言いません。
