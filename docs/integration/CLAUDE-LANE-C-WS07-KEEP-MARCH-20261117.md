## 訂正（2026-11-17、同じ日、ブランチ `claude/lane-c-ws07-keep-march-fix-20261117`。起点 `8771bcde`）

独立の逆レビューで、二つの誤りが見つかりました。

### 誤り 1：前の一覧から、いまの番号のボタンを作っていた

- 初版の `marchesToKeep` は、進軍の一覧の**世界**だけを確かめました。herald を替えた直後や、別の村を選んだ直後は、前の読み込みの一覧（別の herald のもの、別の村のもの）が、次の読み込みまで残ります。世界は同じなので、通りました。
- ボタンの文脈の番号は、**描いたとき**の番号でした。前の一覧から作ったボタンが、いまの番号を持ち、押したときの確かめも通りました。
- 直し方：
  - `controller` `readMarches`：読み込みを**始めたとき**の、文脈の番号・読み手・村を控え、一覧と一緒に書く印（`FS.marchesRead`）に足しました。読み込みの回数・順番、公開・帳面・結果の受け取りの扱いは、変えていません。
  - `screens/tracker.mjs` `marchListNow`：一覧が、いまのページのもの（世界、文脈の番号、読み手、選んでいる村）かを答えます。一覧の番号を返します。
  - 砦のカード、追跡の行の入口、行動（`keep-track`、`march-keep`）は、すべてこれを通します。ボタンは、一覧の番号を持ちます。

| 場合 | 結果 |
|---|---|
| 同じ世界で herald を替えた直後 | 一覧は、いまのページのものではない。カードは「分かりません」。行の入口は出ない |
| 別の村を選んだ直後（前の村の一覧が残っている） | 同じ。次の読み込みで、選んだ村の一覧になってから出る |
| A → B → A | 三つの別の文脈。最初の A の一覧・ボタンは、二度目の A では使わない |
| 前のボタンを、切替のあとに押す | 何もしない（一覧の番号と、ボタンの番号と、いまの番号が合わない） |
| 追跡へ移る一コマの間に、村・世界・herald が替わる | 移らない（一コマあとに、同じ確かめをもう一度通す） |

### 誤り 2：州までしか分からない進軍を、「この砦へ向かっている」と言っていた

- 行き先が州までしか読めていない進軍は、その州のどのマスへ行くか、分かりません。初版は、それも「この砦へ向かっているあなたの軍勢」に入れ、（　）で添えるだけでした。追跡の行の「この砦を見る」も、同じでした。
- 直し方：
  - 砦のカード：**マスが分かっていて砦のマス**の進軍だけを、「この砦へ向かっているあなたの軍勢」に並べます。州までしか分からない進軍は、別の見出し「この州へ向かっているあなたの軍勢（行き先のマスは、まだ分かりません）」に並べ、「この砦へ向かっているかどうかは、行き先のマスが読めるまで分かりません」と言います。
  - 追跡の行：マスが砦のマスなら「この砦を見る」、州までなら「この州の砦を見る」。
  - 行動の確かめ（`keepMarch`）も、同じ分け方です。「この砦へ」のボタンは、押したときにもマスが分かっていて砦のマスであること、「この州へ」のボタンは、マスがまだ分からないこと、を確かめます。あとでマスが読めて、別のマスだったと分かった進軍のボタンは、何もしません。
