## 実際の欠落

1. **村を替えると、前の村の「受け取れます」が、替えた先の村に出ました。** 村 A の種を読んで「受け取れます」になったあと、村 B を選ぶと、次の読み込みまで、B の探索のカード・上の帯・最初の手順が「受け取れます」と言いました。
2. **その状態で「結果を受け取る」を押すと**、B に結果待ちの探索がなければ、`settleExplore` は記録のない値を読んで例外になりました。B に結果待ちがあれば、種がまだでも送信の準備に進みました（種がなければ、そこで断られます）。
3. **ほかの村の結果待ちの探索は、どこにも出ませんでした。** 斥候を出した村から別の村に移ると、探索のカードは「斥候の軍勢の『探索』を押すと…」と、何も待っていないように出ました。結果は「ふつうは自動で受け取り」ますが、そうでないとき、本人が気づく手がかりがありませんでした。その村は、受け取るまで次の探索に出せません。
4. **種の読み込みが失敗したとき**、「まだ出ていない」と同じ表示でした。

## 変更

### `controller.mjs`

- **印**（`exploreSeedMark`、`FS.exploreSeedState`）：種を読んだ村・探索のターン・世界と、読み込みの結果（`ready`／`waiting`／`failed` と符号）。
- **`refresh()`**：種の読み込みの二行はそのままです。その隣に、印を消す行と、印を残す行を足しました。読む条件・回数・順番は同じです。
- **`startPlay`**：`FS.exploreSeedReady` を、`FS.localMarch` と同じやり方で、取り出し口のある値にしました。印が、いま選んでいる村・その探索・いまの世界と合うときだけ真です。外から `true` を書かれたときは、そのとき選んでいる村のものとして扱います。
- **新規 `checkExploreSeed()`、`ACTIONS['explore-check']`**：選んでいる村の探索の種を、一回読むだけです。
- **`settleExplore`**：記録がない村では断る。待ちのあとに変わっていたら止める。送るものは同じです。
- `resetViewer`、`useHerald`、`adoptPinnedWorld` に、印と確かめのクリア。

### `app.mjs`

- 行動 `'explore-village'`：その村を選び（`holding-pick` と同じ手順）、軍勢の画面を開き、`explore-check` を一回呼びます。受け取りも送信もしません。

### `screens/explore.mjs`

- `seedReadOf`、`otherExplorations`（読むだけ）。
- カード：選んでいる村について、確かめ中／読み込めなかった（符号つき。「まだ出ていない、という意味ではありません」）／いま確かめたが、まだ、の文と、「結果が出たか確かめる」。ほかの村の結果待ちの一覧と、「この村の探索を見る」。

## 場合ごとの結果（静的な逆レビュー）

| 場合 | 結果 |
|---|---|
| 村 A の種が出た → 村 B を選ぶ | B には「受け取れます」を出さない。B の一覧に A は「ほかの村の探索」として出る |
| そのまま A に戻る | A の「受け取れます」が、また出る（次の読み込みを待たない） |
| A の探索を受け取り、次の探索を出す（別のターン） | 前の探索の印は合わないので、「受け取れます」は出ない |
| 世界が変わる | 印を消す。合わないので、出ない |
| 結果待ちのない村で「結果を受け取る」が押された | 「受け取る探索の結果がありません」。何も読まず、送らない |
| 受け取りの準備の間に、村・世界・読み手が変わる | 送らずに止める |
| 種の読み込みが失敗 | 「読み込めませんでした（符号）。まだ出ていない、という意味ではありません」と、確かめのボタン |
| 「確かめる」を二度押す | 二度目は、何も始めない |
| 「出ている」と読めたあとに、古い「まだ」が届く | 採用しない |
| 「確かめる」の間に、別の村を選ぶ | 答えは、押したときの村の印として残る。選んでいる村には出ない |
| 「この村の探索を見る」 | その村を選び、軍勢の画面を開き、一回確かめる |
| 探索の下書き（マスを選んでいる途中）があるときに「この村の探索を見る」 | 下書きは外す（下書きは、開いたときの村のものです） |
