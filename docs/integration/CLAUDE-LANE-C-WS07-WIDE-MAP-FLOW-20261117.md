## 実際の欠陥

1. **州の読み込みが失敗しても、どこにも記されませんでした。** 選んだ州の札は、「この州のようすを読み込んでいます…」のまま変わりませんでした。読めなかったことも、記録がまだないことも分からず、読み直す手段もありませんでした。わからない状態が、ずっと「読み込み中」に見えていました。
2. **環の村の一覧を読めていない州は、空に見えました。** 村を持つ国も、場所の状態も出ないので、「何もない州」と区別がつきませんでした。
3. **世界が変わっても、前の世界の州の記録が残りました。** 前の束までの対応は、新しい答えに世界の印を付け、古い答えを捨てることでした。しかし、すでに持っている前の世界の記録は、地図と札にそのまま出ていました。`wantProvince` も、それを「持っている」と見て、新しい世界の州を読みませんでした。次に尋ねるまでの待ち（30 秒）も、世界をまたいで残りました。

## 変更

- **`controller.mjs`**
  - `loadEnvelope`：最新の読み込みが失敗したら、`FS.provinceReads` に `failed`（符号つき）か `missing`（NotFound）を記します。記すのは、世界の確認のあとで、その州の記録を持っていないときだけです。読めたら消します。
  - `wantProvince`：
    - 持っていない州を読み始めたら、`loading` を記します。
    - 例外は、同じ世界なら `failed` として記します。
    - 答えを世界の変化で捨てたときは、残った `loading` を消します。
    - 待ちと同時の件数の決まりは、変えていません。
  - `retryProvince`（新しい関数）：その州だけ待ちを外して、すぐ読みます。読み込み中なら何もしません。同時の件数の上限は守ります。
  - `adoptPinnedWorld`：`FS.provinces`（中身だけ）・待ち・読み込みの結果も忘れます。
- **`hud/inspect.mjs`**
  - `inspectModel`：`read`（州の読み込みの結果）と `ringRead`（その環の一覧を読めたか）を持たせました。一覧を読む環だけを対象にします（`ringSeeded`）。
  - `readState`：開いている土地について、次のそれぞれの文を出します：

    - 読めなかった（符号つき）
    - 記録がまだ届いていない
    - まだ読み込んでいない
    - 環の一覧を読めていない

    読み込み中でなければ、「もう一度読み込む」のボタンも出します。以前の、変わらない「読み込んでいます…」の一行は、これに置き換えました。
