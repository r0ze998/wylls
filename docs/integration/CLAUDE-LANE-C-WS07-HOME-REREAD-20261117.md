## 実際の欠落

1. 候補が一つも見つからないとき、文は「候補を更新してください」と言いますが、そのための操作が画面にありません。
   - 国を選び終えている人は、確定のボタンを押すと `confirmHome()` が読み直しますが、**並びの番号が同じ**なので、同じ州・同じ区画を同じ順に読みます。別の候補には進めません。
   - 並びを進めるのは `home-refresh` だけで、どこからも呼ばれていません。しかも、本人の記録の読み込みが失敗している間は通常の `refresh()` を呼び、選択を消して端末に保存します。読むだけの再試行としては使えません。
2. 候補の読み込みは、新しい読み込みが始まったことしか見ていませんでした。読んでいる間に世界が変わると、前の世界の地図の場所を、いまの世界の候補として書きました。世界が変わったとき、候補の一覧も捨てていませんでした。
3. 読んでいる間に本人が地図で別の候補を選ぶと、応答が届いたとき、読み始めたときの古い選択で上書きしていました（画面の選択と、端末に保存した選択が食い違います）。

## 変更

- `controller.mjs`
  - 新規 `rereadHomes()` と ACTIONS `'home-reread'`。`refresh()` は呼びません。順に：参加・確定・読み込み・命令の途中なら何もしない → 本人の記録が失敗中なら、既存の読むだけの `rereadVillage()` を一度 → まだ失敗、または本人・接続先・世界が変わっていたら止まる → 並びの番号をメモリの中で進める → `refreshHomes({ force: true })`。選択は消さず、端末には何も保存しません。
  - `refreshHomes`：読み始めの世界を控え、応答のとき（成功・失敗とも）世界が違えば書かない。残す選択は、応答の時点の `FS.homeChoice.selected` から決める。残す条件の式は同じです。
  - `adoptPinnedWorld`：`++homesRefresh`。候補の一覧は捨てる。参加・確定の途中（`busy`）のものは残し、`loading` だけ外す（外さないと、応答が捨てられたあと「読み込み中」のまま次の読み込みが始まりません）。
- `screens/join.mjs`：`homeReread`（ボタン）。失敗の文の下、2か所。読み込み中の一文、2か所。
- `lang/en-frontier-play.mjs`：3文（末尾に追加。重複なしを確認）。

## 静的な逆レビュー

- **連打・二重**：ボタンは `busy`／`loading` で無効。`rereadHomes` も同じ条件を自分で見ます。`refreshHomes` は `++homesRefresh` で、古い読み込みの応答を捨てます。
- **本人の記録が失敗中**：`needsHomeChoice()` は失敗中は偽を返すので、先に読むだけの読み直しを通します。まだ失敗なら、候補は読まずに知らせて止まります。まだ参加していない人の「記録なし（NotFound）」は、失敗ではありません。
- **世界・本人・接続先の変更**：押したときの `contextSeq` を控え、待ちのあとで比べます。`refreshHomes` 自身は世界を比べます。本人の変更は `resetViewer`（一覧を捨てる）と `++homesRefresh`、接続先の変更は `useHerald` の `homesRefresh += 1` が、これまでどおり受けます。
- **選択**：消しません。読んだ候補の中に、いまの選択があれば残ります。なければ、国が決まっているときは先頭の候補（これまでと同じ決まり）。
- **並びの番号**：国が未選択のときは国の順も変わり、国が決まっているときは州と区画の順が変わります（`planHomes` の既存の作り）。応答が捨てられても、番号は進んだままです（害はありません。次の読み込みが別の並びになるだけです）。
- **確定の途中に世界が変わる**：一覧は残し、`loading` だけ外します。確定そのものの帰属は `confirmHome()` のもので、変えていません。
