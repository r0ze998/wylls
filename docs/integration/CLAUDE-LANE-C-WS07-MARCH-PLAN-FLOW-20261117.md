## 完成させた導線

地図で村や軍勢を選ぶ → 札で自分の軍勢を知る →「進軍させる」→ 下書きがその軍勢の村から開く → 行き先を選ぶ → 道のり・着くターン・条件を読む → しまう／選び直す、という一続きです。

## 実際の断線・欠陥

1. **ほかの村の軍勢は、札から出せませんでした。** 札（`inspectActions`）は、開いている村の軍勢にだけ「進軍させる」を出していました（`ownHostsOn` → `hostRows` は開いている村だけを見ます）。複数の村を持つ人が、別の村の軍勢がいるマスを選ぶと、軍勢は札に出るのに、出すためのボタンがありませんでした。
2. **入口そのものも、開いている村の軍勢しか見つけませんでした。** `ACTIONS.compose` の `hostRow` は、開いている村だけを見ます。次の入口は、先に村を切り替えていました：
   - 地図からの命令
   - 「村へ戻す」（手の中の軍勢から）
   - 砦への進軍

   しかし次の入口は切り替えず、別の村の軍勢については、押しても何も起きませんでした：
   - 札
   - 軍勢の一覧
   - 手引き
   - 通知からの行軍
3. **行き先を選んだあとの道のりが、古い下書きや古い行き先に書かれることがありました。** `setDestination` は、規則のモジュールを待ったあと、下書きと行き先が今も同じかを確かめずに、道のりを書いていました。
4. **世界が変わっても、下書きと手の中の軍勢が残りました。** 前の世界の軍勢・村・道のりのまま、新しい世界に出ていました。

## 変更

- **`hud/inspect.mjs`**
  - `ownHostsOn`：開いている村の軍勢に加えて、その州の記録から、自分のほかの村の軍勢（そのマスにいて、出せる状態のもの）も返します。村の番号と `other` を付けます。
  - `inspectActions`：ほかの村の軍勢には、「（別の村の軍勢：その村から出します）」と添えます。
- **`controller.mjs`**
  - `ACTIONS.compose`：軍勢を探す前に、その軍勢の村へ切り替えます（既存の `holdingIndexOfHost` を使います）。下書きが名乗る村は、その村になります。すでに切り替えていた入口では、何も変わりません。
  - `ACTIONS['march-home']`：村は、下書きを開いたあとに読みます（その軍勢自身の村）。上の切り替えによって、別の村の軍勢を前に開いていた村へ「戻す」ことにならないようにするためです。
  - `setDestination`：待ったあと、下書きがまだ開いていて、その行き先を今も指しているときだけ書きます。
  - `adoptPinnedWorld`：ただの下書きはしまい、手に取っていた軍勢は手放します。送信中・送信待ち・予約済み（`sending`・`pending`・`pendingDriver.armed`）の下書きには触れません。選んだ場所は残します。
- **英語**：一文を辞書の末尾に加えました。

## 変えていないこと（逆レビュー）

- **送信**：`march-send`・`sendTheMarch`・送信待ち・手数料・権限・ローカルプレイの送信前の確認（`localMarchFor`）は、そのままです。入口は下書きを作るだけです。
- **同じ世界の選び直し**：`compose-close` でしまえます。別のマスを選べば、`dest-from-map` で行き先を選び直せます。下書きがなければ、札にまた「進軍させる」が出ます。
- **わからない状態**：州の記録を読めていない札は、前の束の表示（読み込み中・読めなかった・待っている）を出します。「軍勢なし」とは言いません。
- **主の範囲**：`orderOf`〜`actOnce`（300–580 行付近）、`providerWorld()`、`viewerKey()`、通常の建設・訓練、`hud/turnlist`・`hud/status` には触れていません。
- **D の範囲**：公開 RPC・MCP・認証・ウォレットには触れていません。
