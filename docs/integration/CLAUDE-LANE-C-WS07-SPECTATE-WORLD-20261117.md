## 照合した実際の経路

- **観戦の流れ**：`startSpectate` の `tick` は、`refreshPlay`（controller の `refresh`。中で `refreshChronicle`）→ `spectateBells` → `followBattles` の順に進みます。失敗した回は `catch` に入り、追いません。
- **`followBattles`**：記録の中の最新の衝突を `watchSeen` と比べます。新しければ `playBattle(focus)` を呼び、それが false を返したら、代わりの位置へ `mapRef.flyTo` します。
- **`playBattle`**：`await heraldRef.clash(...)` のあとで、場面を組み立て、その州の `FS.provinces` と合わせます。`focus` ならカメラを動かします（`camKeep` と `flyTo`）。そして `FS.battles` と効果の層へ渡します。呼ぶのは次の四か所と、この束の追従です：
  - ターンの場面
  - 報告の「見る」（`leaveReport` のあと）
  - 見本の画面
  - `autoBattles`
- **`refreshChronicle`**：世界（世代を含む）が変わったら、記録を捨てて `FS.chronicleWorld` を記します（前の束）。
- **報告（`openReport`）**：もとから `reportWorld` で世界を確かめています。この束では変えていません。

## 実際の欠陥

1. **`watchSeen` に世界がありませんでした。** A → B のあと、B の記録の最初の衝突は A の最後の衝突と違うので、「新しい戦い」としてカメラが飛び、場面が始まりました（新しい世界の最初の読み込みで、偽の知らせが出ていました）。A → B → A でも同じです。
2. **`playBattle` は、待ったあとに世界を確かめていませんでした。** 世界が変わる前に尋ねた衝突でも、答えが届くと、前の世界の入力と新しい世界の州を合わせて場面を見せ、カメラを前の世界の座標へ動かしました。追従の場合は、false のときの代わりの `flyTo` も、前の世界の場所へ飛びました。答えを待つ間に観戦の自動の追従が切られたり、報告が開かれたりしても、カメラは奪われました。
3. **`autoBattles` の `battleSeen`（「州 → 最後に見た決着のターン」）にも世界がありませんでした。** 前の世界の値より新しい世界のターンが大きいと、同じ座標の州を「新しい」として場面を見せました。

## 訂正（2026-11-17、同じ日、ブランチ `claude/lane-c-ws07-spectate-source-20261117`。起点 `bdc5bcac`。`bdc5bcac` は保留）

**残っていた穴**

1. **ヘラルドの取り違え**：`playBattle` は、世界かヘラルド（`heraldRef`）が変わると false を返しました。しかし追従の `still` が見ていたのは、世界・自動の追従・報告だけでした。そのため、同じ世界のままヘラルドが替わると、前のヘラルドへの要求は false になり、`still` は真のままでした。その結果、古い衝突の場所へ `flyTo` が飛ぶことがありました。取り消された要求を、通常の「場面なし」と同じものとして扱っていたことが原因です。
2. **カメラの手動操作**：前の版の報告は、「本人の操作は奪わない」と言いながら、残りの項目では「本人が動かしても飛ぶ」と書いていました。言い過ぎでした。
3. **同じ世界の古い答え**：同じ州で、前のターンの答えが遅れて届くと、地図が自分で見せる場面（`auto` と追従）を、新しいターンの再生中の場面で上書きしていました（`FS.battles` は州ごとに一つです）。

**直したこと**

- **`playBattle`**
  - 取ったヘラルドそのものに尋ねます（`source.clash`）。
  - 待つのは一度だけです。そのすぐあとで、世界かヘラルドが変わったか、`still` が成り立たなければ、**null**（取り消し）を返します。**false** は「場面なし」（衝突がない・見せる場面がない）だけです。
  - 地図が自分で見せる場面（`auto` か `still` があるもの）は、同じ州の、より新しいターンの場面が再生中なら null にします。名前で頼まれた場面（報告の「見る」）は、これまでどおり見せます。
- **`followBattles`**
  - 尋ねたときのヘラルドそのもの（`source`）と、地図の移動の数（`mapRef.moves`）を取ります。
  - `still` は次のすべてです：同じ世界、同じヘラルド、自動の追従が入っている、報告が開いていない、移動の数が変わっていない。
  - 代わりの位置への `flyTo` は、`ok === false`（場面なし）で、しかも `still()` が成り立つときだけです。null（取り消し）では、決して飛びません。
- **呼び出し元**：五か所すべてが null を扱えます。
  - ターンの場面・`autoBattles`・「見る」は、戻り値を使いません。
  - 見本の画面は `if (ok)` で判断します。

**守れることと、守れないこと**（言い過ぎないように分けて書きます）

- **実際のカメラの手動操作**：地図がもともと持つ決まりの範囲だけで守ります（`map/fmap.mjs`）。`moves` は、自動でない `setView` のたびに一つ増えます。これには、ドラッグ・ホイール・ピンチ・地図のキーやボタン・名前で頼む移動（「そこへ行く」など）が入ります。`map.restore` の `ifStill` も、この数を「その後に誰もカメラを動かしていない」の意味で読んでいます。尋ねてから答えが来るまでにこの数が増えたら、追従は場面を見せず、飛びません。
