## 訂正（2026-11-17、同じ日、ブランチ `claude/lane-c-ws07-s1-trade-plan-fix-20261117`。起点 `d83e7e49`）

独立の逆レビューで見つかった欠陥と、初版で「つながっていない」として残したものを、この束の中で直しました。この節が、上の「場合ごとの結果」と「つながっていないもの」の該当する行を置き換えます。

### 欠陥 1：古い成功が、新しい計画を消していた

- 初版は、隊商が受け付けられると、**そのとき立っている計画**を無条件に外しました。送信の間に本人が別の場所（または同じマス）を選び直したり、世界を切り替えて新しい計画を作ったりすると、古い送信の成功が、その新しい計画を消しました。
- 直し方：
  - 計画は、押すたびに新しい object で、通し番号を持ちます（同じマスの選び直しも、別の計画です）。
  - 送信の最初の待ちより前に、「そのときの計画」と「フォームがその計画の場所を使っているか」を控えます（`s1PlanAtSend`）。
  - 答えが来たとき、**受付**で、**使っていて**、**その計画そのものがまだ立っている**ときだけ外します（`s1PlanDone`）。
  - 要塞のフォームも、同じ条件にしました。`act` の引数は変えていません。

| 場合 | 結果 |
|---|---|
| 計画 A で送信 → 受付 | A を外す |
| 計画 A で送信 → 送信の間に B を選ぶ → A の受付が戻る | B はそのまま |
| 計画 A で送信 → 同じマスをもう一度選ぶ（A′）→ A の受付が戻る | A′ はそのまま |
| 計画 A で送信 → 世界が変わる（A は外れる）→ 新しい世界で C を選ぶ → 古い受付が戻る | C はそのまま |
| 計画 A があるが、フォームで別の行き先に選び直して送信 → 受付 | A はそのまま |
| 断られた・失敗・結果が未確認 | 計画はそのまま |

### 欠陥 2：広い在庫の村のカードが出ていると、交易のフォームに着かなかった

- 村の画面は、広い在庫の村を選んでいる間（`FS.wideSelect`）、もとの村のカードの代わりに、その村のカードを出します。交易のカードは、もとの村のものです。
- 直し方：ボタンの行動で、既存の戻り方（`wide-close` と同じ `clearWideSelect`）を呼んでから、村の画面を開きます。

### 欠陥 3：注記と、実際の欄の選択が食い違い得た

- 画面の描き直し（`keepState`）は、本人が欄で選んだもの（作りの最初の選択と違う値）と、折りたたみの開閉を、描き直しのあとに戻します。交易のフォームがもう画面に出ているときにボタンを押すと、本人の前の選択が残り、折りたたみも閉じたままで、注記だけが「入れました」と言うことがありました。
- 直し方：
  - ボタンを押したそのときに一度だけ、その計画のカードが描かれたのを確かめてから、計画の欄を計画の値にし、折りたたみを開き、カードへ移ります（`landS1Plan`。計画の番号で、そのカードを確かめます。数フレーム待っても出なければ、何もしません）。
  - 数量の欄は触りません。フォームは送りません。
  - 注記は「最初の選択にしました。欄で選び直すと、送るのは選び直した場所です」に直しました。あとから本人が欄で選び直しても、注記と食い違いません。

### 古い要求の通知

- 送信の準備の間に世界・読み手・村が変わったときの「隊商は送っていません」は、この要求が出した「準備中」の表示がまだ残っているときだけ、その表示と置き換えます（残したままだと、回り続けるためです）。表示が消えている、または別の表示に替わっているときは、古い要求は何も出しません。
- 準備の読み込みが失敗したときの通知は、世界・読み手が変わっていないことを確かめたあとにだけ出ます（確認が先です）。
- `act` に渡したあとの通知（受付、拒否、未確認）は、主の命令の流れのものです。この束では変えていません。
