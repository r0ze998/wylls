## 1. 結論：部品は4つ＋「まとめる」

| # | 部品 | 一言で | 例 |
|---|---|---|---|
| 1 | **倉** | 物を預かる入れ物 | 「組合の倉」「峠の倉庫」 |
| 2 | **札（権利）** | 持ち主に何かを許す、売り買いできる札 | 「工場を1日3回動かせる札」「この倉の取り分10％の札」「この倉から鉄を週20まで受け取れる札」 |
| 3 | **送る（条件つき）** | 条件がそろったら、倉から倉へ物や札を送る | 「毎日、鉄30を工場へ」「代金が届いたら、兵器を渡す」 |
| 4 | **動かす** | 施設を一回動かす。倉から材料を取り、できた物を倉へ入れる | 「鉄3と木2で兵器1」 |
| ＋ | **まとめる** | 1〜4の組み合わせに名前を付けて、一つの「仕組み」として公開する | 「軍需組合」「定期配送」 |

### なぜこの4つか

- **組合、定期配送、保険、先渡しなどを、運営が一つずつ作らずに済む。** どれも「入れ物」「権利」「条件つきの移動」「生産」の組み合わせとして書ける（3章で確かめる）。
- **「分配」は部品にしない。**「取り分の札を持つ人へ、札の割合で送る」という「送る」の使い方の一つとして書ける。部品を増やさないほうが、読みやすく、壊れにくい。
- **札が、レゴのつなぎ目になる。**
  - 仕組みの取り分も、施設を使う権利も、受け取る権利も、全部「札」なので、売り買いでき、倉に預けられ、別の仕組みの条件にも使える。
  - 「完成した仕組みが次の人の部品になる」のは、この札があるから。

## 2. 世界のルール（部品をどう組んでも破れない）

| ルール | 中身 |
|---|---|
| **無から増えない** | 物は施設で作るか、運ぶか、奪うしかない。札は、裏付けの倉や施設を持つ人しか出せない。裏付けが足りなければ、札は約束どおりに働かない |
| **許可なく触れない** | 動かせるのは、自分の倉・施設と、自分が持つ札が許す範囲だけ |
| **運ぶには時間がかかり、襲われうる** | 「送る」は、倉どうしの距離に応じて時間がかかり、途中の荷は地図の上を移動する（軍事とつながる） |
| **維持費がかかる** | 倉には容量と維持費、施設には1日に動かせる回数と維持費がある |
| **失敗は止まるだけ** | 条件がそろわない・物が足りないときは、その送りは実行されない。失敗は記録に残り、誰でも見られる |
| **公開** | 仕組みの中身（何を受け取り、何をし、誰に渡すか）は誰でも読める。隠れるのは移動中の軍だけ（[13](13-hidden-information.ja.md)） |

## 3. 確かめ：軍需組合を4つの部品で作る

**登場人物：**
- **A：** 鉄鉱山を持つ。
- **B：** 兵器工場を持つ。
- **C：** 農場を持つ。
- **X・Y・Z：** 組合に物資を出す住人。
- **D：** 防衛拠点（砦）を持つ。

**組み立て：**
1. **倉：** X・Y・Z が「組合の倉」を作り、鉄と食料を預ける。預けた量に応じて「組合の取り分の札」を受け取る。
2. **札：** B が「工場を1日3回動かせる札」を組合に渡す。見返りは、できた兵器の10％。
3. **送る＋動かす：**
   - 毎日、組合の倉から鉄9を B の工場へ送る。
   - 工場を3回動かし、兵器3を作る。
   - 兵器の10％を B へ、残りを組合の倉へ送る。
4. **送る（分配）：** 組合の倉の兵器を、取り分の札を持つ人へ、札の割合で送る。
   - 札の持ち主は、自分の分の届け先を変えられる。例：自分の村ではなく D の砦へ。
5. **まとめる：** 1〜4 に「北の軍需組合」と名前を付けて公開する。

**ここから、運営が決めていない動きが生まれる：**
- **D の参加：** D は、X から取り分の札を買う。砦に兵器が毎日届くようになる。D は工場も鉱山も持っていない。
- **先渡しの市場：** E が、組合の札を倉に預け、「来週の兵器を今の値段で売る札」を出す。札が別の札の材料になった。
- **輸送の襲撃：** 盗賊の F は、組合の倉から D の砦へ毎日兵器が運ばれることを、公開の仕組みから読む。そして途中を襲う。
- **組合の対抗：** D は、倉を砦の隣に移すか、運搬の護衛を雇う仕組みを組合に足すかを迫られる。
- **鉄の価格交渉：** A は、組合が自分の鉄に頼りきっていることに気づき、鉄の値段を上げる。組合は、遠くの別の鉱山との契約を足して、仕入れ先を分散するかどうかを迫られる。

最後の2つが、方針の「なぜ戦略になるか」（遠い・近い、依存・分散）にあたります。

## 4. 普通のプレイヤーが使う形

- **地図の上で見る：** 仕組みは地図の上に、倉や施設を結ぶ線として見える。
- **中身を読む：** 押すと、「何を受け取り、何をし、誰に渡すか」が普通の言葉で出る。札の値段と、これまでの失敗の記録も見える。
- **つなぐ：** 「つなぐ」は、札を買う、または自分の倉を送り先に指定する、の一つの操作。
- **作る：** 作るときは、テンプレート（組合・定期配送・先渡し）を選んで数字を入れる。または、AIに「鉄を毎日、砦に届けたい」と伝えて組み立ててもらう。
- **AIも同じ：** AIエージェントも、同じ部品・同じ費用・同じルールで作り、使う。

## 5. まだ決めていないこと

1. **「送る」の条件の種類。** 時間、量、物が届いた、代金が届いた、公開された世界の事実（砦を持っているか等）。どこまで入れるか。
2. **誰が実行するか。** 条件がそろった送りを、手番ごとに誰が動かすか（運営、誰でも、手数料を受け取る人）。費用は誰が持つか。
3. **裏付けが足りないときの順番。** 札が複数あって物が足りないとき、先着か、割合か。
4. **仕組みを作り変えるとき。** 持ち主が中身を変えたら、すでに札を持つ人はどうなるか（札の期限までは古い条件のまま、など）。
5. **チェーン上の形。** 倉はアカウント、札はトークン、という対応が考えられるが、未決定。
