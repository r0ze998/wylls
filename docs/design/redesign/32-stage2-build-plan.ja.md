# 段階2の実装計画（札と引き換えの預かりを、今のゲームのどこに足すか）

**状態：** 計画の第1版（2026-10-24）。4章の L1〜L9 は、すべて推奨案で決定しました（2026-10-24、あなたの判断）。

**対象：** ブランチ `ccr-184d6862-fqutoz`（段階1の1a〜1f まで入ったもの）。

**段階2で作るもの（決定済み。[20](20-stage2-play.ja.md)、[29](29-remaining-decisions.ja.md) の A1〜A3）：**
- 札3種：持ち分の札、受け取りの札、使用権の札。
- 引き換えの預かり。両方そろったら同時に交換し、期限までにそろわなければ両方に返す。
- 規則（[20](20-stage2-play.ja.md) の5章）：
  - 倉が奪われたら、その倉の札は無効になる。
  - 中身が足りなければ、札の割合で均等に減らす。
  - 札を受け渡すたびに清算する。
  - 札を出すには少しの費用がかかる。
  - 札は国とは関係なく残る。
- 材料は、使う側の倉から施設まで荷車で運ぶ（A2）。
- 預かりに入れられるのは、物と札だけ（A3）。

## 1. コードを読んで分かった、計画を決める事実

1. **倉（貯蔵庫）には、持ち主が一人しかいない。**
   - 倉のアカウントには、持ち主・中身8種・上限・世代があります。
   - 空きは280バイトです。
   - 持ち分を持つ人の一覧を倉の中に置くなら、1人24バイトで、入るのは10人ほどです。
2. **物は、荷車でしか動かない。**
   - 荷車を出せるのは、出発地（村か倉）の持ち主だけです（`SendCaravan`）。
   - 他人の倉から物を引き出す仕組みはありません。
   - 受け取りの札・持ち分の札で「引き出す」には、**札を持つ人が、他人の倉から荷車を出せる** ようにする必要があります。
3. **工房には「1回動かす」という単位がない。**
   - 今の工房（1a）は、村の建物です。村の鉱石と木材を、1時間に兵器4へ、途切れなく変えます。
   - 使用権の札（「1日3回動かせる」）を作るには、**「1回」の中身を新しく決める** 必要があります。
4. **新しいアカウントの家賃は、中継サーバー（relay）が払っている。**
   - 倉・荷車・建物・国の家賃は、中継サーバーが払っています。1つの鍵に、1日あたりの上限があります（`lamportsPerDay`）。
   - 札を持ち手ごとのアカウントにすると、札が分かれるたびに家賃がかかります。上限の見直しが要ります。
5. **他人に物を送るには、ウォレットの署名が要る（段階1の決まり）。**
   - ゲーム内の鍵（session）で送れるのは、自分の場所あてだけです。
   - 札の受け渡しも同じ扱いにするか、決める必要があります。
6. **倉が奪われると、持ち主と世代が変わる（1b、決定 J2 の作り）。**
   - 札に「どの世代の倉の札か」を書いておけば、奪われた倉の札が無効なことは、世代の違いだけで判断できます。札を一枚ずつ消して回る必要はありません。
7. **規則の変更なので、新しいシーズンが要る（段階1の J5 と同じ）。**
   - プログラムの版を上げます（S2、program_version 5）。新しい規則の指紋を作ります。
   - 検証ツール・herald・画面の WASM も作り直します。

## 3. 計画に足りていなかったもの（コードを読んで判明）

- **他人の倉から荷車を出す仕組み**（1章の2）：札で引き出すには必須です。荷車の出発地の確認を、「持ち主」か「その倉の札を持ち、取り分が残っている人」に広げます。
- **工房の「1回」**（1章の3）：使用権の札の前提です。4章の L4 で決めてください。
- **混ざった中身の倉の持ち分**：組合の倉には、鉄も木材も食料も入ります。預けた物の量を、どう持ち分の割合に直すか決める必要があります（L2）。

## 4. 実装の前に判断してほしいこと［決定 2026-10-24：L1〜L9 とも推奨案を採用］

| # | 項目 | 推奨案 | 理由 |
|---|---|---|---|
| **L1** | **札の置き場** | 持ち手ごとの小さなアカウント（「札の束」）にする。束には、発行元の倉・種類・世代・量・持ち手を書く。束をまるごと渡すときは持ち手を書き換えるだけで、家賃は要らない。分けるときだけ新しい束を作る | 倉の中の一覧（10人まで）だと、組合や投資の倉がすぐ満員になる。束なら人数の上限がない |
| **L2** | **混ざった中身の持ち分の数え方** | 資源ごとの固定の換算表で「値」に直して数える（例：食料1・木材1・石1・鉱石2・兵器4・金3。数字はフェーズ6）。引き出すときは、倉の中身を割合どおりにまとめて受け取る（鉄だけ、とは選べない） | 資源ごとに別の持ち分にすると、作った兵器を誰の分にするかが決まらない。換算表なら、預け入れも配分も一つの割合で済む |
| **L3** | **札で引き出すときの物の動き** | 札を持つ人が、その倉から自分の村か倉へ荷車を出す。送りの費用と危険は札を持つ人が負う | 物は荷車でしか動かない（決定済み）。倉の持ち主が眠っていても引き出せる |
| **L4** | **使用権の「1回」** | 1回 ＝ 工房1つ分の1時間ぶんの変換（鉱石8・木材4 → 兵器4）を、**すぐに** 行う。材料は、使う側の倉のうち **工房と同じ州にある倉** から取り、出来上がりも同じ倉に入る。工房の持ち主の生産は減らない。1日に使える回数の合計は、工房の数×24回まで | 材料を荷車で運ぶ（A2）を、「工房の州に自分の倉を置き、そこへ運ぶ」で満たせる。持ち主の生産を減らす形は、計算が大きく複雑になる |
| **L5** | **受け取りの札の均等割りの時期** | 1日を1期間にする。期間中の受け取りの請求を集め、次の期間の始めに、在庫が足りなければ割合で減らして渡す（渡すのは荷車の出発の許可） | 請求のたびに渡すと先着になり、実行役が順番を操作できる（決定の理由）。1日まとめると公平で、計算も軽い |
| **L6** | **預かりの中の物の扱い** | 物は、出す側の倉の中で **動かさずに押さえる**。交換が成立すると、受け取る側は「その量をその倉から荷車で出してよい」権利（一回きりの受け取りの札）を得る。札はそのまま持ち手が替わる | 物を預かりのために瞬間移動させない（決定済みの「札は物を瞬間移動させない」）。倉が奪われれば、その権利も無効になる（5章の規則どおり） |
| **L7** | **札の受け渡しの署名** | 引き換えの預かりを通す交換は、ゲーム内の鍵でできる（両方が預けるので、両方の同意がそろう）。預かりを通さない贈与は、ウォレットの署名を要る | 他人あての送りはウォレットが要る（段階1の決まり）と同じ考え方。交換は日常の操作なので手軽にする |
| **L8** | **札を出す費用** | ゲーム内の金を払い、その金は消える。数字はフェーズ6 | 乱発を防ぐ（決定済み）。賞金の倉へ回すかどうかは、お金の構造（[25](25-money-structure.ja.md)）と合わせてフェーズ6で決める |
| **L9** | **段階2を試すシーズン** | 新しいシーズン（S2、program_version 5）。段階1の部品はすべて引き継ぐ | 規則の変更なので、新しいシーズンが要る（J5 と同じ） |

## 5. 危険

- **家賃と中継サーバーの上限：** 札の束が増えると、家賃が増えます。1日の上限（`lamportsPerDay`）の見直しが要ります。束の数の上限も要るかもしれません。
- **計算量：** 期間の清算（L5）は、請求の数に比例します。1回の命令で扱える数に上限を置き、残りは次の命令に回す形になります。
- **検証ツール：** 命令ごとに改ざんの検出を作ります。段階1と同じく、作業の多くはここにかかります。
- **AI：** 札の売り買いは、今のAIの判断の範囲を大きく超えます。段階2のAIは、まず「組合の倉に預ける」「受け取りの札で引き出す」の2つから始めるのが現実的です。
