# 見えない情報をどう作るか（たたき台）

**状態：** たたき台（2026-10-23）。

**目的：**
- 見張り塔に本当の意味を持たせる。
- チェーンを直接読む人やAIだけが得をする形にしない。

**あなたの方向：** zk（ゼロ知識証明）で作る。

---

## 1. 何を隠し、何を見せるか

| 情報 | 扱い | 理由 |
|---|---|---|
| 地形、建物とその設定、持ち主、市場の値段、終わった戦いの結果、歴史 | **全員に公開** | 依存と連鎖を読み合うための土台。ここを隠すと読めないゲームになる |
| **移動中の軍の位置と規模** | **本当に隠す** | 見張り塔・待ち伏せ・奇襲が成り立つ唯一の材料 |
| 備蓄の使い道、次の計画 | 隠さない（もともと誰にも分からない） | 数が見えても、売るのか使うのかは分からない（10-19 のあなたの言葉） |

**隠すのは「動いている軍」だけ** にします。地図そのものは隠しません。Dark Forest は地図を隠したため、計算機をたくさん回せる人ほど地図を早く見つけられる問題を抱えました。地図を隠さなければ、この問題は起きません。

## 2. zk でどう作るか

**zk でできること：**「中身を見せずに、中身が規則を守っていることだけを証明する」こと。

1. **軍の位置は、持ち主だけが知る。** チェーンに載るのは位置の「封」（ハッシュ）だけ。
2. **軍を一歩動かすたびに、持ち主は証明を出す。**
   - 動きが規則どおりであること（速さ、道、燃料）。
   - **どの見張り塔の範囲にも入っていないこと。** 塔の位置と範囲は公開なので、それと比べて証明できる。
3. **塔の範囲に入ったときは、隠れられない。**
   - その一歩には「範囲外」の証明が作れないので、代わりに位置を **塔の設定で決まった相手にだけ読める暗号** にして出す必要がある。
   - 「その暗号の中身が本当の位置である」ことも、zk で証明する。
   - どちらも出さなければ、軍はその場から動けない。
4. **見えるのは、決まった建物からだけ。**
   - 見張り塔、砦、村は、公開の位置から範囲を見張る。
   - 動いている軍どうしは、互いを見られない。
5. **戦いは、見える場所で起きる。**
   - 公開の物（村・砦・橋・市場など）を攻めるには、そこに着いて姿を現す必要がある。
   - 見張りに見つかった軍は、攻撃の的になる。
   - 隠れた軍どうしが野原ですれ違っても、戦いにならない。

**ポイント：** 5つめの単純化で、zk に「隠れたものどうしの計算」をさせずに済みます。zk は「隠れたものと公開のもの」の比較なら得意で、「隠れたものどうし」は苦手だからです。

## 3. 見張り塔がどう意味を持つか

- **塔の設定：** 見えた位置を誰が読めるか。
  - 自分だけ／自分の国／払った人／許可した人。
  - 暗号の宛先が変わるだけで、仕組みは同じ。
- **情報の商売が本物になる。** 払っていない人は、チェーンを読んでも暗号しか見えない。
- **塔は狙われる。** 塔を壊すか奪えば、そこは見えない場所になる。
- **塔も燃料で動く。** 燃料が切れれば見張りが止まり、その間は誰でも通れる。

## 4. 「チェーンを読む人やAIだけが得をしない」ことの確認

| 心配 | この形でどうなるか |
|---|---|
| チェーンを直接読めば、画面より多く分かる | チェーンには封と暗号しかない。鍵がなければ人もAIも読めない。画面は「自分が読める分」をそのまま見せるだけ |
| 計算機を回せる人が地図を早く見つける（Dark Forest） | 地図は隠さないので起きない |
| AIは24時間見張って即座に反応する | 隠し方では解けない。全員に同じ通知と、「見つけたら門を閉める」などの自動反応の設定を渡す。手番の区切りも全員同じにする |
| 運営がこっそり覗く | 運営も鍵を持たない。証明は数学で確かめられる（「Rules no one can bend」） |

## 5. 他の作り方との比較

| 方法 | 長所 | 短所 |
|---|---|---|
| **zk（この案）** | 信じる相手が数学だけ。仕組みが成熟している（Groth16 は2016年、Dark Forest は2020年）。「枯れた技術」に当たる | 回路づくりが重い。証明は手元の端末で作る（スマホで数秒程度［未確認］）。隠れたものどうしの計算は苦手 |
| 暗号のまま計算する多者計算（Arcium、Solana で2026年2月にメインネット・アルファ） | 隠れたものどうしの計算もできる。同じ発想の作例（Encrypted Forest）がある | まだ新しい。参加ノードの多数が正直であることを信じる必要がある。遅さと費用 |
| 安全な処理装置（MagicBlock の Private Ephemeral Rollups、Intel TDX、2025年9月） | 作るのが最も簡単 | Intel の装置と運営を信じる必要がある |
| 時間ロック（決まった時刻に自動で開く） | 単純 | 時刻まで誰にも見えないので、見張り塔が「早く見る」ことができない |

## 6-1. zk が入るまでの見張り塔（2026-10-23 追記）［決定：B 案と線引きを採用］

### 今の封で、何が見えて何が見えないか［事実］

今の進軍の封（`frontier/season-complete` の `permutation-rules/src/frontier/seal.rs`）では、次のようになっています。
- **出発したときに公開されるもの：** 出発地、規模、着くターン。
- **封の中身：** 行き先、通る道（最大32歩）、構え。これが開くのは、**着くターンになったとき**。それより前には、誰も（運営も）開けられない。
- 荷車は、段階1の決定どおり、すべて公開です。

**つまり、zk が入るまでは、見張り塔が「隠れた軍を途中で見つける」ことはできません。** 封が開くのは着いたときだけで、特定の人にだけ早く見せる方法がないためです。

### 選択肢

| 案 | 中身 | 良い点 | 悪い点 |
|---|---|---|---|
| **A. 塔は zk まで作らない** | 段階1〜4では見張り塔を出さない。段階3の「塔が見たら」という合図も、zk の後に回す | 単純。嘘のない形 | 決定済みの「塔の持ち主は塔の目撃を合図に使える」が、長い間使えない |
| **B. 塔を「公開の出来事の見張り」と「通る者を削る防御」にする（推奨）** | 2つの働きを持たせる。<br>① 範囲の中で起きた **公開の出来事** を、持ち主（と設定した相手）に知らせ、合図にできる。公開の出来事とは、敵の出発、荷車の出入り、到着など。<br>② 封が開いたとき、**その道が塔の範囲を通っていたら、通ったターン数に応じて兵を削る**。着いたときにまとめて計算する | 今の封のままで作れる。道を選ぶ意味が生まれる（塔のある道を避けるか、損を承知で通るか）。合図も使える | 「隠れた軍を早く見つける」働きはない。情報を売る塔は、zk までは価値が小さい（知らせる中身は、もともと公開されているため） |
| **C. zk を早める** | 段階1の前か並行で、移動中の軍を zk で隠す仕組みを入れる | 本来の見張り塔がすぐ作れる | 最も重い作業を先頭に置くことになる。段階1の遊びを試すのが遅れる |

### B 案の細部

- **知らせる（①）：**
  - 塔の設定で、知らせる相手を選ぶ（自分／国／払った人）。
  - 知らせる中身は公開の情報なので、チェーンを読む人やAIが得をすることはない。塔の価値は、「見張って、知らせ、合図で自動に動ける」便利さにある。
- **削る（②）：**
  - 封が開いた軍の道を、塔の範囲と照らし合わせる。通ったターン数に応じて、着いた時点で兵を減らしてから戦いに入る。
  - 決まった計算なので、検証ツールで後から確かめられる。
  - 敵の荷車が範囲を通るときは、公開なので、その場で削れる。
- **削る相手：** 塔の設定で決める（戦争中の国／同盟以外）。
- **zk が入った後：** ①に「隠れた軍を見つけて、設定した相手にだけ知らせる」が加わる（6章までの本来の形）。

### 「自動の攻撃」との関係

- 段階3では「攻撃や進軍は自動にしない」と提案していました。
- B 案の「削る」は、建物がその場で働く **守りの効果** で、軍を出して攻めることではありません。
- そこで、次のように線を引くことを提案します。
  - **建物が自分の範囲で働く守り（塔の矢、砦の守り）は、自動でよい。**
  - **軍を動かして攻めることは、自動にしない。**

この線を引けば、[27](27-design-v1.ja.md) の5章に残っている「自動の攻撃」の食い違いも、同時に解けます。

## 6. まだ決めていないこと

1. **一歩の大きさと手番の長さ。** 一歩ごとに証明が要るので、細かすぎると重くなります。
2. **見張りの範囲の形。** 範囲内かどうかの判定が、回路の重さを決めます。
3. **暗号の宛先の扱い。** 「払った人」が増えたとき、宛先をどう増やすか。塔の持ち主だけを宛先にして、持ち主が他人に渡す形が軽いですが、持ち主が嘘をつかない仕組みが要ります（渡した中身がチェーン上の暗号と一致することを、受け取った人が確かめられるようにする）。
4. **Solana での検証の費用。** Solana には zk の検証を助ける機能がありますが、1回の証明の確認にかかる計算量を確かめる必要があります［未確認］。
