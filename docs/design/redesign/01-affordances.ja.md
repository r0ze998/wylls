# フェーズ1b・1c：媒体の性質（ブロックチェーン・AIエージェント・トークン）

**状態：** 下書き（2026-10-22）。

**目的：** 三つの素材が、ゲームに**何を初めて可能にし、何を壊すか**を整理します。過去の成功例と失敗例も並べます。ここではまだ仕組みを考えません。フェーズ3で、柱（フェーズ2）と掛け合わせる素材にします。

**表記：**
- ［事実］出典あり
- ［既知］広く知られているが、今回は出典を取り直していない
- ［未確認］
- ［判断］
- 法律に関わる点は概要だけです。法的な助言ではありません。

## A. ブロックチェーン（Solana を中心に）

### 初めて可能にすること

| # | 性質 | ゲームでできること | 前例 |
|---|---|---|---|
| A1 | **審判なしで信用できるコミット** | 同時の秘密の手、封をした入札、「明かすのを拒む」嫌がらせの防止（時間ロックなら、時間が来れば誰でも開ける） | Dark Forest（ゼロ知識証明）、Bittensor（drand の時間ロックを本番で使用）［事実］ |
| A2 | **誰でも参加でき、誰でも道具を作れる** | ボット、別のクライアント、プラグインを「ゲームの物理」として認める | Dark Forest のプラグイン文化、有志が開いた大会［事実］ |
| A3 | **運営がいなくなっても世界が残る** | 「元のクライアントが今日閉じても、明日遊べるか」（gubsheep の問い） | Autonomous Worlds の論考、Pirate Nation は閉鎖時にコードを公開［事実］ |
| A4 | **他人が世界を拡張できる** | 他のプログラムが状態を読み、上に作れる | Loot の派生作品が約1か月で100以上［事実］。熱は早く冷めた |
| A5 | **ルールが公開され、公平さを確かめられる** | 乱数や判定を、誰でも検証できる | ［既知］ |
| A6 | **持ち物が運営を越えて残る** | 資産が、作った会社より長く残る | Pirate Nation が作品を自由な利用許可で公開［事実］ |
| A7 | **機械どうしの支払い** | 1回の行動ごとに支払う、AIエージェントの課金（x402） | x402 は Coinbase が作った規格で、2026年4月から Linux Foundation の財団が運営。Solana は主要な決済先［事実］ https://decrypt.co/363173/coinbase-linux-foundation-launch-x402-foundation |
| A8 | **速くて安い実行の仕組み** | 一時的な検証者（MagicBlock の一時ロールアップ）で、手数料なしの即時実行。毎回の承認なしで動かせる一時鍵（セッションキー） | MagicBlock［事実］、セッションキー［既知］ |
| A9 | **誰も中身を持たない共有の秘密** | 暗号計算（MPC）で、霧や手札を誰にも見えない形で保つ | Arcium（Solana、2026年2月2日にメインネットのα版）［事実］ https://www.theblock.co/post/387564/arcium-launches-privacy-preserving-mainnet-alpha-on-solana-as-umbra-debuts-shielded-finance-layer、Encrypted Forest［存在は事実、遊べるかは未確認］ |

### 壊すもの・代償

- **状態は公開が基本。** 何かを隠すには、時間ロック・ゼロ知識証明・暗号計算のどれかが要り、どれも作る手間と処理時間がかかる。
- **別アカウント（シビル）が無料。** 一人が100人になれる。「1人1票」「同盟の数」に頼る仕組みは、担保・評判・本人性がないと壊れる。
- **ボットは常に最適に動く。** 誰でもクライアントを作れるので、操作の速さや細かさを競う部分は、必ずスクリプトが勝つ。
- **変えられないことの両面。** バランス調整がすぐできない。更新の権限を持てば「運営なしで続く」が弱まる。バグがお金のからむ悪用になる。
- **チェーンが死ねば、世界も死ぬ。** Pirate Nation は自前のチェーンごと終了し、ポイントは無価値になった。Treasure も自前のチェーンを閉じた［事実］。
- **預かりと橋渡しが攻撃の的になる。** Axie の Ronin の橋が約6億ドル盗まれた［事実］。

## B. AIエージェント（言語モデル）

### 初めて可能にすること

| # | 性質 | ゲームでできること | 前例 |
|---|---|---|---|
| B1 | **言葉による交渉** | メニューではなく、自由な文章で条件・はったり・取引をする | CICERO：Diplomacy で人間の平均の2倍以上の得点、上位10%。AIだと疑ったのは1人だけで、人間はむしろ組みたがった［事実］ |
| B2 | **記憶と関係** | 恨みと恩を、手番をまたいで覚えている | Generative Agents／AI Town［事実］ |
| B3 | **眠らず、数が多い参加者** | 人が少なくても世界が生きている | Project Sid：最大1,000体以上で、役割・規則・文化が生まれた（予備的な結果）［事実］ |
| B4 | **プレイヤーとしてのAI** | 人間と同じ通信の形で、同じルールで遊ぶ | Golemreach、OpenMMO（待ち時間で公平にする）、SpaceMolt（AIだけ）［事実、規模は小さい］ |
| B5 | **持ち主が任せるAI** | 「1.5人用」の遊び。不在の間の代理。AIが指示を断ることもある | Parallel Colony［発表は事実、提供状況は未確認］ |
| B6 | **交渉できるNPC** | 雇ったり、寝返らせたりできる | Eternum＋Daydreams のエージェント［事実］ |

### 壊すもの・代償

- **見分けられないことと信頼。** ボットは人間のふりをしている間は協力ゲームで成果を上げるが、正体を明かすと成果が消える（Nature Machine Intelligence 2019）［事実］。表示すれば割り引かれ、隠せば倫理の問題になる。
- **AIどうしのプロンプト注入。** 相手が送る文章は、こちらのAIへの攻撃になりうる。悪意の指示が多エージェントの中で自己増殖する研究がある［事実］。
  - **対策［判断］：** 会話は信頼しないデータとして扱い、行動は型の決まった命令だけにし、会話で支出の権限を与えない。
- **幻覚と、予測できなさ。** できない取引を持ちかける、約束を忘れる、矛盾する。**言葉は提案し、判定はコードがする**ことが必要。
- **費用と待ち時間。** 1手ごとに数秒と費用がかかる。数千体になると計算の予算の問題になる。誰が払うか（運営か持ち主か）。
- **人間との公平さ。** 注意力・操作量・記憶でAIが勝つ。対策は待ち時間・手番制・回数制限。「一番良いモデルを使える人が勝つ」は課金で勝つのと同じになる。モデルや予算の上限を確実に設けるには、運営が推論を握るか、安全な実行環境などで「どのモデルで動いたか」を証明させる必要がある（詳しくは [01-ai-roles.ja.md](01-ai-roles.ja.md)）。
- **別アカウントがさらに増える。** 一人が100体のAIを動かせる。
- **協調しすぎる。** Generative Agents のAIは断らない。目的が対立しなければ、ドラマは生まれない（参考作品の分析L9）。

## C. トークン（フェーズ1c：ゲームの素材として）

### できること

| # | 使い方 | ゲームでできること | 前例と注意 |
|---|---|---|---|
| C1 | **担保・コミット** | 預け入れつきの参加、破ると没収される同盟、保証金つきの約束で、約束を破るのに代償が生まれる | きれいな前例はない。賭博や証券とみなされる危険と、大口の有利 |
| C2 | **賞金の原資** | 参加費や出資者の賞金を、プログラムが配る | Dark Forest、Sky Strife S0、Eternum S1（100万LORDS＋10万STRK、内訳にAIとの交流の枠）［事実］ |
| C3 | **ゲームをまたぐ共通通貨（世界の持ち分）** | 複数のゲームで同じ通貨と取引所を使う | LORDS（供給3億、Realms の各ゲーム）［事実］。価格の変動がバランスに漏れる |
| C4 | **統治** | 保有者が数値やシーズンを決める | Treasure のチェーン閉鎖の投票［事実］。金持ちの支配、別アカウント、投票率の低さ |
| C5 | **運営が管理する現実の通貨との交換（暗号資産でない例）** | 時間をお金で買えるが、強さは買えない | EVE の PLEX（毎月の経済報告で流入と流出を公開）、Albion の金↔銀の交換［事実］ |
| C6 | **元本を失わない賞金** | 預け入れの利回りを賞金にする | PoolTogether：違法なくじだとする集団訴訟は、原告の適格がないとして却下され、中身は判断されていない［事実］ |

### 壊れ方（よくある失敗）

- **上限のない報酬トークン＋使い道の不足＝インフレの死の連鎖。**
  - Axie の SLP は、発行が消費の約4倍で、価格は約99%下落した。
  - StepN の GST は、時価総額が1か月で1.4億ドルから0.24億ドルに落ちた。後から入る人の支払いで報酬が成り立つ構造だと批評された。
  - DeFi Kingdoms は悪用と、売りの圧力で崩れた［事実］。
- **取り出しか、価値の創出か（ここに挙げた失敗例は、どれも「発行で報酬を払う」型。発行しない設計は別に検討する。詳しくは [01-token-primer.ja.md](01-token-primer.ja.md)）。** 参加者の多くが稼ぐために来ると、すべての報酬が売り圧力になり、新しいお金の流入が必要になる。それはねずみ講の構造になる。**仮説：** トークンは、遊びが生んだ価値（手数料・賞金・預け入れ）を配り直すときに一番合い、新しく発行して配るときには合わない［判断、文献と一致］。比較の基準として、「トークンなし／USDCの賞金」も常に並べる。
- **自分のトークンに頼る金庫。** Treasure は、年約830万ドルの支出を自分のトークンで支えていたため、価格の下落で立ち行かなくなった［事実］。
- **ポイントは価値ではない。** 将来の価値を約束すると、守れない期待が生まれる（Pirate Nation）［事実］。
- **規制（概要のみ）。**
  - 運営の努力から利益を期待させて売るトークンは、証券とみなされる危険がある。
  - 「有料の参加＋偶然＋賞金」は賭博・くじの典型的な三要素。
  - 腕前で決まる賞金で、無料で参加できる道があると、危険が低い形とされることが多い。国や地域によって違う。

### 設計の原則（文献から）

- 流入と流出を明示してモデルにする。
- 遊び続ける理由を、トークンの価格に依存させない。
- 長く大規模に成功した「遊んで稼ぐ」ゲームは、今回の調査の範囲では見つからなかった［未確認：網羅的な調査ではない］。成功の前例は狭く、賞金のトークン（Dark Forest、Sky Strife）と、シーズンの賞金のための共通通貨（LORDS）くらい。
