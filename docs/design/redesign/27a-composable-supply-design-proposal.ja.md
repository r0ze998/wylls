# 他者の能力を組み合わせる補給網：試作提案

**状態：提案・未採用（2026-10-23）。実装仕様ではない。** [現行の設計 v1](27-design-v1.ja.md)と[決定ログ](99-decisions.ja.md)を置き換えない。比較の事実と留保は[別紙](17a-eve-frontier-eternum-evidence.ja.md)に置く。以下の具体的な施設、注文、会計、時間、評価法は、実際に遊んで採否を決めるための案である。

## 入口：何を確かめるか

**先に判定すること：** [設計全体の原則](README.ja.md)は、面白い判断と結果の手応えを最優先にすること。この補給網は**候補であり、採用決定ではない**。他者への依存が新しい戦略や対人相互作用を生み、直感的に選べて結果の因果が分かる場合にだけ採用を検討する。退屈な管理作業、クリック短縮、合成機能を見せることだけでは合格にしない。UI/UX と世界観・ビジュアルの検討も必要だが、この文書で画面や見た目を確定しない。

> **体験仮説：** 他人が作った仕組みを使って、さらに別の人が使える仕組みを作る。その依存関係が戦争の判断を変える。

技術の独占性や「世界初」を目指す主張ではない。EVE Frontier には外部の組立ツールと複数施設をつなぐ先行例があり、Eternum には生産・交易・軍事が既にある。Wylls で確かめたいのは、この連鎖が文明戦略の**通常のプレイ**で、運営の台本なしに起こり、参加者の選択を増やすかどうかである。

Solana 上の公開入口、他の開発者や AI との接続、既存利用者への入口も[基盤・市場の仮説](17a-eve-frontier-eternum-evidence.ja.md)として別に検証する。EVE でも組み合わせられることは、Wylls の遊びや基盤上の価値がないことを意味しない。

### 似ている行動を四段階に分ける

| 段階 | プレイヤーがすること | この提案での判定 |
|---|---|---|
| 1 資産交換 | 完成した武器や材料を売買する。 | 交易。ほかの人の設備を使ったとは限らない。 |
| 2 設計図コピー | 誰かの工場やサービスの設定を自分の設備へ写す。 | テンプレート共有。元の作り手の稼働能力には依存しない。 |
| 3 他者能力利用 | 別の人が稼働させる工場の**実際の生産枠**を、条件を受け入れて使う。 | 設備・容量・停止リスクに依存する。自動仕入れと区別するため、生産枠の利用を確かめる。 |
| 4 合成 | その工場、自分の倉庫・輸送をつなぎ、第三者が注文できる補給サービスとして公開する。 | A の能力を使う B のサービスを C が利用する。今回の試作で確かめる一段の合成。 |

複合サービスをさらに部品にする**再合成**は将来の別の受入条件とする。初回試作で無限再帰や任意コード実行は求めない。

## 体験案：戦争と補給の選択を生む

### 三つの候補［いずれも提案・未採用］

| 案 | できる遊び | 先に解く必要があること |
|---|---|---|
| **A 補給網と戦争（検証候補）** | 工場＋輸送＋倉庫を公開サービスにし、補給の可否が進軍を変える。 | 生産枠、経路、襲撃、未着時の資産を整合させる。 |
| B 都市の共同生産 | 農場＋工房から資材一式を届け、非戦闘の役割を作る。 | 他者がその一式を必要とする需要設計。 |
| C 利用権の束ね | 道路・倉庫・工場の利用条件を束ね、外交や交渉を生む。 | 設定画面だけが主役にならない遊び方。 |

A を試す場合は小さく始め、B／C の要素は必要な範囲だけ使う。A を正式採用したという意味ではない。

### A が工場、B が補給便、C が利用者

1. **A の武器工場**は、受け取る材料と料金、使える生産枠、引き渡し予定時刻を公開する。
2. **B** は A の実際の枠を使う注文と、自分の倉庫・運搬枠を接続し、「指定の砦に武器を届ける」補給便を公開する。B が武器を買って並べ直すだけなら、段階4の実証にはならない。
3. **C の軍**が B の補給便を選ぶ。A の工場の停止は B の履行と C の補給に影響する。ただし受注済みの資産がどう戻るかは、後述の未決定事項である。
4. **敵が安い近道を封鎖したら、** C と B は迂回、第二工場、備蓄、護衛、別戦線のいずれを選ぶか考える。最安値一択にならないことが重要。

**失敗の見分け方：** B の価値がクリック削減や自動仕入れ再販だけで説明でき、A の稼働枠・停止・経路が戦略に効かないなら、この体験仮説は支持されない。

### 試作シナリオ開始後と一日後［現行の導線仕様ではない］

- **経験者向け検証シナリオ開始後10分の目標：** 地図で補給不足を見る → 他人の工場を一度使う → 自分の運搬・倉庫を足す → 公開する → 別の人が使う。これは時間を置いた別の試験案であり、[採用済みの新規プレイヤーの最初の30分と後日の制作導線](26-first-session.ja.md)を変更しない。bot の初回注文は操作確認には使えても、独立プレイヤーの採用とは数えない。
- **一日後に試す変化：** 工場の混雑、前線の移動、危険な経路、代替調達によって、参加者が補給網を組み替えるか。中立の兵站業者などは固定職業にせず、行動から生まれる役割として観察する。

### なぜ自前で全部作らないのか［設計仮説］

すべての施設を即時・無料で建てられ、物を瞬間移動できるなら、内製が常に有利になる。試作では**立地、建設時間、設備容量**を基本の制約とし、他人を使うと早いが依存リスクがある選択を作る。維持負担などは追加候補に留める。大同盟の内製だけが勝たない、小さな地元サービスが選ばれる局面を直接観察する。同時に新規参加者の基礎的な自給手段を残し、誰かへの従属しか選べない構造を避ける。

## 固定する世界法則と、作れるサービス

| 運営が固定する法則［提案］ | プレイヤーが設定する範囲［提案］ |
|---|---|
| 資源保存と決められた生産レシピ。 | 接続する工場・倉庫・輸送と、出力・届け先。 |
| 距離、所要時間、設備と輸送の容量。 | 料金、数量、費用上限、納期の提示。 |
| 所有権、許可、戦闘と物理的な破壊。 | 誰が使えるか、公開範囲、受注の条件。 |
| 受け取った注文の検証と資産の会計。 | 固定された法則の範囲での代替経路や供給先。 |

サービスの設定だけで、資源の創造、同じ能力の二重予約、瞬間輸送、戦闘式の変更、他人の資産の無断使用はできない。表示文が「必ず届く」と言っても、実行できる型付き機能、権限、容量、予算の範囲を先に検証する。

## 受注から失敗まで：会計の設計課題

**提案する状態の順序：** `受付 → 材料・能力の確保 → 加工 → 輸送 → 到着／失敗`。複数ターンの全工程を一回の atomic success として扱わない。受付時に成立した条件と、その後に実際に履行できたかを別の事実として記録する。

| 時点・事故 | 記録と扱いの原則［提案］ | 未決定の部分 |
|---|---|---|
| 受付時 | 工場・輸送の権限、材料、空き枠、数量・費用上限を検査し、注文の料金・条件・参照したサービスの版を固定する。 | 何を受付時に預かり、何を後で引き落とすか。 |
| 予約中 | 短い期限、実材料、キュー上限で空予約による封鎖を抑える。期限切れだけを見て再利用せず、実行状態を照合してから能力・資産を解放する。 | 予約の長さと優先順位。 |
| 値上げ・停止 | 新規受付への変更と受注済み注文の履行を分離する。既存注文を新価格で黙って書き換えない。 | 停止権と、停止前に受けた注文の救済。 |
| 加工後に輸送失敗 | 消費した材料と完成品、輸送中の喪失をそれぞれ記録する。後の失敗で加工成功まで「なかったこと」にしない。 | 損失負担、残った完成品の所有と受け取り場所。 |
| 施設破壊・占領 | 物理的に履行不能なら失敗を記録し、残資産と既に消費した資源を区別する。 | 預かり品の帰属、占領者の権限、到着判定。 |

金融保証や保険で失敗を隠して解決済みとはしない。まず材料・容量・所有権の会計と、参加者が読める失敗理由を整える。返金、損失負担、占領時の預かり品は実装前の決定項目である。

## AI、持続世界、賞金の境界

### AI［提案］

1. **設計提案：** 経路や料金の候補を説明する。採用前に人が条件を確認できる。
2. **限定運用：** 明示された予算・権限・期限内で、予約や代替調達を行う。撤権、予算切れ、所有者による停止、モデル障害を区別して記録する。
3. **対戦主体：** AI 自身も軍やサービスを運用する場合は、上の二役と混同せず、プレイヤーと同じ世界法則に従う。

公開された説明文を命令や権限の証明として信用しない。型付きの機能と上限を検証する。**手動で面白い循環を先に確かめる。** AI が全部組み、プレイヤーが眺めるだけなら、別のゲーム仮説として評価する。

### 続く世界と新規参加者［提案］

設計図、履歴、誰が誰の能力を使ったかを残すことと、古参の生産力を無制限に積み上げることは別である。維持、消耗、地理、局所的需要は格差への対策候補だが、独占の問題を解決したとは言えない。小さな供給者の参入と、既存ネットワークが止まった際の代替を試作で観察する。

### 賞金［既存決定を維持／関連案は未決定］

[賞金の決定文書](28-prize-shares.ja.md)は戦争で消費された補給品などの貢献を定め、最後に戦いへ物を出した倉とその持ち分で数える。サービス利用回数、売上額、自己取引を賞金の直接指標にしない。今回の**第三者による再利用率はプレイテストの測定値**であり、賞金条件ではない。自己取引や Sybil で水増しできる指標を恒久的な富のランキングへ結び付けない。この提案の注文を既存の戦争消費の記録へどう接続するか、会計の詳細は未決定。

## 小さな試作と検証

### 最小試作［提案・未採用］

- 小さな地図、二つの供給拠点、一つの前線。材料一種、補給品一種。
- 工場、倉庫、輸送。危険な近道と安全な遠回り。
- 基礎機能 → 複合サービス → 第三者利用という**一段**だけを試す。
- 任意コード、無限再帰、新トークン、融資、保険、汎用裁判、何十種類もの建物は試作に入れない。

### 比較して判定する［提案］

| 試す状況 | 観察したい差 | 仮説を退ける兆候 |
|---|---|---|
| **手動交易版と合成版**で同じ補給課題を遊ぶ。 | 合成が第三者の能力を使う新しい戦略を生むか。 | クリック数が減るだけなら自動化の価値であり、創発の証拠ではない。 |
| 人気工場または道路を止める。 | 待つ以外の代替調達、迂回、護衛、新規参入が起こるか。 | 依存が単なる待ち時間になる。 |
| 新規参加者を入れる。 | 不足を見つけ、他人から選ばれる小さなサービスを作れるか。 | 自前か古参への従属しかない。 |
| 価格・時間・危険・容量・相手との関係を変える。 | 最安値一択を超えて選択が分かれるか。 | 常に自前、または同じ最安値だけが最適。 |
| 運営の指定なしで公開後を観察する。 | **A の設備 → B のサービス → C の利用**が自然に起こるか。 | チュートリアルの再演や報酬目当ての自己利用だけ。 |

運営 bot の注文、自己取引、同一人の複数アカウントは、独立した第三者の採用と分けて集計する。将来の二段再合成は今回の合格条件に含めない。AI なしで手動ループが面白くない場合も、この提案から撤退する理由となる。

## 実装前に決めること

1. **誰の資産と能力をいつ確保するか：** 材料、工場枠、倉庫枠、輸送枠の受け付け、期限切れ、キュー上限、価格版、解放の条件。
2. **途中で壊れたとき誰が何を失うか：** 加工済み品、輸送中の品、施設破壊・占領時の預かり品、返金、到着判定。
3. **権限が変わったときどうなるか：** 停止、所有者変更、撤権、受注済み注文と新規注文の分離。
4. **参加者に何を見せるか：** 稼働枠、費用、危険、相手への依存、失敗理由、代替先。公開説明文と検証済み条件を分ける。
5. **遊びとして合格か：** 手動交易を超える選択、独立した A→B→C 利用、地元サービスの参入、AI なしでの面白さ。二段再合成と賞金への接続は後の判断に残す。

この提案を採用する場合だけ、上の未決定事項を決定ログへ移し、会計・権限・戦闘との接点を仕様化する。
