## 2. 選ぶ

今の操作（村や軍を地図で選ぶ、軍の札、命令を出せる範囲が光る）はそのまま使う。変えたのは範囲の見え方（上の格子）。

## 3. 比べる（進軍の命令の札）

札の頭に **見通し** を置いた（`hud/marchcard.mjs` outlook）。4 つの事実を一目で：

| 欄 | 中身 | 出どころ |
|---|---|---|
| 到着 | ターン N、約 M 分後 | 今の到着の窓（fmarch / screens/march） |
| 費用 | 体力 −74、次に動けるターン | DEPART_STAMINA と体力の戻り（今の規則） |
| 相手 | 守り N と、兵数の目安の言葉 / 守り手なし / わからない（見えていない土地） | 札が持つ州の記録。測量の範囲の外では数を言わない |
| 予測 | 残る兵の幅（ルールで 12 回）。点線の「予測」札 | hud/forecast.mjs（ルールの核を使う） |

守り手がいる行き先では、構えの欄が **構えを比べる** 表になる（`stanceCompare`）。4 つの構えを、同じ行き先・同じターンで、ルールで 8 回ずつ試し、残る兵の幅と、いちばん多かった結果を並べる。各行がその構えのボタン。どの構えでも幅が同じなら、そう書く（例：村の守備隊は構えを持たないので、差が出ない）。行き先を変えたら、前の行き先の比較は出さない（`compareKey`）。

予測であることは、形（点線の札と枠、縞の背景）と言葉（「予測」「ルールで N 回試した幅」「封印中のほかの進軍は数えていない」）の両方で言う。

## 4. 送る

- 封の押印の上に、**取り消せないこと** と、いつまで封印されるかを一行で（`order-irrev`）。
- 送ったあとの段階（封をしています → この端末に保存 → 送信 → ゲームに記録）は今の表示を使い、進行中を「待機」の色、済んだ段を「確定」の色にした。
- 断られたときは今のまま、地図の上の知らせと「もう一度」。

## 5. 結果を知る（衝突の報告）

送るときの予測を、この端末に残す（`hud/forecastbook.mjs`、季ごと、最大 60 件、どこにも送らない）。報告では、自分の到着の軍について、**出発時の予測** と **確定（記録の数）** を並べる（`screens/report.mjs` renderPrediction）。確定が予測の幅の外なら「予測の幅の外」と書く。残していない（別の端末で送った、予測が出なかった）軍の行は出さない。後から予測を作り直して見せることはしない。

## 6. 確かめたこと

- 見本の世界（フィクスチャ）で、ロウェルの町（守備隊 120）を行き先にした：見通しに「守り 120 · 優勢 · 予測 残る兵 584〜587」、構えの比較は 4 行とも同じ幅で「構えを変えても結果の幅は同じ」と出た。
- 見えていない土地を行き先にした：相手は「わからない · 見えていない土地」、予測の欄なし。
- 封をして送った：予測が端末に残った（ターン 50 着、構え 1、584〜587）。
- 単体の試験 `permutation-gateway/test/web-frontier-uplift.test.mjs`（5 件）。

確かめられなかったこと：見本の世界で、その進軍は到着のあと「開封を待っています」のまま 2 ターン以上進まなかった。変更前のビルドでも同じかは、操作の試験（`screens/interaction.screen.mjs`）の結果で確かめる（04-VERIFY）。
