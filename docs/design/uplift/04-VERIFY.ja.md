### 3 回目：S1 の世界で見つけて直したこと

起点のままでは、S1 の世界は作れても遊べなかった。原因を一つずつ追って直し、ローカルの S1 の世界（`uplift-s1d`、季 303）で、参加 → 最初の村 → 倉の建設（本物の取引、slot 595）→ herald の情報 → 地図の絵 → マスの札、まで通した。

| 見つけたこと | 原因 | 直し方 |
|---|---|---|
| S1 の季節が作れない | スタックの道具に S1 の設定が無い | `frontier-stack up --s1`（S1 の設定で季節を作る） |
| 季節はできても土地がひらかない | キーパーが S1 の季節にも MC の予算表を使い、最初の種の取引が `MaxLoadedAccountsDataSizeExceeded` で 10 回とも失敗 | `keeper follow_abi`：S1 の季節は S1 の表（試験つき） |
| 倉を建てても地図に出ない | herald は `h/caravans.json`・`h/structures.json`・`h/nations.json` を書いているが、配る道が無かった（いつも 404） | herald に 3 つの道（書いたものをそのまま配る。中身は設計どおり公開の情報） |
| 地図が平らな色だけで、村も地形も描かれない | クライアントが S1 の季節にも征服の規則モジュールを読み、ルールのハッシュが合わない（`RulesetMismatch`）ので地形を作らない | 季節の版で規則モジュールを選ぶ（`kernelFile`：S1 は `frontier-v3.wasm`）。モジュール自体は持ち主の再現ビルドで作る |
| 倉を建てる命令を送れない | クライアントの送信前の確認が S1 の命令の番号を知らない | 倉と建物の 2 つの形を足す（送る画面はまだ無い：下） |
| 季節が始まる前に「始める」を押すと失敗する | 最初のターンの前は村を置くターンが無い（プログラムが `WrongStatus` で断る） | 始まる前はボタンを止め、「季節の始まりを待っています（あと約 N 分）」と言う |
| 最初の村の札の在庫が「306.533」 | 千分の一の単位をそのまま割っていた | 整数に切り下げ（上の帯と同じ） |
| 倉が村の家と見分けられない | 屋根が国の色で、村の家と同じ | 倉はスレートの屋根。国は小旗で言う |
| 倉のマスを押しても「平原」としか言わない | マスの札が S1 の物を知らない | マスの札と選択の一行が「倉庫 · あなたのもの」と言う（地図と同じ情報、同じ決まり） |

最初の表示が 13〜16 秒かかったのは、アプリの中のブラウザが隠れていて描画が絞られていたため。見えている headless の Chromium で同じ世界を測ると、地形がそろうまで温かい状態で約 0.45 秒、初回 2.9 秒。地面の焼き込み（なじませ・岸・土地の使い方）の有無で差はない。

### 3 回目：命令の札を状態ごとに（`uplift-states.mjs`）

| 状態 | 確かめたこと | 結果 |
|---|---|---|
| キーボード | 構えの比較で ↓ が次の構えを選び、フォーカスがついていく。Home で最初へ | 直してから成功（それまで矢印は何もしなかった：`hud/radiokeys.mjs`） |
| 動きを減らす | 札の中に動き・移り変わりが残らない | 成功 |
| 規則モジュールなし | 比較も「残る兵」も出さない。到着・費用・相手は出す | 成功 |
| 中継が落ちている | 送れなかったことを言葉で言い、もう一度の手段がある。予測を「送った」として残さない | 成功 |
| 英語・幅 360 | 横にはみ出さない、切れない、行の高さ 44 px 以上（66〜71） | 成功 |
| 色なし | 状態の札がどれも言葉を持つ | 成功 |

この確認で、もう一つ直した：命令を書いている間の道の札が「到着：ターン 44」と言い切っていた。送るのが断られたあとも残るので、進軍が出たように読める。「到着予定：ターン 44」にした（送った進軍には、別の封の線がある）。

## 実ブラウザでの操作

- **見本の世界（フィクスチャ、時計が進む）**：軍勢の引き出し → 進軍させる → ロウェルの町（守備隊 120）を行き先に → 見通しと構えの比較が出る → 構えを変える（比較は計算し直さない）→ 封をして出発 → 予測が端末に残る → 地図に自分だけの封の線「ターン 50 に到着 · あなたにだけ見えます」。
- **見えていない土地** を行き先に：相手は「わからない · 見えていない土地」、予測なし（数を漏らさない）。
- **ローカルの本物のチェーン**（征服の世界、ボット 10、`frontier/season-complete` のビルド、このブランチのクライアント）：参加して最初の村を得るまでを、変更前と変更後の両方で操作した。変更後で見つけた重なり（下）を直した。
- **S1 の施設**：S1 の世界を起動できないため、S1 の情報の見本を差し込んだ場面（`uplift-shots.mjs s09-s1sample`）で、変更前の平たい絵と変更後の描いた絵を比べた。

### 確かめられなかったこと

- 見本の世界（ターン 30 秒）で、封をした進軍が到着後「開封を待っています」のまま 2 ターン以上進まなかった。操作の試験（同じ世界、既定の時計）では、変更前も変更後も開封まで通る。時計を速めた場合の見本の世界の挙動とみて、この作業では追っていない。
- 本物のチェーンで、試験の行列が CPU を使っている間、最初の村の表示まで約 13 秒、羊皮紙だけの画面が続いた。→ 3 回目で原因の一つが分かった：アプリの中のブラウザが隠れていると描画が絞られる。見えている headless では 0.45〜2.9 秒。
- S1 の世界での荷車・物見櫓・要塞の絵（倉と柵は本物の世界で建てて確認：倉 slot 595、柵 slot 5290。地図の絵、マスの札「柵」、読み上げ「柵 を選びました」。塔と要塞は石材が足りず、荷車は送る画面が無いので、見本の情報でのみ）。
- 実機のスマホ（確認は 390 × 844 の描画のみ）。

## アクセシビリティ

- 状態は色と形の両方で言う（03-COMPONENTS）。予測は点線、確定は塗り、待機は丸、失敗は欠けた角、取り消せないは錠。
- 構えの比較の各行はボタン（role=radio、aria-checked）。Tab で移り、Enter / Space で選べる。スマホで高さ 56 px 以上。
- 新しい文はすべて日本語と英語。英語の辞書の一貫性の試験を通る。
- 動きを減らす設定では、比較の行の押下の動きを止める。

## 目で見た批評（自己採点ではなく、直したところ）

- 1 回目の比較ページでは、A の決定の札が攻める先のマスを覆っていた → 場面の枠を右へずらし、札の左に行き先が来るようにした。
- 1 回目の見通しは、到着の段（下の段）と同じ「ターン N · 約 M 分後」を繰り返し、休みの一行とも重なった → 休みの一行を見通しの費用の欄にまとめた。
