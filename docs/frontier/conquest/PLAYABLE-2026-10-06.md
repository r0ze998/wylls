# Human shared-world play: validation and local preview

Validated 2026-10-06. The clean human preview is [Wylls](http://127.0.0.1:41840/frontier/frontier/index.html), season **73**, run `human-world-cq`. It uses program version **3**, account layout **2**, the standard **14-day / 600-second bell** rules at **10×** clock speed. Dormancy begins after five game days; release after fourteen. No NPC fleet or test players were added to this world. At readiness, all six nations had zero members and holdings, and the first synchronized control and territory-time standings were available.

National score is the sum of each province's authoritative six territory-bell counters. A province grants one point per completed bell to its keep holder. A capture at bell `b` first earns points for the new holder at `b+1`. Holdings, troop strength, membership, and capture bonuses do not change that score. The herald publishes the current synchronized result after each resolved bell. The first result waits for the protocol's reveal window to close; at 10× this is approximately two real minutes from genesis.

## Independent audit and restart proof

The independent CQ verifier passed over **22,373 program transactions** and **160 chained program entities**, with no findings. Its explicit checks are:

- CQ1: event chain continuity and pinned final account state.
- CQ2: program binary, season and ruleset identity.
- CQ3: exact ownership-time replay and capture accounting.

This is a bounded CQ audit. It does not claim the legacy V1–V13 full combat, economic, randomness or seal-cryptography replay, or a liveness assessment. Failed historical transactions remain in the archive and are excluded from successful state transitions.

A paused snapshot was stopped and resumed with the same program and persisted ledger. Persistence safeguards include an exclusive supervisor lock acquired before setup, an exclusive ledger writer lock acquired before WAL reading/replay, exact saved process command and birth-stamp checks before stopping anything, saved program checksums, and run-local native service copies with a checksum manifest. Missing/corrupted metadata does not make an existing ledger disposable. Relay JavaScript and web assets remain development-checkout files rather than immutable release artifacts.

## Service corrections found by integration

- Peaceful CQ provinces now resolve each closed turn rather than waiting for a legacy 24-bell batch, so public scoring advances without player activity.
- Historical standings reconstruct each bell from the prior counters and capture events; later poststates cannot lend future points to an earlier synchronized result. Missing historical views stop publication rather than substituting a future snapshot.
- CQ checkpoints require `scoreVersion: 3`; older checkpoints are rejected and rebuilt from the signed archive. The smoke's old derived files were preserved separately during this rebuild.
- The shared program-version constant now agrees with the live version 3, allowing season-end results to publish.
- The player endpoint retains occupied holding slot 3 when slot 2 is empty, and counts established members using the first-home FINAL flag.

## Run and resume

Install the toolchains listed in [RUNNING.md](../../RUNNING.md). For a fresh checkout, run these from the repository root:

```sh
scripts/build-frontier.sh --features test-beacon
npm ci --prefix permutation-gateway
(cd frontier-node && cargo build --locked --release --bins)
```

The following commands run from `frontier-node/`.

Create the clean preview once (it is already running):

```sh
target/release/frontier-stack up --conquest --mode accel --beacon test-key \
  --preseason-scale 10000 --scale 10 --game-hours 336 --bots 0 --personas off \
  --run-id human-world-cq --base-port 41800 --season 73 --keep-running
```

Stop and resume the same saved world:

```sh
target/release/frontier-stack down --run-id human-world-cq
target/release/frontier-stack resume --run-id human-world-cq
```

State, program, pinned native binaries, keys, logs and ledger are under `frontier-node/.local/frontier/human-world-cq/`. Its `QUICKSTART.txt` repeats the exact commands. This ignored directory is local runtime data; back it up separately from Git. Starting `up` with an existing world never resets it. Use a new run ID and unused ports to create another world.

Repeat the two-wallet test only on a fresh disposable world, not the human preview:

```sh
target/release/frontier-stack up --conquest --mode accel --beacon test-key \
  --preseason-scale 10000 --scale 1 --game-hours 72 --season-end-at-play-end \
  --bots 0 --personas off --run-id cq-smoke-new --base-port 42100 --season 74 --keep-running
```

In a second terminal from the repository root:

```sh
CQ_SMOKE_URL=http://127.0.0.1:42140 CQ_SMOKE_RPC=http://127.0.0.1:42110 \
  node permutation-gateway/scripts/conquest-smoke.mjs
```

The script writes `.local/conquest-smoke.json`; private wallet/session keys remain in memory. For a restart equality check, pause the disposable RPC, run `conquest-persistence-check.mjs snapshot RPC_URL REPORT_PATH`, stop it, resume with `--start-paused`, and run the script's `compare` mode. Only then resume the RPC clock. `frontier-stack verify --run-id RUN_ID` performs a consistent paused read and restores the prior clock-running state.
