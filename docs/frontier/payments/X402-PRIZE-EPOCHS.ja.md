# ⑰ 継続世界の賞金：精算の区切り（テスト用 USDC、ローカルと devnet のみ）

英語版：[X402-PRIZE-EPOCHS.md](X402-PRIZE-EPOCHS.md)（詳しい比較と試験は英語版にある）。

**状態（2026-11-18）**：2026-11-18 18:26 JST、所有者が⑰を再開した。この決定は、14:42 の「A：賞金なし」と PR #37 の終了記録に代わる。対象は **devnet とローカルだけで、テスト用 USDC だけ**を扱う。mainnet と実際のお金の USDC は対象外。**mainnet で実際のお金の賞金を出すには、先に法務確認が必要**。日本では、参加費を集めて勝者に配る仕組みが、賭博、景品、資金決済の規制に当たるおそれがある。配備はしていない。SOL も鍵も使っていない。

## 1. 問題

賞金プログラム（`permutation-prize`）は、Season が Ended になったときにしか入金を出せない。継続世界は終わらないので、従来のプールでは入金が金庫から永久に出ない（`X402-PRIZE-CONTINUITY.ja.md` D2）。そのため、stack（`config.rs`）とプログラム（`InitPool` の `ContinuousSeason`）の両方が、継続世界で従来のプールを拒否している。

## 2. 設計：区切りごとのプール

cargo の機能フラグ **`epochs`** を付けたビルドだけで動く。このフラグは既定でオフ。既定のビルドには新しい命令がない（目印の文字列がなく、`build-prize.sh` が確かめる）。

- **InitEpochPool**：継続世界でだけ開ける。期間は終わりの鐘（`end_bell`）で区切る。プールの PDA は `["epool", game, season, epoch]`。
- **支払い**：参加費は、終わりの鐘の時刻まで受け付ける（それ以後は `EpochClosed`）。
- **EpochTally**：時刻が過ぎたあとに、誰でも送れる。終わりの鐘より前の鐘がすべて解決した州を数える。砦の持ち主は、その鐘の時点の持ち主にする。
  - ゲームは、鐘 `b` で砦を奪ったときに `since_bell = b + 1` と書く。だから `since_bell ≤ end_bell` なら、今の持ち主が終わりの時点の持ち主である。
  - 区切りのあと、集計の前に奪われた砦は、どの国にも数えない（暫定）。
- **EpochFinalize**：州を最も多く持つ国が勝つ。同点なら等分する（暫定）。受取の期間が始まる。
- **SetShares、Claim、WithdrawOps、RecordNation**：従来と同じ命令をそのまま使う。
- **Sweep**：受取の期間が過ぎたら、誰でも送れる。受け取られなかった残りを、まだ参加費を受け付けている後の区切りのプールへ移す（暫定）。運営の取り分は変わらない。

数値は所有者の決定どおり。**参加費 25 テスト USDC、80% を賞金、20% を運営**に回す。所有者が決めていない既定値は次の2つ。

- 区切りの長さ：2,016 鐘（14日。Y6 のシーズンの長さに合わせた）
- 受取の期間：1,008 鐘（7日）

つなぎ込みはローカルのビルドだけで、既定ではオフ。

- **stack**：`frontier-stack up --conquest --continuous --prize-so <epochs の .so> --prize-epochs`
- **中継**：`--prize-epoch N`。localnet と devnet でしか使えない。mainnet の USDC の mint は拒否する。
- **devnet の dry run**：`--with-prize` を付けると、賞金プログラムの検査と費用を計画に加える。賞金プログラムは送信しない。
- **mainnet**：mainnet のプロファイルはない。中継と dry run は、クラスタの名前と mint の両方で mainnet を拒否する。

## 3. OSS との比較（詳細は英語版 §3）

- **Jito の tip-distribution**：エポックごとの口座、merkle root、期限を過ぎた残りの回収。Wylls の形に一番近い。
- **Jito の merkle distributor**：期限を過ぎると、残りを回収できる（clawback）。期間ごとの仕組みは持たない。
- **PoolTogether v5**：一定の期間ごとに抽選し、残りは次の回に持ち越す。持ち越しの考え方はここから採った。抽選の仕組みは合わない（Wylls の勝者は盤面で決まる）。
- **Streamflow の分配（ストリーミング）**：勝者が区切りの終わりまで分からないので、合わない。

## 4. 所有者への質問（コードは安全側の既定値で動く）

1. **参加費は区切りごとか、世界に1回か。** 今の既定値は区切りごと。
2. **区切り 0 が終わったあとも、参加を有料のまま閉じておくか。** 今は、次のプールを開いて中継を切り替える道具がない。そのため区切り 0 のあとは、有料の参加ができなくなる。
3. **区切りのあと、集計の前に奪われた砦をどう数えるか。** 今の既定値は、どの国にも数えない。別案は、奪われる前の持ち主（`last_taken_from`）に数える。
4. **同点のとき。** 今の既定値は等分する。別案は、従来どおり領有の鐘で決める。
5. **受け取られなかった残り。** 今の既定値は、次の区切りへ持ち越す。別案は、払った人に返す、または運営に回す。
6. **区切りの長さ。** 今の既定値は 2,016 鐘（14日）。
7. **⑭の無限の地図。** 集計できるのは輪 17 まで。`r_max_ceiling` が 17 を超えるシーズンは拒否する（`CeilingPastTally`）。
8. **⑤ W4。** お金を扱う区切りに AI の住人を入れるか（Q17 は未決）。今は、運営の AI は招待で参加し、Entry を持たないので受け取れない。
9. **⑮は変えていない。** 達成は称号と年代記にとどめ、賞金には結びつけない。
