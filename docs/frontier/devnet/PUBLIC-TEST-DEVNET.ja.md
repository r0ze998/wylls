## 3. 進め方（案）

**段階 A：ローカルだけ（devnet に触れない）**

1. G1〜G4 のコードを書く。
   - TLS クライアント（rustls など、依存を足すにはオーナーの承認が要る）
   - keeper の RPC 読み取り（herald の `RpcPoll` を使い回す）
   - live の drand
   - 運営の道具
2. S1 の 7 日のプリセットと、賞金プログラムの設定を決める。
3. 本番用（`test-beacon` なし）のプログラムを `--twice` でビルドし、sha256 を記録する。
4. ローカルで、本番用のプログラムと、保存済みの quicknet の記録（archive ビーコン）を使って通しのリハーサルをする。keeper の強制再起動も試す。

**段階 B：devnet（手順ごとに承認）**

5. **[承認]** devnet への読み取りだけの確認（G6、G7）。
6. **[承認]** テスト SOL の入手（devnet の蛇口は回数に上限がある。見積もりは M1 文書 §5 の小さい案で約 37〜43 SOL）。
7. **[承認]** frontier と prize のプログラムを配備し、sha256 を照合する。
8. **[承認]** テスト USDC のミントを作る。季を告知し、作る。keeper、relay、herald を起動する。
9. **[承認]** 技術リハーサル：外部の数人が自宅から参加し、1 日以上止まらずに動くことを確かめる。
10. **[承認]** 公開テスト（7 日）。
