# キーパーの「毎ターン全州」処理を減らす設計案

2026-10-28。前提は [README.ja.md](README.ja.md) の計測です。817州のとき、キーパーは1ターンに約855件を送っていました。

**状態：設計案だけです。コード・プログラム・ルールは変えていません。** 数字はすべて見積もりで、計測はまだです。

## 0. 結論

- **ルールもプログラムも変えずに減らせます（案A）。** 静かで何も起きていない州は、毎ターンではなく最大24ターン分をまとめて SkipQuiet で進めます。
  - 得点（領地ターン）の最終値、征服、ドミニオン、Tally の結果は、毎ターン進めた場合とまったく同じです。
  - 変わるのは、チェーン上の得点の数字が更新される**タイミング**だけです。最大24ターン遅れます。
  - その遅れは、ヘラルドで「チェーンの値＋まだ書かれていないターン数」として正確に補えます。
- **見積もり**：817州で、動きのある州が50なら、1ターンの送信は約817件から約85件になります。
- **オーナーに決めてほしいことが1つあります**：「得点の数字は毎ターン、チェーンに確定済みであること」が要件かどうか。要件なら案Aは使えず、減らすにはルール変更（§4）が必要です。
- 州の数に比例する処理そのものをなくすには、ルール変更が要ります（§4。領地ターンを、砦の持ち主が変わった時点の記録から数える方式など）。

## 2. 「州ごとの得点の進め方を変えない」の意味

次の3点が、毎ターン送る今と**同じ値**になることを条件にします。

1. 各州の `TERRITORY_BELLS`（国ごとの領地ターン）の最終値と、`SCORE_NEXT_BELL` の進み方（1ターンずつ、飛ばしなし）。
2. 砦の争奪・包囲・占領の結果と、それが起きるターン。
3. マーチのドミニオン（fold）の結果。Lost の時間が増えないこと。

変わってよいのは「チェーン上の数字がいつ書かれるか」だけです。ここが許されるかどうかが §0 の判断点です。

## 3. 案A：休んでいる州はまとめて進める（ルール・プログラムは変えない）

### 3.1 州を2つに分ける

キーパーは毎ターン、各州を「動いている」か「休んでいる」かに分けます。

次のどれか1つでも当てはまれば**動いている州**で、今どおり毎ターン進めます。
- その州で戦いがある、または到着がある（今も解決に回っている）
- 砦の争奪・包囲・占領が進行中（`active_count > 0`）
- 予定された変更、出発、退去がある（今の `skip_target` が対象にしているもの）
- 催促（nudge）された
- マーチの fold が遅れている（今の `fold_urgent`）
- 前線（`cq_front`）にある州
- 最後の書き込みから24ターンたった
- シーズンの終わりに届く

どれにも当てはまらなければ**休んでいる州**です。今の M1 のやり方どおり、24ターンたまった時点か、上の条件が生じた時点でまとめて1件送ります。

コードの変更は、`play.rs:1668-1669` の条件に「休んでいる州なら毎ターン送らない」という判定を足すだけです。まとめて進める処理そのもの（`skip_now`）は、もうあります。

### 3.2 なぜ結果が同じになるか

- **得点**：休んでいる州では砦の争奪が起きていないので、持ち主は変わりません。24ターンまとめて進めても、1ターンずつ進めても、持ち主に+24が入ります（`score_territory` は1ターンずつ順に数えるので、まとめても同じ計算になります）。
- **途中で何か起きた場合**：到着などで途中のターンが静かでなくなれば、SkipQuiet はその手前で止まります（プログラム側の保証）。そこからは今と同じ解決の流れになります。
- **fold**：休める上限は24ターン（4時間）です。記録の保存は6時間分あり、fold が3時間遅れればキーパーが遅れた州をすぐ進めます。この組み合わせなら Lost にはなりません。**ただし、余裕は「6時間 −（4時間＋送信の遅れ）」しかないので、計測で確かめる必要があります。**
- **シーズン終了**：`skip_now` は終わりのターンに届いた時点で必ず送ります。Tally の条件（全州が終わりまで進んでいること）は今と同じく満たされます。

### 3.3 画面の数字（ヘラルド）

休んでいる州のチェーン上の得点は、最大24ターン古くなります。ヘラルドが順位や州の表示を出すときは、次のように補います。

`表示する値 = チェーンの値 +（今のターン − SCORE_NEXT_BELL）` を、砦の持ち主の国に加える（シーズンの終わりで頭打ち）。

休んでいる州では持ち主が変わらないので、この値は後でチェーンに書かれる値と一致します。動いている州は今どおりチェーンの値をそのまま出します。

直す場所の候補は `herald/src/control.rs:313` と `herald/src/conquest.rs:1275` 付近です。補った値と確定値を区別して出すかどうかは画面側で決めます（数字自体は同じになります）。

### 3.4 効果の見積もり（計測ではない）

- 休んでいる州は、平均して24ターンに1件になります。
- 1ターンの送信数 ≈ 動いている州の数 ＋ 休んでいる州の数 ÷ 24。
- 817州で動いている州が50なら 50 + 767/24 ≈ 82件（今は約817件、ほかの送信を含めると約855件）。
- 動いている州は「プレイヤーがいる場所」の数に比例するので、地図の広さにはほぼ比例しなくなります。

### 3.5 リスクと、確かめること

- **24ターン分の SkipQuiet の計算量**：S1 は1ターンごとに征服の処理（`cq::step`）が入ります。プログラムには途中で区切る仕組みがあります（ヒープ上限 `SKIP_HEAP_STOP`、記録ターン上限 `SKIP_RECORD_BELLS_MAX = 288`）。区切られた場合は件数が少し増えるだけで、結果は同じです。実際に1件で何ターン進むかは計測が必要です。
- **fold の余裕**（§3.2）。混雑したチェーンで送信が遅れたときに Lost が出ないか。
- **ほかの人の送信**：SkipQuiet は誰でも送れます。他人が毎ターン送っても、結果は同じで無害です。
- **得点の見え方**：§0 の判断点です。

### 3.6 確かめ方

1. **単体テスト（キーパー）**：同じ州を「1ターンずつ24回」と「24ターン1回」で進め、州のバイト列（特に `TERRITORY_BELLS` と snapshot）が一致することを確かめる。`keeper/src/conquest.rs:1755` 付近のテストと同じ作り方でできます。
2. **ローカルの2世界比較**：同じ設定で「今の方式」と「案A」の世界を動かし、シーズン後に各州の `TERRITORY_BELLS`、マーチのドミニオン、Lost の時間数を比べる。乱数（drand）が世界ごとに違うので完全一致は求めず、検証ツールの CQ3（領地ターンの再計算）がどちらでも合格すること、Lost が0であることを見る。
3. **負荷**：`scripts/map-growth-measure.py` で、817州のときの1ターンの送信数、ターン完了の遅れ、キーパーのメモリを、今の方式と比べる。
4. **段階的に入れる**：キーパーに設定（例：`--rest-batch`）を足し、最初は既定で今の方式のままにする。

### 3.7 作業量の目安

キーパーの判定、ヘラルドの補正、テストを合わせて、1〜2日程度です。プログラムの再デプロイは不要です。

## 4. ルール変更が要るもの（分けて扱う）

案Aでも、休んでいる州は24ターンに1回は書かれます。州の数に比例する処理をなくすには、次のルール変更が要ります。どれもオーナーの判断が必要で、プログラムの変更と再監査も伴います。

| # | 変えること | 何が要らなくなるか | 影響 |
|---|---|---|---|
| R1 | 領地ターンを、毎ターンの加算ではなく「砦の持ち主が変わった時点の記録（`since_bell`）」から計算する（持ち主 × 持っていた期間） | 静かな州を進めること自体 | `score_territory`、検証の CQ3、ヘラルドの集計、Tally の同点処理が変わる |
| R2 | Tally の条件「全州が終わりまで進んでいる」を、R1 の計算に置き換える | シーズン後に全州をまとめて進めること | 賞金プログラムの変更（テスト用トークンのみで運用中） |
| R3 | マーチのドミニオンを、6時間分の記録ではなく、持ち主が変わった時点の記録から計算する（または記録の保存数を増やす） | fold のために州を進めること、Lost の心配 | 州のデータ配置（`SNAP_N`）か fold の規則が変わる |
| R4 | 野営地（camp）の毎日の判定を、だれかが近づいたときに数日分まとめて行う | 何もない州の日ごとの処理 | 野営地が現れる時期の規則が変わる |

R1〜R3 がそろえば、だれもいない州には、シーズン中ずっと何も送らずに済みます。案Aより大きく減りますが、ルール・プログラム・検証ツール・賞金の4か所に及ぶ変更です。

## 5. ルールは変えないが、プログラムに命令を足す案（参考）

- **B：複数の州を1件で進める命令（SkipQuietMany）**。計算の総量は変わらず、件数と手数料だけが減ります。1件に入るアカウント数に上限があるので、1件あたり数州が限度です。プログラムの更新と svm テストが必要です。
- 案Aで足りるなら不要です。**案Aを先に入れて計測し、それでも件数が問題なら検討する**のがよいと考えます。

## 6. おすすめの順番

1. §0 の判断（得点の数字は毎ターン確定済みである必要があるか）をオーナーに確認する。
2. 不要なら案Aを、キーパーの設定で切り替えられる形で入れ、§3.6 の1〜3で確かめる。
3. それでも足りない、または毎ターン確定が必要なら、§4 のルール変更をまとめて設計する。
