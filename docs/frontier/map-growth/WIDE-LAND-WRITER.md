# Wide land writer: host-only opening and outpost lottery, with march still closed

Status: host-only experimental code. The current third slice is based on `87088006`; native validation is recorded below. Sections 1–6 describe the earlier `455f03af` slice and are superseded where §0 says so. No keypair, signature, network, browser, CI or deployment was used. This is a host-only preparatory implementation in the game program, not playable wide land. Most remaining work is engineering: connect existing game rules, readers and the complete asset lifecycle. Only changes to product rules require an owner decision.

## −2. Fourth slice (2026-11-07, on `9815bfd8`, same worktree): the wide march mapped, its identity proposed, Depart corrected, movement **not** connected

Written with source tools only; not compiled or run by its author. Host-only as before. This slice does **not** make a wide host move. ### −2.1 The legacy march, stage by stage, and what each stage keys the host by

| stage | handler | identity and coordinate inputs that no wide province has | wide requirement |
|---|---|---|---|
| Muster | `host::muster` | `addr::host_id(P, Q, site, gen, seq)` (a 20-bit dense province index); the roster entry's `u64 id`; the kernel `Host.owner = holding_key_of_host(id)` | a wide Muster writing the alias into the wide province's entry table and the full reference beside it; the kernel `Host` keyed by the full reference |
| Depart | `host::depart` | the roster lookup `find_entry(province, id)`; `caller_host` by `split_host_id`; the 96-byte Holding transit slot's `u64 host id`; `host_in_transit`; the `DEPART` record with `i32` P/Q | **done in part**: the deployed shape (standing province + issuing holding's province), the boundary refusal, the identity gate, the alias lookup; **no** transit record and no escrow, because nothing below exists |
| SettleDeparture | `host::settle_departure` | the origin's roster by `u64`; `host::march_values` | a wide form over the standing province and the wide transit record |
| Reveal (keeper) | `reveal::reveal` | the plaintext's `i16` destination and path provinces; `land_of` over deployed Provinces; `ctx.arrival_slot(P, Q, bell, faction, i)`; `clash::slot_key(P, Q, bell, id)` and the quota `admit`; `ctx.clash_inputs(P, Q, bell)`; `region_of(P, Q)` and the bell anchor | a wide plaintext (full coordinates: the 165-byte seal cannot carry 17-byte sort keys for four path provinces; a versioned wide seal format), wide ArrivalSlot/ClashInputs addresses, `wide_slot_key`, a wide region rule (the ticket slice uses `rules::wide_region`), and the keeper |
| GatherClash | `clash::gather_clash` | the destination's `(P, Q)` stamped into the transit as `gathered_at` | the canonical **full** destination key stamped (the reviewer's point: a bad seal must be forfeitable only against the province that gathered it) |

| SettleTransit | `transit::settle_transit` | `split_host_id(t.host_id)` matched to the Holding's P/Q/site/gen; `valid_outcome(dest, bell, SlotEntry{host_id, citizen, troops}, set)`; the fee/bond/tip refunds and the forfeit; `return_target` by the id's bits | a wide settle over the wide transit record and the wide ClashInputs; the same refund destinations (tip to the resolver, fee and bond as deployed) |

Every stage derives identity from the bits of one `u64`. The reviewer's finding is pinned here: `tie_key(cs, id)`, `slot_key(P, Q, bell, id)` and `clash_seed(seed, P, Q, bell)` are byte formulas over that id and the `i32` pair, so a wide host **must not** be keyed by a sorted local index (another host's insertion would re-roll unrelated outcomes) nor by a hash fed into those formulas as if it were a dense id.

### −2.2 The experimental identity proposal (`frontier-abi` `world_index::march`)

`HOST_IDENTITY_FULL_REF_V1 = 1` names the shape every wide stage must share; it is **defined, not carried**: `WideHolding::read` still refuses any version but the unallocated one, so no wide holding carries it, no host can be mustered and no march can be debited. It is experimental versioning, not a production protocol number.

* **Canonical identity**: the 56-byte `WideHostRef` (`world ‖ 17-byte sort key ‖ site ‖ gen ‖ seq`). Every ownership check compares it (`holding_ref()` for the issuing holding, as `holding_key_of_host`).
* **Roster alias** `wide_host_alias(ref) = 1<<63 | sha256("PSF-WIDE-HOST-ALIAS-v1" ‖ ref)[..8] >> 1`: the `u64` a wide province's entry table and the Holding-layout transit slot may carry for **lookup only**. `addr::split_host_id` refuses it (its province-index field is at least `2^19`), so no legacy reader parses it, and it is **never** an input of a kernel formula.
* **Wide formulas** `wide_slot_key(key, bell, ref)`, `wide_tie_key(seed, ref)`, `wide_clash_seed(seed, key, bell)` under the domains `frontier/slot/wide-v1`, `tie/wide-v1`, `frontier/clash/wide-v1`, over the world, the full sort key and the full reference. The legacy path keeps its formulas byte for byte. No handler uses the wide ones yet; they exist so that a wide reveal and resolve are written against one definition.
* **Transit record**: the 256-byte `WideTransit` at `with_seed(season, wm ‖ hash(holding ‖ slot))` (`transit_address`), not the 96-byte slot inside the Holding layout. The slot would keep the alias and the `in_transit` state so `host_in_transit` keeps refusing a second departure.

### −2.3 What the program now does (through the real `dispatch`)

WideDepart (0xDA) has the deployed Depart's shape: the player prologue, `[holding w] [province w] [system] [holding_province r]`, where `province` is the province the host **stands in** and `holding_province` the issuing holding's own (the earlier draft wrongly used the holding's province as the standing one). Checks, in the deployed order where it has one: the holding canonical and the Citizen's at the reference's generation; its own province present, canonical and not capture-locking it; the standing province a wide province of this world. **The boundary**: a deployed Province in the standing position is refused `NotImplemented` before anything else is read: the arrival quota, the roster caps and the resolution of a destination bell are one per province and bell, and a wide host standing in or marching across the disk would need the legacy and wide paths to share them, which they do not (separate quotas or rosters for one bell would skip combat or double garrison damage). The destination is sealed at Depart, so the boundary can only be judged where the host stands; a reveal would have to judge the sealed destination. Then: final, the standing province resident, the seal's syntax, the **identity gate** (`NotImplemented`: every wide holding is founded under the unallocated identity), the alias lookup in the standing roster (`NotResident`), the arrival window and end bell, the tip floor, the transit slot, the funds, and then an explicit final `NotImplemented`: with no settle, reveal, resolve or return to follow, a transit record and an escrow would be a debit into an unfinished destination. **Nothing is written or debited on any path.**

### −2.4 Blocked, explicitly

Not implemented, and not approximated: a wide Muster; wide SettleDeparture; a wide seal/plaintext format carrying full coordinates for a destination and up to four path provinces; wide ArrivalSlot and ClashInputs addressing; a wide Reveal (path walk over wide provinces, quota by `wide_slot_key`, latch); a wide GatherClash stamping the full destination key; a wide ResolveClash/SkipQuiet (the combat kernel over `wide_clash_seed`/`wide_tie_key`, a wide retreat rule replacing `wedge`, the keep and garrison effects, the keeper to drive it); a wide SettleTransit (seal judgement against the region's anchor, the fee/bond/tip refunds, forfeit, strand, return credit); a wide return settle and RetireHost; any mixed ring-128/129 movement (one shared quota, roster and resolution across the boundary would be a new rule nobody approved, and splitting them is unsafe). Production requirements left open and not decided here: the wide region rule for anchors (a candidate exists in `rules::wide_region`, unapproved), the wide retreat rule, the wide seal format and its bond, the keeper's wide support, verifier and herald support (a wide march would be unverifiable and invisible), and prize eligibility of wide hosts. No cost, probability, ownership or prize rule was invented; the mixed-nation outer map remains the only approved product change.

### −2.4a The clash kernel over the full identity (executable, same day)

`permutation-rules/src/frontier/clash.rs`: both bodies (`resolve_clash`, the Phase A production body, and `resolve_clash_ref`, the reference) are now one algorithm generic over `ClashIdentity`, the scheme that names hosts and garrisons, derives the clash seed from the province and the bell, gives each host its tie key, keys each engagement's variance dice and names the retreat wedge. The legacy scheme is `u64` (dense id, `i32` pair, `tie_key`, `clash_seed`, the 9-byte `city ‖ LE64(id)` key, `ProvinceCoord::wedge`, `sort_by_key3`), and the legacy entry points are its instantiation: every hash takes the same bytes and every sort the same total key, so legacy outcomes are unchanged (`frontier_clash_equiv.rs` keeps pinning 4,320 inputs; `frontier_clash_identity.rs` adds fixed data, input-order and insertion invariance, and a delegating newtype scheme that reproduces the legacy outcome field for field). `Fighter`, `Garrison`, `ClashInput`, `FighterResult`, `GarrisonResult` are aliases of the `…Of<u64>` generics; `ClashError` stays an enum (`From<ClashErrorOf<u64>>`); `ClashOutcome` is unchanged. Compact unit indices order iteration and result arrays only. `RULESET_HASH` and `CLASH_VERSION` do not change.

`frontier-abi` `world_index::march`: `WideHostRef` implements the scheme (province = `ProvinceKey`, seed = `wide_clash_seed`, tie = `wide_tie_key`, key = `city ‖ 56-byte reference`, wedge = the coordinate's exact geometric `WideCoord::wedge`, stable sorts over the reference's order; the roster alias is never read). `resolve_wide_clash` runs the production body under it and `resolve_wide_clash_ref` the reference; tests show them equal on fixed data that fights, order- and insertion-invariant, results named by full references (the garrison by its holding's reference), duplicates refused by reference. `claim_alias` is the authenticated collision check a roster or transit writer must run before writing an alias (every table entry's alias must be its own reference's; the same alias under another reference is refused; the alias alone proves nothing). `wide_plain_commit` is the model of what a wide seal must commit to (host reference and full destination key inside the commitment); it is not a seal format: no ciphertext, beacon binding or bond exists. **This is the executable combat core of the wide world, not a movement**: no handler calls it, no wide roster, arrival record, ClashInputs or Reveal exists, and nothing is debited. It is an experimental proposal, not a decided production identity.

### −2.4b The wide seal, the arrival records, the roster side table (second review point, same day)

Built on the kernel milestone (`828128a7`). Still **no handler reads or writes any of it**; these are the versioned, authenticated components a wide Reveal, Gather, Resolve, SettleTransit and Muster must share, with fixed-byte tests and no key, signature or fixture transaction.

* **Wide seal** (`frontier-abi` `world_index::seal`): a 136-byte plaintext (version 2) that commits to the **full 56-byte host reference** and the **full 50-byte destination key**, the deployed path encoding, bell, tile, stance and retreat; sealed as `IBE (128, the deployed tlock block, unchanged) ‖ body (136)` = 264 bytes under the deployed keystream (`seal::keystream_xor`, the legacy 37-byte body's two blocks continued) and the commitment domain `PS-FRONTIER-MARCH-WIDE-v1`. The legacy `Plain37`, its 165-byte seal, its commitment and every vector are untouched. `validate` refuses a mismatched host, a synthetic identity, another arrival bell, a destination in another world, and the deployed path/tile/stance/retreat faults; a legacy-disk destination is a *valid* plaintext (the boundary is the reveal's to refuse by the standing roster, not the seal's). `permutation-rules` `seal` gained `keystream_xor` and `commit_slice`, both pinned equal to `body_xor`/`commit` over 37 bytes.
* **Opener** (`permutation-frontier` `crypto::seal`): `open` is now `recover_key` (the pairing, `sigma`, `k`, the FO check: the same steps in the same order over the 128-byte IBE block) followed by the 37-byte body; `open_wide`/`judge_wide` (feature-gated) run the same `recover_key` and then the wide body and `world_index::seal::validate`. **Untested cryptography**: the pairing and FO check are the deployed code and the host cannot run them; the wide tests reuse the recorded seal vectors' IBE blocks and keys and pin only the body/commitment path (a wide plaintext sealed under a vector's `k` behind the vector's IBE block opens to itself under the wide commitment and to nothing under the legacy commitment or a wrong key).
* **Arrival records** (`world_index::arrival`): wide ArrivalSlot (288 B) and ClashInputs (3,008 B, 24 × 112-byte positions) keyed by the full destination key, arrivals named by full reference and Citizen key, the deployed quota, flags and fate codes, a conversion to the kernel's `WideFighter`; with-seed addresses under provisional tags `wa`/`wi`. Every read and write checks the host is of the destination's **world** (an arrival's reference keeps its home province, which normally differs from the destination), every typed field (faction, slot, unit, stance, tile, retreat ≤ 60,000, flags, fate) and, for ClashInputs, the header (magic, version, reserved bytes, a decodable key, masks and `n_present` in range) before any position. The extra rent over the deployed 160/1,280 bytes is an explicit experimental storage cost; no deployed fee changes.
* **Roster side table** (`world_index::roster`): one full reference per Province entry index (3,248 B, tag `wo`, immutable original rent recipient), its header naming the province the hosts **stand in**. Every method takes the roster it expects and refuses bytes whose header is another's (province or season); `claim` is the only write (same world required, any home province; `march::claim_alias` over the whole table; returns the alias the entry carries), `entry_matches` the only trusted read of one entry. `table` **regenerates** aliases from the stored references and proves nothing about the Province's actual `u64` entries; `validate_paired` is the explicit check of the two tables against each other a handler must run first.
* **Tagged combat identity** (`march::WideCombatant`): the kernel's wide identity is `Host(WideHostRef) | Camp { key, gen: u32 } | Keep { key, gen: u32 }`, 57 bytes under a tag byte. The host codec stays strict (no site ≥ 12 decodes anywhere), the camp and keep carry the full `u32` generation the deployed records keep, no variant decodes as another, and `resolve_wide_clash` refuses a synthetic resident or arrival before the kernel runs; a garrison may be any variant. The roster, the arrival records and the seal store hosts only, so none of them can hold a camp or keep.
* **Keystream bound** (`seal::keystream_xor`): at most 8,192 bytes (the one-byte block counter), a longer body refused untouched; pinned at 8,192 and 8,193.
* **The beacon binds the bell, not the region.** All regions of one bell share the round `T(arrive)`; a seal that opens proves the bell, not the destination's region. A wide reveal or settle must take the destination from the committed plaintext, derive its region by the configured experimental rule, require THE anchor or archive entry of that region and bell at its canonical address, open with `T(arrive)` and take the combat seed `S(A)` from that anchor. The host BLS syscalls are fail-closed stubs: **no test demonstrates a real decryption of a wide seal**; `open_body` under a recorded key is a body/commitment check only.

Blocked, unchanged: no wide Muster, Depart effects, SettleDeparture, Reveal (the walk over wide provinces, the quota by `wide_slot_key`, the latch), Gather, Resolve, SettleTransit (seal judgement against the region's anchor, refunds, forfeit, strand, return), return settle; no keeper, verifier or herald support; no wide sealer (the off-chain tlock encryption of a 136-byte body is `fclient`'s to add, over the same IBE block). Cross-boundary moves stay refused at Depart.

### −2.4d The closed host lifecycle through the dispatcher (on `aea0180c`, the native-reviewed model)

Host-only, feature-gated, written with source tools only; not compiled or run by its author. It connects the native-reviewed one-bell model (`world_index::resolve`) to the real `dispatch` as a **closed** lifecycle — Muster → Resolve → Dissolve → Resolve → Return, and the roster's season-end close — and enables the reserve debit only inside it. Depart stays refused (now at its final gate under the allocated identity, as before at the identity gate); no arrival path exists; no legacy/wide mixing; no second quota.

**The envelope.** The band is full, so the five commands ride inside three tags of the band **whose class they share**, under an explicit escape, version and sub-operation byte (`wide_ix` module doc): `0xDA ‖ 0xFF ‖ 0x01 ‖ op` for the player Muster (op 1: `unit, troops, tile`, 10 bytes) and Dissolve (op 2: `host ref`, 60 bytes); `0xDC ‖ …` for the keeper Resolve (op 1: `bell, beneficiary`, 40 bytes, **top-level**) and the permissionless Return (op 2, 4 bytes); `0xDE ‖ …` for the roster close (op 1, 4 bytes). Every legacy encoding keeps its exact length and decodes as before (a Depart is 267 bytes and its second byte is a host-reference version; a SettleTicket is 2 bytes whatever `k`; a Close is 2 bytes); any other length must be a whole envelope or it is `BadData` — no malformed fallback. `WideCommand::decode` is the one parser; the dispatcher routes, and the account table, the class, the top-level rule and the act's whitelist are read off the **decoded command** (the act accepts a Muster or Dissolve inner and refuses a Resolve, a Return or a roster close under the same tags). Why these tags: the audit's class-preserving option — a P sub-operation under the band's player march tag, D under its keeper settle tag, N under its season-end close — so no keeper classifier sees a class change behind a tag. Unresolved: the envelope is as provisional as the band; a real allocation (workstream 4) may give these commands tags of their own, and the escape byte then retires.

**What the handlers do** (`proc::wide`, each refusing before its first write; the host tests witness it):

* **WideMuster**: the player prologue (wallet or NFT resident through the band's act, the signed holder generation), the holding at its canonical wide address and the Citizen's, its own province unlocked; the deployed Muster's checks in its order (final, resident through `b − 2`, the unit, the reserve, the kernel's host bounds, a passable tile, the caps and a free entry); the roster side table present and this province's **or absent and created from the payer** (its immutable rent recipient the payer); the tables paired, the alias claimed through the authenticated `claim`; the Citizen's bucket and the end bell on a scratch copy (`PlayerStart::finish`). Effects: the muster-pending entry under the alias, `roster_epoch`, `n_entries`, the reserve debited, `host_seq + 1`, and at the holding's **first** muster the full-reference identity allocated (`WideHolding::allocate_identity`: `read` now accepts v1, still refuses any used transit or explore slot under either version, so Depart's old rejection stands); the wide `WIDE_MUSTER` record (below).
* **WideDissolve**: the host by full reference (the holding the Citizen's at the reference's generation), the standing province wide (a deployed one is the boundary, `NotImplemented`) **and the holding's own** (a foreign standing province is `NotImplemented` until a source-capture proof exists: the closed path is local), final, resident, the roster present and the entry **paired** with the reference at its index, state 1, no pending change; the pending `Leave` of `b`; the wide `WIDE_DISSOLVE` record.
* **WideResolve**: the keeper prologue, `bell = resolved_next`, below the end bell; **the reveal window of the bell closed** for the province's **stored region** against THE anchor or its archive entry (`proc::clash::window_closed`, the same function the deployed ResolveClash runs at its line 1259; `NoAnchor`, `BadAddress`, `TooEarly`); the bell seed from the SeedCache or the archive (`holding::bell_seed`, the deployed resolves'); the wide ClashInputs position of the province and bell **absent** (`NotImplemented` otherwise: no reveal or gather exists); the roster present or **absent while no entry is live** (the bootstrap: an opened province resolves before its first muster, with no table and no deadlock); the model on scratch copies; the resolve summary; the province and the roster written whole on success; the wide `WIDE_RESOLVE` record with the **input digest** (province key, bell, seed, the province and roster bytes as read) and the **output digest** (the kernel outcome's digest and the bytes the bell left).
* **WideReturn**: Running or Ended; the roster present and paired; the holding present (its live generation, the capture lock; **of this province**, else `NotImplemented`) or absent; every departed `Leave` entry whose **full reference** (world, coordinate, site through the roster, never a packed id) names the holding account is freed, at most three per transaction (a reference of another province is `NotImplemented`): whole troops (`/ 1,000`, once) into `reserve[unit]` when the holding is live at the reference's generation (`WIDE_RETURN`), lost otherwise (`WIDE_STRANDED`); the reference released. Permissionless; the credit goes to the holding record, so it survives a transfer of the Citizen.
* **WideCloseRoster**: season end (Ended + 72 h, Aborted, the tombstone); the record at the canonical address of the province its header names closes whole to its immutable rent recipient; the wide `WIDE_ROSTER_CLOSED` record (recipient, lamports; no chain: the account is gone).

**The wide event format** (`frontier-abi` `world_index::event`; the review rejected deployed kinds keyed by the alias, whose `chains_of` reads a dense host id). A wide record is logged under the prefix `PSW1` (never `PS2`), its body starts with version **`0x82`** (the deployed decoders refuse it as `Version(0x82)`: a reader without the wide format sees the wide world as **unknown**, never misread; version `0x81`, the local-only lifecycle's 56-byte host keys, is **retired** and refused by name, `EventError::RetiredVersion` — a trace saved under it needs that revision's decoder, and no `0x81` record exists on any chain), its kinds are the module's own (1 Muster, 2 Dissolve, 3 Resolve, 4 Return, 5 Stranded, 6 RosterClosed, 7 Departed, 8 TransitSettled, 9 DepartureSettled, 10 Revealed, 11 Gathered: no deployed or other team's kind code), every key is a **full identity** (the 106-byte `host ref ‖ standing province key`, both of one world, or the 50-byte province key), every width is fixed by the kind and decoding is strict (a wrong version, kind, key, width, tail order or trailing byte refuses). **Link sets are exact per kind**: Muster, Dissolve and Return chain the province and the holding; Resolve and Stranded the province only; RosterClosed nothing; a missing or an extra link refuses at encoding and at decoding (`EventError::Links`). The chain: `seq' = seq + 1`, `head' = sha256("PSF-WIDE-CHAIN-v1" ‖ entity ‖ LE64(seq') ‖ head ‖ body_without_tail)`, written into the wide accounts' `event_seq`/`event_head` header fields, which only wide records advance; the emitter computes every link and the whole tail **before** it writes any header, so a refused record changes no chain. **Attribution**: a record concerns exactly one province and at most one holding, derived from its full key and never from the alias — a host-keyed record's province is the host's home province (the closed path is local) and its holding the host's issuing holding (site, generation, sequence 0); a province-keyed record's province is its key. `verify_chain(target, start, trace)` takes a **full target identity** (`WideTarget::Province(key)` or `WideTarget::Holding(holding ref)`), consumes only the records attributed to it (a record of another province or holding is skipped whatever link it carries; a record of the target must carry the target's link and that link must recompute) and refuses a skipped record, a tampered byte or a forged link; interleaved traces of two provinces and two holdings verify each account alone. The resolve's digests: the input commits to the province key, the bell, the bell seed, **the authenticated Season bytes whole** (ruleset hash, program version with the wide bit, the clock, the conquest block the step parameters come from — what the handler's keeper prologue, `require_wide_season` and `StepParams::of_season` read) and the province and roster bytes as read (`sha256("PSF-WIDE-RESOLVE-INPUT-v2" ‖ key ‖ LE32(bell) ‖ seed ‖ sha256(season) ‖ sha256(normalized province before) ‖ sha256(roster before))`); the output to the kernel outcome's digest and the bytes the bell left including the summary (`sha256("PSF-WIDE-RESOLVE-OUTPUT-v2" ‖ clash digest ‖ sha256(normalized province after) ‖ sha256(roster after))`). **Normalization**: both province digests are over the bytes with the header's `event_seq` and `event_head` zeroed (`normalize_chained`), so the output is the state before the record's own link and a replay compares normalized bytes; the chain itself is committed by the link, not the digest. Not an allocation: the prefix and the kinds are as provisional as the band.

**Transaction status and the collectors.** One transaction may log several records (a return of several hosts). Raw logs can remain on failed transactions and must be filtered by transaction status; the host executor (`run_tx`) models successful receipts only by truncating both log collectors (`PS2`, `PSW1`) back to their pre-dispatch lengths on a refusal, beside restoring every account. `records()` / `wide_records()` therefore return the receipts of successful transactions only, and a record logged before a later step refused is never counted as an event.

**Second retention review, same day.** With a single mutable funder, a payer B who only topped up the escrow for a refile would have received A's record rent at the close. ## 4. Safety properties the tests pin

- **No alias.** Wide addresses use a separate domain from legacy Province, RingSeed and Holding addresses (the legacy grammar is untouched); tested samples do not alias, but this is not a proof against cryptographic collisions. No wide record passes a legacy presence check: different magic, different size, `layout_version 3`.
- **No relabel.** Prefix `P`, `Q`, `RING` of a wide province are zero and a nonzero value is refused (`LegacyIdentityInPrefix`); the dense index and `host_id` are never computed for a wide coordinate.
- **No genesis substitute.** A wide ring seed has one path: request (round fixed) → verified consume. A zero seed is refused as a seed; a requested record with a seed is refused as malformed.
- **One inventory.** A slot is spent in exactly one representation; the tested legacy slot allocator skips a wide-bound slot; complete legacy-reader and writer compatibility remains unproven; a wide binding counts in `holdings_n`; slot 1 stays legacy.
- **No partial debit.** A wide holding with any issued host, transit or explore under identity version 0 is unreadable; a wide departure is refused at the identity gate before any escrow.
- **Fail closed, write nothing.** Every refusing handler is compared before and after on the fund, payer, Citizen, holding and seed count.
