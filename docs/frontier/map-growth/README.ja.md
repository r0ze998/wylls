# マップの外側への拡張（2026-10-28）

ブランチ `map/region-append`（origin/main ca21ce2f から）。シーズン制の変更は対象外。

## 0. 結論

- **オンチェーンの世界は、もともと「追記型」の構造です。** 州（Province、61マス）は座標 (P,Q) ごとに独立したアカウントで、リング単位で外側へ追加されます（OpenRing → 種 → OpenProvince）。州の地形はその州のリングの種と座標だけで決まり、隣の州も既存の州も読み書きしません。境界の中央3マスは両側で必ず通行可能にされるので、後から生まれた州とも必ずつながります。同じ州・同じリングをもう一度作ろうとすると、プログラムが `AlreadyDone` で拒否します。
- **そのため、プログラム・ルール・プリセットは一切変えていません。** 足したのは、この成長を「データとして読む口」「画面で区別して見せる層」「ローカルで検証・計測する道具」です。
- **足りなかったのは次の3点でした。**
  1. 画面に「このシーズンの地図の外（r_max より外）」という状態がなかった（雲海＝未開と同じに見えていた）。
  2. 「リングは開いたが種や州の作成を待っている」状態を、ヘラルドもクライアントも出していなかった。
  3. 世界の広さ（どのリングがどの状態か、各リングの州が何個チェーン上にあるか）を、全域を走査せずに読める安定した口がなかった。

## 1. 調査結果

### 1.1 周囲の霧は何か

クライアント（`permutation-server/web/frontier/`）には、もともと2種類の「見えなさ」がありました。

| 見え方 | 意味 | 由来 |
|---|---|---|
| 雲海（L0） | そのリングがまだ開いていない。土地は**まだ存在しない** | 季節レコードの `rings`（種が出たリングの数）。`map/survey.mjs`、`map/cloudsea.mjs` |
| 海図・測量済み（L1/L2） | 開いた土地だが、自分はまだ見ていない／前に見た | 自分の村・軍勢からの視界（端末内の記憶つき）。表示だけの霧で、ルールではない（全アカウントは公開） |
| 視界内（L3） | いま見えている | 同上 |

**足りなかったもの：** `r_max` より外（このシーズンでは絶対に土地にならない場所）と、未開の雲海の区別がありませんでした（クライアントは `rMax` を読んでいなかった）。また、リングが開いて種を待っている間は、ただの雲海に見えていました。

### 1.2 固定の上限

| 上限 | 値 | 場所 |
|---|---|---|
| シーズンの最外リング `r_max` | S1 のローカルプリセットで 16、プログラムの上限 128 | `frontier-abi` プリセット、`ProvinceCoord::checked` |
| 州の数（リング128まで） | 49,537 | `geometry.rs`（`provinces_within(128)`） |
| 州の密な番号 `index()` | リング128まで。軍勢IDに20ビットで入る | `geometry.rs`、`permutation-rules/src/frontier/addr.rs` |
| 命令データの P,Q | `i16` | `frontier-abi` の命令 |
| マス座標 | \|q\|,\|r\| ≤ 2¹⁶ | `geometry::check_hex` |
| 州あたり | 61マス（u64マスク）、12拠点、構造物12、要塞2、隊商5 | `province` レイアウト |
| 行軍 | 32歩・4州まで・72ターン先まで | `travel.rs`、`reveal.rs` |
| ヘラルドの支配表 | `provinces_within(R ≤ 127)` 個の配列（R² に比例） | `herald/src/cqfmt.rs`、`control.rs` |
| クライアントのマス鍵 | ±2047（リング128の外周 ≈ 1,250 マスより内側） | `map/survey.mjs` `hexKey` |
| クライアントのキャッシュ | 州レコード256、地形256、測量記憶512州 | `herald.mjs`、`map/terrain.mjs`、`map/survey.mjs` |

地形生成そのものには上限がありません（座標と種の純関数）。

### 1.3 各機能はマップの大きさにどう依存しているか

| 機能 | 依存 | 外側のリングで使えるか |
|---|---|---|
| 地形・資源・拠点 | 州ごと（リングの種＋座標）。隣を見ない | そのまま使える |
| 最初の村（PlaceHome） | リング 2〜`heartland_max_ring`（S1 は 3）・自国の方角に限る | **使えない（仕様どおり）**。外側は2つ目以降の村（前哨）・構造物・行軍の場 |
| 前哨・構造物・貯蔵庫・隊商・襲撃 | タイル規則のみ（リングの規則なし。前哨は中核リングの外） | 使える（今回、リング5で柵を建てて確認） |
| 砦・自由都市・野営地 | 州を開くときにリング2以上で置かれる | 使える（リング5・6の州にも各国の砦が置かれた） |
| 行軍・戦闘 | 通る州と行き先の州がチェーン上にあること。4州・32歩まで | 開いた州なら使える。未生成の州へは行けない |
| 二重処理の防止 | 行軍はどちらの州でもなく**出発元の村（Holding）の移動記録**に乗る。行き先の州が解決した後で精算し、記録を消す。各州は `resolved_next` 順にしか進まない | 境界をまたいでも同じ |
| 保存 | すべてチェーン上の PDA。ヘラルドはチェックポイント、キーパーは SQLite | 再起動で保持（今回確認） |
| ターン処理（キーパー） | S1 では**開いた全州に毎ターン1トランザクション**（SkipQuiet か解決）。M1 の「静かな州は24ターンまとめて飛ばす」は S1 では無効 | 州の数に比例して増える（§5） |
| ヘラルド | 取引ごとに全州（`complete_through`）と全アカウント（`standings::members`）を走査。全アカウントをメモリに保持 | 州の数に比例、取引数×州数で増える |
| クライアント | 画面に入る州だけ取得（同時12件まで）。概観はリングごと | 州の数にはほぼ依存しない |

### 1.4 コンポーザビリティを支えている仕組みと制約

支えているもの：

- **安定した識別子：** 州 (P,Q)、マス (P,Q,idx 0..60)、拠点 (P,Q,site)、全体のマス (q,r) と `geometry::locate`。どれも世界が広がっても変わらない（既存の州の番号は振り直されない）。
- **アカウントの番地（PDA）はすべて (P,Q) から決まる：** 州、村、構造物、貯蔵庫、到着枠、衝突入力など。全体の数を持つ配列はオンチェーンにない（ウェッジ別6要素だけ）。
- **誰でも送れる命令：** OpenRing / OpenProvince はクラスD（支払う人は誰でもよい）。条件はプログラムが判定する。
- **公開の読み口：** ヘラルドの `/h/*`、WASM の純関数（`generate_province` など）、エンティティごとのハッシュ連鎖。

制約：

- 軍勢ID・帰還精算の `site_ident` は州の密な番号を使うので、**リング128を超える世界は ID 形式の変更が必要**。
- ヘラルドの支配表・`control` ファイルは全州の配列（R² に比例）。
- キーパーの毎ターン全州処理と、ヘラルドの取引ごとの全走査（§5）。
- 行軍は4州まで。外周が広がると、中心まで何度も行軍を重ねる必要がある（設計 §3.6 にある既知の性質）。

## 2. 設計：既存の世界を壊さずに外へ足す

既存仕様の「リングで育つ世界」をそのまま使い、足りない口と見せ方だけを追加しました。

### 2.1 場所の4つの状態

ヘラルドとクライアントが同じ言葉で区別します（`frontier-node/crates/herald/src/world.rs`、`permutation-server/web/frontier/map/world.mjs`）。

| 状態 | 条件 | 画面 |
|---|---|---|
| `outside` このシーズンの地図の外 | リング > `rMax` | 破線の境界の外。「ここはこのシーズンの地図の外です」「第7輪（このシーズンの地図の外）」 |
| `unopened` 未開 | `rMax` 以内で、リング ≥ `ringsOpened` | 雲海。「まだひらいていない土地です」「第6輪（まだひらいていません）」 |
| `pending` 生まれるところ | リングは開いた（`ringsOpened` に入る）が種待ち、または州がまだチェーンにない | 雲海。「この土地は生まれるところです」「第5輪（生まれるところです）」 |
| `open` 開いた土地 | チェーン上にある | 地形。霧は自分の測量（未測量／測量済み／視界内）で、世界の状態ではない |

古いヘラルド（新しい欄がない）でも、クライアントは従来どおり `open` / `unopened` だけで動きます。

### 2.2 将来の機能が使える読み口（安定したインターフェース）

| 口 | 中身 | キャッシュ |
|---|---|---|
| `GET /h/world` | `rMax`、`rMaxHard`、`genesisRing`、`ringsOpened`、チェーン上の州の総数、各リングの `{d, seed: seeded/requested/absent, provinces, size}`、識別子の定義、関連パス | 5秒 |
| `GET /h/world/ring/{d}` | リング d のチェーン上の州 `{p, q, region, wedge, openedBell}` | 5秒 |
| `GET /h/season` に追加 | `ringsOpened`、`ringProvinces[d]` | 30秒（既存） |

どれも**リング単位**で、全域の一括読み込みを前提にしません。新しい状態は持たず、ヘラルドがもともと取り込んでいるアカウント（Season、Frontier、RingSeed、Province）から作ります。将来の市場などは、この口と (P,Q) 系の識別子・PDA で既存の世界とつながれます。

### 2.3 変えなかったこと（意図して）

- プログラム、ルールカーネル、`RULESET_HASH`、`frontier-v3.wasm`。
- 土地を足す権限（OpenRing は誰でも送れる。条件はプログラムが判定）と経済ルール（θ、ウェッジ資金の家賃、`r_max`）の既定値。
- キーパーの開放方針（前のリングが全部チェーンに乗り、その後の集計が終わってから次を開く）。

## 4. 検証（ローカル、2026-10-28）

世界1：`--conquest --scale 10 --ring-theta-bps 100 --r-max 6 --bots 0`（季節71、基準ポート41600）。2人のプレイヤー（同じアステル）でブラウザから参加。

| 完了条件 | 結果 |
|---|---|
| 1. 既存地域を保持したまま隣に地域を追加 | アステルの村が2つになった時点でキーパーがリング5を開き（混雑条件）、種の公開後に30州を作成。その後、手動の `land --do open-ring` でリング6（36州）も開いた。世界2（§5.2）では、リング0〜4の61州の地形を成長前に記録し、817州まで育った後に比べて61州すべて一致 |
| 2. 境界をまたぐ移動と新地域での建築 | 州(2,0)の村から槍兵100を、リング3・4を通ってリング5の州(5,0)の砦へ行軍（22マス、ターン14到着）。到着後、州(5,0)のマス6に**柵**を建築（既存と同じメニュー・費用）。ヘラルドの `structures.json` に `p:5,q:0,tile:6,kind:2` |
| 3. 再起動後も保持 | `down` → `resume`。127州の地形ハッシュ（州ごと・全体）、2つの村の位置・所有者・国、柵、`/h/world` が前後で一致。ヘラルドは再起動の4.1秒後に応答、4.3秒後に127州すべてを把握。ゲーム時計も継続 |
| 4. 重複生成・二重処理の防止 | 既存の州 (4,0)・(5,0) への OpenProvince → `AlreadyDone`(52)、`r_max` の外 (7,0) → `BadData`(1)、リング6開放後の OpenRing → `AtMax`。行軍は村の移動記録で精算され、到着後に記録が消えた |
| 5. 霧と未生成・地図外の区別 | ブラウザのインスペクタで「第5輪（生まれるところです）」「第6輪（まだひらいていません）」「第7輪（このシーズンの地図の外）」、開いた土地では「未測量」を確認。全体図で、開いた土地・雲海・破線の境界とその外が分かれて見えることを確認 |
| 6. 計測 | §5 |

**注意（手動の OpenRing）：** リング6は、キーパーの方針（リング5が全部そろって次の集計が終わるまで待つ）より早く、`land --do open-ring` で開きました。プログラムの規則（混雑・1ターン経過・資金）は満たしているので通りました。OpenRing は誰でも送れるため、**キーパーの待ち方針は他人には強制されません**（設計どおりですが、知っておくべき性質です）。

数値は `scripts/map-growth-measure.py summary` の出力と、ブラウザの Performance API から。macOS の開発機1台、ローカルのテストチェーン、時計10倍速（1ターン=実時間60秒）。ほかのセッションの世界（基準ポート41300）が同時に動いていました。1回ずつの測定で、ばらつきの評価はしていません。

### 5.1 世界1（ルールどおりの拡張、2人のプレイヤー）

| 州の数 | ターン完了の遅れ（中央値） | メモリ（平均）localnet / keeper-a / herald |
|---|---|---|
| 61 | 1.0 秒 | 43 / 15 / 15 MB |
| 127（リング6まで） | 1.3 秒 | 50 / 19 / 27 MB |

再起動（`resume`）からヘラルドが応答するまで 4.1 秒、127州すべてを把握するまで 4.3 秒。

`--ring-theta-bps 0`（村がなくても混雑条件が成り立つ）で、キーパーの方針どおりにリングを1つずつ開かせました。61州→817州まで約24分（ゲーム内約24ターン）。

|---|---|---|---|---|---|---|---|
| 61 | 0–4 | 1.3 / 1.3 秒 | 44 MB | 14 MB | 13 MB | 0.31 ms | 4.2 KB |
| 127 | 0–6 | 1.2 / 1.3 秒 | 51 MB | 19 MB | 22 MB | 0.27 ms | 4.4 KB |
| 217 | 0–8 | 1.1 / 1.3 秒 | 61 MB | 25 MB | 30 MB | 0.29 ms | 4.5 KB |
| 397 | 0–11 | 1.3 / 1.3 秒 | 85 MB | 37 MB | 48 MB | 0.44 ms | 4.8 KB |
| 631 | 0–14 | 1.5 / 1.6 秒 | 126 MB | 49 MB | 65 MB | 0.30 ms | 5.0 KB |
| 817 | 0–16 | 1.9 / 2.1 秒（10ターン） | 186 MB（最大 252） | 59 MB（最大 70） | 79 MB（最大 86） | 0.31 ms | 5.2 KB |

- **ターン完了の遅れ**は、ルール上の待ち（次のターンの開始＋開示の窓 W）が終わってから、ヘラルドが全リングの概観を書き終えるまでの実時間。ルール上の待ち（10倍速で約60秒）は含みません。
- **キーパーの送信数**：1ターンに開いている州の数と同じ数の SkipQuiet（817州で817件/ターン、ほかと合わせて約855件/ターン）。州の数に比例します。
- **メモリ**は州の数にほぼ比例（61→817州の平均値の差から、キーパー約60KB/州、ヘラルド約85KB/州、ローカルチェーン約190KB/州）。
- **ディスク**（817州・34ターン）：ローカルチェーン 126MB、ヘラルド 448MB（世界1、127州・約20ターン：27MB / 74MB）。
- **再起動**：817州の世界でも、ヘラルドの応答まで 4.4 秒、817州すべてを把握するまで 4.5 秒（127州で 4.1 / 4.3 秒）。
- **ブラウザ（観戦ページ）**：61州で ヘラルドへ16要求・109KB・453ms、JSヒープ13MB。817州で 19要求（概観がリングごとに1つ）・31KB（キャッシュあり）・487ms、JSヒープ51〜60MB。ヒープは州の数とともに増えます。プレイ画面は画面内の州だけを読むので、取得件数は世界の大きさにほとんど依存しません。

## 6. 測定した限界と、まだ対応していないこと

**測定した範囲は「817州（リング16）、プレイヤー2人まで、1台のローカルチェーン」です。** それより大きい世界や多人数での動作は測っていません。「無限に広がる」「大人数に対応」とは言えません。

構造上の上限（コードで決まっているもの）：

- リング128（49,537州）。軍勢ID が州の密な番号を20ビットで持つため、これを超えるには ID 形式の変更が必要。
- 行軍は4州・32歩まで。外側が広がるほど、中心との行き来は何回もの行軍になる。

測定で見えたコスト（増え方）：

- **キーパー**：S1 では毎ターン全州に1件ずつ書く（M1 にあった「静かな州をまとめて飛ばす」が S1 の得点処理のため無効）。817州で約855件/ターン。州が増えるほどチェーンへの書き込みと手数料が線形に増える。**全域走査を前提にしない構造にするには、ここを「何かあった州だけ」にする必要があるが、S1 の州ごとの得点（`SCORE_NEXT_BELL`）の進め方に関わるため、ルールの判断が必要で今回は変えていない。**
- **ヘラルド**：取引1件ごとに全州（`complete_through`）と全アカウント（`standings::members`）を走査し、全アカウントをメモリに持つ。817州ではまだ CPU 1% 未満・ターン完了の遅れ2秒程度だが、取引数×州数で増える。支配表（`control`）も全州分の配列。
- **ローカルチェーン**のメモリが最も速く増える（817州で平均186MB、最大252MB）。本番の Solana ではこの数字は意味が違う（ローカルの検証用ノードの値）。

まだ対応していないこと：

- 州を必要になったときだけ作る（今はリングが開くと、キーパーがそのリングの全州をすぐ作る。プログラムは州ごとの作成を許しているので、方針の変更で可能）。
- キーパーの毎ターン全州処理、ヘラルドの取引ごとの全走査の削減（上記）。
- 「生まれるところ」の州を雲海以外の見た目で描くこと（今は文言とインスペクタだけで区別。雲海の描画は手を入れていない）。
- 境界線（`r_max`）は、開いた土地から2リング以内に来たときだけ描く。それより遠いと紙の外になるため。
- キーパー外部の事前判定 `fclient::land::PROVINCE_RENT` が M1 の大きさ（4,096B）で資金を見積もっている（プログラムは S1 で 4,736B）。資金がぎりぎりのとき、キーパーが「開ける」と判断してもプログラムが `Insufficient` で拒否しうる（害は送信の無駄だけ）。今回は直していない。
- 手動の OpenRing がキーパーの待ち方針より早く通ること（§4 の注意）。プログラム上は正しい挙動。
- 2人を超えるプレイヤーでの検証、devnet・本番での検証。

## 7. 再現手順
