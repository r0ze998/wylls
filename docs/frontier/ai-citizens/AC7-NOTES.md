## 2. Decisions and deviations (read these)

1. **Extra files** beyond the §11.5 list: `badges, cards(roster), parts, dom, api, ballot` hold logic that the row names but splits differently, plus `lang.ja.json`. All under `council/**` (§0.2).
2. **Japanese lives in `council/lang.ja.json`, not in a `.mjs`.** The existing test `web-lang.test.mjs` (completeness (b)) scans every `web/frontier/**.mjs` and `.html` for "unmarked Japanese" and fails on a dictionary written in a module; `council.html`'s toggle uses character references. `main.mjs` fetches the file at start (`api.getUrl`, same origin); until it is loaded, or if it fails, the page is English. Tests register it through `fixtures/ai-page-lang.mjs`. Static markup uses `data-t` / `data-t-attr` (not `data-i18n`) because `web/lang.mjs`, which the lazily loaded identity module pulls in, translates `data-i18n` elements by Japanese keys and warned on every one.
3. **The page's code strings avoid the `code: '…'` literal form** (a helper `refused(code)` instead): the existing test `web-frontier-errors.test.mjs` requires every such literal under `web/frontier/` to have a text in the design session's `fi18n.mjs`, which this page must not edit.
4. **Where the page loads from.** `serve.mjs` serves `/council.html` and `/council/*` from the page directory; the design-session modules the page uses (`people/identity.mjs` for derived names, `faddr.mjs` for the script bots' citizen tags, `session.mjs` for Ed25519) are **read only and loaded lazily by absolute path** `/frontier/frontier/…` and `/frontier/session.mjs`, which `serve.mjs` forwards to the herald, whose web root is `permutation-server/web` (`herald/src/server.rs` `web`, `stack/src/up.rs --web`). A relative import from `council/` would not resolve under `serve.mjs` (`../lang.mjs` is `/lang.mjs`, not served), so the page imports no design-session module statically; a test walks the import graph through the real `serve.mjs` and a fake herald that serves the web directory the way the real handler does. If one of the three cannot be loaded the page degrades (names fall back to short tags, script bots lose their badge in tag-only lines, signing says why it cannot). The text in §1.2 of the contract that the page is reached at `http://127.0.0.1:41902/council.html` holds.
5. **No wallet or key text is ever printed** (§9.4 item 4); a browser run asserts the visible text contains no 32-44 character base58 string while signed in. The seat key file holds the **wallet** keypair as well; `parseKeyText` reads the session keypair out of it and keeps nothing else. The key is memory only (not stored; a reload asks again).
6. **Badges.** Script bots in tag-only lines (episodes, departures, chronicle) get their badge from a tag set derived in the browser from `roster.script.wallets` with `faddr.mjs` (`withSeed(seasonAddress, seedOf('Citizen', {wallet}), programId)`, then the first 8 bytes little-endian); a test asserts this equals AC6a's `citizenTagOfTag15`. `roster.script.tags` is also read if a registrar ever adds it (not pinned). Flags in files (`ai`, `kind`, `ai_written`, `ai_roster`) are ignored on purpose. An actor not in the roster gets **no** badge (the page does not say "human").
7. **Derived names** for non-roster citizens come from `identity.mjs` `displayName(identityOf(tag), {language})` (never `withProfile`), the same function the services use; the seat prints "Presenter seat".
8. **Pivotal indicator.** Ballots are hidden until the order opens (or the close when nothing was adopted), so the verdict is exact only after the opening: the page decodes the opened ballots (`open.ballots[].bytes_b64`) and re-runs the §6.5 rule without the viewer's ballot (`decideTally`, tested against AC4's own close over 200+ ballot multisets, with and without a human present). Before the opening it can only say "yes: the only human or scripted-seat ballot" for a ballot this page cast, otherwise "not known yet". It never claims a count before it is public.
9. **Compose preview.** The contract (§4.6) says the sanitiser is "also used by the page preview"; that module (`citizens/mind/sanitize.mjs`) is Node-side and not served. The page shows the length counter and the line "the service stores your text after its own cleaning"; it does not port the sanitiser.
10. **Strings**: the heading and labels the contract fixes are verbatim in EN ("AI's words (model-written, not verified)", "Remembered (cited by the model):", "progress not computed", "script bot: not AI, not human", "presenter seat (human operator)", "AI-assisted (self-declared)", "You are writing to an AI citizen."). The word "Call", "shade", "remembers", pacts and betrayal appear in no string (a test).

## 5. Open points for the integrator, AC6 and the architect

1. **Shapes the contract does not pin, read tolerantly** (each has a test): `open/<bell>.json` (accepted: `{records:[…]}`, `{opened:[…]}`, an array or one record; fields as §7.2 opened record, `remembered[].text` as `{en,ja}` or a string, a destination `"unrevealed"`); `events/latest.json` (`{events|rows|items:[…]}` rows with `kind` containing `depart` or `clash`, actor as `actor|tag|citizen|owner|actors[]|fighters[]`, `from|origin`, `troops|mass|dep_mass`, `arrive_bell`, `destination|to` only when public, clash `p,q`/`at`, `engagements`, `lost` as `{faction: n}` or a list); `chronicle/latest.json` lines with `text` as `{en,ja}` or a string (without `text` only the kind label and the actors are printed). **AC6 should write these shapes or tell us; if AC6's differ, the fix is in `events.mjs` and `decisions.mjs` `normalize*`.**
2. **Finding opened decisions.** There is no index of `open/` files, so the page probes `open/<b>.json` for b from each sealed record's `release_bell` to `release_bell + 8` (bounded at 8 requests per poll, a present file is cached, a miss is retried until its bell is 3 bells old), plus the bells named by `ai_march_opened` chronicle lines. A cheap `open/latest.json` or an index would remove the probing.
3. **404s are expected**: each probed-but-absent `open/<b>.json` shows as a Chrome console "Failed to load resource" line (22 on the first load of the slice-4 stage, one-off).
4. `GET /f/ai/council?faction=<f>` is the live source (it carries `open` and `result` once they exist); the period file is the fallback. `GET /f/ai/talk` is paged from `after=0` (oldest first, 200 per request, up to 5 pages per poll), so on a very long run the first load shows the oldest 1,000 messages of the first pass, then incremental ones.
5. The page shows nothing from `/h/ai/cards/index.json` (it is not needed: the roster lists every tag).
6. **Not run:** the page against AC6's real files, a real mind, the real herald, any model, the A/B seat script (`origin 2` is only unit-tested), the `scripted` seat label in a browser, and `verify-minds`. The Japanese strings were checked for presence and layout, not reviewed by a native reader (the contract says the integrator reviews creeds; the page strings need the same review).
7. `council.html` is not in any gate script of the run (`page_tree` of the commitments is `null` in slice-4); the hash of `permutation-server/web/frontier/council` now includes `lang.ja.json`.

## 6. Claims this unit does and does not support

Supports: the page labels AI citizens, script bots and the seat from the signed roster, prints model words as "model-written, not verified", prints Remembered lines from code text only (a test feeds a model "Remembered:" imitation and checks it never enters the block), and prints "progress not computed" for null. Does not claim: any behaviour of the model, any result of a run, human play, devnet or mainnet.
