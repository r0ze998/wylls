What the GET counters are and are not. They count the brain's own extra GETs (R6's "Recall's `/h/events` feed, up to 3 owner-province GETs, `obs_digest` re-reads", the path fetch, the brain's `/h/me` read) at their call sites, each checked against the herald log in the tests. The first observation of every step (`Bot::step`) is the bots' baseline and is not counted (a rule bot makes it too). `gets:reobserve` is `1 + provinces + per-bell envelopes + bell files` of the re-observation: a lower bound, because a 404 and a refresh of the shared `/h/season` or overview caches cannot be seen from outside `Bot::observe` (an MC file). The script bots' follow micro-step GETs are not counted per AI (they are not AI GETs).

## 3. Deviations from the contract (and additions the architect should record)

1. **New mind route `POST /v1/brain-stats`** (§8.1 lists four routes). Needed because a `no_session` step makes no mind call and leaves no record, so only the brain can count it. Body `{v:1, index, bell?, counters:{name: non-negative integer}}`; answer `{ok, applied}`. Counter names are the brain's (`steps`, `no_session`, `no_session:*`, `reobserved`, `gets:*`).
2. **New files outside the unit rows**, all under `citizens/**` or `bots/src/ai/**`: `citizens/lock.mjs`, `citizens/bin/llama-check.mjs`, `citizens/llama/why-check.mjs`, `bots/src/ai/getcount.rs`. The lock file name `wylls-ai-stack.lock` and the claim directory `KEYS/anchor-claims/` are mine; §1.1 and §6.3 name the mechanism only.
3. **"Smoke" is the config's file name** (`smoke.json`), as §7.1 says ("every config except `smoke.json`"); a copy of the smoke config under another name is a non-smoke run.
4. **The prompt text changed** (R2 requires it): `prompt_templates_sha256` is different from every earlier commitments file (slice-4's, integ-A's preflights).
5. **`goals_served` order**: it now follows the persona's goal order, so a guardian's `recall` candidate prints `serves G3, G4` (wave A: `G4, G3`). Every other persona and kind gives the same set and order; a test keeps wave A's table as the regression oracle (as sets).
6. **Existing tests edited, minimally**: `citizens-registrar.test.mjs` (the default commitments now say `unmeasured`), `citizens-run-check.test.mjs` (stand-in `AI_MODEL` and `AI_LLAMA_DIR` in the environment, `lock.mjs` copied into the throwaway repo, a recorded argv file for the llama check in the real-start test, `/props` answers with the fields the check reads), `citizens-mind-memory.test.mjs` (`goalsServedDefault` is gone), `test/fixtures/ai-mind-doubles.mjs` (`personaOfDouble` takes the library's goals), and on the Rust side `tests/ai_brain.rs` (a wrong token now gives two 401s, the decide and the stats post, and `brain_stats_post_failed` is 1) and `tests/ai_common.rs` (`FakeMind` records `/v1/brain-stats` bodies).
7. `anchorPass` returns `{anchored, gaps}` as before and adds `claimed` only when a bell was left to another live process.

## 4. Open points and what other units must know

- **AC8 / verify-minds (M1):** print an `unmeasured` `model.sha256`, `model.file` or `server.tree_sha256` as `unmeasured`, never as PASS (`UNMEASURED` is exported by `registrar.mjs`).
- **AC9 / G5 corpus:** the R2 case of §10.2 (a sealed march `why` that names a coordinate or place must be withheld; one that names only the kind of target must pass) is covered at unit level in `test/citizens-ac10a-sealed-why.test.mjs`; the corpus still needs it with real Gemma. The report (`report.mjs`) reads `brain` from `/v1/metrics` or `PUB/metrics/latest.json` (`per_ai[tag].gets_per_step`, `totals.no_session`, `totals.no_session_share`, `totals.gets_per_step`) and may read `fleet/ai-brain.json` for the process-wide counters and `per_bot`; it should label `gets:reobserve` a lower bound.
- **Run script users:** until the integrator merges this branch, run scripts in other worktrees still use their per-worktree lock file; the shared lock exists only for trees that contain this change. A run that was started before the merge and one after cannot see each other's lock.
- **The model hash is cached** by `modelSha` on path, size and mtime (wave-A code, in `$TMPDIR/wylls-ai-model-sha.json`); a file edited without changing size and mtime would keep its old hash. For the main run the integrator may delete that cache file to force a fresh read of the 14.6 GB file (the check above did not).
- **Residual race of the lock takeover** (documented in `lock.mjs`): a starter that crashes between creating the takeover claim and removing it leaves a claim whose pid is dead; the next starter clears it. This needs two crashes inside one microsecond window to matter.
- **Anchor claims:** a process that sent a memo and died before writing the anchor file leaves a claim with its signature (or none, if it died before the send returned): with a signature the next process checks the chain first; with none it sends, so a crash exactly between the RPC accepting the transaction and the signature being recorded can still double-send once. Not hidden, not measured.
- **Brain restart:** the mind keeps the latest cumulative post per AI and ignores a post with fewer `steps`; if the fleet process is restarted mid-run its counters start from 0 and are ignored until they pass the old values. The end-of-run `ai-brain.json` is then the figure for the second process only. A fleet restart is not part of any planned run.
- **Not in this unit** (named in §14.4 as code follow-ups of other units): R1 `--blank-ok` wherever a script runs the hook check as a gate (not touched here; I ran the check with the flag), R8 `serve.mjs` (`minds/late/` immutable), R10 the release job and AC8's as-of-bell cap. Item 5 of the task (waitCursor and watcher wake delivery) needed no work here, as stated.
- Nothing was started that is still running: llama-server (41901) stopped; no stack, no registrar process, no listener of this unit on 41900 to 41999 (the listeners on 41994 to 41996 at the time of the check belong to other units).
