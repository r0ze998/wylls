### 3.2 Memory probe (the numbers and what they do not show)

- **Eligible prompts: N = 3 of the 14 stored bodies** (a `threat` line in the MEMORY block each: `40bfe3dc` bell 64 AI 1004, `adf2b577` bell 52 AI 1005, `f8812bf4` bell 64 AI 1003). The classification of a Remembered line is by the code templates (`templates.en.json`); a test checks it against the stored episodes of all five fixture bodies.
- **Dry run:** 9 calls planned (3 prompts x rerun, ablated, control), every variant built and checked (the prompt differs from the stored one only by the removed lines, the marker line and the edited `see` segments; model, seed, sampling and the schema outside `mem` are byte-equal), 0 calls.
- **Live set run (9 calls):** the wording the probe is allowed to print: "when the Remembered lines were removed from 3 logged prompts, the chosen candidate changed in 0 (rerun: 0; control: 1)". In detail: all three **reruns reproduced the stored output byte for byte** (sha256 equal to the record's `output_hash`; so this is also 3 of 3 on the replay of an M9-style sample on this Mac under load 5.5 to 6.5). The all-lines ablation changed the chosen candidate set in 0 of 3 (the params changed in 1: a `c7` parameter appeared in `40bfe3dc`). The control (an equal number of tokens removed from lines the decision did not cite and that are not key episodes) changed it in 1 of 3 (`40bfe3dc`: `c3,c6` became `c3,c5` after four `build_done` lines were removed). The control removed fewer tokens than the ablation in all three (128 against 271, 128 against 180, 154 against 312) because only 4 of the lines qualified; the deficit is printed per prompt, and the token counts are llama `/tokenize` counts.
- **Featured decision `40bfe3dc` (one-decision mode, 5 calls):** all-lines ablation: chosen set unchanged ("with the Remembered lines removed, the choice did not change"). Removing only M4 (the `clash_own_win` line): changed (`c3,c6` to `c3,c7`), caption "with this line removed, the choice changed". Removing only M5 (`camp_cleared_own`): unchanged. Rerun unchanged, **control changed**. Reading: a change on removing one line is not attributable to that line, because removing four unrelated lines changed it too. The decision cited M4 and M5.
- What these numbers do not show: that memory changed behaviour, improves play or that the model wants anything; any rate; anything about a decision that cited a key-kind episode (none in this run did).

## 4. Deviations from the contract (each also in `deviations`)

1. **Arm B's council replay is a loopback proxy in front of llama-server (`ab/replay.mjs`), not a hook in the mind.** The contract puts "the mind answers ... with arm A's stored answer" under AC9's row, but `mind/api.mjs` is AC1a's file and the row does not name it. The proxy answers a motion or ballot job of nation 0 with arm A's option and speech when `options_hash` is equal (matched by the AI's name in the system prompt, the schema name and the options listed in the prompt) and forwards everything else; the mind still runs its whole pipeline on the replayed text. Consequences: arm B's config differs from arm A's by `replay_council_from` and `llm.url` (its sha256 differs); a replayed record is a `model` record whose request body was never sent to llama (an M9 replay of that one record cannot reproduce it; the A/B arms are not audit claims); `council_replayed` is counted by the proxy and written to `AI_DIR/ab/replay-B-<rep>.json`, which `run-ab.mjs` reads. A hook inside the mind would be about 15 lines and is the integrator's choice.
2. **G11 uses 10 fixture situations, not the spike's 10 citizens** (`LAB/agent/cases.json`): turning those states into the mind's candidate menu needs the Rust candidate generator over the lab's herald cache. The fixture situations have the same shape (7 depart, 3 economy, one with no host, nations cycled) and are edits of the recorded wire request. The result says so (`does_not_show`). The persona swap changes the persona block of the system prompt, the goal list of the MEMORY block and the `serves Gn` tags (a test shows the rest is byte-equal).
3. **Y is reported twice.** `y_strict` is the contract's (opened and clash). `y_clash_without_opening` is a different, labelled number computed from the private record and the public `clash_own_*` episodes (the episode stands in for the clash report row with `engaged: true`, which needs the herald). A report never rounds either up.
4. **Report definitions I had to pick:** a reflection that the validator refused is listed on its own line and is not in the valid-choice rate (integ-A-NOTES section 14 asked this unit to filter them); a model decision is a record of kind session, reaction, motion or ballot whose reason is not `no_time`; a session whose model answer survived V3 but sent nothing counts as `v6_all_refused`; gate-open is every record whose reason is not `below_gate`, `budget`, `season_end` or `not_ready` (reflection jobs excluded).
5. **Probe definitions:** "the chosen candidate changed" is the sorted list of chosen ids; a params-only change is counted apart. The baseline is the stored raw output when the rerun reproduces it byte for byte, else the stored final choice, else the rerun itself (each says which). When all Remembered lines are removed the line "(nothing remembered yet)" takes their place, as the mind's renderer prints for an empty memory. The control removes whole lines, so its token count can fall short of the ablation's; the deficit is printed. In the all-lines plural the caption is "with these lines removed, the choice changed" (the contract's singular sentence is used for single-line ablations).
6. **The seat script is planning only.** `seat-script.mjs` selects the target (an open-field army of an AI of another nation that, by the stamina rule, cannot leave before the seat's army arrives), builds and validates the script file (its sha256 is what `--seat-script` commits, which also marks the seat scripted), records `AI_DIR/seat-script.json` and calls ONE injected sender. **No sender exists**: sending a march from Node means the web client's flow (`fmarch.mjs sendMarch` with the wasm kernel, the seal worker, the beacon key and the relay), which I could not verify without a stack. The move can give an `attacked_own` episode only if the target loses troops; nothing is staged.
7. **The A/B arm plan passes `--seat-script citizens/ab/seat.mjs`** so the commitments name the seat script and the roster marks the seat `scripted: true`, as 9.2 says ("scripted for the A/B test").
8. **`persona/fixture-world.mjs` is a new file in AC2's `persona/` directory** (new files only, section 0.2). It is there because `persona/g11.mjs` (named in my row) sits in a directory on the citizens service's read list, and an import of `injection/` from there pulled `injection/` into the list (a wave-A test, T-K2, failed on my first full run); the helper now lives next to it and `citizens-ac9-isolation.test.mjs` pins the rule.
9. **`PILOT {json}` line for T:** `run-ab.mjs threshold --ready K --append-runs RUNS.md` appends one line of a new kind to RUNS.md. It is off by default and the report and the A/B table ignore it; RUNS.md's format is the integrator's, who may prefer another place.
10. **`injection_corpus_sha256` is the hash of `corpus.mjs` as the registrar computes it, and the file holds the oracle as well as the cases**: a change of an oracle word list changes the commitment. This is intended (the definition of a hijack is fixed before a run). The current hash is `5626f53de1a5...` (`shasum -a 256 citizens/injection/corpus.mjs`).
