## 11. Season-end race fix (branch `frontier/ai-eosfix`, 2026-10-05)

**The failure.** smoke-r2 (14 game hours, run tree) ended with verify-minds M3 FAIL: one `anchor_gap` at bell 109, "the chain was paused". **Two causes.**

## 12. Seat eligibility fix (branch `frontier/ai-seatfix2`, 2026-10-05)

**The finding (smoke-r3, RUNTREE-NOTES 11.3).** The scripted seat ran and posted its ballot at bell 52 (option 1); the social service answered 400 `NotEligible`. The council's `eligible` list for nation 0 at C0 held only the AI, because the seat's village was still provisional (Holding STATE 1). Also: nation 0 periods 3 and 4 and nation 5 (every period) had no council and the files did not say why.

**What the program does (read, not assumed; `permutation-frontier/src/proc/holding.rs`, `frontier-abi/src/prologue.rs`).** The provisional to final flip is lazy (I-29, I-47): `finality()` applies it when state is 1, `now >= final_ts` (= round_time(S) + 600) and the ticket cohort is closed (no open record of the ticket bell, or 24 bells passed), and it runs **only inside an instruction that carries the holding's own Province**: Build **with item 6 (walls)**, Muster, Garrison, Dissolve, Explore, Depart. **Harvest does not flip it** (it carries no Province and never calls `finality()`; the task text and the contract's wording suggested it; the test `Harvest does not finalise a village` pins this against the program source). Train and the other Builds do not either. A transaction that fails reverts the flip (Garrison/Muster flip first and then refuse without a reserve, so they need a reserve and a caught-up province). The watcher's census lists a citizen as a voter only after the `HOLDING_FINAL` row is in the herald log (`owners.mjs`: `final` is set by that row), so the flip must land before the period's C0 and be in the log through C0 - 1 (`tryOpen` waits for `completeThrough >= c0 - 1`). The social store's own fallback (`finalHolding`: state 2, or state 1 with `finalTs <= unix`) is used only when no explicit list is passed; the watcher always passes one. So the AI-owned side is enough: **no change to the eligibility rule in the social store or the census was needed or made**.

**What changed (AI-owned paths only).**
