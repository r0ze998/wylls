## 2. 照合した項目と、接続での扱い

| 項目 | ⑨ | ⑩ | 接続 |

### 加工中と完了後の状態の対応

| ⑨ の予約 | ⑩ の区画・注文 | 物の所在 |
|---|---|---|
| 予約済み・投入前 | 利用注文が `QTY_LEFT` を予約（`HELD` は変わらない） | 区画（所有者 M） |
| 区画から投入（開始前） | `HELD −= q`、`CONSUMED += q`、注文の `QTY_LEFT −= q` | ⑨ のホッパー（予約の置き場。動かせるのはカーネルだけ） |
| 加工中 | 変わらない | ホッパーから消費され、出力の置き場に兵器 |
| 完了・取消・施設の喪失 | 変わらない（⑩ には区画へ戻す入口が無い） | 余った鉱石はホッパー、兵器は出力の置き場。**引き渡しは保留**（§4 D1, D2） |
| 注文の期限切れ・取消（投入の後） | 以後の投入だけが拒否される | 投入済みの分は影響なし |
| ⑩ の倉の押収（投入の前） | 区画は凍結（`Forfeited`）、投入は拒否 | ⑨ は何も変わらない |
| ⑩ の倉の押収（投入の後） | ⑩ の没収は `HELD` だけを対象にする | 投入済みの分は ⑨ 側にあり、⑨ の規則に従う |

## 3. 契約試験（`bridge10/tests/contract10.rs` 12 件、`tests/lots.rs` 6 件。すべて通過）

| 鉱石だけ | ⑩ は木材・兵器の区画を開けない |

## 5. ⑩ の adapter-09 との接続（2026-11-06）

⑩ は統合候補に、⑨ の `Custody` trait を ⑩ の区画で実装したアダプター `workstreams/10-custody/adapter-09`（`LotCustody`、commit `52a43745`、tree `f5784e40…`）を置き、⑨ への要求 R1–R6 と食い違い F1–F5 を書いた（⑩ の `08-adapter-09.ja.md`）。⑨ はこれを受けて次をした。

### 5.1 ⑨ の模擬を外した範囲

- `bridge10` の ⑨ 側の預かりを、⑨ の模擬（`MockCustody`）から **⑩ の `LotCustody`** に替えた。予約のホッパー・出力の置き場、隊商・Holding の置き場、利用者自身の区画は、⑩ の区画カーネルと口座バイト（576 B）で動く。
- 利用者**自身の区画**の鉱石は ⑩ の経路で動く：⑨ の通常の `Deposit`（`from = Vault(v)`）で区画から出し、区画が返却用の容量を予約する。余りは `ClaimSplit` で整数単位が区画へ戻り、予約はちょうど一度終わる（⑩ の `Returned` 通知と一致）。
- **他人の区画**の鉱石（利用注文）は、これまでどおり bridge の経路（⑩ の `consume`）。⑩ のアダプターに利用注文の口がまだ無いので（⑩ の R6）、利用注文の区画は bridge 側に別に持っている。**二つの区画の表を一つにするのは ⑩ の作業**（§5.4）。
- ⑨ の試験の大部分（kernel/tests）は今も ⑨ の模擬で動く。⑩ の実装は bridge10 の試験と、⑩ 自身の adapter 試験（このブランチの kernel に対して実行）で通している。

### 5.3 加工結果の記録を ⑩ と揃えた

- 予約ごとに **⑩ と同じ言葉の口座**（`Job::accounts()`：材料 2 つと成果物、`IN_TOTAL = HELD + OUT_TOTAL + CONSUMED + FORFEITED`）を持つ。返却（`returned`）と喪失による移転（`forfeited_*`）を予約に記録するようにした。
- 予約の記録を閉じるとき（`Retire`）に **`Event::Receipt`**（その口座）を出す。
- 試験：ランダム 300 通りの毎手で口座が釣り合い、ホッパー・出力の残高と一致する（kernel）。⑩ の `Consumed`・`Produced`・`Reserved` 通知の合計が受領書と一致する（bridge `the_receipt_agrees_with_10s_notes`）。

## 6. ⑩ のパッチの取り込み（2026-11-06、⑩ `79fbce83`）
