# 09 継続世界への対応（r4、2026-10-31）

**前提（オーナーの方針訂正）。** 世界は一定期間で終了・リセットしない。戦期は世界の寿命とは別で、その区切り・集計・賞金は未決定。⑪の担当は「manifest・許可・状態・返却義務を継続できるようにし、拡張自身の期限と世界の終了を混同しない」こと。共有コアの変更は④、横断設計は⑧から④へ集約するので、⑪は World／Period の正本を作らない（試験の「境界」は試験の道具で、期間の定義ではない）。

結果はすべて**ホスト上の試験**で、オンチェーンの保証ではない（[08](08-host-vs-onchain.ja.md)）。案 B、Burn、運営の停止権限は引き続き未採用。

## 1. 残っていたシーズン依存

### ⑪自身の設計（r3 まで）

| # | 依存 | 場所 | 影響 |
|---|---|---|---|
| E1 | 拡張の口座（登録・Grant・instance）を Season PDA から導いていた | [patches/0002](patches/0002-core-extension-instructions.md) の初版の表（`[season r]`、`create_with_seed(season, …)`） | 新しい Season を作ると、前の期間の拡張の状態・預かりが別の根の下に取り残される |
| E2 | ExtCall・ExtWithdraw を `player_prologue` に通していた | 同上 | 今のコアでは `bell(now) ≥ end_bell` と Running 以外を拒否（`frontier-abi/src/prologue.rs` 1056–1070、1102–1108 行）。**期間の終わりで預かりの返却が拒否される** |
| E3 | Grant・instance の鍵（`citizen`）が何を指すか書いていなかった | `host.rs`、契約 §4 | コアの Citizen 口座（`ct‖tag15(wallet)` を Season PDA の下で導く）を指すと、期間ごとに鍵が変わる |
| E4 | 検証器の証拠が「1 つの archive」を前提にしていた | `verify.rs`、契約 §6 | 終わらない世界では archive が無限に伸びる。区切って検証し、区切りの間をつなぐ方法がなかった |
| E5 | 再送の判定が他の検査の後だった | `host.rs` の検査順 | Grant の回数切れや停止の後に再送すると `SeqMismatch` でなく `GrantCalls`／`Paused` になり、④の Run が「完了済み」を判別できない（`c06` で発見） |

**依存していなかったもの（確認）:** 拡張の時刻は絶対時刻（`now_ts`）と `now_ts / 600` だけで、コアの鐘（Season の `genesis_ts` から数える u32）は使っていない。Grant の期限（`expires_ts`）は拡張自身の期限で、期間とは無関係。登録の履歴、seq、receipt の鎖は期間の区切りを持たない。

## 2. 変更した挙動（`ext-kernel`）

| # | 変更 | 試験 |
|---|---|---|
| B1 | 拡張の状態・Grant・預かり・receipt は、所有者の**変わらない識別**で引くと明記（`host.rs`）。Holding は所有者で探すので、作り直された Holding にも返せる | `c03` |
| B2 | 出口（ExtWithdraw）の条件は拡張自身の規則（停止・Grant の終了・コアの版の変更）だけ。世界の時計・期間の状態では閉じない。返却義務に期限はなく、返却先の Holding が無い間は預かりのまま待つ | `c02`、`c04`（30 年後に返却） |
| B3 | 拡張自身の期限（Grant の `expires_ts`）は境界で変わらず、境界をまたいで有効、期限でだけ終わる | `c05` |
| B4 | 古い seq の呼出し（再送）は、何より先に `SeqMismatch`。停止・Grant の終了・規則の変更の後でも同じ答えで、鎖の先頭で完了を判別できる | `c06` |
| B5 | `verify_windows`: 証拠を区切り（窓）ごとに検証し、各窓が前の窓の終わりから始まることを照合（食い違いは FAIL `WindowGap`、終わりが無ければ UNVERIFIABLE、前の窓に無い Holding はコアの領分として UNVERIFIABLE） | `c01`–`c03`、`g01` |
| B6 | パッチ 0002 を改訂: 拡張の口座の根を期間で変わらない根（④が決める）に、ExtWithdraw を期間の状態で拒否しない、絶対時刻だけを使う | [patches/0002](patches/0002-core-extension-instructions.md) 冒頭 |

## 3. 試験で確認したこと（ホスト、`tests/continuity.rs`、`tests/long_run.rs`）

**境界の通過（固定した短い期間、試験用の境界）**

| 境界の種類 | 確認したこと | 試験 |
|---|---|---|
| 何も変わらない | 誓いを境界の前に、返却を後に。同じ instance・鎖・Grant・預かり。費用（Grant の予算）は 1 回だけ数えた（30,000→22,000、回数 10→8）。境界の前後 2 窓と全体で検証 PASS | `c01` |
| 規則が変わる | 呼出しは `CoreVersion`、出口が開き（理由 3）、全量が戻り、2 度目は `InstanceClosed`。各窓はそれぞれの規則で検証 PASS | `c02` |
| Holding が別アドレスで作り直される | 古いアドレスへの返却は `NotOwner`、新しいアドレスへは返る。B の木材の合計は不変。境界の作り直しは UNVERIFIABLE（コアの領分）で、PASS にも FAIL にもしない | `c03` |
| Holding が一時的に無い | 預かりは残り、30 年後に新しい Holding へ返る（Grant の期限切れで出口が開く） | `c04` |
| 拡張自身の期限 | 境界は Grant と登録の履歴を変えない。期限の 1 秒前まで使え、期限で終わる | `c05` |
| 再起動 | 40 回の呼出しのうち 14 回で、記録の後に再起動し同じ呼出しを再送。すべて `SeqMismatch` で 1 回だけ適用、記録数＝seq＝受理数、予算の消費も 1 回ずつ、全体の検証 PASS。Grant の取消・停止の後の再送も `SeqMismatch` | `c06` |

**長期運用（境界とは別に）**

| 確認したこと | 試験 |
|---|---|
| 20,000 回の呼出し（約 140 日）。所有者ごとの状態は固定長（欄 4、預かり 8）のまま。増えるのは記録だけで、登録の履歴と Grant の更新は変更のときだけ増える。2,000 件ずつ 10 窓に区切ってつないだ検証が PASS（ホストで呼出し 0.08 秒、検証 0.03 秒） | `g01` |
| 数の上限（例の「名声」1,000）に達すると fulfil は返却ごと拒否されるが、所有者が Grant を終えれば出口で全量が戻る。上限は拡張自身の寿命で、世界の寿命ではない | `g02` |
| 西暦 3000 年、`i64::MAX / 4` の時刻でも通常どおり動く。seq が `u64::MAX` なら `Overflow`、欄の宣言した範囲を超える時刻なら `FieldBounds` で、どちらも何も書かない（折り返さない） | `g03` |
| 2,001 人が使おうとしても、状態は manifest が宣言した 2,000 人分で止まる（2,001 人目は `InstanceCap`） | `g04` |

## 4. 移行や仕様判断が残る点

| # | 残る点 | 誰の判断 |
|---|---|---|
| M1 | 拡張の口座の根（Season PDA に代わる、期間で変わらない根）と、所有者の変わらない識別とコアの Citizen・Holding との対応 | ④（⑧の横断設計） |
| M2 | ExtWithdraw の返却先。今は「所有者のどれかの Holding」。Holding が閉じられる・無い間の受け皿を⑩の「所有者別の引出し義務」と同じにするか | ⑩・④（⑩の実物を照合してから） |
| M3 | 期間の切替で規則の版（`program_version`・`ruleset_hash`）を変えるか。変えるなら全拡張が止まり出口が開く（`c02`）。変えないなら拡張はそのまま動く。規則の版と期間を別の番号にするのが⑪の推奨 | ④ |
| M4 | 既存の Season 下の口座からの移行（読取り・旧版の再検証・未完了の処理）。拡張は本番に無いので⑪に既存データは無いが、パッチ 0002 の初版の形（Season 根）で作らないこと | ④ |
| M5 | 検証の窓の区切り方と、窓ごとの archive の保管。⑪の `verify_windows` は区切りを外から受け取るだけ | ④・⑧ |
| M6 | instance を閉じて rent を戻す命令と、`max_instances` を「生きている数」で数えるか（長期では作られた数が上限に張り付く） | ⑪の設計（案 B 採用後） |
| M7 | 再生検証器（パッチ 0001・0003 の対象）自体が 1 シーズンの archive を前提にしている（K4） | ④ |
