# 0004 コアで範囲を絞った委任（②と共同で決める要求。実装しない）

courier の仮アダプター（[04](../04-interface-contract.ja.md) §4）で、「所有者のオンライン署名なしで動く」こと自体は今のコアの session 鍵で成り立った（`t12`）。しかし「限定」はコアの保証ではない。②の Grant を設計する時の入力として、③から見えた要求だけを並べる。

1. **命令の範囲。** session は「session 可」の全命令を行使できる。委任先が外部プログラムの PDA の場合、そのプログラムのアップグレード権限者が範囲を広げられる。命令（タグ）ごと、資源・量ごと、回数・期限ごとの範囲をコアが持つ必要がある。
2. **複数の委任先。** session の枠は Citizen に1つで、relay のエージェント財布と外部プログラムが取り合う。
3. **意図の束縛。** 委任先が出発元・宛先・経路を自由に選べる。所有者が宛先などを固定できる形が要るか、②で決める。
4. **他人への受け渡し。** session は他人宛の送付ができない（`WalletRequired`、計画 §1-11 の意図的な規則）。委任で他人に渡せるようにするなら、この規則の扱いを②と決める。
5. **取消の即時性。** 今は所有者の SetSession が取消の本体。委任口座を閉じても session は残る。
6. **CPI との関係。** コアが委任を検査する場合、委任先の署名は CPI の `invoke_signed`（PDA）で来る。コアは署名者が PDA かどうかを区別しない（区別する必要もない）が、どのプログラムの PDA かを委任に記録すれば、範囲の検査に使える。
