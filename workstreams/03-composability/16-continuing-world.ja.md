# 16 継続する世界への対応（③：MCP 接続、本人確認、操作履歴）

作業日 2026-10-31。ブランチ `ws03/runreceipt-port`（ローカルだけ）。

方針の訂正を受けて：世界は期間で終わらない。戦期は世界の寿命とは別。「シーズン終了 → 賞金受取」を完成形とする前提はとらない。

③の担当は、MCP の接続・本人確認・操作履歴を世界の継続に対応させること。

- 共有コア（program、abi、relay、gateway、herald）は変えていない。依存の一覧は④（統合）と⑧（継続世界の横断設計）に渡す。
- ③は World／Period の正本を作らない。③が持つのは「relay が今どの文脈を出しているか」の観測だけである。
- 本番の移行は実行していない。

## 1. 残っていたシーズン依存

### 1.1 ③の中（直した）

| # | 依存 | 何が起きたか | 直した挙動（§2） |
|---|---|---|---|
| S1 | `Game.season()` が relay の `/f/season` を**プロセスの一生で一度だけ**読み、program と season id、アドレス、herald の照合を固定していた | 長く動くサーバーは、文脈が変わっても古い文脈のアドレスで読み続ける。herald の照合が合わず `WrongSeason` で止まる。再起動で直っても、古い操作のカーソルを新しい索引に当てる | 文脈を一定の間隔（既定 15 秒）で読み直し、変化を記録する |
| S2 | 計画が、作った時の文脈を持たない | 文脈が変わった後に古い計画（古いアドレスの caravan 番号）を送りうる | 計画に文脈を記録する。違えば `PlanStale` |
| S3 | 操作の再送（同じ requestId）が文脈を見ない | 結果不明の操作を、新しい文脈で古い計画の口座のまま試しうる | 文脈が違えば新しい試行をしない（§2） |
| S4 | 操作の追跡が、herald の索引の番号（カーソル）と caravan の番号を文脈なしで使う | 新しい文脈の索引に、古い操作のカーソルを当てる | 文脈が違えば記録を読まない。保留 `ContextChanged` |
| S5 | 操作の履歴を、毎回すべて書き直す 1 つのファイルに持つ | 世界が終わらないと履歴が増え続ける。5 万件で 1 回の保存が 1.5〜2.7 秒（実測）。保存は呼び出しのたびに起きる | 終わった操作を追記だけの保存庫へ移す（§2） |

### 1.3 ③で season に依存しないと確かめたもの

| もの | 根拠 |
|---|---|
| 所有者の本人確認（ウォレットの署名）、接続（link）、トークンの期限 | season を含まない。トークンと接続の期限は有限のまま（永久化しない） |
| 所有者の署名つき照会（`/owner`） | 署名する文は `aud`（この MCP）、所有者、時刻だけ |
| 自分の要求の証明（自分の署名） | 署名はチェーン全体で一意。文脈をまたいでも、他人の記録を自分の物と取り違えない |
| 接続の上限（② MOCK） | 期限は接続の期限。世界の寿命とは別 |

## 2. 変更した挙動

1. **文脈の観測**（`game.mjs` `context()`）
   - relay の `/f/season` を、既定 15 秒ごとに読み直す。
   - 変われば herald の照合を新しい文脈に合わせ、以前の文脈を `contextChanges` に記録する。
   - `get_connection` が、今の文脈と変化の記録を返す。
2. **計画と操作に文脈を記録**
   - `plan.context` と `op.context`（`programId:seasonId`）を持つ。
   - 受領証に `context` と `contextRecorded` を出す。この版より前の操作は `contextRecorded: false` とし、今の文脈のものと仮定しない。
3. **文脈が違う時**
   - 古い計画は送らない（`PlanStale`）。
   - 結果不明の操作の再送は、新しい試行をしない。試行が 0 なら、何も送っていないので `ContextChanged` で失敗にする。試行があれば保留 `ContextChanged` にし、予約は数えたまま。
   - 追跡は自分の署名（着地・finalized での失敗・証明された不在）だけで決める。herald の記録は読まず、保留 `ContextChanged`。
   - **その文脈がまた出されたら、追跡は続きから進む。**
4. **履歴の保存庫**（`store.mjs`）
   - 終わった操作は、終わってから 1 時間（`archiveAfterMs`）後に、`<store>.archive.jsonl` へ移る。追記だけで、書き直さず、消さない。
   - 移す時は、行を書いて fsync してから、本体から外す。途中で落ちて両方にあれば、本体の写しを読む。途中で切れた最後の行は読み飛ばす。
   - id、requestId、一覧、所有者の照会で、移した後も同じ物が読める。同じ requestId の再送は記録の再生のまま（新しい送信をしない）。
   - 終わっていない操作（保留、予約、追跡中）は移さない。

## 3. 試験で確認したこと（2026-10-31）

### 3.1 期間の境界をまたぐ（模擬：relay と herald が別の文脈に切り替わる）

`test/context.test.mjs`。境界の前に、隊商の 3 つの状態を作った：

- A：送って着地し、道中
- B：relay に届かず、結果不明
- C：計画だけ

境界の後：

| 確かめたこと | 結果 |
|---|---|
| 接続は続き、今の文脈と以前の文脈を返す | 通過 |
| 接続の上限は境界の前と同じ | 通過 |
| 所有者の村は、新しい文脈では古い文脈の物として読まない（`WrongKey` で読めない） | 通過 |
| C は送られない | 通過 |
| B の再送は新しい試行をせず、保留 `ContextChanged` | 通過 |
| A は、古い文脈の settle の記録が出ても、新しい文脈では読まず保留（完了にしない） | 通過 |
| チェーンへの送信の数は、境界の前と同じ | 通過 |
| 履歴（一覧）はすべて残る | 通過 |
| **同じ保存ファイルで再起動**した後も同じ。所有者の署名つき照会で、両方の操作の文脈が読める | 通過 |
| A の文脈がまた出されると、A は settle を読んで完了する。2 回目の送信は無い。上限の合計（使用 + 予約）は境界の前と同じで、何も返していない | 通過 |
| 文脈を記録していない古い操作は `contextRecorded: false` | 通過 |

**この模擬は、season の切替を「移行」の代わりに使っている。** 加工、預かり、封印進軍の境界は③の担当外で、試していない（⑨⑩⑱、⑯の通し試験）。
