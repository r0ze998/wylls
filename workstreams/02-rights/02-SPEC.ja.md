# ② 最小仕様と脅威モデル：工房の利用権（WorkshopUse）

**状態：** 採用待ちの提案。共有仕様として既成事実にしない。数字は例。

## 1. 目的と一行の定義

所有権も秘密鍵も渡さずに、「**この工房を、あなたの材料で、合計 N 個まで・M 回まで・期限 T まで使ってよい**」と許可できるようにする。UI・MCP・relay を通らずにチェーンへ直接送っても、許可の範囲を超えられないこと。

最初に開く権利は **1種類だけ**：工房の利用権（WorkshopUse）。倉の受け取り・持ち分・代理の札は対象外。

## 2. 定義

| 項目 | 定義（v0） |
|---|---|
| **対象施設** | 発行者の村（Holding）1つ。工房が1つ以上あること（`production[ARMS] ≥ WORKSHOP_DELTA`）。**鍵と世代（`GEN`）と所有者**で固定する |
| **発行者** | 対象施設の所有者の Citizen。発行には**財布の署名**が要る（セッション鍵は `WalletRequired`） |
| **利用者** | 別の Citizen 1人。国は問わない。**国籍だけでは、他人の施設も資源も使えない**（①の国の方針とは独立） |
| **入力資源の所有者** | 利用者 |
| **入力資源の所在** | 利用者の村（「受取口」= station）。**対象施設と同じ州（Province）**にあること。遠くの材料は、先に自分の隊商で運ぶ |
| **出力の所有者・受取先** | 利用者。出力は同じ受取口の村に入る |
| **変換** | 武具1 = 鉱石 `ORE_PER_ARM`（2）＋ 木材 `WOOD_PER_ARM`（1）。工房の規則と同じ比 |
| **回数** | `max_uses`：消費した予約の数の上限 |
| **数量** | `max_units`：消費した武具の合計の上限。1回の予約は 1〜10,000 |
| **期限** | `expires_ts`：発行から最大30日（セッション鍵と同じ） |
| **予約** | ReserveUse：入力（受取口から）と出力（施設の倉から）を、権利アカウントに預かる。同時に開ける予約は1つ。全部か、何もしないか |
| **消費** | ConsumeUse：預かった武具を受取口へ、鉱石・木材を施設へ。**確定し、返らない** |
| **解放** | ReleaseUse：開いている予約を、両側とも元へ戻す。利用者はいつでも。期限切れ、または施設・受取口の世代が変わった後は誰でも |
| **失効（取消）** | RevokeGrant：発行者（財布またはセッション）。開いている予約は解放と同じく戻す。未使用の枠は消える。消費済みは戻らない |
| **期限切れ** | 新しい予約も消費もできない。開いている予約は誰でも解放できる |
| **施設の世代** | 施設または受取口の `GEN` か所有者が発行時と違えば、その権利は使えない（`StaleHolding`）。占領が決着前なら待つ（`CapturePending`） |
| **後始末** | CloseGrant：予約がなく、使えなくなった（取消・期限切れ・枠切れ）権利の賃料を、発行時の支払い者へ返す |

### 2.1 容量（なぜ「交換」なのか）

工房の生産は連続で、施設の倉の材料を自動で変換する（`01-AUDIT.ja.md` §4）。利用権は、**施設の倉にすでにある武具**を出し、同じ量の材料を施設の倉へ入れる。

- 施設が作っていない武具は出ない。発行者が自分に権利を出しても（別アカウント）、生産量は増えない。
- 施設の倉に入った材料は、その後の工房の連続生産の材料になる。
- 発行者は、武具を自分で使えば利用者の予約を失敗させられる（`Insufficient`）。**予約した後は**、預かった分は守られる。発行者が取り消せば、その分は戻る。

この方式は**提案**。施設の容量を利用者ごとに割り当てる方式は `04-PROPOSALS.ja.md` §2。

## 3. 不変条件（実装とテストで確かめたもの）

1. **鍵：** 発行者の財布は発行だけに使う。利用・解放は利用者自身の鍵（財布か、利用者が SetSession で指名したセッション）。発行者の鍵も、発行者のセッションも、利用には使えない。
2. **範囲：** 消費した武具の合計 ≤ `max_units`。消費した回数 ≤ `max_uses`。どの予約・消費も `now < expires_ts`、状態は Active。
3. **固定：** 施設と受取口は、権利に記録した鍵・世代・所有者・生きている村と一致する。同じ州アカウントの占領ロックも確認する。
4. **保存：** 予約は、受取口の鉱石・木材と施設の武具を、同じ量だけ権利の預かりへ移す。消費は、預かりを相手側へ移す。解放と取消は、預かりを元の場所へ戻す。施設＋受取口＋預かりの合計は、各資源で変わらない。例外は、戻し先の村がもう存在しない場合だけ（§4 の T10）。
5. **原子性：** 片側が足りなければ何も動かない。
6. **偽造：** 権利アカウントは、このプログラムが所有し、大きさと magic が合い、季節の id が合い、**自分の欄（発行者の tag・nonce）から再計算した、季節 PDA の with-seed アドレス**にあるものだけを受け入れる。
7. **所有者の活動ではない：** 利用者の操作は、施設の `LAST_OWNER_ACTION` を更新しない。不在の所有者の村を、他人が起こしておくことはできない。

## 4. 脅威モデル

| # | 攻撃 | 防ぎ方 | テスト |
|---|---|---|---|
| T1 | 許可のない者が施設を使う | 使う口は権利経由だけ。権利がなければ `BadGrant`。施設の所有者でない者は発行できない（`NotOwner`） | `no_grant_no_use` |
| T2 | 同じ国の人が、国籍を理由に使う | 国は検査に入らない。`grantee` の一致だけ | `no_grant_no_use`（C は A と同じ国） |
| T3 | 別人が、利用者の Citizen を名指しして直接送る | 前処理が actor を利用者の財布かセッションに限る（`Auth`） | `another_person_cannot_use_it`, `signers_and_flags_…` |
| T4 | 発行者のセッション（代理 AI）が勝手に権利を出す | 発行は財布だけ（`WalletRequired`） | `issuing_needs_the_issuers_wallet…` |
| T5 | 別の施設・別の受取口・別の州をすり替える | 権利に記録した鍵と照合（`BadGrant`）、州は正規アドレス（`BadAddress`） | `another_facility_or_station_is_refused` |
| T6 | 別季節の権利を使い回す | アドレスは季節 PDA から導出し、中の季節 id も照合 | `another_season_is_refused`（id だけが違う場合も） |
| T7 | 偽の権利アカウント（他プログラム所有、別アドレス、別種のアカウント、上限を書き換えた複製） | 所有者・大きさ・magic・再計算アドレス | `forged_grant_accounts_are_refused` |
| T8 | 期限切れ・取消済みの利用 | `Expired` / `Revoked` | `expired_…`, `revoked_grant_is_refused` |
| T9 | 上限超過、二重消費、同時要求で上限を超える | 枠の検査、予約は同時に1つ、権利アカウントへの書込みロックで直列化 | `quota_is_enforced`, `double_use_is_refused`, `concurrent_requests_…` |
| T10 | 占領後に古い権利で使う／預かりを奪う | 世代と所有者を固定（`StaleHolding`）。決着前は `CapturePending`。預かりは**元の場所へ、今の持ち主のもとへ**戻る（設計 20 §5〔採用済み〕：奪われた倉の中身は奪った側のもの）。戻し先の村が消えていれば失われる | `stale_facility_generation_…`, `generation_and_owner_are_each_pinned`, `a_station_that_is_gone_…` |
| T11 | 利用者が施設の武具を予約したまま抱え込む | 発行者はいつでも取り消せる。取消で預かりは戻る | `revoking_after_a_reservation_…` |
| T12 | 権利で、不在の所有者の村を起こしておく | Grant 命令は `touch_owner` しない | `legitimate_use_…`（`LAST_OWNER_ACTION` 不変） |
| T13 | 自分宛ての権利で生産を増やす（Sybil） | 出力は施設の倉にある武具だけ（§2.1） | 構造上の性質（数式）。専用テストなし |
| T14 | UI・MCP・relay の迂回 | すべての検査がプログラム内にある。テストは relay も UI も通さず、`dispatch` を直接呼ぶ | 全テスト |
| T15 | 解放の悪用（他人の予約を早く崩す） | 期限前で世代も正しい間は、利用者以外は `NotGrantee` | `another_person_cannot_use_it` |
| T16 | 賃料の横取り | CloseGrant の送り先は、記録した `RENT_TO` だけ | `close_returns_rent_…` |

**範囲外（このモデルで扱わないもの）：** 利用者の財布やセッション鍵そのものの漏洩（チェーン上ではその本人と区別できない）、運営による relay の検閲、プログラムの upgrade 権限、検証器・herald が権利の操作を記録できないこと（`03-CONTRACT.ja.md` §8 の前提条件）。
