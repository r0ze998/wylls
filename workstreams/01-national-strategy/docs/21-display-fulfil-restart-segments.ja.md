## 21-1. 到着量の言い方（④ HANDOFF §2、CONTRACTS §8.1 に合わせた）

| 実際の到着量の状態 | ④ | 画面（到着の表の「到着量」） | 数えた量（別の欄） |
|---|---|---|---|
| n と分かる | Recorded・RuleDerived、`delivered: Some(n)` | 「届いた 木材 196」 | n（受取人・時刻も確かめたとき） |
| 分からない | Unverifiable、`delivered: None` | 「到着したが、入った量を確認できない（最大 木材 200）」。最大は記録の cargo（上限）。上限が無ければ「最大」を出さない | 「算入 0（…）」。**「0 個」「全損」「失敗」「届いた」「一部届いた」とは言わない** |
| 0 と分かる | KnownZero、`delivered: Some(0)` | 「届かなかった（理由）」：行き先がない・村の世代が変わった／依頼の届け先とは別の場所に確定した／襲撃で奪われた／襲撃で焼かれた | 算入 0 |
| 輸送中 | — | 「輸送中 木材 200」（送った荷が分かれば） | — |

共同の目的の欄の「届いたが量を証明できない隊商」は、④の禁じる言い方（量の分からない到着を「届いた」）だったので「到着したが数えられない隊商（入った量を確認できない・受取人や時刻が未検証）」に直した。場所：`coop/ws04.mjs` `deliveredText`、`coop/coop-ui.mjs`。

## 21-2. Fulfilled と Partial（19章 D4 を解いた）

二つを分けて出す。

| 単位 | 比べるもの | 結果 | 場所 |
|---|---|---|---|
| 隊商ごと（④の run と同じ） | 検証した量 と 送った荷（チェーンの最初の CARAVAN_SENT の cargo、整数単位、依頼の資源）。④ `executor.rs` の `res_ge(c, ship.cargo)` と同じ | 以上 Fulfilled、少ない Partial（途中の塔で減った等）、全部 0 Failed、量が分からない DeliveredUnverified、失われた・奪われた等 Failed、輸送中 InTransit。**送った荷が分からなければ `Delivered`**（Fulfilled とも Partial とも決めない） | `toWs04Terminal(a, shipped)`、到着の表の「④の終わり」 |
| 依頼ごと（①の依頼は複数の隊商で満たしうる） | 依頼に割り当てた到着の数えた量（算入量）の資源ごとの合計 と 依頼の need | fulfilled（どの資源も依頼量以上）／partial（0 より多いが足りない）／unverified（数えた量 0 で、到着したが数えられないものがある。0・失敗と言わない）／pending（数えた量 0 で、輸送中・不明がある）／failed（すべて終わり、すべて 0 と分かる）／none | `fulfilmentOf(q, arrivals)`、依頼の行の「依頼の充足」 |

依頼量を超えた分は依頼で切らない（共同の目的は資源ごとの合計で判定する。変えていない）。

## 21-3. 再起動の後の結果不明の送信

前からあったもの：`sending` の記録は残り、結果が分からない間は同じ依頼への次の送付を断る（20章、9-3h）。

**今回ふさいだ穴：** 送信が着地した後、結び付け（link）の前に画面を閉じた・板が再起動した場合、前は「着地」で止める条件が解け、同じ依頼にもう一度送れた（同じ物を二度送る）。いまは **着地したのに結び付けていない送信** も次の送付を止め、画面は「着地した隊商 #n をこの依頼に結び付ける」を出す（押すと結び付けの記録に署名して出す）。結び付ければ解ける。文脈の違う同じ番号の結び付けでは解けない。

場所：`coop/pending.mjs` `pendingSendOf`（板の `submitOne` と画面の両方が使う）。

残る前提：チェーンを読まない板（`--rpc` なし）では結果がいつまでも「分からない」なので、送付は止まったまま（安全側）。

## 21-4. 記録の区間（20章 M5 の①の側）

| ファイル | 中身 |
|---|---|
| `records.jsonl` | 今書いている区間（追記だけ） |
| `records.000001.jsonl` … | 閉じた区間。閉じる時は**名前を変えるだけ**（中身のバイト列は変えない）で、読むだけ（0444） |
| `segments.json` | 閉じた区間の一覧：ファイル名・SHA256・バイト数・記録の数・受け取った時刻の最初と最後 |

- 今の区間が `--segment-mb`（既定 64 MB［仮］、約 20 万件）以上になったら、追記の直後に閉じる。書きかけの最後の行があれば閉じない。
- 名前を変えた後・一覧を書く前に止まったら、次に開いた時に一覧に無い区間を見つけ、SHA256 を計って一覧に足す（中身は変えない）。
- 読み直しは区間の番号の順、その後に今の区間。一覧と SHA256 が合わない区間・消えた区間は `problems` として画面に赤で出す（黙って捨てない。読み込みは続ける）。
- 旧い板のフォルダ（`--legacy-data`）も同じ読み方で、何も書かない。
- 板の記録の形・畳み込みは変えていない。

場所：`coop/store.mjs`、`coop/board.mjs`。④と合わせること：区間の大きさ、閉じた区間を別の場所へ写すか、SHA256 の一覧をどこに残すか（21-7）。
