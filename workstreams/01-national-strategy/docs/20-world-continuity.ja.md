# 20. 世界の継続：①の依頼・共同達成・進捗をシーズンの終わりに依存させない

**状態（2026-10-31）：** ブランチ `ws/01-coop-s1`。2026-10-31 の方針（シーズン制の廃止、世界は続く、戦期は世界の寿命と別）に合わせた①の部分。**本番の移行は行っていない。** 共有コアの変更はしていない（④へ渡すもの・④⑧が決めるものは 20-4）。①は独自の World／Period の正本を作らない：チェーンの文脈（`programId`・シーズン ID の組）は、④⑧が決める共通の識別子が来るまで、今のシーズン ID をそのまま「口座を確かめる文脈」として使う。

## 20-1. 残っていたシーズン依存

### ①の中（直した）

| 箇所 | 依存 | 何が起きたか |
|---|---|---|
| `coop/record.mjs` `fold` | 板の一つのシーズン以外の記録を「別のシーズンの記録」として断る | シーズンが変わると、前の依頼・応答・結び付けがすべて断られ、共同の目的の進捗が消える |
| `coop/board.mjs` 記録のフォルダ | 既定が `.local/ws01-coop/<program>-<season>` | 新しいシーズンでは空の板になる（前の記録は別のフォルダに置き去り） |
| 隊商の鍵（`record.mjs`・`arrival.mjs`・`goal.mjs`・板のキャッシュ） | `ownerTag:seq` だけ。Citizen はシーズンごとの口座で、隊商の番号もその Citizen ごとに 0 から | 文脈をまたぐと、別の隊商を同じ隊商とみなして結び付けを断る・割り当てを取り違える恐れ |
| 確かめ（`board.mjs` の `checks`・結び付け・送信の結果） | 板の一つのシーズンの口座で確かめる | 前のシーズンの依頼の隊商・村・国を、間違った文脈の住所で読む |
| 輸送中の表示 | ヘラルドの一覧（ヘラルドはシーズンごと） | 前のシーズンの隊商は「不明」になる |
| 板の状態 | 表示・受け取りのたびに記録を全部畳み込み直す | 世界が続くほど遅くなる（記録 2 万件で受け取り1件に約 0.5 秒） |

依頼の期限（`expiresAt`、最長 30 日）は依頼ごとの期限で、世界の期限ではない（変えていない）。判定（仮A・仮B）・共同の目的・国と個人の表示に、シーズンの終わりを条件にしたものはなかった。

### ①が使う S1 の経路（共有コア：④⑧へ。①は変えていない）

| 依存 | 根拠（基準 `4cd901de`） | ①への影響 |
|---|---|---|
| すべての口座の住所がシーズンの PDA から作られる（Citizen・Holding・Caravan・Vault） | `frontier-abi/src/addr.rs`（`citizen_seed`、`AddrCtx::of`）、`permutation-server/web/frontier/faddr.mjs` 冒頭 | 新しいシーズンでは、同じウォレットでも別の Citizen・村・隊商。前の依頼の届け先の村は、新しい文脈では別の口座 |
| 参加（Join）はシーズンに1回、国はその Citizen の `FACTION` | `proc/citizen.rs`（Join） | 国籍は文脈ごと |
| プレイヤーの命令（SendCaravan を含む）は `RUNNING` だけ | `frontier-abi/src/prologue.rs` `player_prologue`（1102〜1107 行、`STATUS_RUNNING`） | シーズンが ENDED になると、前の文脈の依頼に新しい隊商を送れない |
| EndSeason は `end_bell` で `ENDED` にする | `proc/season.rs:625-659` | — |
| 隊商の確定・襲撃の決着は `RUNNING` と `ENDED` で受ける | `proc/caravan.rs:927`（SettleCaravan）、`:1474` | 終わりの前に送った隊商は、終わりの後も確定する（①はこれを数える：20-3） |
| CloseSeason は口座を閉じ、Season を 128 B の墓標にする。残った Holding・Citizen も閉じる | `proc/season.rs:940-1104`（コメント：「Holdings and Citizens left open … still close on the tombstone」） | 閉じた後は、前の文脈の村（到着時の受取人）・Citizen（国籍）を口座から確かめられない。取引の記録（ログ）は台帳に残るが、RPC の保存期間に依存する |
| ヘラルド・規則の版はシーズンごと | ヘラルドの `--season`、Season の `RULESET_HASH` | ①は文脈ごとに規則の版を確かめる |

## 20-2. 変更した挙動

| 変更 | 場所 |
|---|---|
| **複数の文脈を読む。** 板は「今の文脈」と「前の文脈」（`--previous <program>:<season>`）の記録を読み続ける。一覧に無い文脈の記録だけを断る | `record.mjs` `createFolder`、`board.mjs` |
| **依頼は文脈が変わっても閉じない。** 前の文脈の依頼は、自分の期限まで開いたまま。新しい依頼は今の文脈で出す（受け取る時だけの規則。保存した記録の読み直しでは断らない） | `record.mjs` |
| **依頼に続く記録は依頼と同じ文脈で確かめる。** 応答・取り下げ・取消・送信・結び付けを別の文脈で出すと断る。隊商・村・国・規則の版は、依頼の文脈の口座で確かめる（旧版の証拠を新版の証拠に読み替えない） | `record.mjs`、`board.mjs` `checks`・`submitOne`・`sendingStatus`、`goal.mjs` `coopView` |
| **隊商の鍵に文脈を含める。** 重複の割り当て・結び付けの重複防止・キャッシュ・観測の鍵 | `arrival.mjs` `caravanKeyOf`、`record.mjs` |
| **共同の目的は依頼した人ごとに文脈をまたいで続く。** 前の文脈の依頼に届いた量と、新しい文脈の依頼に届いた量を、それぞれの文脈で確かめて合わせる | `goal.mjs`（変更なし。鍵と確かめの文脈を直した） |
| **輸送中はチェーンの隊商の口座で出す。** ヘラルドは今の文脈しか出さないので、前の文脈の隊商は口座で。ヘラルドの写しが食い違えば示す | `arrival.mjs`、`board.mjs` |
| **記録のフォルダはシーズンで分けない**（`.local/ws01-coop/<program>`）。旧い形のシーズンごとのフォルダは `--legacy-data` で**読むだけ**（書き換えず、写さない） | `board.mjs` |
| **記録を一つずつ畳み込む。** 受け取り・表示のたびに全部をやり直さない | `record.mjs` `createFolder`、`board.mjs` |
| **終わったものは読み直さない。** 確定した隊商・送信の結果・確かめた国・規則の版を覚え、同じ村の今の口座は一回の表示で一度だけ読む | `board.mjs` |
| 文書：比較案 Y を「戦期・評価期間を閉じる比較案（世界は終わらない）」に、0a を「シーズンの終わりに集計する旧経路（互換の確認用）」に直した | 14章 14-8、16章 |

## 20-3. 試験で確認したこと

**境界をまたぐ（`test/coop.continuity.test.mjs`、3件。固定した短い試験期間：文脈 90 → 91。偽のチェーンを二つ並べた）：**
- 境界の前に文脈 90 で依頼・応答・送信・結び付け → 文脈 90 の Season を ENDED にする → 板を作り直す（今 91・前 90）→ 前の依頼は開いたまま、隊商は輸送中（口座で）→ 境界の後に文脈 90 の隊商が確定 → 文脈 90 の口座と規則で RuleDerived として数える。
- 文脈 91 で新しい依頼と隊商（番号はまた 0 から）→ 共同の目的は 2 つの文脈を合わせて達成（木材 200・石材 200）、国はそれぞれの文脈の Citizen で確かめた。
- 再起動の後も同じ表示。数えた到着は 2 件だけ（二重に数えない）。保存した記録は読み直しで断られない。
- 前の文脈での新しい依頼・別の文脈での応答・一覧に無い文脈の記録は断る。
- 同じ持ち主の印・同じ番号でも、文脈が違えば別の隊商として結び付けられる。
- 旧い形の板のフォルダ（シーズン 89）を読むだけで取り込み、ファイルの SHA256 は変わらず、こちらへ写さない。依頼は自分の期限で「期限切れ」。

**長く続く（`test/coop.longrun.test.mjs`、2件。境界とは別に）：**

| 測ったこと | 結果（この環境） |
|---|---|
| 記録 20,000 件（6.7 MB、1件 337 B）の読み直し（再起動） | 563 ms |
| 表示（依頼 5,000 件） | 93 ms |
| 新しい記録の受け取り | 1件 0.8 ms（以前は受け取りのたびに全部を畳み込み直していた） |
| メモリ（heap） | 78 MB |
| チェーンを読む回数（確定済みの依頼 60 件） | 1回目：口座 4・取引の一覧 60・取引 120。2回目：口座 1（同じ村）・取引 0 |

ほかの①の試験：作り直した板の上で `node --test` 全体（217 件）・依頼の画面（9 件）・国の卓（14 件）・本物の中継とヘラルド（4 件）を回し、すべて通った（09章 9-3i）。

**確かめていないこと：** 本物のチェーンでの境界（Agave 未承認）。④⑧の移行の後の口座（20-4）。

## 20-4. 移行や仕様判断が残る点（④⑧へ）

| # | 残る点 | ①の今の扱い |
|---|---|---|
| M1 | 文脈（世界・戦期の識別子）の正本と、前の文脈の一覧をどこから得るか | ①は板の起動の引数（`--season`・`--previous`）で受け取るだけ。④⑧の共通方針に置き換える |
| M2 | 新しい文脈で、同じ人・同じ村をどう引き継ぐか（口座がシーズンの PDA から作られるため、住所が変わる） | 前の文脈の依頼に、新しい文脈の隊商を結び付けない（住所の対応表が無いので推測しない）。依頼した人（ウォレット）ごとの共同の目的は、文脈をまたいで合わせる |
| M3 | 前の文脈の依頼に、境界の後も物を送れるか（今の S1 では ENDED のシーズンにプレイヤーの命令は通らない） | 前の文脈の依頼は期限まで開いているが、送信はプログラムが断る（①は送信の結果を「失敗」と示す） |
| M4 | CloseSeason で口座が閉じた後の、前の文脈の到着の証拠（受取人の村・国籍） | 口座が無ければ未検証で数えない。すでに表示した値を残す仕組みは作っていない（板の観測を証拠にするかは未決定）。取引のログの保存期間も④の判断 |
| M5 | 記録の追記ファイルは増え続ける（1件 約 340 B、100 万件で約 340 MB） | 書き換え・削除はしない。分割（古い区間を読むだけのファイルにする）の方針は④と合わせる |
| M6 | 観測の時刻（`observed.json`）とキャッシュも履歴とともに増える | 終わったものだけを覚える。上限は決めていない |
| M7 | 受諾の後の送信の判定（板の時計と blockTime） | ±5 秒は保留。世界の継続とは別の前提 |
| M8 | 戦期・評価期間の区切り、集計、賞金 | ①は決めない。共同・国・個人の記録は戦期で閉じない |
