# 7. 他の担当へ渡す要求（②④⑤⑦）

**この文書の役割：** ①（国の戦略）が、他の担当に求める「ゲーム上の条件」を並べる。実装のしかたは各担当が決める。①は他の担当の成果物を変更していない。

**担当の範囲について：** 依頼で示されたのは「②＝資源と施設の権限」「④＝実行状態」だけ。**⑤と⑦の範囲は、この作業の依頼に書かれていなかった。** 下の⑤⑦は、残る領域（画面と情報の公開、試遊と検証）から推測した宛先で、**割り当ては本人に確認したい**（8章 Q9）。宛先が違っていても、要求の中身はそのまま使える。

---

## ② 資源と施設の権限へ

| # | 要求（ゲーム上の条件） | なぜ①に要るか | 試作での扱い |
|---|---|---|---|
| 2-1 | 物の持ち主は、いつも一人に決まる（国・目標・調整役は持ち主にならない） | R1。国を財布にしない | `inventory` のテストで保存を確認 |
| 2-2 | 「持ち主のまま、他人が使う（預ける・使用権）」を作るなら、**使える人・量・期間・取り消し**を持ち主が決められること。持ち主の不在中も、決めた範囲だけが効くこと | 「預ける」の選択肢を開けるため（R4）。今は閉じている | 「預ける」「他人の工房を借りる」を閉じた選択肢として表示 |
| 2-3 | 使用権がない間は、他人の施設を動かす道がないことを、画面で理由つきで示せること | 選べない理由を出す（R12） | 理由の文言を試作で使用 |
| 2-4 | 他人の倉に「贈る」ときの、倉の上限（`VAULT_CAP`）と、上限を超えた分の扱い | 拠点の倉に複数人が贈るため | 試作は上限なし（未対応） |
| 2-5 | 倉・砦が奪われたとき、**中身と、向かっている荷**の持ち主がどうなるか（奪った人か、失われるか）を一つに決めること | 失敗後の説明（2-7）に要る | 試作のルールでは、奪われた倉に着いた荷は奪った人の物になる（倉を奪う出来事は試作になく、未テスト） |
| 2-6 | 鍵の共有はしない。不在の人の物は、本人か、本人が決めた権限（代理の札など）以外は動かせない | R9 | 不在の人の操作はすべて断る |

## ④ 実行状態へ

| # | 要求 | なぜ①に要るか | 試作での扱い |
|---|---|---|---|
| 4-1 | 荷の状態を少なくとも **準備中／送信済み（未確定）／輸送中（確定）／到着済み（確定）／送信失敗／失った** に分けて返すこと | 進み具合を到着済みだけで数える（R5） | `shipment.state` |
| 4-2 | 到着の**見込みターン**と、遅れていればその**理由**（占領の決着待ち `CapturePending`、確定を誰も呼んでいない、道が柵でふさがれた など） | 遅延のとき、誰に何を選ばせるかを決める | `eta`・`delay`・`reason` |
| 4-3 | 送信が確定しなかったとき、荷が**送り主の手元に残っている**ことを確かめて示すこと | 「送信済み」を「消えた」とも「届いた」とも扱わない | 出来事「送信が確定しない」 |
| 4-4 | 卓の申し出と、実際の隊商を結びつける手段（隊商の id を卓が記録する、など） | 「この荷はこの申し出の発送」と示すため | 申し出 id を荷に持たせた |
| 4-5 | 輸送中の荷を呼び戻す・行き先を変える操作が S1 にないことの確認（あるなら規則） | 退出のとき、輸送中の荷がどうなるかを説明するため | 「そのまま届く」とした |
| 4-6 | 砦の守備兵の「次のターンから数える」（`pend_bell`）のような遅れを、実行状態として返すこと | 成立の判定に「今いる兵」だけを使うため | 1ターン後に数える |
| 4-7 | **軍の出発は、持ち主の明示の操作でしか起きない**ことを、実行の側でも保つこと（補給の到着や目標の成立を合図に、軍の命令を出さない） | R6。依頼の境界 | テスト「ターンを何度進めても、軍は自動で出発しない」 |

## ⑤ 画面と情報の公開へ（推定の宛先）

| # | 要求 | 理由 |
|---|---|---|
| 5-1 | 国の卓を、国の仲間だけに見せる。閲覧・投稿の権限を、署名だけでなく国ごとに確かめる | handoff 未検証事項5 |
| 5-2 | 護衛（封じた進軍）の中身を卓に出さない。件数だけ | 秘密の進軍を漏らさない |
| 5-3 | 卓に「隊商の動きはもともと公開」と明示する | 卓で隠せるのは計画と約束だけ |
| 5-4 | 共有ナビに「国の卓」の入口を置くか（`proposals/0001-nav-nation-table.patch`、未適用）。英訳 `'国の卓': 'Nation table'` | 入口を一か所に |
| 5-5 | 用語：送信済み・輸送中・到着済み・準備中・再確認待ち・供給元を失った・調整役・賛同・申し出・提供の上限 を用語集に | 状態の区別を言葉でも守る |
| 5-6 | AI 住人が卓に申し出るとき、決定済みの表示 A 案（世界として共存を告げ、個々には表示しない）と、評議会の「AI の印」をどうそろえるか | 表示の決定と評議会の画面が食い違っている |

## ⑦ 試遊と検証へ（推定の宛先）

| # | 要求 | 理由 |
|---|---|---|
| 7-1 | 人間3〜5人で、試作（または甲の試遊）の作例を遊ぶ。役割は割り振らず、持ち物だけを配る | 「人が協力を選ぶか」は人間でしか分からない |
| 7-2 | 測るもの：申し出の数、依頼に応じた割合、取り下げ、遅延・退出のあと選び直した人の数と、待つだけだった人の数、ただ乗りの数、成立までの時間 | 協力の理由が働いているか |
| 7-3 | 聞くもの：協力した理由／しなかった理由、遅延のとき何を考えたか、調整役は負担だったか、「送った物は相手の物」は嫌だったか面白かったか | 9章の試遊案 |
| 7-4 | **AI のロールプレイや自動テストを、人間が面白いと感じた証拠に数えない**。報告では分けて書く | 依頼の完了条件 |
| 7-5 | 甲の試遊（手動の台帳）で、目標・申し出・到着を台帳の列として記録できるか確認（`ledger.csv` に `goal`・`pledge` を足すか） | 試遊の正本を増やさずに試す |
