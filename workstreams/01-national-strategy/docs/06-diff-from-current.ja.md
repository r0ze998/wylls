# 6. 既存実装との差分

**この文書の役割：** 推奨ルール案（5章）を今の S1 に入れるとき、何がそのまま使え、何が新しく、何が今の設計と食い違うかを並べる。**共通コア・共有ナビ・共有翻訳・他担当の成果物は、この作業では変更していない。** 接続の差分は `proposals/` に提案として分けた。

## 6-1. そのまま使う（チェーンの変更なし）

| 推奨ルール | 使う既存の仕組み |
|---|---|
| 物を贈る（R4） | `SendCaravan`（他人の村・倉へ、ウォレット署名）。PR #20 で画面に入った |
| 自分の場所に置く（R4） | `BuildVault`＋自分の倉への隊商 |
| 建てる（R2-3） | `BuildStructure`（砦・塔・柵）、倉 |
| 砦に兵を置く（R6-3） | `FortGarrison`（持ち主だけ） |
| 護衛（R6-5） | 封じた進軍（J1：道の途中へ先に送って待ち構える） |
| 構えの前提（R2-4、R8-3） | 国の議会 `Propose`/`Vote`（構え）。`h/nations.json` |
| 到着の判定（R5） | 隊商の確定（`SettleCaravan`）と、ヘラルドの `h/caravans.json` |
| 不在でも働く守り（R6-4） | 砦・塔・柵の自動の判定（`stops()`、clash） |

## 6-2. 新しく要るもの（オフチェーン）

| 新しいもの | 中身 | 置き場所の案 |
|---|---|---|
| 目標の記録 | 目標（版つき）、賛同、申し出（量・上限・状態）、依頼と返事、方針変更の履歴 | 評議会のサービスと同じ、署名つきのオフチェーン記録（`/f/ai/talk` と同じ仕組みに「目標」の種類を足す）。チェーンの命令は増やさない |
| 荷と申し出の結びつき | どの隊商が、どの申し出の発送か | 発送のときに卓が隊商の id を記録する。または、隊商の記録に任意の「目的」欄（④と相談） |
| 進み具合の計算 | 到着済み・輸送中・期限後・申し出・不在の人の申し出 | 卓の画面の中で、ヘラルドの公開データと目標の記録から計算（試作の `needProgress`） |
| 次に必要な判断 | 人ごとの判断と選択肢と結果 | 卓の画面の中（試作の `decisionsFor`） |
| 国の卓の画面 | 共同目標・物の流れ・申し出・判断・記録 | 新しい画面（`proposals/0001-nav-nation-table.patch` で入口だけ提案） |

## 6-3. 変わるところ（提案）

| 今 | 推奨 | 理由 |
|---|---|---|
| 協力は、評議会のページで鍵を貼り、伝言で頼み、隊商の画面で贈る（Eternum UX 調査の「変更前」） | 国の卓で、目標・申し出・発送・到着が一つの場所に見える | 「送ったか」「着いたか」「足りているか」を一か所で読む |
| 評議会の議題は AI 住人の「攻撃の指令」 | 国の目標は人間も AI も同じ規則で出せる呼びかけ。攻撃の指令とは混ぜない | 軍の出発を自動にしない線を守る |
| 隊商の画面は「送った」で終わる | 卓は「送信済み／輸送中／到着済み」を分け、成立は到着で判定 | 送信を到着や達成と混同しない（handoff 未検証事項1） |

## 6-4. 設計文書と食い違うところ（判断は本人）

| 決定済みの設計 | この作業の推奨 | どうするか |
|---|---|---|
| 国の設定「国の取り分（生産の0〜20％を国の倉へ）」（14 の5章） | 試作の範囲では徴収と国の共有資産を作らない（R1、範囲の限定） | **既存の決定は上書きしない。** 国の卓とは別の未統合事項（8章 Q1） |
| 国の中の賞金の取り分に「国の倉への納め」（28） | 試作では報酬を扱わない（R1-3） | 賞金の取り分の設計そのものは残る。卓の記録を賞金の数え方に使うかは本人（8章 Q2） |
| 「同盟」の構え | S1 では効果なし（1章） | 卓は構えの事実だけを使う |
| 国を移れる（決定） | S1 に命令がない | 卓は「目標から抜ける」だけを扱う |

## 6-5. 試作と本番の違い（試作で単純にしたこと）

| 試作 | 本番 | 影響 |
|---|---|---|
| 移動ターンは表の固定値 | 道・地形・道路・塔で決まる（`fastest_path`） | 期限の見込みは、本番では道の計算が要る（Eternum UX 調査の「部分的な輸送時間を全部そろう時間として表示しない」） |
| 遅延は「受け取り側の決着待ち」として、ターン数を足す | 遅れの主な原因は、占領の決着待ち（`CapturePending`）と、確定（Settle）を誰も呼ばないこと | ④の実行状態で、何を「遅延」と出すかを決める必要 |
| 工房は1ターンに整数個 | 毎時4（1ターン約0.67）の連続の産出 | 準備中の見込み時間は本番の計算を使う |
| 守備兵の訓練は食料だけ（仮） | `train_v2` の費用 | 機会費用の数字が変わる |
| 偵察は兵10・往復で、知らせは12ターン有効 | `explore.rs` の偵察の規則（未確認） | 見張りの判定は⑤と相談 |
| 投票の締め切り6ターン | 144ターン | 試作は短くしただけ |
| 襲撃は出来事で起こし、護衛がいれば守れる | 襲撃は戦い（clash）の結果 | 護衛の判定は本番のルール |
| 護衛は行き先で12ターン［仮］待ち構え、その後は持ち主の村へ戻る。待ち構えている間だけ守る | 封じた進軍は着いた後に持ち主が動かす | 2026-10-30 に「戻らない」単純化を直した。それでも数字と戦いの判定は仮なので、**護衛を含む経済評価と面白さの検証は対象外** |
| 成立は期限のターンに判定。倉の物は「今ある量」を提案の古い目標から割り当てる | 本番の判定のしかたは未定（卓はオフチェーン） | ヘラルドの倉・砦の公開データから、期限のターンの状態を読む必要がある |
| 賛同は「判断する人」で数える（試作では人物ごとに運営が割り当て） | 本番では判断する人は分からない | 8章 Q3 |
| 村の占領は起こさない | 占領後に向かう荷と在庫の扱いは未確認 | 8章 Q14 |
| 構えの議題を出し返す操作 | 本番では投票権のある村が出せる | 試作では閉じた選択肢として表示 |
