# 03 略奪・占領・障害で所有権がどう変わるか（採用済みルールとの関係）

「事実」は 4cd901de のコードと決定ログで確かめたこと、「この実装」は custody カーネルとモデルがすること、「衝突」は依頼文の条件と採用済みルールが食い違う点です。採用済みルールを上書きする例外は**足していません**。

## 1. 依拠した採用済みルール（事実）

| ルール | 出典 | 内容 |
|---|---|---|
| J2 | [99-decisions](../../docs/design/redesign/99-decisions.ja.md) 2026-10-23、`proc/caravan.rs` の `settle_raid` | 奪うと、襲われた隊商が積荷ごと襲撃者のものになる（`OWNER_CITIZEN`・`FACTION` が変わり、`OWNER_TAG` は seed のまま） |
| 焼く | 同上 | 積荷はすべて消え、空の隊商は宛先へ進む |
| 倉の押収 | `S1-1B-CONTRACT` §3.6、`seize_vault` | 押収者の軍が倉のマスに立ち、持ち主の軍がいない。持ち主が変わり `GEN += 1`、物は倉に残る（＝押収者のもの） |
| 段階2 §5 | [20-stage2-play](../../docs/design/redesign/20-stage2-play.ja.md) §5（2026-10-23 採用） | **倉が奪われたら、その倉の持ち分の札と受け取りの札は無効、中身は奪った側のもの**。対象は段階2の**札**（未実装）。区画は札ではない |
| 宛先の消失 | `S1-1B-CONTRACT` §3.4、`settle_caravan` | 宛先がない、または世代が違えば積荷は失われる（`STATE_LOST`） |
| 隊商は呼び戻せない | 同上 | 送ったら途中で止められない |
| 他人への送りは財布 | plan §1-11、`send_caravan` | session 鍵は自分の場所の間だけ |

## 2. この実装での扱い

| 出来事 | 所有権 | 物の状態の記録 |
|---|---|---|
| 保管の隊商が**奪われた** | J2 のとおり襲撃者へ。隊商は通常の隊商になり（`CUSTODY 1→2`）、SettleCaravan で襲撃者の一般在庫へ入る | 奪われるまで「不明（襲撃中）」、奪われた後は「不明（照合待ち）」、ReconcileLot で **損失確定 `Raided`（相手＝襲撃者）** |
| **焼かれた** | 物が消える | SettleCustody で **損失確定 `Burned`**（届いた量との差） |
| 区画のある倉が**押収された**（占領） | 押収者へ（**⑩の判断**：段階2 §5 と S1 §3.6 からの類推で区画にも当てはめた。区画への適用は決定されていない。[05](05-integration-review.ja.md) §4.4） | 押収の瞬間から区画は「凍結」（誰も動かせない）、ReconcileLot（誰でも）で倉の一般在庫へ移り **損失確定 `Seized`（相手＝押収者）**。注文は無効 |
| 取り返した（再押収） | 戻らない（札は押収の時点で無効） | 世代がさらに進むだけ。照合時の持ち主の一般在庫へ |
| 輸送中に**宛先の倉が押収された** | 既存の「宛先消失で失われる」に従う | **損失確定 `DestinationGone`（記録上の相手＝倉の新しい持ち主）**。物はどこにも入らない（既存ルールどおり） |
| 宛先の保管者が**倉や区画を閉じようとした** | — | **拒否**（`CUSTODY_LOTS ≠ 0`、到着予定のある区画は閉じない）。避けられる消失は起こさせない |
| 塔に**削られた** | 物が消える（S1 1d） | 出発時に **損失確定 `Worn`** |
| 運搬者が**途中で抜けた** | 変わらない | 精算は誰でもできるので届く |
| 保管者が**抜けた** | 変わらない | 所有者だけで引き出せる（保管者の署名は不要） |
| 所有者が**抜けた** | 変わらない | 誰も動かせない（保管者も運搬者も）。戻れば引き出せる |
| **権限を取り消した** | 変わらない | 発送済みの隊商は呼び戻せないので、そのまま A の区画へ届く。未使用の予約は解放 |
| **期間の切替**（戦期の終了など。2026-10-31 の方針で世界は終わらない） | 変わらない | 何も起きない：区画・注文・予約・輸送中の隊商は境界を読まない。注文は自分の期限（`EXPIRES_BELL`）だけで切れる。ただし現在のコアにはシーズン終了に依存する箇所が残る（[06](06-continuity.ja.md)） |

## 3. 依頼文の条件との衝突（明記）

1. **「所有者を変えず」と押収・襲撃。** 依頼は所有者を変えない保管・輸送を求めるが、採用済みの J2 では襲撃（奪う）で、S1 §3.6 では倉の押収で**所有権が移る**（倉の中身。段階2 §5 は札を無効にする決定）。区画の押収への適用は⑩の判断。この実装は採用済みルールに従い、所有権が移ったことを損失確定（原因と相手つき）として記録する。「所有者を変えない」は**本人と許可した相手の行為の範囲**で保証し、戦闘・占領では保証しない。
2. **「取り戻せない物を消して帳尻を合わせない」と既存の宛先消失。** 既存のルールでは宛先が消えた積荷はどこにも入らずに消える。この実装もそれに従う（例外を足さない）が、(a) 保管者が自分で宛先を消す道（CloseVault・CloseLot）は塞ぎ、(b) 消えた量は `DestinationGone` として記録する。押収による宛先消失だけが残る。
3. **既存コードの静かな消失（発見、[README](README.ja.md#食い違い) にも記載）。** `settle_caravan` は倉への配達で `CAP` を超えた分を捨て、`CARAVAN_SETTLED` には積荷の全量を記録する（捨てた量は記録されない）。保管品はこの経路に乗せない（SettleCaravan は保管品を拒否し、区画の到着予定は出発時に容量を予約する）。一般在庫への通常の配達については既存の挙動を変えていない（改定は `CAP − CUSTODY_QUOTA` への上限の変更だけ）。

## 4. 足さなかった例外（「安全な倉庫」を作らない）

| 足さなかったもの | 理由 |
|---|---|
| 押収されても区画が残る | 押収に強い倉ができ、段階2 §5 と食い違う |
| 区画の物は襲撃されない、保管品の隊商は奪えない | 隊商の安全な通り道ができる |
| 宛先が消えたら送り主へ自動で戻す | 新しい規則。戻り道は襲撃対象になるので案として [README](README.ja.md) の判断待ちに置いた |
| 預けた人の軍も倉を守る（押収の条件に数える） | 押収の条件（S1 §3.6）の変更。判断待ち |
| 自分の倉に自分の区画を開く | 意味がなく、一般在庫と区画の二重管理になるだけ（`SelfDealing`） |
| 区画の容量を倉の容量の外に置く | 預かるほど倉が広がる。区画は `CAP` を一般在庫と分け合う |

保管は物を**安全にしない**：区画は倉と同じマスで同じ条件で押収され、保管品の隊商は普通の隊商と同じく襲われる。

## 5. 判断が要る点（所有者・④へ）

1. **保管品の隊商の国は運搬者の国**（この実装）。塔・柵・護衛・同じ国の襲撃の扱いは運搬者で決まる。したがって、A を止める柵も、中立の運搬者なら通れる。これを「雇った運び屋」として認めるか。
2. **宛先消失時の送り主への返送**（この実装は既存どおり消失）。
3. **預け主の軍を倉の防衛に数えるか**（この実装は数えない）。
4. **保管者と押収者の共謀**：B が味方に自分の倉を押収させれば、A の区画も押収者のものになる（採用ルールの帰結）。A が保管者を選ぶ責任とするか、記録（`VAULT_SEIZED` の同じ国フラグと `LOT_LOSS`）で信用に反映させるか。
5. ~~シーズン終了後の区画の口座~~（2026-10-31 撤回：世界は終わらない。期間の切替で区画を閉じない。現在のコアのシーズン終了依存は [06](06-continuity.ja.md) で④・⑧へ）
6. **CloseVault を区画が塞ぐこと**：保管者が預かりをやめたいとき、所有者が引き出すまで倉を閉じられない。立ち退き（期限つきで送り返す）の命令を足すか。
