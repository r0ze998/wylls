# 08 ⑨との接続：保管・容量予約側のアダプターと契約試験（2026-11-05）

⑨（能力貸出）のカーネルが呼ぶ預かりの口（trait `Custody`、`workstreams/09-capacity/kernel/src/custody.rs`）を、⑩の区画カーネル（`custody/src/lot.rs`）で実装した。**⑨のコードと⑩の本体は一行も変えていない**（このブランチの基点 `d0949fd4` との差分は `workstreams/10-custody/` の中だけ）。試験は⑨自身の `Harness`（`kernel/src/ledger.rs`）をそのまま動かし、預かりだけを `MockCustody` からこのアダプターに差し替えている。

> **読み方。** 「確認した」は実行して確かめたこと。「提案」「仮」は④・所有者の判断待ち。ABI 番号・版はこの作業で一つも足していない（§6）。

## 0. 結論

| 求められたこと | 判定 | 根拠 |
|---|---|---|
| 材料利用（⑨の `consume`）を⑩の区画と照合 | **確認した（モデル）** | 区画から job に入った材料は区画の外（job の hopper）にあり、⑨の精算で使われる。使った量は⑨の `Settled.used` と預かりの `Consumed` 通知が job ごとに一致（乱択 2,000 種で照合） |
| 加工中の予約 | **確認した（モデル）** | 区画から job に出した量だけ、区画が**返却用の容量**を予約する（⑩の到着予約と同じ枠）。加工中に他の隊商・入庫がその容量を取れない（`return_room_holds_against_arrivals_and_quota_cuts`） |
| 返却・完了通知の照合 | **確認した（モデル）** | 返却は予約を使って区画に戻る（`Returned`）。使い切り・別の場所への返却・施設喪失では予約が解放される（`Released`）。予約ごとに終わりがちょうど一つ、量が一致（乱択試験の `fold`） |
| 重複通知で二重消費・二重返却しない | **確認した（モデル）** | ⑨の全操作を 2 回ずつ送っても 2 回目は預かりを 1 バイトも変えない。預かりの呼び出しを同じ鍵で再送すると何もしない、違う中身なら `KeyReused` |
| 再起動で二重にならない | **確認した（モデル）** | 世界全体（⑨の台帳＋アダプター）を毎段階 borsh で書き出して読み直しても、再起動なしと最終状態がバイト単位で一致。再起動を挟んだ重複も同じ |
| 予約の解放漏れがない | **確認した（モデル）** | 全 job を受け取り・退役させた後、返却予約・job の記録・job の冪等鍵が残らない（乱択 2,000 種すべて）。`forget` で解放せざるを得なかった予約は 0 件 |
| ⑨側を書き換えない／双方の入出力を明示 | **した** | §3 の表 |
| 成果物の所有者・多資源・押収 | **決めていない** | §5。アダプターはどれも決めずに安全側で止める |

**オンチェーンではない。** ⑨の操作は⑨のモデル（`Harness`）、⑩の区画は⑩のカーネル関数とその口座バイト（576 B）で動かしている。SBF・LiteSVM・プログラムの命令は通っていない（Agave の導入は許可されていない）。

## 2. 置き場の対応

| ⑨の `Place` | アダプターでの意味 | 誰が出せるか |
|---|---|---|
| `Vault(v)` | **所有者ごとの区画**（⑩の Lot、倉 `v`×所有者×資源）。一つの山ではない | 区画の所有者本人だけ（`By::Actor(owner)`）。保管者・他の利用者・⑨のカーネルは出せない |
| `Hopper(job)` | job の材料。所有者は job の利用者 | ⑨のカーネルだけ（C4） |
| `Output(job)` | job の成果物。所有者は⑨が `produce` で名指しした者 | ⑨のカーネルだけ |
| `Caravan(id)`・`Holding(site)` | 区画でない置き場（⑨の模擬と同じ：置き場×資源ごとに所有者一人） | その所有者だけ |

区画が関わる移動は次の 3 つだけを受け付ける。それ以外（区画⇄隊商・区画⇄Holding・区画⇄区画、区画からの `export`）は⑩自身の命令（運ぶ時間のある保管品の隊商、WithdrawLot）なので、この口では `Forbidden`。

1. **区画 → job の材料**（⑨の Deposit、`from = Vault(v)`）：⑩の `spend_ship`（所有者による持ち出し。整数単位、利用可能量の範囲）＋返却予約（`begin_inbound`）。
2. **job → 区画**（⑨の Claim の返却・成果物、`to = Vault(v)`）：その job の返却予約を先に使い（`finish_inbound`）、超える分は区画の空き容量で受ける。
3. **到着 → 区画**（⑨の `import`、`at = Vault(v)`）：区画の空き容量で受ける。

倉と施設が同じ州（`(P, Q)`）にあるときだけ 1・2 を受け付ける（**仮**：倉は升目に、job は施設にある。距離の決め方は④）。

## 3. 双方の入出力

### 3.1 ⑨ → アダプター（⑨が今すでに渡しているもの。変更なし）

| 呼び出し | ⑨が渡す | アダプターが使うもの |
|---|---|---|
| `transfer` | `key{scope = job の uid, kind, n}`、`by`、`from`、`to`、資源、量（milli）、移動後の所有者 | `scope` で job を覚える（返却予約の札 = `RETURN_TAG ‖ uid`）。`by` が本人なら所有者＝本人であること（贈与は不可） |
| `consume` | 鍵、`Hopper(job)`、資源、量 | hopper から減らす。空になったら返却予約を解放 |
| `produce` | 鍵、`Output(job)`、所有者、資源、量 | ⑨が名指しした所有者のまま置く（決めない） |
| `import`／`export` | 鍵、置き場、量 | 区画への到着は空き容量の範囲。job の置き場への `import` は不可 |
| `forget(scope)` | 退役した job の uid | 鍵を捨てる。job の置き場が空であることを確かめ、残った返却予約を解放（空でなければ `Stranded` を記録し `check()` が落ちる） |

### 3.2 アダプター → ⑨

| 返すもの | 内容 |
|---|---|
| `Result<(), CustodyError>` | ⑩の理由を⑨の型に写す：量が足りない→`Insufficient`、それ以外（権限・凍結・資源・整数単位・容量・枠・桁あふれ）→`Forbidden`。正確な理由はアダプターの `try_*` が `Refusal::Lot(…)` で返す |
| `balance(Vault(v), r)` | 倉に `r` を持つ所有者が一人ならその人と量、複数なら `None` と合計 |
| 通知（`take_notes()`） | `Reserved`（区画から job へ、返却容量を予約）／`Returned`（job から区画へ。予約で受けた量 `covered` と、余った予約 `released`）／`Released`（返却なしで予約終了：`Emptied`＝hopper が空、`Forgotten`＝⑨が退役）／`Consumed`／`Produced`／`Stranded`。**確定した仕事だけ**が載る（⑨の `apply` は失敗時にアダプターごと巻き戻すため） |

### 3.3 ⑨に求めること（⑨のコードは変えていない。④・⑨の判断用）

| # | 内容 | 理由 | 試験 |
|---|---|---|---|
| R1 | 退役した job の操作は預かりに届く前に拒否する（今の⑨はそうしている） | アダプターは `forget` 後に墓標を残さない（継続世界で鍵の記録を有界にするため）。届けば同じ鍵がもう一度実行される | `a_retired_job_cannot_be_replayed_into_custody` |
| R2 | `balance(Vault(_))` から所有者を読まない | 倉は複数の所有者の区画 | — |
| R3 | 区画への返却は整数単位の量で送るか、整数単位でない返却を区画以外へ送る | ⑩の区画は整数単位（`whole`）。⑨の部分精算の残り（例：鉱石 15.556）は区画に入らない（§4 の F1） | `a_fractional_refund_…` |
| R4 | 受け取り（Claim）の宛先を資源ごとに選べるようにするか、区画を宛先にしない | Claim は成果物（兵器）と返却材料を同じ宛先に送る。兵器は区画に入らないので、宛先が区画の Claim は成果物がある限り必ず失敗する（F2） | `materials_from_a_lot_…` |
| R5 | `CustodyError` に理由（⑩のコード）を運ぶ欄 | 今は「容量がない」「凍結」「整数単位でない」が全部 `Forbidden` になり、利用者に理由を出せない | — |
| R6 | 所有権を変えずに使う（A の区画の鉱石を B の job で使い、A のまま消費）なら、hopper に job の利用者以外の所有者を許すか、⑩の利用注文の id を Deposit に載せる | 今の trait では移動後の所有者が job の利用者に固定され、⑩の利用注文（`ConsumeLot`）に当たる口がない | `nobody_but_the_owner_reaches_a_lot`（他人の区画は使えない、までを確認） |

### 3.4 ⑩・④（コア）に必要なこと

| # | 内容 |
|---|---|
| Q1 | 返却予約を区画の到着予約の枠（`MAX_INBOUND` = 4）で表した。札の最上位ビット（`RETURN_TAG`）を返却に使う。S1 の隊商 id は 47 ビットの所有者タグ＋16 ビットの番号なので重ならないが、**④が隊商 id の形を変えるなら合わせる必要がある**。枠は保管品の隊商と共有なので、一つの区画から同時に 4 つを超える job／隊商へは出せない（`NoSlot`） |
| Q2 | ⑨の `Place::Vault(u64)` に倉の世代がない。押収で世代が変わった倉の区画は、アダプター側で凍結として扱う（⑩の `usable`）。オンチェーンでは区画の鍵（世代を含む）で区別される |
| Q3 | 倉と施設の「同じ場所」の定義（今は同じ州で仮置き） |

## 4. 見つかった食い違い（⑨の契約と⑩の区画）

| # | 内容 | 影響 | 今の扱い |
|---|---|---|---|
| F1 | ⑨は milli 単位で部分精算する（兵器 1 milli ごとに鉱石 2 milli）。⑩の区画は整数単位だけを受ける | 途中で止めた job の材料の残りはほぼ必ず端数で、区画に戻せない | 区画への返却は拒否（何も動かない）。利用者は隊商・Holding へ受け取れ、予約は解放される。**区画が端数を受けるかは④・⑩の判断待ち** |
| F2 | ⑨の Claim は成果物と返却を一つの宛先へ送る。兵器は区画に入らない（⑩は鉱石のみ） | 成果物のある job は区画へ受け取れない | 拒否して何も動かない |
| F3 | ⑨の `MockCustody` は job の置き場への `import`、本人による他人名義への移動を許す | アダプターはどちらも拒否（job の置き場は預け入れでだけ増える／本人の移動で所有者は変わらない）。⑨の今の呼び方には影響しない | 厳しい側に寄せた |
| F4 | ⑨の `forget` は「退役した job の操作はカーネルが先に拒否する」ことに頼る | 重複通知が預かりに届けば再実行される | R1 として明記、試験で⑨の拒否を確認 |
| F5 | ⑨の `CustodyError` に容量・凍結・単位の区別がない | 理由が `Forbidden` にまとまる | R5 |

## 5. 決めていないことと、決めないままの挙動

| 未決 | アダプターの挙動 |
|---|---|
| 成果物の所有者 | ⑨が `produce` で名指しした者のまま置く。アダプターは選ばない。兵器は区画に入らない（下の多資源） |
| 多資源（木材・兵器を区画に入れるか） | ⑩のカーネルの `ENABLED_RESOURCES`（鉱石だけ）に従う。木材・兵器は区画を開けず、区画への返却・受け取りは `Resource` で拒否。⑨の材料の木材は隊商・Holding の置き場で扱える |
| 押収時の区画 | 押収（倉の世代が進む）で区画は**凍結**：誰も出し入れできない（所有者・押収者・保管者・⑨のカーネル）。⑩の没収（`forfeit`）は提案のままで、アダプターは実行しない。凍結した区画への返却は拒否し、利用者は別の場所へ受け取れる（`a_seized_vault_…`） |
| 施設喪失（⑨の LossPolicy） | ⑨の方針どおりに動く（押収者へ移るなら hopper→Holding、予約は解放）。方針自体は⑨の仮 |

## 6. ABI 番号・版

アダプターは命令タグ・口座種別・記録種別・エラー番号・版のどれも足していない。⑩の core 差分（`96fe6abf`）の仮番号（タグ 0xC1–0xCB、記録 104–112、エラー 94–98）と、⑧（0xC1・104・94）・⑨の命令案（0xC1–0xCE）との衝突は [07](07-handoff-status.ja.md) §1 のまま、**④との調整事項**。返却予約の札（`RETURN_TAG`）は口座の中の値で ABI 番号ではないが、隊商 id の形（Q1）と合わせて④の確認が要る。
