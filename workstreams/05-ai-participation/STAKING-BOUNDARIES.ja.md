## ② 権利（Grant）への依頼

⑤の仮の物：委任条件（`src/adapters.mjs` `grantFrom`）と、カテゴリ別の上限（`src/staking/budget.mjs` `BudgetGuard`）。どちらも中継の方針を**狭めるだけ**で、⑤の実行層の中でだけ効きます。

| # | 依頼 | 理由 |
|---|---|---|
| G1 | Grant に、カテゴリ（推論・ゲーム）ごとの1回・1日・総額の上限を持たせる | 本人の「一つの予算」を、使い道ごとに縛れるように |
| G2 | 資源の量（兵の数・荷の量）を、命令ごとに縛れる形 | 今の方針は USDC と行動の種類だけ。量はどこでも強制されていない |
| G3 | 対象（村・施設）と、権限の期限・取消・版 | 施設の利用はまだプログラムにないので、対象の形だけ先に決める |
| G4 | 強制する場所（中継か鎖か）を決める | ⑤の層はトークンを持つ者には迂回できる。③の 0004 と同じ要求 |
| G5 | session の枠が村に1つしかない問題を、どう扱うか | 代理の財布と③の courier が同じ枠を取り合う（③ 04 §4） |

⑤の差し替え点：`grantFrom()` が Grant を読むようにし、`BudgetGuard` の上限を Grant から取る。実行の流れ（`participate()`）は変えない。

## ③ 公開API への依頼

③の成果物（未 merge）から⑤が使う事実：
- 外部プログラムは SendCaravan を CPI で呼べる。
- 委任の「限定」はコアの保証ではない。
- 中継は外部プログラムの取引を受け付けない。

| # | 依頼 | 理由 |
|---|---|---|
| A1 | `action_status`（requestId で、送らずに結果を確かめる） | 再起動の後、送ったか分からない行動を確かめるには、今は頼み直すしかない（送っていなければ、そこで送ってしまう）。⑤の MCP-EXTENSIONS §1 |
| A2 | トークンの有効性を確かめる読み取り（`agent_whoami`） | 古いトークンの代理が、断られる前にモデルの料金を払う（MCP-EXTENSIONS §2） |
| A3 | 本人向けの明細の公開形（利用可能・処理中の内訳・確定のカテゴリ別・取り消せるか） | ⑤の `statement()` の形を、公開API の型にする |
| A4 | エラーコードの追加：`PerCallLimit`・`CategoryLimit`・`PolicyExpired` | パッチ 0001 が足す。③の命令契約のエラー表に載せる |

## ④ 実行・結果の追跡（Run）への依頼

⑤の仮の物：`RunJournal`（`src/adapters.mjs`）と `trace()`（`src/staking/budget.mjs`）。

| # | 依頼 | 理由 |
|---|---|---|
| R1 | Run の状態に「受理」「着地」「効果」（隊商なら「出発」「到着」）を別々に持たせる | 受理を成功と混同しないため。隊商は、道を外れただけでは着いたことにならない（`src/staking/outcomes.mjs`） |
| R2 | Run に費用の行（推論の呼び出しごと・ゲームの確保ごと）を結びつける | 台帳の行（`spend`・`release`）とのつなぎは、今は⑤がキーで突き合わせている。ビューの履歴は最後の50行だけで、古い行は見えなくなる |
| R3 | 「考えた内容」（モデルの理由・設定したモデル・実際のモデル）を Run に残す | 本人が、何を考えて何を払ったか確かめられるように |
| R4 | 結果の確認を、herald の公開記録から（兵の待機、`h/caravans.json`、倉の蓄え） | 今のデモは fixture の世界で確かめている |
