## 必要な権限と、現状の不足（訂正：②に依存しない）

前は「②の Grant にこれを持たせる」と書きました。②の現行案（StockSwap）は交換の権利で、AI の権限や予算を縛る物ではありません。なので、下は**誰が作るか決まっていない、必要な権限の一覧**です（②への依頼ではありません）。詳しくは [GUARANTEES](GUARANTEES.ja.md) §1・§2。

⑤の仮の物：委任条件（`src/adapters.mjs` `grantFrom`）と、カテゴリ別の上限（`src/staking/budget.mjs` `BudgetGuard`）。どちらも中継の方針を**狭めるだけ**で、⑤の実行層（1プロセス）の中でだけ効きます。

| # | 必要な権限 | 現状の不足 |
|---|---|---|
| P1 | カテゴリ（推論・ゲーム）ごとの1回・1日・総額の上限 | 中継は全体の額だけ。パッチ 0001（未適用）が中継に足す案 |
| P2 | 資源の量（兵の数・荷の量）を、命令ごとに縛る | 中継にも鎖にも仕組みがない |
| P3 | 命令ごとの範囲（例：物流だけ）を鎖で縛る | session 鍵は「session 可」の全命令を使える。範囲の欄が Citizen にない |
| P4 | 対象（村・施設）、権限の期限・取消・版 | 村は中継だけ（鎖では Citizen の全村）。施設の利用はプログラムにない。方針の期限はパッチ 0001 の案 |
| P5 | 委任先を複数持てること | session は Citizen に1つ。代理の財布・同じ持ち主の別の代理・③の courier が取り合う |
| P6 | 中継を通らない送りも縛ること | 代理の鍵（seed）を持つ者が RPC へ直接送れば、鎖の session 検査だけ |

⑤の差し替え点：仕組みが決まったら、`grantFrom()` がそれを読み、`BudgetGuard` の上限をそこから取る。実行の流れ（`participate()`）は変えない。

## ③ 公開API への依頼

③の成果物（未 merge）から⑤が使う事実：

| A2 | トークンの有効性を確かめる読み取り（`agent_whoami`） | 古いトークンの代理が、断られる前にモデルの料金を払う（MCP-EXTENSIONS §2） |
| A3 | 本人向けの明細の公開形（利用可能・処理中の内訳・確定のカテゴリ別・取り消せるか） | ⑤の `statement()` の形を、公開API の型にする |

## ④ 実行・結果の追跡（Run）への依頼

⑤の仮の物：`RunJournal`（`src/adapters.mjs`）と `trace()`（`src/staking/budget.mjs`）。

| # | 依頼 | 理由 |
|---|---|---|
| R1 | Run の状態に「受理」「着地」「効果」（隊商なら「出発」「到着」）を別々に持たせる | 受理を成功と混同しないため。隊商は、道を外れただけでは着いたことにならない（`src/staking/outcomes.mjs`） |
| R2 | Run に費用の行（推論の呼び出しごと・ゲームの確保ごと）を結びつける | 台帳の行（`spend`・`release`）とのつなぎは、今は⑤がキーで突き合わせている。ビューの履歴は最後の50行だけで、古い行は見えなくなる |
| R3 | 「考えた内容」（モデルの理由・設定したモデル・実際のモデル）を Run に残す | 本人が、何を考えて何を払ったか確かめられるように |
| R4 | 結果の確認を、herald の公開記録から（兵の待機、`h/caravans.json`、倉の蓄え） | 今のデモは fixture の世界で確かめている |
