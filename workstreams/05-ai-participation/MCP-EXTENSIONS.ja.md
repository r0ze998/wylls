# 必要な MCP 拡張の案

**状態：提案。どれも実装していません。** 共有の MCP サーバー（`permutation-gateway/mcp/agent-mcp.mjs`）と中継の route は変えていません。下の案は、この作業の局所デモで「足りない」と分かった順に並べています。共有コードの変更になるので、代理の財布・中継・herald の担当と、②③④の契約の担当が決めることです。

共通の決まり（今の MCP の約束を保つ）：
- 道具は**一つの代理**のためだけ。別の代理・別の村は名指しできない。
- 持ち主の命令（作成・方針・停止・出金・トークン）は道具にしない。
- 読み取りは、人間が読める公開の記録だけ。運営の情報・秘密の進軍は返さない。
- プレイヤーの書いた文は、`untrusted` と分かる形で返す。権限にもシステムの指示にもしない。

## 優先度 高（局所デモで、ないと困った物）

### 1. `action_status` — 送った行動がどうなったか
| | |
|---|---|
| 入力 | `requestId`（自分が `agent_act` に渡した物） |
| 答え | 中継の記録（`sent`・`refused`・`failed`、署名）＋鎖の答え（`GET /f/tx/{signature}` の `landed`・`failed`・`expired`・`unknown`） |
| なぜ | MCP だけのAIは、送った行動が着地したか確かめられない（今のデモは `GET /f/tx` を MCP の外から読んでいる）。「結果を確かめて記憶する」に要る。もう一つ：再起動の後、送ったか分からない行動を確かめるには、今は同じ id で `agent_act` を頼み直すしかない（送っていなければ、そこで送ってしまう）。そのため、本人が委任を取り消した後は、確かめることもできず「不明」で保留している（テスト「restart under a revoked mandate」）。**送らずに確かめる**道具が要る |
| 守る | 自分の代理の記録だけ。読み取りだけ |
| 変える所 | `agent-mcp.mjs`（道具を足す）。中継の route は既存（`GET /f/tx/`、`GET /f/agent` の履歴） |

### 2. `agent_whoami`（または `agent_view` でのトークン確認）
| | |
|---|---|
| 答え | このトークンが今も有効か、トークンの版（`capabilityVersion`） |
| なぜ | 今の `agent_view` は公開の読み取りで、トークンを確かめない。持ち主がトークンを取り替えた後も、古いトークンの代理は計画を立て、モデルの料金を払ってから `agent_act` で断られる（テスト「stopped or revoked」） |
| 守る | 副作用なし。トークンそのものは返さない |
| 変える所 | 中継に確認だけの route（例：`POST /f/agent/check {capability}`）。`routes/agent.mjs` |

### 3. `village_state` — 自分の村の状態
| | |
|---|---|
| 答え | 蓄え（世界の時計で計算した値）、生産、予約の空き、兵の待機、自分の軍の数。運営の runner がモデルに渡している `villageState()` と同じ形 |
| なぜ | 「自分の在庫を確かめる」に要る。今の `world_read` は season と province の生の記録だけで、村の蓄えは読めない |
| 守る | 持ち主の村だけ（herald の公開記録：`/h/me/{owner}`、`/h/province/{p},{q}/latest`） |
| 変える所 | `agent-mcp.mjs`。中身は `runner.mjs` の `AgentObserver`・`villageState` を使う |

### 4. `nation_requests` — 国の公開の依頼
| | |
|---|---|
| 答え | 依頼ごとに：id、国、書いた人（財布で署名された身元）、期限、**数値の部分**（何を・いくつ・どこへ）、**文の部分**（`untrusted` と印をつけて） |
| なぜ | 共同作戦に参加する入口。今は依頼板そのものがない（プログラム・herald・中継のどこにもない）。デモは fixture |
| 守る | **国ごとの閲覧の権限**（その国の村だけが読める。引き継ぎ文書の確認事項5）。秘密の進軍や国の内輪の情報を、依頼の文で漏らさない仕組みは、依頼を書く側の画面でも要る |
| 前提 | 国の卓・依頼の記録（設計の決定待ち）。先にこれが要る |

## 優先度 中（今は「本人の判断」で返している物）

### 5. `world_read` の範囲を広げる
`what: 'caravans' | 'structures' | 'nations'`（herald の `h/caravans.json`・`h/structures.json`・`h/nations.json`、どれも公開）。隊商の道や倉の持ち主を、依頼の確認に使う。

### 6. 自分の倉どうしの隊商を代理に開く
- 鎖は session key での自分の場所どうしの隊商を許している（`caravan.rs`：他人宛てだけ `WalletRequired`）。
- 代理の経路（`gateway.mjs` の `accountsFor`）と許可リスト（`contract.mjs` の `ACTION_GROUPS`、例えば新しい `logistics`）に足す必要がある。
- 足すなら、**資源の量の上限**（1件・1日）が方針に要る。今の方針は USDC と行動の種類だけで、荷の量を縛れない。②の Grant と一緒に決める。

### 7. `owner_draft` — 本人に渡す下書き
- 他人の倉への隊商、投票、施設の利用のように、代理が送れない物を、本人の画面に「宛先・荷・量・理由」として出す。
- **実行の経路ではない。** 署名するのは本人の財布。代理は下書きを置けるだけ。
- 今のデモは、同じ内容を実行の記録（`needs_owner` と `ownerDecision`）に書いている。

## 優先度 低（今は不要、将来の注意）

### 8. 外部のAIのモデル料金
MCP でつながる外部のAIは、自分のモデルの料金を自分で払う。中継の `meterInference` は中継の中の runner 用。外部のAIに中継の予算からモデル料金を払わせる仕組みは作らない（作るなら、料金の証明が要る）。デモでは、局所の確かめのために中継の meter を使った。

### 9. 速さの上限
`agent_act` は今、住所ごと 40/2秒、代理ごと 30/1秒。人間と同じ「1時間30回」（24 の共通の決まり）と合わせるかは、中継の担当が決める。
