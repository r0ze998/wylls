## 1. ④の質問：送り手ごとの capability の持ち主を、依頼者（actor・generation）に結び付けられるか

**事実（⑤の relay、④ 970c50a1 と同じコード）：**
- capability の記録は `{hash, version, issuedAt}` だけです。そこから分かるのは、代理の財布の所有者（`rec.owner`）と session の鍵（`rec.agentKey`）だけです。
- NFT の持ち主の generation と Citizen は、認証の時には決まりません。送信を作る時に、④の住民の確認（`residentRefusal`）で、その時の値を読むだけです。
- capability で認証した要求を、④の `run accept` に渡す route はありません。

| 案 | 中身 | 実際の影響 |
|---|---|---|
| R-a 発行の時に結ぶ | capability を出す時に、その時の持ち主の generation と Citizen を記録する。持ち主が変われば、その capability は無効 | 依頼者が固定され、監査しやすい。持ち主が変わると token の出し直しが要る。新しい欄と規則（共有コア） |
| R-b 依頼の時に読む | intake を呼ぶ時に、持ち主の generation をその場で読み、actor・generation として渡す | 新しい欄は要らない。読めない時は拒否（今の `ResidentUnverified` と同じ）。読んだ時と送る時の間の譲渡は、送る時の確認に頼る |
| R-c 結ばない | capability の経路からは intake を呼ばない | 何も増えない。⑥・⑬の run の経路は `NotAuthorized` のまま |

**提案：R-b**
- 今ある住民の確認と同じ考え方で、新しい保存の欄が要りません。
- 読めない時に拒否する点も、今と同じです。
- ただし、route を足すこと自体が新しい入口なので、D1・D5 と一緒に決める必要があります。

## 2. D1：計画を誰が動かせるか（計画と依頼者の結び付け）

| 案 | 実際の影響 |
|---|---|
| D1-a 採用に、財布で署名する | 新しい署名の方式になり、承認の画面が増える。代理（AI）は採用できない。最も強い |
| D1-b Citizen で結ぶ | 新しい署名は要らない。その Citizen の session（代理を含む）なら、採用済みの計画を何度でも動かせる |
| D1-c 採用は財布、実行は session | 採用の時だけ一度署名する。各回は今の認証のまま。代理は、本人が採用した計画だけを動かせる |

**提案：D1-c**
- 計画を採用できるのは本人だけで、代理ができるのは、採用済みの計画を、本人の予算と期限の中で動かすことだけ、という境界になります。
- ⑤の今の考え方（本人が委任し、代理はその中で動く）と同じです。
- 代償：財布の署名の画面が1つ増えます。

## 3. D3：`deadlineSlot` と `budget` をどこから取るか

| 案 | 実際の影響 |
|---|---|
| D3-a route が固定の値を入れる | 簡単。ただし本人の上限と関係がなく、気づかない支出の恐れがある。勧めない |
| D3-b 本人の委任（mandate）から取る | 本人が決めた上限と期限の中だけで動く。値が無ければ拒否。手数料（lamports）の上限の欄を、委任に新しく足す必要がある（今の⑤の予算は test-USDC で、単位が違う） |
| D3-c 計画ごとに本人が入れる | 細かく決められる。毎回の入力が要る。代理は値を作れない |

**提案：D3-b**
- 委任に、手数料の上限（lamports）と期限を、それぞれ別の欄として足します（test-USDC の予算と混ぜない）。
- 期限は⑤と同じく 30 日までにし、合計の上限を必ず入れさせます。
- `deadlineSlot` は委任の期限より後にしません。slot と unix の秒の換算をどこで行うかは、④の判断です。
- 値が無い・単位が合わない時は、拒否します。

## 4. D5：どの route が intake を呼ぶか

| 案 | 実際の影響 |
|---|---|
| D5-a ③も⑤も route にならない | 何も増えない。intake は MCP クライアントの側（act の経路）だけ。④の run（到着・量の判定）は使わない |
| D5-b ③が route（MCP の道具） | 新しい入口。③の OAuth の主体（owner・agentId・linkId）には citizen と generation が無いので、R-b の読み取りが要る |
| D5-c ⑤が route（自動運転・ブラウザ） | **自動運転の行動の範囲が物流（run）まで広がる。** ⑤が今止めている「到着量を検証できない隊商」を扱うことになる |

**提案：今は D5-a**
- D1・D3 と R-b が決まった後なら、D5-b を、③の道具1つから始めます。
- D5-c（⑤を route にする）は、自動運転の行動の範囲の判断なので、別に決めてください。⑤からは勧めません。
