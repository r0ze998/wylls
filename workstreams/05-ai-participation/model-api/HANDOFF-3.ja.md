# ③への引き継ぎ：本人の MCP と⑤の自動運転が、同じ Citizen を使うときの境界（提案、2026-10-30）

**③の契約の実物（`47b05ac6`、パッチ 0005）は、この環境にありません。** ここにあるのは、⑤の側で実装してテストした境界です。今の中継から読める物だけを使っています。③の側の約束は、§3 の欄が決まるまで⑤の仮定です。

## 1. 前提（コードで確認済み）

同じ Citizen と同じ代理の上で、次のものを共有しています。
- **session 鍵は1つ**（Citizen に1つ）。⑤は設定も変更もしない
- **中継の台帳と、1日の予算は1つ**（代理1つにつき1つ）
- **後払い取引の1日の枠**（Citizen 単位）
- **中継の記録**（`agent_view.history` の最新 50 件と `historySeq`）

**記録の上での区別：** MCP の `agent_act` は、今は `source: 'mcp'` に固定で、冪等キーも `mcp:<requestId>` です。⑤と③の操作は、requestId の接頭辞でしか区別できません（⑤は `p05.`）。パッチ 0003 を当てると、⑤は `source: 'ai'`・キー `ai:p05.…` で記録されます。

## 2. ⑤が守ること（実装済み：`src/citizen-boundary.mjs`。テスト：`test/citizen.test.mjs`）

| 境界 | ⑤の動き | 止まる時のコード |
|---|---|---|
| 順序（seq） | 観測した時の `historySeq` を印にする。送る直前に、印より後の記録に⑤以外の操作（別のクライアントの操作、本人の命令、出金）があれば、その観測では送らない。次の回に観測し直す | `OwnerActed` |
| 記録の窓 | 窓（最新 50 件）が印まで届かなければ、本人が操作したか分からないので、送らない | `HistoryGap` |
| 取引の枠 | 送った後にも、本人の分（既定 1件）が残る時だけ判断する。残らなければ、モデルも呼ばない | `QuotaReservedForOwner` |
| 1日の予算 | 次の操作の後にも、本人の分（既定 0）が残る時だけ判断する | `BudgetReservedForOwner` |
| session 鍵 | 設定も変更もしない。代理の鍵が session でなければ始めない・止まる | `NotReady`・`NotDelegated` |

**テストで確かめたこと（HTTP の fixture、Claude・GPT の両方）：**
- ⑤のモデルが考えている間に、③の代わりのクライアント（同じ代理の2つ目の MCP、requestId `o3.…`）が操作すると、⑤はその観測では送らない（`OwnerActed`）。次の回には送る。
- 本人の分の枠や予算が残らない時は、モデルを呼ばない（要求も予約もない）。
- 記録の窓が届かない時は送らない（`HistoryGap`）。

**この境界で守れないこと：**
- ③が、⑤の観測の前後の印を見ずに、同時に送ること（③側の約束が要る）。
- 同じ代理を使わない③の操作（本人のウォレットから直接チェーンへ）。中継の記録に出ないので、⑤には見えない。
- 2つ目の⑤のプロセス（検出しない）。

## 3. ③に決めてほしい欄（契約にするために必要な物）

| 欄 | 何のため | ⑤の今の仮定 |
|---|---|---|
| ③の requestId の接頭辞 | ⑤の操作と分けるため | `p05.` 以外は⑤のものでない |
| ③の `source` | 中継の記録で分けるため（パッチ 0003） | ③は `mcp`、⑤は `ai` |
| ③が使う代理と資格情報 | 同じ台帳・同じ予算かどうか | 同じ代理の接続トークン |
| ③は⑤の印を尊重するか | ③が先、⑤が後の順を、両側で守るため | ⑤が一方的に引く |
| 本人の取り分（枠・予算） | ⑤が使い切らないため | 枠 1件・予算 0 |
| ③が操作中の印 | ⑤を一時的に止めるため（`mode manual` か、中継の新しい印か） | なし（seq の確認だけ） |
| session 鍵の持ち主 | 1つしかないため | 代理の鍵（本人がウォレットで委任） |
