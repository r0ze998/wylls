# ③への引き継ぎ：本人の MCP と⑤の自動運転が、同じ Citizen を使うときの境界（提案、2026-10-30）

**2026-10-30 に③の実物（ws03-handoff-v4、HEAD `acdcd0bf`、パッチ 0005 を含む）を受け取り、照合しました**（`RECEIVED-2026-10-30.ja.md`）。下の §2 の境界を、③の本物の MCP サーバーと同じ代理の上で試しました（§5）。③の側の約束（§3）は、まだ③が決める事項です。

## 1. 前提（コードで確認済み）

同じ Citizen と同じ代理の上で、次のものを共有しています。
- **session 鍵は1つ**（Citizen に1つ）。⑤は設定も変更もしない
- **中継の台帳と、1日の予算は1つ**（代理1つにつき1つ）
- **後払い取引の1日の枠**（Citizen 単位）
- **中継の記録**（`agent_view.history` の最新 50 件と `historySeq`）

**記録の上での区別：** MCP の `agent_act` は、今は `source: 'mcp'` に固定で、冪等キーも `mcp:<requestId>` です。⑤と③の操作は、requestId の接頭辞でしか区別できません（⑤は `p05.`）。パッチ 0003 を当てると、⑤は `source: 'ai'`・キー `ai:p05.…` で記録されます。

## 2. ⑤が守ること（実装済み：`src/citizen-boundary.mjs`。テスト：`test/citizen.test.mjs`）

| 境界 | ⑤の動き | 止まる時のコード |
|---|---|---|
| 順序（seq） | 観測した時の `historySeq` を印にする。送る直前に、印より後の記録に⑤以外の操作（別のクライアントの操作、本人の命令、出金）があれば、その観測では送らない。次の回に観測し直す | `OwnerActed` |
| 記録の窓 | 窓（最新 50 件）が印まで届かなければ、本人が操作したか分からないので、送らない | `HistoryGap` |
| 取引の枠 | 送った後にも、本人の分（既定 1件）が残る時だけ判断する。残らなければ、モデルも呼ばない | `QuotaReservedForOwner` |
| 1日の予算 | 次の操作の後にも、本人の分（既定 0）が残る時だけ判断する | `BudgetReservedForOwner` |
| session 鍵 | 設定も変更もしない。代理の鍵が session でなければ始めない・止まる | `NotReady`・`NotDelegated` |

**テストで確かめたこと（HTTP の fixture、Claude・GPT の両方）：**
- ⑤のモデルが考えている間に、③の代わりのクライアント（同じ代理の2つ目の MCP、requestId `o3.…`）が操作すると、⑤はその観測では送らない（`OwnerActed`）。次の回には送る。
- 本人の分の枠や予算が残らない時は、モデルを呼ばない（要求も予約もない）。
- 記録の窓が届かない時は送らない（`HistoryGap`）。

**この境界で守れないこと：**
- ③が、⑤の観測の前後の印を見ずに、同時に送ること（③側の約束が要る）。
- 同じ代理を使わない③の操作（本人のウォレットから直接チェーンへ）。中継の記録に出ないので、⑤には見えない。
- 2つ目の⑤のプロセス（検出しない）。

## 3. ③に決めてほしい欄（契約にするために必要な物）

| 欄 | 何のため | ⑤の今の仮定 |
|---|---|---|
| ③の requestId の接頭辞 | ⑤の操作と分けるため | `p05.` 以外は⑤のものでない |
| ③の `source` | 中継の記録で分けるため（パッチ 0003） | ③は `mcp`、⑤は `ai` |
| ③が使う代理と資格情報 | 同じ台帳・同じ予算かどうか | 同じ代理の接続トークン |
| ③は⑤の印を尊重するか | ③が先、⑤が後の順を、両側で守るため | ⑤が一方的に引く |
| 本人の取り分（枠・予算） | ⑤が使い切らないため | 枠 1件・予算 0 |
| ③が操作中の印 | ⑤を一時的に止めるため（`mode manual` か、中継の新しい印か） | なし（seq の確認だけ） |
| session 鍵の持ち主 | 1つしかないため | 代理の鍵（本人がウォレットで委任） |

## 5. 受領した③のコードとの照合（2026-10-30）

| 項目 | ③の実物 | ⑤の対応 |
|---|---|---|
| 冪等キー | `ws03:<linkId>:<requestId>`、`source: 'mcp'`（③自身のサーバーで、`agent-mcp.mjs` ではない） | ⑤の境界は `ws03:` を「本人の MCP（③）」と読む |
| ③の文書「runner は `ai`」 | 中継の中の runner のこと | ⑤の自動運転は `agent-mcp.mjs` を通るので、今は `mcp`。パッチ 0003 で `ai` |
| capability | 同意（caravan のスコープ）の時に、本人が `rotate-capability` に署名する | **代理1つに1つなので、③が接続すると⑤の token は無効になる**（逆も同じ）。⑤は `BadCapability` で自動運転を止める。分け方は共有コア（④）の判断：`CONTRACT-DIFF-4.ja.md` §2.1 |
| mode | 1つで全員に効く | ⑤の停止は⑤だけを止める。中継の mode は分けない |
| SendCaravan | パッチ 0005 で代理人の行動になる（既定では許されない） | **⑤の判断：** 本人が `transport` 群を選んだ時だけ有効、で良い。ただし**⑤の自動運転は隊商を送らない**（到着量を検証できないことがあり、⑤はそれを数えも表示もできない）。価格は付けない（`prices.game.SendCaravan` は空のまま）。runner の候補にも加えない |
| 0005 と⑤の 0001 | ③は照合していなかった（⑤の資料が無かった） | 0001 とは、どちらの順でも当たる。0002 とは文字の上で衝突し、0002b で解く（`CONTRACT-DIFF-4.ja.md` §1） |

**試験（`integration/ws03-same-citizen.test.mjs`、③の本物のサーバー、試験用の鎖）：**
1. ③の同意で token が回ると、⑤の古い token の操作は `BadCapability` になり、何も送られない。
2. 同じ token を共有した場合（今これしか両立の方法が無いという仮定を試すため、試験の中だけで token を写す）：⑤のモデルが考えている間に③が隊商を送ると、⑤はその回は送らない（`OwnerActed`、記録 `ws03:…`）。次の回に送る。
3. 本人が⑤のために token を回すと、③は送れない。

## 6. capability の競合について（2026-10-30 追記）

- ⑤は token を回しません。③の封印された token を無効にする操作は、⑤には一つもありません。
- ⑤は `BadCapability` を受けたら止まり、本人が新しい token を渡した時だけ再開します。その token は、モデルを呼ぶ前に確かめます（代理・所有者・範囲・有効性）。
- ③と⑤が同時に書き込むための形（送り手ごとの capability、送信の窓口の一本化など）は、④の統合判断です。選択肢は `AUTH-OPTIONS-4.ja.md` にあります。③の同意の流れ（今は回す）が変わるかもしれない点を、③の判断事項として挙げています。
- ③の本物のサーバーを使う競合の再現試験（予算・隊商の番号・手動の優先・取消・再起動）は `CONTENTION-SCENARIOS.ja.md` にあります。
