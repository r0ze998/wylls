# ⑤：世界が続く前提での点検と変更（2026-10-31）

**前提：** Wylls の世界は、一定期間で終わったりリセットしたりしません。戦期（戦争や競争の区切り）は世界の寿命とは別で、区切り方・集計・賞金は未決定です。⑤はそれらを決めません。World／Period の正本や移行処理も作りません（④・⑧の担当）。この文書の「境界」は、試験の中だけの時刻です。

**⑤の担当（方針）：** 予算と委任の有効期限は維持します。世界が続くことを理由に、認可を永久にしたり、予算の上限を外したりしません。

## 2. 変更した挙動（⑤のコードだけ。共有コードは変えていない）

| 変更 | 場所 | 中身 |
|---|---|---|
| **権限を有限に保つ** | `src/bounds.mjs`、`autopilot.mjs`（開始・再開の前） | 委任条件に期限が無い・期限が30日より先・推論の予算に総額の上限が無い、のどれかなら開始も再開もしない（`MandateUnbounded`・`MandateTooLong`・`BudgetUnbounded`）。モデルを呼ぶ前に確かめる。更新するのは本人で、⑤は延ばさない |
| 費用の台帳を、再起動しても失わない | `run-cost.mjs` `toJSON`・`fromJSON` | 保存した状態から新しいプロセスで復元する。復元の時に、呼び出し中は「未確定」、呼ぶ前の予約は「解放」（再起動の規則） |
| 長く動いても台帳が膨らまない | `run-cost.mjs` `compact` | 前の日の確定・解放の項目を、日ごとの合計にたたむ。上限の計算は、たたむ前と同じ答えになる。**未確定・予約・呼び出し中は決してたたまない**。たたんだキーは 35 日（session の最長 30 日より長い）覚えていて、同じキーで二度予約させない |
| 記録と判断の記録に上限 | `run-cost.mjs`（記録 2,000 件）、`inference.mjs` `DecisionRegistry`（終わった判断 10,000 件、古い物から）、`run-receipt.mjs` `prune` | 飛行中の判断と、開いている受領証は消さない |

これらは「シーズン」という名前を変えたのではなく、**終わりで捨てられることを前提にしない**ための変更です。

## 3. 試験で確認したこと（`test/continuing.test.mjs`、5件。すべて通過）

**境界：** 試験の中の時刻（世界の時計の UTC の0時。⑤の1日の推論の上限が切り替わる所）。世界を終わらせる物ではありません。

| # | 確かめたこと |
|---|---|
| T1 | 期限の無い委任・30日を超える委任・総額の上限の無い予算は、モデルを呼ぶ前に断られる。本人が更新すれば始められる |
| T2 | session が切れると、⑤はモデルを呼ばず、委任を延ばさない。**見つけたこと：** 中継の時計のキャッシュ（壁時計で 1 秒）の間は、まだ「委任あり」に見える（試験は待ってから確かめる） |

## 4. 移行や仕様の判断が残る点（④・⑧へ）

1. **Citizen と委任の識別子をシーズンから切り離すか。** 今は Citizen がシーズンごとなので、委任（session）もシーズンごとに作り直しになります。⑤は、委任の期限（最長30日）と本人による更新を前提にしています。識別子が変わっても、この前提は変えません。
2. **中継がシーズン ID に結びつく設定**（`app.mjs:128`）をどうするか。切り替えの間、⑤の自動運転は止まります（試験 T4）。
3. **program のシーズンの状態の確認**（`prologue.rs:1102`）を、戦期の区切りにどう使うか。戦期の終わりに、通常の操作（⑤の自動運転を含む）を止めるのか。⑤は止めることを前提にしていません。
4. **中継の時計のキャッシュ**（壁時計で 1 秒・5 秒）：委任の期限の直後と、切り替えの直後の扱い。
5. **1日の区切りが2つある**（中継は壁時計、⑤は世界の時計）。どちらに合わせるか。
6. **⑤の費用の台帳は mock** です。本物の台帳とその保存・圧縮は④の契約で決まります。⑤の `toJSON`・`compact` の規則（未確定をたたまない、キーを 35 日覚える）を、④への要件として渡します。
7. **実行の記録（`RunJournal`）のファイルの増え方**：回転や④の run store への移行。run id の続きはこの記録から読むので、回転しても最後の run id は残す必要があります。
8. **戦期・賞金・参加費：** ⑤の予算は、戦期ごとの参加費や NFT パスの買い直しを前提にしていません。料金の周期は決めていません。
