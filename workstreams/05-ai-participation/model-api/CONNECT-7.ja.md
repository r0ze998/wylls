### 2.1 SendCaravan の重複拒否（0006）

- 中継の `Duplicate` は、「**この全く同じバイト列が、前にもう出ている**」という意味です。同じ Citizen の同じ seq なので、効果も同じです。これは、過去に送っていないことの証明になりません。
- 今：
  - 答えは `failed` で、`sent: null`、code は `Duplicate` です。
  - 前の送信の署名（中継の `Duplicate` の答えに入っている）と寿命を付けます（`duplicateOf`・`signature`・`lastValidBlockHeight`・`slotFloor`）。
  - 呼び出し側は、その署名の fate を追います。
    - `pending`・`unknown`（結果不明）・`unqueryable`（照会不能）の間は**保留**
    - `landed` なら、効果は起きた
    - 証明された `expired` の時だけ、新しい試行ができる
  - 署名が無い時は `unknown`（保留）です。
- この要求の分の hold は戻します（この要求は何も送っていない）。
- ④の `actionFateView` の読み方と、④の GatewayPort（`sent` が無い・null なら保留）、⑤の participate（`failed` で `sent` が false でなければ追う）のどれも、保留の側に倒れます。
- この道は、作る時に署名するので、鍵を使わない試験では通していません。試験は、記録の形を④の `actionFateView` で読んだ結果で確かめています。

### 2.2 Citizen ごとの送信の列（0006、B1）

- 同じ所有者の代理の行動（Citizen も session 鍵も1つ）は、中継のプロセスの中で、作る → 署名 → 送る を**1つずつ、届いた順に**行います。
- 一般の送り手（③の MCP、⑤の自動運転、中継の中の runner、所有者のブラウザの `action` 命令）は、すべて `submit` を通るので、同じ列に入ります。
- 1つが失敗しても、列は次に進みます。別の Citizen は待たされません。
- 冪等の記録で返せる繰り返しは、列に並びません。
- 限界：列の中の1つが RPC で止まり続けると、その Citizen の後ろも待ちます（今の `#run` には時間切れが無い）。

## 3. ⑬：費用の予約の直後に止まった場合

- **⑬の指摘：** ⑬は「⑤に予約した直後、⑬の状態を保存する前に止まると、⑬はその鍵を知らない。⑤の `recoverStale` で戻るはずだが、試験が無い」と書いていました。
- **⑤の変更：**
  - `FileCostLedger.openFenced({dir, lease, init})` を足しました。lease を先に取り、その後で、前の持ち主が残した物に再起動の規則を当てます。
  - 規則：呼ぶ前の予約は解放します。呼び出し中の物は**未確定**にします（解放もせず、0 にもしない）。
  - ⑬が鍵を知らなくても、⑤だけで回復します。
- **試験（`test/ws13-stop.test.mjs`、本物の子プロセスを SIGKILL、鍵なし）：**
  - W1 予約の直後に停止：回復するまでは、その額が上限に数えられます（二重には使えない）。次に開いた時に解放されます。古い鍵は使い回しません。もう一度開いても何も変わりません。
  - W2 呼び出し中に停止：未確定のまま、額も残り、上限にも数えられます。証拠の無い返金（0 にすること）は拒否されます。
  - W3 別の生きたプロセスが持っている時：開くことを拒否します（`AlreadyRunning`）。その予約には触りません。
- **⑬への提案：** ⑬の `ws05Factory` は、`lease.acquire()` と `new FileCostLedger` を別々に呼んでいます。`FileCostLedger.openFenced` に替えると、順番の間違いが起きません。⑬のコードは変えていません。

## 4. 複数の機械では保証できない部分

| 保証 | 範囲 | 複数の機械では |
|---|---|---|
| 1つの代理に1つの自動運転（⑤の lease） | 同じファイルシステムの、同じ機械のプロセス | **保証しない。** 別の機械のプロセスは見えません。共有のファイルシステム（NFS など）では、`O_EXCL` と rename の性質も、pid の生死の判断も信用できません |
| 費用の予約が二重にならない（⑤の台帳） | 同上（ファイルの mutex） | **保証しない。** 機械ごとに台帳が別になれば、上限は機械の数だけ使われます |
| 予約直後の停止の回復（openFenced） | 同上（pid で生死を見る） | **保証しない。** 別の機械の pid は見えません |
| Citizen ごとの送信の列（0006） | 1つの中継プロセスの中 | **保証しない。** 中継のプロセスや機械が複数あれば、列は別々です。今の代理の財布は、状態ファイルを1つの中継プロセスで使う作りです |
| 実行が1回（中継の冪等の記録） | 1つの中継の状態 | **保証しない。** 中継が別々の状態を持てば、同じ requestId でも別々に実行されえます |
| 行動の登録簿（④の run store、SQLite） | 1つの DB ファイル | **保証しない。** 機械をまたぐなら、④の store を共有の DB にする必要があります |
| 鎖の上で効果が1回 | SendCaravan の seq（program が検査） | 鎖が守ります（機械の数に関係なく、効果は1回）。ただし、手数料と予算の二重は防げません |
| 所有者のウォレットからの直接の送信、鍵を持つ者の RPC への直接の送信 | — | どの仕組みの列にも入りません（④ AUTH-ROUTES の R4・R3） |
