## 4. 試作の使い方

- **クリック可能な試作**：`tower-proto.html`（1ファイル。ブラウザで直接開ける。外部の読み込みなし）。
  - 左で案（A/B/C）と状況を選ぶ。同じ「種」なら同じ土地・人・さいころから始まる。
  - 「あなたの村」で一つの村を操作する（例：小国・遠い・途中参加・資源少）。他の村の AI は**あなたと同じ選択肢の一覧**から選ぶ（`model.mjs` の `optionsFor` → `apply`）。
  - 「3案を比べる」タブで、選んだ状況またはすべての状況を、同じ種から3案で走らせて平均を出す。
  - 仮の数字は「仮の数字を切り替える」から変えられる（配置＝⑧の仮置き、依頼の見え方＝①の仮置き、期限と返金、使える人など）。
- **元のソース**：`proto/`（`geometry.mjs` 地図の計算、`model.mjs` 模型、`adapters.mjs` ①⑧⑮との接続点、`compare.mjs` 比較、`ui.mjs` と `index.html` 画面、`build.mjs` で1ファイルにまとめる）。
- **ローカルの試験**（repo の根から）：
  ```sh
  node --test workstreams/14-central-tower/proto/*.test.mjs workstreams/14-central-tower/game/*.test.mjs   # 35件。地図の計算をクライアントの fgeo.mjs に固定する試験、継続する世界の通し試験、⑮へ渡す事実の契約の試験を含む
  node workstreams/14-central-tower/proto/batch.mjs 30             # results/RESULTS.json（約50秒）
  node workstreams/14-central-tower/proto/report.mjs               # results/RESULTS.ja.md
  node workstreams/14-central-tower/proto/build.mjs                # tower-proto.html
  ```

模型の要点：1時間ごとに収入・到着・行動。村は1日2・4・6回のいずれかで訪れ、1回に2行動。物々交換の依頼（①の代わり）、隊商の移動時間と発送回数は規則の定数から計算（32歩・4州で1回の発送、超えると次の訪問まで止まる）。損失は通過した州の数と、中央付近で襲撃者がいるときの追加分。

### 5.3 中心にあることで生じる距離の有利不利と物流の集中

- 中心は6国から等距離なので、**国ごとの有利不利は地図の形からは生じません**（各国の扇は輪1で中心に接する）。差は国の中の「輪」で生じます。
- B は荷を中央に集めないので、中央の環を通る荷は面積比（0.19）より少ない 0.06。
- C は中央の環に 0.44（面積比の2.3倍）、大協約の州だけで 0.22 が集まり、**襲撃がそこに集中**して失う荷車が取引あたり A の約7倍（0.34 対 0.05）になりました。分散配置では面積比0.03に対し0.29（約10倍）。
- 遠い村の代償は、育ちの差よりも**発送の回数（＝人の手間）**に出ます。模型では手間が余っている（どの案でも「何もしない」が多い）ため、育ちの差に表れにくい点に注意してください。

### 5.4 反証：共同事業の名目で、全員に同じ単純作業を強制していないか

- **B**：塔のための作業はありません。掲げる・応えるは、自分の村のためにもともとする行動と同じです。強制はない、と言えます。ただし AI は応答がないとほぼ必ず掲示するため、参加者は38村中34村になり、「事実上みんな使う」状態になります。
- **C**：反証できませんでした。役割の記録（基本、30種平均）は「自分で運ぶ 190・差し出す 51・運び手 50・**護衛 420**・維持費 8」。多様さは 1.54 bit（5役割で最大2.32）、一人の仕事のうち**同じ役割が平均70%**。中身は「中央へ運ぶ」と「中央の道を護衛する」の繰り返しで、役割の名前は違っても、ほぼ同じ単純作業です。参加しない自由は残っていますが（参加しなくても育てられる）、参加した人には単純作業が集中します。分散配置では遠い村が「差し出す」「運び手」に分かれるので多様さは 1.80 bit に上がりますが、同じ役割の割合は65%です。

## 6. 限界

- 玩具の模型です。人間の面白さ、読み合い、会話、信頼は表していません。結果は「この仮定ならこうなる」以上の証拠ではありません。
- **B の効果は、依頼が自国にしか見えないという仮定から生じています。** ①の現行の依頼の板は依頼を全国に見せており（9.2）、それに当たる `world_visible` の状況では B は A と完全に同じです。
- 人の手間（訪問回数）が余っている設定です。手間が限られると、遠い人・途中参加者の不利は大きくなるはずです。
- AI の方針は単純な優先順位です（育てる → 依頼 → 交換 → 塔）。違う方針で結果は変わります。妨害者・独占国の行動も一つの型だけです。
- 経路は州の直線で近似しており、実際の地形・道は使っていません（距離は規則の定数で計算）。中央付近の襲撃は「襲撃中なら損失が増える」だけの単純化です。
- 1段階の必要量・期限・維持費・手数料などはすべて仮の数字です。C の完成率はこれらで大きく変わります。
- 比較の表は14日の観察です（期間の長さではありません。期間は未決定）。期間の区切りや再起動をまたいでも状態が続くことは試験で確かめましたが（12章）、16週を超える長期の比較の表は作っていません。

## 7. 比較からの見立てと代償（採否は未決定）

**見立て：B「掲示の塔」が比較の中では代償が小さい。ただし B に意味があるのは、①が「国をまたぐ依頼を自国にしか見せない」と決めた場合だけ。①の現行の板（依頼を全国に見せる）のままなら、B は A（目印のみ）と同じで、塔の役割は保留になる（9.2）。** どの案も採用していません。

理由：
1. 物を中央に集めないので、物流の集中・中央での襲撃・独占の入口を新しく作らない（独占の状況で変化なし）。
2. 小国・途中参加者・資源の少ない人も伸びる。参加しない人が損をしない（区間が0をまたぐ）。
3. 塔のための単純作業がない。参加は自分の村のための行動の延長。
4. 所有者のいない中立という、今のコードの性質を保てる。

B の代償：
- 必要なものが全国に知られ、荷車が狙われやすくなる。偽の依頼も全国に届く（払われない依頼が増える）。
- 固定連合があると、連合の外の人が少し損をする。
- 「依頼を全国に見せる」ことは、場所が中央の塔である必然性が薄い。画面の一覧でも同じことができる。塔に置く理由は「中立の場所に掲げる」という見せ方だけ。
- ①と機能が重なる。

C を勧めない理由：中央に荷と襲撃が集中し、独占・連合・ただ乗りの影響を一番受け、参加者には同じ単純作業が集中しました。完成すれば参加者は伸びますが、参加しない人は退出・輸送の失敗の状況で下がり、独占・分散配置でも下がる傾向でした。C を採るなら、少なくとも「中央の倉を複数の場所に分ける（⑧の分散配置と組み合わせる）」「護衛以外の役割の中身」を先に設計する必要があります。

## 8. 採用前にユーザーが決める事項

1. **塔に役割を持たせるかどうか**（A のまま目印にするか）。
2. ①の国をまたぐ依頼は誰に見えるのか（自国だけ／連合／全国）。①の現行の板は全国。全国のままなら B は A と同じで、B を検討する意味がなくなります。
3. 大協約に個人の倉や物見櫓を建てられる今の状態を続けるか（独占の入口。どの案にも関係）。
4. B を採る場合：掲示の手数料をどうするか（燃やす・誰かに渡す・なし）、必要の公開による襲撃のしやすさを許すか、偽の依頼の記録の残し方。
5. C を採る場合：中央に物を集めることを許すか。期限と返金（refund）か進捗が残る形（keep）か。使える人を「誰でも」にするか「出した人だけ」にするか（ただ乗りと効果のどちらを取るか）。維持費が尽きたときの扱い。
6. 塔の事実（掲示・完成・休止・襲撃など）を⑮の達成・勝利の評価に使うかどうか（⑭は事実を渡すだけ）。
7. 旧設計の Engine（5段階・文明の取り分・賞金）を正式に廃止とするか。新しい設計は触れておらず、決定ログにも記録がありません。
8. 鐘楼の絵をそのまま使うか。新しい設計の用語の決まり（「鐘」と書かない）と、クライアントの呼び方（鐘・bell）が食い違っています。
9. 継続する世界で、塔の状態を本番のどこに置くか（12.4）。今のチェーンでは中央の州・倉・建物のアドレスがシーズンごとに変わり、州はシーズン終了の72時間後に閉じます。これは④・⑧の共通方針で決まり、⑭は独自に決めません。
10. C を採る場合、塔の「段階の期限」と期間の区切りを結び付けるか。今の試作では結び付けていません（期限は塔の規則で、区切りでは何も起きない）。

### 12.2 変更した挙動（⑭の試作）

- 世界に終わりがない。`days` は観察する長さで、`extend` でさらに観察できる。観察を延ばしても新しい世界にはならない（14日＋14日は28日と同じ記録になる）。
- 期間の区切り `periodHours` は「仮・未決定」の切り替え。区切りは `period.boundary` の事実として記録するだけで、何も戻さない・閉じない・精算しない。
- 状態を丸ごと保存・再開できる（`snapshot`／`restore`）。隊商は「到着したら何をするか」をデータで持ち、乱数の状態も保存する。
- 終わった依頼・申し出・差し出し・襲撃・護衛は、生きている一覧から外す。履歴は事実の記録に残る。
- 物の帳簿を足した：最初の量＋収入−（育成・建設・維持費・手数料・護衛・損失・没収）＝今どこかにある量（`ledgerGap`）。「没収」は退出した村の差し出しだけで、期間の区切りでは起きない。
- C の段階の資材を、維持費に使う在庫と分けた。完成時に余った分だけ在庫に入る。期限切れの返金は資材から返し、去った村の分は在庫に残る。
- 画面は「終了」を「何日目まで観察（世界は続いています）」に改め、「さらに7日観察する」と区切りの切り替えを足した。

C の在庫の修正で、C の数字だけが少し変わった（5章は取り直した値）。A と B は変わっていない。区切りなしの比較は、作り直しの前後で 12 状況 × 3 案 × 30 種の結果が完全に一致することを確かめてから、在庫の修正を別の commit にした。
