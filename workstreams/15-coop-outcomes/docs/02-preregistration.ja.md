# 検証前に決めたこと（事前登録）

作成 2026-10-30。**評価器のコードと試験を書く前に**この文書を commit した（commit の順序は `git log -- workstreams/15-coop-outcomes/` で確かめられる）。後で書き換える場合は、消さずに「変更」節に理由と日時を足す。

この文書の数字（3か国、10%、24 鐘など）はすべて**暫定**で、採用案ではない。比べるための置き値である。

## 1. 比べる案（最大3つ）

| 記号 | 名前（暫定） | 一言 |
|---|---|---|
| **A** | `baseline-competitive` | 現行コードの勝ち方だけ。終了時に要塞（keep）を最も多く持つ国、同点は領土の時間、なお同点は等分。共同・国・個人の目標は**判定しない**（未採用のルールを混ぜない） |
| **B** | `separate-tracks` | 共同達成・国の目標・個人の目標を別々に判定する。共同達成では戦期も世界も終わらない。勝敗と賞金は A と同じ |
| **C** | `joint-chapter` | 共同達成（使われるところまで）が成立すると、予告の後に**その戦期を区切る**。何が終わり何が続くかを判定結果に書く。勝敗と賞金の計算方法は A と同じだが、**数える時刻**が変わりうる |

どの案も、賞金・外からの補助金を足さない。判定結果は「達成」「得点」「資源」「賞金」を別の欄に出し、相互に換算しない。

## 2. 重要な差（これが出なければ、案を分ける意味がない）

| # | 差 | 測り方 |
|---|---|---|
| D1 | 共同達成が、賞金を受け取る国を変えるか | 同じ入力で A/B/C の `prize.winners` を比べる |
| D2 | 一つの国（またはその国と、その国に従う国）が戦期を早く終わらせられるか | 早期終了の悪用シナリオで `period.closedBy` と閉じた時刻 |
| D3 | 新規参加者・小国・敗者・協力しない人に、「待つ」「従う」以外の選択が残るか | 各人の `options` に、`category` が `wait`・`follow` 以外のものが1つ以上あるか |
| D4 | 妨害が、達成を遅らせるだけか、終了の時刻（＝賞金を数える時刻）まで動かすか | 妨害シナリオでの `period.closedAt` と達成の状態 |
| D5 | 固定した連合が、共同達成の取り分を独占できるか | 連合外の国の `credited` と選択肢 |
| D6 | 協力が「意味のある達成」を生むか | 協力シナリオで A には達成の記録がなく、B/C には理由つきの達成があること（A と同じなら協力は意味を持たない） |

## 3. 評価器が満たすべきこと（成功条件）

1. **再生できる：** 同じルールの版と同じ入力（イベント・初期状態）なら、入力の並び順・重複の有無にかかわらず同じ判定（`verdictHash` が一致）。ルールの版か入力が変われば `rulesetHash`・`inputHash` が変わる。
2. **理由を返す：** 判定の各項目に、理由の符号（`code`）と根拠のイベントの id がある。
3. **寄与の理由が、取引件数や配送量だけでない：** 共同目標への寄与として数えるのは「確かめられた到着 → 計画への投入 → 建設の完了で消費された量（要求量まで）」だけ。建設が完了し、さらに使われるまで、共同達成にはならない。配送しただけ・取引しただけの人は寄与者にならない。
4. **異なる資源を合計しない：** 進み具合は資源ごとの組で返す。一つの数にするときは最も足りない資源の割合（最小値）だけを使う。材料の投入・建設完了・実際の利用の3段階を別の欄で判定する。
5. **二重消費と重複報酬を区別する：** 同じ荷（lot）を二度投入すれば2回目を拒否する。同じ報酬枠（目標×戦期×受取人）に2度入れない。一方、一つの投入が共同・国・個人の**別々の目標**に数えられるのは正当で、拒否しない。
6. **記録の問題を扱う：** 往復取引・自己取引・共謀・期限後の到着・未検証量・重複・欠落・順序の逆転。欠落があるとき、その記録に頼る判定は「達成」でも「未達」でもなく「判定できない（`indeterminate`）」にする。
7. **本人識別：** 判定は模型のラベル（国・連合の印など）を使うが、判定結果に「本番で別人であることの保証ではない」と書く。
8. **⑭の塔は任意：** 塔の入力がなくても全試験が通り、塔の入力があるときだけ塔に関わる個人目標が開く。

## 4. 予測と反証の条件（試験を走らせる前に書いた）

| 仮説 | 予測 | 反証される条件 |
|---|---|---|
| H1（共通） | 荷の保存（同じ荷は一度しか消費できない）で、往復取引・自己取引は寄与を増やせない | 往復・自己取引のシナリオで、寄与量が実際に消費された量より大きくなる |
| H2（B） | 共同達成は賞金の受取国を変えない | 協力シナリオで B の `prize.winners` が A と違う |
| H3（C） | 「3か国以上・各国が少なくとも一つの資源で要求量の10%以上」の条件で、**一国だけ**では戦期を早く終わらせられない | 単独の早期終了シナリオで C の戦期が予定より早く閉じる |
| H4（C） | **一国と従う2国**なら早く終わらせられる（防げないと予測） | 予測が外れて防げた場合、その理由を記録する（防げたことを成功として水増ししない） |
| H5（共通） | 本人識別のラベルがない別アカウントは、多様性の条件を満たしてしまう（防げないと予測） | 同上。防げた場合は理由を記録 |
| H6（B・C） | 協力しない人・小国・新規参加者・敗者にも、独立した選択が1つ以上ある | `options` が待つ・従うだけの人がいる |
| H7（C） | 不利な国の妨害は、C では終了の時刻を動かす（＝ C は妨害に終了時刻を握らせる） | 妨害しても終了時刻が変わらない |
| H8（共通） | 欠落のある記録では、達成を断定しない | 欠落シナリオで `achieved` または `not_achieved` と断定する |

## 5. 試験の方針

- 大量の乱数試験で確信を水増ししない。**少数の具体的な失敗ケース**（各必須検証に1〜2件）と、手で遊べる比較の画面を優先する。
- 並び順の不変性だけは、決まった種で数通りの並べ替えを試す（乱数は固定の種）。
- 人間が理解できるか・面白いかは、**人間で確かめていないので「未評価」**とする。画面の試験は「動く」ことだけを示す。
