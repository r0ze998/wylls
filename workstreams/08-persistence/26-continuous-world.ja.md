# 26. 継続世界への移行設計（⑧ → ④）

**状態（2026-10-31）：** 方針の訂正（シーズン制の廃止、世界は継続）を受けた、移行の候補です。

- 隔離した環境での実装と検証です。本番への移行を実行する許可ではありません。
- 戦期の周期・集計・賞金の扱いは未決定のままで、何も採用していません。
- 既存のシーズン（終わるシーズン）は、互換性と既存の受取権を確かめるために残します。新しい世界を終わらせる根拠にはしません。
- 地図拡張の成果（`workstream/08-map-live` `c11b5c6c`）は保持し、その上に積んでいます。重複実装はしていません。

この章は、⑧が④へ渡す横断設計の正本の候補です。各担当が独自の World／Period の正本や移行処理を作らないよう、④で一本化してください。

## 26-2. 移行の方針（候補）

1. **世界の番号には、既存のシーズンの番号を使い続ける。**
   - すべての番地がシーズンの PDA から作られています。番号を変えると、既存の村・倉・記録がすべて新しい番地になり、読めなくなります。
   - 内部の型名 `Season` は残します。移行上の理由として、これは名前だけの問題で、挙動は下の 2・3 で変えます。
   - 1つの継続世界＝終わらない1つのシーズン、とします。世界を続けるために新しいシーズンを作ることはしません。
2. **継続の切替をシーズンの設定に持つ（`continuous`、征服ブロックの位置80）。**
   - 1 なら、`end_bell` と `join_close_bell` を「終わりなし」（`NO_END_BELL` = u32 の最大値）にします。
   - そのうえで、終わりを前提にした挙動を個別に変えます（EndSeason の拒否、キーパーの継続、画面・AI の文言、賞金プールの拒否など）。
   - 「終了時刻を巨大な値にする」だけではありません。巨大な値で壊れる箇所（ヘラルドの配列、掛け算の溢れ）も直します。
   - 0（既存のシーズン）の挙動は、1バイトも変えません。
3. **戦期は世界の寿命から分ける。** 戦期の周期・区切りで何を戻すか・集計・賞金は未決定です。今回は何も実装しません。
   - 戦期の候補として使える既存の仕組み：砦の保持の開始ベル、州ごとの領土の集計、`score_territory(b, end_bell)` と `laurel::accrue(to, end_bell)`。後の2つは、終わりのベルを引数で受け取るので、戦期の終わりを渡せます。
   - 置き場所の候補：Season v2 の予約領域（`RSV_552`）。
4. **賞金は、継続世界では作れないようにする（明示的な拒否）。**
   - 既存の終わるシーズンの賞金と受取権は、そのまま保護します。
   - 戦期ごとの賞金の仕組みは⑰と④の判断です。新しい料金の周期や賞金の制度は決めていません。
   - NFT の参加パスは前提にしていません。
5. **期限のあるものは、期限を保つ。** 鍵の期限（最長30日）、AI への委任（7日）、予算の日ごとの上限は、世界が続くことを理由に永久にしません。更新の流れが必要です（⑤、⑦）。
6. **既存のデータは書き換えない。**
   - 終わるシーズンは、旧版のまま再検証できるようにします。
   - 旧版の証拠を、新版の証拠として読み替えません。
   - 未完了の処理（終了をまたいだ隊商など）は、旧シーズンの不具合として扱います。直すかどうかは④の判断です。

## 26-5. 移行や仕様の判断が残る点（④・各担当へ）

1. **世界の番号：** シーズンの番号を世界の番号として使い続けてよいか（26-2 の1）。
   - 既存の終わるシーズンのデータを、継続世界へ移す処理はありません。
   - 作るなら、旧版の証拠を書き換えない形で、④が決める必要があります。
2. **戦期の正本：** 区切り・何を戻すか・集計・賞金。置き場所の候補は Season v2 の `RSV_552` です。
   - ⑮は期間を `windows: [{id, opensAt, endsAt}]` の形で外から受け取り、重なりを拒否する作りにしています。正本の形の候補になります。
3. **賞金：** 継続世界の賞金プールは今は拒否しているだけです。戦期ごとの賞金、参加費、未請求の扱いは⑰・④の判断です。NFT の参加パスを前提にしていません。
4. **長く続く世界の上限：** いずれも④の判断です。
   - 拠点の世代番号（8ビット）：同じ拠点を255回作り直すと失敗する。
   - 16ビットの回数：頭打ちになる。
   - 32ビットの秒数：約136年で溢れる。
   - シーズンの日数を基準にした保護の規則：「世界の最初の1週間だけの例外」になる。
5. **有限の資金：** 州の資金と防衛の資金をどこから補うか（④・⑰）。
6. **閉じる手段のないアカウント：** 国・決着できない隊商・旧シーズンの終了後の倉と構造物。旧シーズンの不具合2件（終了をまたぐ隊商、終了後の倉）を直すかどうか。
7. **キーパーの再起動をまたぐ送信：**
   - キーパーの「このベルのビーコンの記録は済んだ」という印がメモリにしかなく、再起動で消えるため、同じベルの記録を新しい回でもう一度送ります。
   - プログラムは古い回を拒否するので、状態と費用の重複はありません（キーパーの手数料だけ）。
   - 鍵に回の番号を含めるか、印を記録から復元するかの判断が要ります。
8. **鍵と委任：** 期限（最長30日、7日）は保ったまま、更新の画面と処理を作る（③・⑤・⑦）。
9. **AI：**
   - 記録の公開・封印・正体の開示は、シーズン終了に結び付いたまま。いつ公開するか（⑫・⑬）。
