## 24-2. A：同国分散配置

**仕組み：**

- シーズンの設定 `placement` で切り替えます。0 は今の規則（国＝扇形）で既定値、1 が分散です。
- 国の選択（Join の faction）はそのままです。
- placement 1 では、本国の輪2〜`heartland_max_ring` の州を、輪を一周する順に番号 i を付け、`(i + o_r) mod 6` の国に割り当てます。o_r は、シーズンの種と輪から sha256 で決めるずれです。
- 結果として、各国は輪 r ごとに r 個の州（6つおき）を持ちます。1州＝1つの小集団で、隣り合う州は必ず別の国になります。
- 国ごとの専用資源・固定の役割は足していません。

**本体プログラムで変えた所：**

| 処理 | 変更 |
|---|---|
| PlaceHome | 「自国の扇形」の判定を `home_nation` に置き換えた |
| OpenProvince | 本国の砦の持ち主と本国の守りを `home_nation` で決める（砦のマスは地形の対称性のため扇形のまま） |
| 包囲の本国判定 | placement 1 のときだけ、割り当てられた本国を守る |

**変えていない所：**

- 旧い参加経路（FileTicket と、隣の扇形への逃げ道）。
- 前哨の規則。
- 扇形ごとの資金・空き・占有の数と、輪を開く占有率の条件。

**本体（LiteSVM）で確かめたこと：**

| 検査 | 結果 |
|---|---|
| 配置の再現性 | 同じ種なら同じ配置になる |
| 6国の配置 | 6国それぞれが、割り当てられた5州（輪2に2州、輪3に3州）に最初の村を置けた。各国の州は3つ以上の扇形にまたがる |
| 他国への配置 | 他国に割り当てられた州は、自国の扇形の中でも拒否（`BadData`） |
| 既存の村との重なり | 同じ拠点への二重配置は拒否（`TicketState`）。同じ州の別の拠点には置ける |
| 参加時期 | 締め切り後の参加は拒否（`WrongStatus`） |
| 保護期間 | シーズンの `shield_secs` のまま変わらない |
| 本国の砦 | 持ち主は割り当てられた国で、本国の守りがある |
| 包囲 | 割り当てられた本国は、扇形の外でも包囲を拒否。自国の扇形でも、他国に割り当てられた州は包囲できる |
| 既定値 0 | 既存のテストが全て変わらず通る |

**距離と周辺資源（模型での計算。本体の実行ではない）：** 本国は輪3まで、到達は2州以内、種5つ×6国で計算しました。輪の種は、全ての輪にジェネシスの式を使った近似です。調整はしていません。

| 指標 | 0（扇形） | 1（分散） |
|---|---|---|
| 同じ国の州どうしの平均距離 | 1.30 | 4.03 |
| 最も近い同じ国の州 | 1.00 | 1.97 |
| 最も近い他国の州 | 1.20 | 1.00 |
| 到達できる州の数 | 33 | 64.5 |
| 到達できる資源マス | 129 | 243 |
| 資源の種類 | 3/3 | 3/3 |

**模擬・JS だけのもの：**

- ウェブの候補選び（`homeNation`、`seasonPlace`）とボット・検証ツールの写しは、関数としてだけ確かめました。
- ヘラルドがまだ `placement` とシーズンの種を返さないため、画面は実際には扇形の規則で候補を出します。

## 24-3. B：継続拡張マップ

**名前について：** 「無限」ではありません。上限 `r_max_ceiling`（最大でも輪128）までです。上限までの地域を最初から作っておくのではなく、条件を満たすたびに1輪ずつ範囲を広げ、その輪の州を既存の手順で作ります。

**仕組み：**

- シーズンの設定 `r_max_ceiling` で有効にします。0 は拡張なしで、今までどおり `r_max` で打ち止めです。
- 新しい命令 ExtendFrontier（`0xC1`）は誰でも送れます。次の条件を全て満たすと、実際に使える最外輪を1つ外へ広げます。
  - 今の最外輪まで全部開いている。
  - 前に輪を開いてから1ベル以上たっている。
  - どこかの扇形の占有率が基準 θ に届いている（OpenRing と同じ条件）。
  - 上限を超えない。
- 拡張した値は、Frontier アカウントの予約領域（位置66）を `R_MAX_EXT` にして持ちます。
- 実際の最外輪 = max(シーズンの `r_max`, `R_MAX_EXT`)。広げた後の輪は、既存の OpenRing → 種 → OpenProvince の流れで開きます。

| 項目 | 今回実装したこと | 残る制限 |
|---|---|---|
| 座標範囲 | 実際の最外輪を、OpenRing、FileTicket、FileOutpost、PlaceHome、Join の容量判定で使う | 最大でも輪128（`R_MAX_HARD`） |
| 州の識別 | 変えていない。(P,Q) と PDA のまま。既存の番号は振り直さない | 輪128を超えるには、軍勢 ID・帰還精算の20ビットの番号形式の変更が要る |
| 地形生成 | 変えていない。輪の種と座標だけで決まる | なし |
| 追加条件 | ExtendFrontier（上のとおり） | キーパーは自動では送らない。誰でも送れるので、待つ方針は他人に強制されない |
| アカウント作成 | 新しいアカウントは作らない。州は既存の OpenProvince で作る | 州を必要なときだけ作る方針は未実装 |
| 画面の部分読込 | ヘラルドの `/h/world` の `rMax` を拡張後の値にした。新しい記録 `FRONTIER_EXTENDED` をヘラルドが受け付ける。クライアントは州単位の読込と境界線のまま追従する | ブラウザでの実際の描画は確認していない（Node のテストだけ） |

**本体（LiteSVM）で確かめたこと（`map_extend.rs`）：**

| 検査 | 結果 |
|---|---|
| 上限 0 のシーズン | 拒否 |
| 拒否の理由 | 前の輪が未開・時間不足は `TooEarly`、範囲内は `AlreadyDone`、上限超えは `BadData`、占有率不足は `Capacity` |
| 拡張と再実行 | 1輪だけ広がる。同じ ExtendFrontier の再実行は `AlreadyDone` で、重ならない |
| 新しい輪の州 | 輪5の州は1回だけ作れ、2回目は拒否。開いていない輪6は種待ち（`SeedNotReady`）、上限外の輪7は拒否 |
| 既存の地域 | 既存の州の地形が1バイトも変わらない |
| 境界をまたぐ経路 | 輪2の最初の村から、新しい輪5の州へ前哨（2つ目の村）を置けた |

**JS だけのもの：** 拡張後の `rMax` による場所の状態と、境界線の表示。

## 24-5. ④が決めること

1. **取り込むかどうかと、範囲。** A だけ、B だけ、両方。
2. **ルールセットの版。** `GEOMETRY_VERSION` と `RULESET_HASH_V3` を上げるか。今は上げていません。
3. **契約文書の更新。** `docs/frontier/conquest/CONQUEST-CONTRACT.md` のオフセット表。テスト側の対照表だけを直してあります。
4. **A のルールの判断（①・所有者と）：**
   - 「1州＝1つの小集団」でよいか。
   - 輪ごとのずらし方。
   - 本国の守りを、散らした州に与えてよいか。
   - 扇形ごとの資金・占有の数と、輪を開く条件を、国と切り離すか。
5. **A の残り。** ヘラルドがシーズンの記録で `placement` とシーズンの種を返すこと。これがないと、画面の候補が分散配置に切り替わらない。
6. **B の賞金との関係。** 賞金プログラムの InitPool は `r_max > 17` を拒否しますが、`r_max_ceiling > 17` は検査していません。上限を17までに制限するか、賞金の集計を直すか。
7. **B のキーパー。** ExtendFrontier を自動で送るか。
8. **B の負荷。** キーパーの全州処理とヘラルドの全走査を、地図の大きさに比例しない形にするか（`docs/frontier/map-growth/keeper-load.ja.md`）。
9. **輪128を超える拡張。** 番号の形式の変更が要る。今回は扱っていません。
