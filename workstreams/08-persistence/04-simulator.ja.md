# 4. 小型シミュレーター

`sim/` にある、依存ライブラリなしの Node.js（ESM）のモデルです。リポジトリの既存の戦略シミュレーション（`permutation-state-prototype/*`）と同じく `node --test` でテストします。

**最初に断っておくこと：** エージェントは、**仮定した行動モデル**です。実際のプレイヤーがどう動くかの予測ではありません。結果は「この仮定の下で、案どうしの差がどちらに出るか」を見るためのものです。

## 4-1. なぜ既存の `frontier-sim` を使わないか

`frontier-sim`（Rust）は、本物のルールの部品を使って**1つのシーズン**を回すものです。⑧で比べたいのは、シーズンや戦期をまたぐ持ち越し・再参加・区切りの扱いです。これらは現在のコードにない（1章）ので、`frontier-sim` を変えないと表せません。他担当のコードを変えないため、構造だけを抽象化した別のモデルを作りました。そのため、資源量や戦闘の数値は本番と対応しません（6節）。

## 4-2. 再現手順

```sh
cd workstreams/08-persistence/sim
node --test ./*.test.mjs                 # テスト（約2秒）
node run.mjs --seeds 30                  # 全実験、seed 1〜30（数分）。../results/ に書き出す
node run.mjs --seeds 5 --only core       # 主比較だけを手早く
node run.mjs --seeds 30 --first-seed 101 # 別の seed の組で再現性を見る
```

出力：`results/summary.json`（seed ごとの生の値を含む）と `results/RESULTS.md`（表）。同じ引数なら同じ出力になります（テストで確かめています）。

## 4-3. 構成

| ファイル | 中身 |
|---|---|
| `rng.mjs` | 乱数。値は (seed, 用途, 鍵…) の関数で決まり、順番に引くことはない。だから同じ seed なら、案が違っても同じ出来事に同じ目が出る（共通乱数）。一人の選択が変わっても、他人の目はずれない |
| `params.mjs` | 全パラメーター。値ごとに「code（現在のコードの値）／design（設計文書の例）／assumption（このモデルだけの仮定）」の出どころを書いた |
| `proposals.mjs` | 参照（P0）と3案（A、B、C）の規則 |
| `scenarios.mjs` | 人口と、比較用の集団（初日・途中・終盤・不在・敗北）、悪用のシナリオ |
| `world.mjs` | 世界の1時間ごとの更新 |
| `metrics.mjs`、`stats.mjs` | 測定 |
| `run.mjs`、`report.mjs` | 実験の一覧、seed をまたぐ集計、表の書き出し |
| `sim.test.mjs` | テスト |

## 4-4. 世界の動き（1ティック＝1時間）

1. **区切り**（単位の長さごと）：案ごとの処理をする（3章）。直前の状態を記録する。
2. **参加と建て直し**：参加を予定していた人や、敗北して待っていた人が村を作る。場所は内側・国境・外の環。現在のコードと同じ形で、ある国の埋まり具合が θ（最初の3日は55%、その後は65%）を超えると、外の環が開く。
3. **経済**：畑が1時間ごとに生産する。集めないと12時間分で止まる。兵の維持費と、案によっては規模の維持費を、まず未回収分から、次に倉から払う。5日間何もしないと休眠し、生産が半分になって保護が消える（現在のコードと同じ）。
4. **国の共同作戦**：各国は1日1回、決まった時刻に作戦を開く。6時間の受付の間にオンラインの人が加わる。加わり方は5種類：
   - 補給の荷車（40以上）
   - 兵（5以上）
   - 護衛（兵3以上。荷車が奪われにくくなる）
   - 見張り（塔がある）
   - 工作（工房がある）
   
   荷と兵は移動時間をかけて届く。作戦は、最も遠い村からの行軍が着いた時点で決着する。攻撃なら砦の守備と比べ、守りなら守備隊に加える。
5. **襲撃**：オンラインの人が、行動モデルの確率で他国の村を襲う。保護中の村は襲えない。現在のコード（P0、A）では、保護中の村からは襲えない。設計文書19（B、C）では、襲うと自分の保護が切れる。成功すると、運べる量か、守られていない在庫の半分の少ない方を奪う。守備兵がいなくなるまで負けると、確率で「敗北」になる。敗北の扱いは2種類：
   - 本拠は残り、前哨・在庫・兵の半分を失う（P0、A、B）
   - 村ごと消え、建て直す（C）
6. **荷車の横取り**：オンラインの襲撃者の多さに応じて起きる。護衛の数で確率が下がる。
7. **砦の保持**：保持した国に1時間ごとに得点が入る。守備隊は補給を消費し、補給が尽きると少しずつ減る。

**行動モデル**（`BEHAVIOURS`）：

| 型 | 作戦に出す兵 | 襲撃の確率 | 畑あたりの兵 | 作戦に出す物資 |
|---|---|---|---|---|
| 協力型（coop） | 50% | 4% | 6 | 40% |
| 襲撃型（raider） | 25% | 35% | 10 | 15% |
| 籠城型（turtle） | 10% | 1% | 5 | 10% |

型の混ざり方は3通りで試す：

- mixed：協力60%、襲撃25%、籠城15%
- coop：協力85%、襲撃5%、籠城10%
- raider：協力35%、襲撃50%、籠城15%

人間の接続は1日1〜12回で、毎日±2時間ずれ、15%の確率で休む。AI は毎時間行動する。チェーン上の上限（1時間30回）は人間と AI で同じで、このモデルではどちらも上限に届かない。

## 4-5. 測るもの

| 依頼の項目 | 指標 |
|---|---|
| 新人の実行可能な貢献 | 参加24時間後に実行できる貢献の種類数（0〜5）。最初の7日の貢献量を、同じ期間の初日組（1日2回）と比べた比 |
| 共同作戦へ関われるまでの時間 | 参加を**決めた**時刻から最初の貢献までの時間。締切で待たされた時間も含む |
| 資源と軍事力の集中 | 資産のジニ係数、上位10%の持ち分、最大国の軍事力シェア、砦の保持のHHI、首位の連続率、最初の単位の勝者がその後に持つシェア、最下位の国の次の単位のシェア |
| 敗北後の回復費用 | 失った資産の割合、再び作戦へ貢献するまでの時間、敗北前の能力の50%に戻るまでの時間 |
| 必要な接続頻度 | 1日1・2・3・4・6回の人の貢献量を、1日12回の人と比べた比。常時稼働 AI の比も出す |
| 権利と更新の境界 | 区切りの瞬間に輸送中の物資・兵、砦に預けた物資、失効した量、送り主に戻した量 |

比べ方：全案を**同じ seed 30本**で回します。平均と、10%点〜90%点を示します。さらに、同じ seed どうしで P0 より良かった本数を数えます。一つの seed だけでは判断しません。

## 4-6. このモデルが表さないもの（限界）

- 資源の種類、兵の種類、戦い方の型、地形、封じた進軍、見張り塔の zk、札の細かい規則。物資は「物」の一種類にまとめた。
- 国の中の投票、追放、外交の構え。国どうしは常に敵対している。
- 本物の地図の距離。距離は「内側・国境・環」の3段階と、地域ごとの国の倍率で表す。
- 人の学習、怒り、離脱（ゲームをやめること）。モデルの人は、期間中ずっと遊び続ける。**実際には、負け続けた人はやめる。この点が結果をいちばん大きく歪めうる**（5章「結果が変わる仮定」）。
- 賞金・お金。このモデルには通貨も報酬もない。「国の勝ち」は砦を持った時間だけで測る。

## 4-7. テスト（`sim.test.mjs`）

| テスト | 確かめること |
|---|---|
| 決定性 | 同じ seed なら測定結果が完全に同じ。違う seed なら違う |
| 乱数 | 鍵で決まること、偏りがないこと |
| 保存則 | 毎時間、世界にある物資（村・道・作戦・砦）＝ 帳簿（初期配布＋生産−消費−維持費−失効−区切りでの消去）。全案、5シナリオ |
| 保護 | 保護中の村は襲われない |
| P0 の保護 | 保護中の村からは襲えない（`Shielded` と同じ） |
| P0 の締切 | 10.5日目以降に参加を決めた人は、次の単位の開始まで待つ |
| P0 の保護時間 | 初日は24時間。12時間より後に来た人は、24＋36時間 |
| 敗北 | P0、A、B では本拠が残る。C では村が消え、12時間後に保護48時間つきで建て直す |
| 区切り | P0 は全員が作り直す。B は砦が中立になり、地域が変わり、施設は残る。C は砦の持ち主がそのまま |
| 履歴 | 世界が戻る案でも、履歴は区切りを越えて残る |
| 接続 | AI は毎時間、人間は予定の回数だけオンラインになる |
| 権利 | P0 は失効する。B は砦に預けた物を返す。C は失効しない |
| 集計 | ジニ係数、分位点（∞を含む）、HHI |
| 表 | 小さな実験から表を書き出せる |
