# 06 機械的な成功と、人格・自律性・面白さの評価を分ける

`demo/report.mjs` は報告を二つに分け、混ぜない。

## 1. 機械的な結果（`summary.json` の `mechanical`）：コードが判定する

送った・届いた・拒否された行動、同じ署名の重複、1行動あたりの隊商数、1日の行動数と上限、推論の課金と台帳の `check()`、未解決の推論、掲示板の依頼の状態、監査の指摘、再起動の記録。試験はここだけを合否にする。

**これが通っても言えないこと**：住民に人格がある、自律している、遊んで面白い、人間に役立つ、強い。

## 2. 観察（`summary.json` の `observed`）：人が判断する材料

| 項目 | 何を見るためか | 注意 |
|---|---|---|
| `declines`（理由・説明・代替） | 断り方が相手にとって次の手になるか | 理由はコードが作る。モデルの言葉ではない |
| `excludedOffers` | 受けなかった依頼と理由 | 同上 |
| `outcomesLearned` | 結果から何を学んだか | 記憶に入ったことは、行動の原因である証明ではない（AI 市民の契約 §5.8 と同じ） |
| `requestTargetChanges` | 結果の後に依頼先が変わったか | 冷却期間という規則の結果でもある |
| `idleShare` | 待つだけの割合 | 低いほど良いとは限らない |
| `distinctKinds` | 行動の幅 | — |

## 3. 人による評価の手順（提案。未実施）

fixture provider の結果は「パイプラインが動くこと」の証拠であり、AI の振る舞いの証拠ではない。人格・自律性・面白さは、実モデル（⑤）で次のように評価する。

1. **盲検**：同じ世界の経過を、住民の名前と provider を伏せて評価者に渡す（fixture・実モデル・人間の台本を混ぜる）。
2. **評価項目**（5段階、理由の記述つき）：
   - 一貫性：目的に沿った選択か（目的を知らせずに当てられるか）
   - 応答性：結果（約束破り・襲撃・断り）の後に、筋の通った変化があるか
   - 相手への配慮：断り方に次の手があるか
   - 驚き：評価者が予想しなかったが、振り返ると筋の通る選択があったか
   - 面白さ：この相手と同じ世界で遊びたいか（人間の参加者に聞く。試遊の観察シートに項目を足す）
3. **比較**：同じ世界で fixture（コードの最上位）と実モデルを並べ、差が出た判断だけを取り上げる。差がなければ、その場面ではモデルは何も足していない。
4. **報告**：点数の平均でなく、評価者の記述と、差が出た判断の一覧を残す。「AI に意志がある」とは書かない（AI 市民の契約 §5.9 と同じく、観察できる振る舞いとして書く）。
