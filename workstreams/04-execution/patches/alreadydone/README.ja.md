# AlreadyDone で終わる取引の抑制（費用を**減らす**修正の最小案。④、2026-10-31。未採用）

費用を**数える**修正（⑯の P12、`../from16/`）とは別のもの。P12 は数を正しくするだけで、無駄な取引は減らさない。この案は取引を減らすだけで、数え方は変えない（P12 なしで測った）。

## 事実（基準 bc09689a、④の試験 v6 の再試行の場面）

再試行の場面の 27 件の Reveal の版を、送った slot と着地した slot で並べた（`../r18-check/` の試験が表示する）：

- 版を上げた 4 進軍それぞれで、slot 702〜707 に 1 版ずつ、計 6 版を送った。slot 707 の版が slot 708 に着地して Ok、702〜706 の 5 版は slot 713 に着地して `AlreadyDone`（52）。
- **無駄になった 20 版は、すべて勝った版が着地する前に送られていた**。勝った版の着地の後に送った版は 0。

したがって「着地したら残りを取り消す」は効かない（Solana では送った取引を取り消せない）。無駄は「結果がまだ分からない間に版を足す」ことから生じる。

## 三つの状態と、今の engine の動き

| 状態 | 今の動き（W 級＝Reveal） | この案 |
|---|---|---|
| 確定済み（ある版が着地した） | その書き込みは終わり、新しい版は出さない（既存） | 変えない。単体試験で確認 |
| 結果不明（送った版の status が未確認で、blockhash が有効） | 毎 slot 新しい版を出す（契約 §8.2、`per_write_cap` まで） | 未確認の版が `w_max_in_flight` 本あれば、次を出さずに待つ |
| 失敗が分かった版（retry の段など） | すぐ次を出す（既存） | 変えない（失敗の分かった版は数えない） |
| 期限切れ（sent_slot + 151 を過ぎた） | 数えない | 数えない（また出せる） |
| 再起動の後（journal から引き継いだ版） | `adopt` で書き込みの版に入る | 引き継いだ未確認の版も数える（再起動で上限が空にならない） |

## 最小の修正（`engine-w-in-flight-cap.patch`、sha256 `143f0b9f1563f024ac9d6f8f7185195f2a02a3a5a225f465f192642920154591`）

- `EngineParams::w_max_in_flight`（keeper.toml の `w_max_in_flight`）。**既定 0 ＝上限なし＝今の挙動のまま**。
- `resend_waits` の W 級：未確認で期限内の版の数が上限以上なら待つ。
- 単体試験 `w_in_flight_cap_unknown_confirmed_and_restart`：結果不明で 2 版の後は待つ／期限が切れたらまた出す／失敗が分かった版は数えない／着地したら何も出さない／再起動で引き継いだ 2 版で待つ／0 なら毎 slot。

## 回帰試験（`play-retries-with-cap.patch`、sha256 `1bd26ed9844c64580ab7da9b365eec082a9292d9af8da79a4267ded5a62ddd00`。`../r18-check/` の v6 と上の patch の上に当てる）

`ws04_retries_with_in_flight_cap`：同じ再試行の場面を、上限なしと上限 2 で走らせる。

| | Reveal の取引 | Ok | AlreadyDone | チェーンの手数料 | 勝った版の着地 |
|---|---|---|---|---|---|
| 上限なし（今） | 27 | 7 | 20 | 681,118 lamports | slot 708 |
| 上限 2 | 11 | 7 | 4 | 74,212 lamports | **slot 713（5 slot 遅い）** |

- 7 進軍すべてが Ok で Reveal され、取り残しはない（正常の場面と同じ集合）。AlreadyDone は進軍ごとに 1 以下。
- keeper の既存の試験はすべて合格（既定 0 なので挙動は変わらない）。`keeper-all-summary.txt`。

## 代償（採否の判断材料）

- 上限があると、版が出ている間は入札が上がらない。この場面では、slot を高い優先度で塞ぐ相手（1,900）を、版を上げた 707 の版が 708 で抜いていた。上限 2 では 713（塞ぎが終わった後）まで着地しない。塞ぎが Reveal の期限まで続けば、Reveal は間に合わない。つまり、**手数料の無駄と、争われた slot での防御の強さの交換**である。既定を 0 にしたのはこのため。
- 無駄を 0 にしつつ入札を上げ続けるには、全版で同じ durable nonce を使い「どれか一つしか着地しない」形にする方法がある。nonce の口座という新しいチェーン上の準備が要るので、この案には入れていない（新規導入は未承認）。
