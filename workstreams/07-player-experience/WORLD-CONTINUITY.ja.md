# ⑦ 継続世界への方針訂正：表示の点検と変更（v6、差分 0012）

**前提**
- 世界は期間の区切りで終わったりリセットしたりしない。
- 戦期（戦争と競争の区切り）は世界の寿命とは別。区切り方、集計、賞金は未決定。

**⑦ がしたこと**
- 世界が終わる・リセットされると読める文言と画面を点検した。
- ⑦ の持ち分を直した。
- 「世界の継続」と「戦期の集計」を別々に出す表示の受け口を作った。

**⑦ がしていないこと**
- 共有コアや World・Period の正本、移行処理は作っていない（④ と ⑧ の担当）。
- 共有のクライアントの変更は、④ へ渡すパッチ 0012 に分けた。
- push・merge・deploy、実資金、有料 API、鍵、OAuth、ソフトの導入はしていない。

## 2. 変更した挙動（0012）

- **終了ターンを、世界ではなく「このプログラム」のものとして言う。**
  - ダイヤルは「受付終了」。
  - 参加画面の行は「このプログラム（旧方式のシーズン）が新しい命令を受け付けるのは第 N ターンまでです」。
  - 終了後の行は「…第 N ターンで新しい命令の受付を終えました」。
  - `WrongStatus` の理由は「このプログラム（旧方式のシーズン）は第 N ターンで新しい命令の受付を終えたため、この操作は受け付けられません」。
  - 征服戦のカードは「この征服戦（旧方式のシーズン）は終わりました」。
- **世界の継続と戦期を別の行で言う**（`hud/worldclock.mjs`）。⑦ は世界も期間も定義しない。④・⑧ が登録したことだけを言う。
  - 受け口 `continuity`（`{continuous: true}`）が登録されると、「世界：期間の区切りで終わったり作り直したりしません」と出す。さらに、プログラムの終了ターンは言わず、`WrongStatus` をそのせいにもしない。
  - 受け口 `warPeriod`（`{fromBell, toBell, label?, tally?}`）が登録されると、「戦期：第 A〜B ターン。集計：…（世界はこの区切りで終わりません）」と出す。集計が渡されなければ「集計の方法は未決定です」。
  - 何も登録されていなければ、どちらの行も出さない。プログラムの事実だけを言う。
  - 賞金や周期を勝手に表示しない。
- **地図、操作回数の上限、輪の説明、留守の要約の文を直した。**
  - 地図は「いまの地図の外」。
  - 操作回数の上限は「ゲーム内の日付が変わると」。
  - 輪の説明は「ターンが進むと」。
  - 留守の要約は「前に見ていたものとは別のシーズン記録（ID が違う記録）です」。

## 3. 試験で確認したこと

`permutation-gateway/test/web-frontier-ws07-world.test.mjs` の 6 件。すべて通常テスト（`npm test`）に入る。

| 試験 | 確かめたこと |
|---|---|
| 何も登録されていないとき | 世界・戦期の行を出さない。プログラムの終了ターンを「旧方式のシーズン」のものとして言う。世界が終わる・リセットの言葉が無い |
| 継続と戦期が登録されたとき | 終了ターンを言わず、`WrongStatus` もそのせいにしない。世界と戦期は別の行。集計の方法は未決定と言う。受け口が例外を投げたら何も言わない |
| 文言の点検 | ⑦ が持つ文と直した画面の文に「世界が終わる」「リセット」「新しいシーズンです」「シーズンは終わりました」「このシーズンの地図」が無い。英語の辞書にも旧い言い回しが無い |
| 期間の境界をまたぐ | 戦期の境界（ターン 300）の前に既読にした位置が、境界のあとも同じ記録で続く。境界の前の出来事を二度出さない。境界の前に送られて境界のあとに決着した隊商は、同じ隊商として扱う（持ち主の帳簿が既読位置と一緒に境界を越える）。送付記録は境界の前で既読なので、入った量だけを言い、比較は作らない |
| 再起動 | 境界のあと再起動しても、既読位置から読み直し、同じ記録を二度出さない |
| シーズン ID が変わったとき | 「別のシーズン記録」と言い、世界が作り直されたとは言わない |

**通過した既存の試験**
- 全部当てた木での `npm test`、M1 画面テスト、S1 の画面テスト 4 本（`patches/v6/SERIES.ja.md`）。
- 旧い文言を固定していた既存の試験 5 本は、新しい文言に合わせた：shell、world、errors、conquest-hand、ws07-terms。

**ここで確かめていないこと**
- 期間境界をまたぐ通し試験（隊商、加工、預かり、未確定取引、封印進軍を、プログラムとチェーンでまたがらせる）は ⑯ の担当で、⑦ は行っていない。⑦ の試験は、表示側の状態（既読位置、持ち主の帳簿、到着の判定）が境界と再起動で続くことまで。
- 長期運用で状態が増え続ける場合（記録の連番、既読位置の帳簿の大きさ）
  - 帳簿は 256 件で古いものから落とし、落ちた隊商は「持ち主不明」と言う（v2 から）。
  - 連番は BigInt で扱う。
  - それ以上の長期試験はしていない。

## 4. 移行や仕様判断が残る点

| 項目 | 担当 | ⑦ が受け取りたいもの |
|---|---|---|
| 世界が続くことを、どの口座のどの欄で知るか（`continuity` の出どころ） | ④・⑧ | 受け口 `registerWorldSource('continuity', FS => …)` に渡す値と、その根拠 |
| 戦期の区切り方、集計、賞金 | 未決定（④・⑧、⑰） | 決まったら `warPeriod` に渡す。⑦ は周期を決めない |
| シーズン ID が残る場合の、鍵・口座の住所・herald の固定・封の控えのキー | ④ | 「ID は変わらない」なら、⑦ の既読位置はそのまま続く（試験済み）。変わるなら、旧 ID の記録をどう読ませるか |
| 旧方式の終了ターンを過ぎたプログラムの扱い（受付終了の表示を残すか） | ④・⑧ | 旧版の再検証の経路として残すなら、いまの「このプログラム（旧方式のシーズン）」の言い方で足りる |
| 征服戦の賞金と受取権の表示 | ⑰ | 既存の受取権を守る表示として残している。新しい周期の料金や賞金は表示しない |
| 年表・振り返り・測量数の名前 | ④・⑧ | シーズン単位の Citizen をやめるなら、測量数の数え方も変わる |
| NFT 参加パス | 別途 | ⑦ は戦期ごとの買い直しや参加費を前提にした表示を作っていない |
| 試作（`prototype/`、`src/season-terms.mjs`） | ⑦（未修正） | v1 の比較用。シーズン終了の文が残っている。正となる基準はパッチ側 |
