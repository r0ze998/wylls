# ⑦ 表示契約：④・⑤ の状態と ① の協力入口

④（送信の取消と到着）、⑤（費用と手動復帰）、①（国の協力）の状態を、⑦ の画面がどう表示するかを決めた契約です。状態の中身と規則は各担当のもので、⑦ は決めていません。

**④・⑤・① の成果物はまだ受け取っていません。** そのため、この契約は報告の要約だけをもとにした⑦側の要求です。受け取った時点で、名前と遷移を突き合わせる必要があります（§4）。

実装は接続パッチ 0004 にあります。
- `permutation-server/web/frontier/hud/statusview.mjs`：④・⑤ の状態の表示
- `permutation-server/web/frontier/hud/coopentry.mjs`：① の協力入口

テストは `permutation-gateway/test/web-frontier-ws07-contracts.test.mjs`（8件、通常テスト）と、画面テスト `screens/ws07-s1.screen.mjs` の表示契約の項目です。

## 1. 共通の決まり

- 各表示は `{ok, key, symbol, text, details, tone, errors}` を返します。
- 状態は**記号と文**で伝えます。`tone` は CSS の class 名で、同じことを繰り返すだけです。色だけでは何も伝えません。強制カラー（白黒）でも記号と文が残ることを、画面テストで確かめました。
- 知らない状態や、欠けた欄があれば、「状態を受け取れていません」（記号 `?`）と表示し、`errors` に理由を並べます。**推測で埋めません。**
- 欄を省いた場合と、空であることがわかっている場合は、別の状態として扱います。
  - 例：取消の前に成立した分（`settled`）は、欄が無ければ `null`（まだ受け取っていない）、`[]` なら「成立した分はない」です。

## 2. ④：取消の3段階と到着量

### `cancelView({ stage, signedPending?, settled? })`

| stage | 記号 | 表示 | 欠けたとき |
|---|---|---|---|
| `stopNew` | ‖ | 新しい送信を止めました／署名済みの要求はまだ止まっていません。チェーンの確認を待ちます | — |
| `awaitSigned` | ⌛ | 署名済みの要求 N 件の確認を待っています／確認が済むまで、取消は終わっていません | `signedPending` が無ければ「件数は受け取っていません」 |
| `cancelled` | ■ | 取消が終わりました／取消の前に成立した分は戻りません：（④が渡す文の一覧） | `settled` が無ければ「まだ受け取っていません」。`[]` なら「ありません」 |
| それ以外 | ? | 状態を受け取れていません | `errors: ['stage: …']` |

### `arrivalView(x)`：隊商の到着（v5 で補正）

**経緯**
- v2 の3状態（`unverified`・`partial`・`full`）は v4 で廃止しました。倉庫宛てでは、決着の記録と実際に入った量が一致しないためです。
- v5 では次の2点を補正しました（パッチ 0011）。
  - 「全量」「一部」の比較の基準を、文に必ず出すようにしました。
  - 「入った量が分かるか」と「送付記録と比べられるか」を、別の判定にしました。

量は「資源の順に 8 つの整数」で渡します。単位は記録の単位で、`cargo_log` は内部の 1/1000 単位を整数に切り捨てています。

**v7（パッチ 0013）**：村に入った量は記録の数を**下限**として「n 以上」と言います（資源ごとに 1 未満多く入っていることがある）。ただし記録は `u32::MAX`（4,294,967,295）で飽和するので、その値に達した資源があるときは「1 未満」と言わず、「そこに達した資源は、記録よりどれだけ多く入ったかわかりません」と言います。下限であることは変わりません（2026-11-17）。すべて 0 なら「0 以上」で、「なし」とは言いません。全量・一部・入った量のみ、のどれも同じです。

| state | 記号 | 表示 | 判定 |
|---|---|---|---|
| `overdue`（`bell`） | … | 到着予定のターン N を過ぎました。まだ決着していません | 隊商 feed にまだ載っていて、予定ターンを過ぎた。**「着いた」とは言わない** |
| `settledUnverified`（`why`） | ? | 倉庫宛て（`vault`）は「到着しましたが、入った量は確認できません（記録の積荷：n）」（2026-11-17 訂正。v7 の「最大 n」は誤り：記録は 1 未満の切り捨てと上限での飽和なので、入った量の上限にならない。全 0 の記録も「記録の積荷：0」で、入った量 0 とは言わない）。それ以外は「決着しました。入った量はまだ確かめられていません」 | 入った量：わからない。理由（`why`）は `vault`、`dstUnknown`、`rulesUnknown`、`outcomeUnknown` |
| `misdelivered`（`recorded?`、v7） | → | 別の場所に着きました（原因を確認中）／この隊商の到着としては、入った量を数えません | 送付記録の行き先と違う場所で決着し、奪取の記録を読んでいない。原因や相手を言わない（④ の `DestinationMismatch`） |
| `unread`（v7） | ? | 状態不明：道中の一覧から外れましたが、終わりの記録をまだ読んでいません | ページを開いているあいだに一覧から消え、決着も略奪もまだ読んでいない。メモリだけで、再読込のあとは出さない |
| `verifiedIntake`（`intake`、`compare`） | ○ | 村に入った量：（量）以上／比べない理由／単位 | 入った量：わかる（下限）。比較：できない（`compare` は `sentUnknown`、または奪った側の到着の `dstChanged`） |
| `verifiedPartial`（`basis: 'sentRecord'`、`sent`、`arrived`、`wornBps?`） | ◐ | **送付記録の数量に対して**一部が入りました：（量）／送付記録の数量：（量）／比べた基準／差の理由は決めない／単位 | 入った量：わかる。比較：できる（一部） |
| `verifiedFull`（`basis: 'sentRecord'`、`sent`、`arrived`、`wornBps?`） | ● | **送付記録の数量に対して**全量が入りました：（量）／比べた基準／単位 | 入った量：わかる。比較：できる（全量） |
| `lost` | ✕ | 積荷は失われました（記録の積荷：n）／行き先が無くなっていたため、どこにも入っていません（確定） | `outcome` 1。記録の積荷は記録の数のまま示し、全 0 は「0」で「なし」とは言いません（1 未満の端数は記録に残らないため。2026-11-17） |

- 「全量」と「一部」は、`basis: 'sentRecord'` が無ければ表示しません（「状態を受け取れていません」になります）。
- 比べた基準の文は「比べた基準は送付記録の数量です。送付記録の数量は経路の減少を引いたあとの量で、最初に積んだ量と経路の損失は、この記録からは確定しません」です。
- 送付記録に経路の減少率（`worn_bps`）があれば、「送付記録には経路の減少率 X% が記されています」と、記録どおりに引くだけです。最初に積んだ量は逆算しません。

**「入った量がわかる」の条件（すべて）**
1. 決着の結果が「配送」（`outcome` 0）。
2. 宛先の種類が村（`dst` の種類 1）。
3. シーズンのプログラムの版が S1（`program_version` 4）。根拠は `Holding::credit` で、記録の積荷を上限なしでそのまま加えます。
4. 数量は記録の単位で言う。

**「送付記録と比べられる」の条件（上に加えて）**
5. 同じ隊商の `CARAVAN_SENT` を読めている。
6. その行き先（種類・州・場所・世代・マス）が、決着の行き先と完全に同じ。

**持ち主が確かめられない隊商の決着（帰ってきた人への要約、2026-11-17）**
- 送り主があなたで、いまの持ち主が記録から確かめられない隊商の決着は、記録の `outcome` で言い分けます。0 は「到着が記録されました」、1 は「積荷が失われたと記録されました」、それ以外は「決着が記録されました。結果を記録から読めないため、着いたとも失われたとも言いません」。1 やそれ以外を「到着」とは言いません（`hud/returnsum.mjs`・`hud/returnwords.mjs`）。
- あなたが持ち主の隊商でも、`outcome` が 0 でなければ「届いた」（`delivered`）としては扱いません。到着の表示は `arrivalSettled` の `outcomeUnknown` です。

**倉庫宛て**
- 倉庫は資源ごとに `min(have + c, max(cap, have))` で切り捨てますが、記録には元の積荷が載ります。
- 記録の積荷は `floor(milli / 1000)`、`u32::MAX` で飽和です（`permutation-frontier/src/proc/caravan.rs` `cargo_log`）。倉庫はミリ単位で加えてから切り捨てるので、記録の数は入った量の下限にも上限にもなりません。表示は記録の数をそのまま「記録の積荷」と言い、「最大」とは言いません（2026-11-17）。
- その配送の実加算量の記録か、検証できる計算根拠（`REQUESTS.ja.md` ④-5）が無いあいだは、常に「決着・実入荷未検証」です。
- 倉庫の現在の残高や、残高の差からは決めません。

**元の送り主には到着を言わない場合**
- 焼かれた隊商：空のまま進み、`outcome` 0（配送）で記録されます。持ち主が無いので、到着の項目自体を作りません。
- 奪われた隊商：持ち主が奪った側に変わるので、元の送り主には到着を出しません。
- 奪った側の到着は、送付記録と行き先が違うので比べず、「入った量のみ確定」になります。
- どれも回帰テストで固定しています（`web-frontier-ws07-connect.test.mjs` の burned、taken）。

**④ の実契約との照合（未）**
- 受け口 `caravanArrival` に ④ が登録すると、道中の隊商の行は ④ の状態に置き換わります。
- 実物との契約テストが通るまで、画面テストの mock はテストの中でだけ登録します。本番の画面は、推測した ④ の状態を出しません。

## 3. ⑤：費用の4区分と手動復帰

### `costView({ phase, amounts? })`

| phase | 記号 | 表示 |
|---|---|---|
| `reserved` | ◇ | 予約：（額）／まだ支払っていません。使える量からは引いて見せます |
| `committed` | ◆ | 確定：（額）／支払いが確定しました |
| `unsettled` | ◇? | 未確定（額はまだ決まっていません）、または「未確定：最大（額）」／予約とも確定とも違います |
| `released` | ↺ | 予約の解放：（額）／予約が戻りました。使える量に戻して数えます |

「支払った」と言うのは `committed` のときだけです。

### `spendable(have, costs, { committedInHave })`

手持ちから費用を引いた、使える量を返します。
- 予約分と、未確定分の最大額を引きます。
- 未確定のものが1つでもあれば、`uncertain: true` を返します。
- 確定分を引くかどうかは、`committedInHave` の値で決まります。これは「確定した費用は、すでに手持ちから引かれているか」で、**⑤ が決めることです。** 渡されなければ誤りとして返します。

### `manualView({ signedPending? })`

| 入力 | 表示 |
|---|---|
| `signedPending: N`（N > 0） | 手動に戻しました／すでに署名した操作 N 件は止まらずに進みます |
| `signedPending: 0` | 署名済みで進行中の操作はありません |
| 欠けている | すでに署名した操作は止まりません（件数は受け取っていません） |

手動に戻しても、すでに署名した操作は止まりません。止まったように見せる表示（ボタンを灰色にするだけ、など）はしません。

## 4. ①：協力入口（最小の接続点）

- S1 の村カード（`screens/s1.mjs` の「交易と防備」）の、「国の議会」の下に枠を1つ置きました。
- ① が登録しなければ、枠は空で、画面は今までと同じです。
- 国どうしの協力や中央塔のルールは、⑦ では決めていません。

```js
import { registerCoopEntry } from './hud/coopentry.mjs';
const off = registerCoopEntry({
  id: 'nation-coop',
  title: () => L`…`,                         // ボタンの文（①が決める）
  state: FS => ({ available, why }),          // 押せるか、押せないならその理由（①が決める）
  open: FS => { … },                          // 押したときの動き（①が決める）

```

- 押せないときは、ボタンを無効にし、理由をその下に出します。理由がなければ「理由を受け取れていません」と出します。
- 押されると、画面は HUD の操作 `coop-open` から `open` を呼びます。呼ぶ前に `state` をもう一度確かめます。
- `state` が例外を投げたら、ボタンを無効にします。

## 留守の要約：読めなかったこと・確認の位置の保存（2026-11-17、Lane C）

実際の導線：`app.mjs` の `awayPump` → `hud/awayread.mjs`（ページを読む）→ `hud/returnsum.mjs`（`summarize`・`confirm`・`loadMarks`）→ `hud/returnwords.mjs`（`headText`・`confirmText`・`confirmedText`）。

- **読めなかったことと、記録が無いことを分ける。** 範囲内に読めた記録が 0 件のとき、読み込みが最後まで終わっていれば「新しい記録はありません」と言います。失敗した・続きがある・欠けがあるときは「新しい記録があるかどうかは、まだわかりません」と言い、「読めた分だけを出しています」とも言いません。確認の案内も、この場合は「まだ記録を読めていないため、確認の位置は進めません」で、「新しく確認する記録はありません」とは言いません。
- **読めない記録は数えて伝える。** ページの中で中身を解読できなかった記録（`bad`）は推測せず、件数を「読めない記録が N 件ありました。その中身は推測しません」と伝えます。範囲内に読めた記録が無く、読めない記録だけがあるときは「新しい記録はありません」とは言わず「中身を読めた新しい記録はありません」と言い、確認の案内も「読めない記録のほかに、新しく確認する記録はありません」と言います。確認の位置の進め方は変えていません。
- **確認の位置（主）と、最後に使ったウォレットの記録（補助）の保存を分ける。** 確認の位置を書いて読み戻せたときだけ「確認済みにしました」と言います。補助の `ws07-return:last` だけ保存できなかったときも、確認の位置は進んでいるので失敗とは言わず、その旨を添えます（`lastSaved: false`）。画面では、そのときだけ要約の先頭の通知を閉じずに残し、その言葉に替えます（「確認した」はもう出しません）。別のタブが間に先へ進めていたら「すでに確認済みです」と言います。主が保存できなければ、これまでどおり「保存できませんでした。次に開いたときも同じ範囲が出ます」です。
- **確認の位置は世界に結び付ける。** 新しく保存する確認の位置と補助の記録には、固定した世界（クラスター・プログラム・シーズンの口座。シーズンの口座は `setPin` が導き、ヘラルドの記録と照合したもの）を記します。読み込みの範囲（scope）も同じ世界を含み、世界が固定されていないあいだは読み込みません（値を作りません）。遅れて届いた別の世界の読み込みは採らず、「確認した」は要約を読んだときの世界で、いまもその世界のときだけ保存します。違う世界の確認の位置は使いません（同じシーズン番号と同じウォレットでも、別の世界の位置から読むと、この世界の未読を飛ばすため）。世界を記していない以前の確認の位置は、これまでどおり読みます。保存先の鍵（`ws07-return:{シーズン}:{ウォレット}`）は変えていないので、別の世界で確認すると、前の世界の位置は置き換わります（その世界は、次は最初の見方から読み直し、未読を飛ばしません）。

## 地図の上の出来事（moments）は同じ世界の中だけで比べる（2026-11-17、Lane C）

実際の導線：`app.mjs` の `checkMoments`（毎秒）→ `people/moments.mjs` の `momentSnapshot`・`detectMoments` → 効果の bus → `fx/stage.mjs`。

- 前回の見え方と今回の見え方を比べるのは、固定した世界（クラスター・プログラム・シーズンの口座。`setPin` が導き、ヘラルドの記録と照合したもの）が同じときだけです。世界が固定されていない状態も一つの状態として扱い、値を作りません。
- 世界が変わったら、前回の見え方とあなたの村の一覧を捨てます。読み込み側は、読んだ世界を記録します：州の記録は `world` を持ち（`controller.mjs` の `loadEnvelope`。別の世界のために始めた読み込みの答えは何も書かずに捨て、`latestEnvelope` は同じ世界の記録どうしだけを番号で比べます）、あなたの村の一覧は `FS.holdingsWorld` を持ちます（`applyMeResult`。`refresh` は始めたときの世界のままのときだけ反映します）。配列や記録が入れ替わったことだけでは、この世界のために読んだ証拠にしません。
- あなたの村の一覧がこの世界のために読まれるまで（村があるとき）は見え方を取りません。その後は、この世界のために読んだ州だけを見ます。村の暮らしの記録（収穫・建設）は、読み込み側がこの世界のために読み直したと記録してから（`FS.lifeWorld`、`refreshChronicle`）見ます。そのとき最初に見えた暮らしは基準で、知らせではありません。その後の最初の変化からは、いつもどおり知らせます。キーが消えたことや、配列・記録が入れ替わったことは、出どころの証拠にしません。
- 世界の区別には、固定の**世代**も使います（`fchainio.setPin`：別の世界の固定に成功したときだけ一つ進み、同じ世界の読み直しや失敗では進みません）。A → B → A は三つの世代なので、最初の A で始めた読み込みの答えや記録は、B のあとに固定し直した A のものとして使いません。読み込みの範囲・読み込み側の記録（州の `world`、`FS.holdingsWorld`、`FS.lifeWorld`）・出来事の比較・報告・留守の要約の範囲は、この世代を含みます。端末に保存する留守の確認の位置は、読み込み直しても合うように世界そのもの（世代なし）を記します。
- そのため、別の世界の同じ座標の村・建物・軍勢を「村を失った」「村を取った」「建物ができた」とは言いません。新しい世界で最初に見えたものも出来事とは言いません（「最初の読み込みは知らせではない」のまま）。同じ世界の中の新しい出来事は、これまでどおり知らせます。

## 賞金の残高表示・行軍・領土の読み込みも、読んだ世界の中だけで反映する（2026-11-17、Lane C）

実際の導線：`controller.mjs` の `refreshPrize`・`refreshMarches`（`readMarches`）・`refreshConquest`（`refreshS1`・`refreshKeepEvents`・`wantKeepHistory` を含む）。

- どの読み込みも、始めたときの固定の世界（世代を含む `providerWorld()`）を覚え、待ったあとに書く前に、まだ同じかを確かめます。違えば何も書きません。A → B → A は三つの世代なので、最初の A で始めた読み込みの答えを、あとの A に書きません。
- 賞金の読み込み（`refreshPrize`）は、ウォレット・中継先（relay）・世界の三つが始めたときと同じときだけ、賞金の情報と成績表を書きます。この理由で捨てた読み込みは、間隔の制限を自分の分だけ解き、新しいウォレット・中継先・世界ですぐ読み直せるようにします。支払い・参加・テストトークンの受け取り・受け取りの権利の意味と実行は変えません（`paidJoin`・`faucet`・`payAndJoin` はそのまま。参加の経路が `FS.prize` で決まることもそのまま）。
- 行軍の読み込み（`readMarches`）の身元（ヘラルド・ローカルプレイ・村・帳簿の鍵）に世界を加えます。最後の書き込み（帳簿の保存・`FS.marches`・`FS.bellItems`・`FS.formingBells`）は同じ身元のときだけです。自分で鍵を出す送信（self-reveal）とその記録は変えません。
- 領土の読み込み（`refreshConquest`）は、要求の番号と世界をまとめた `current()` で、待ったあとのすべての確認をします。世界が変わったら、領土の状態（拠点・順位・最終結果・読んだ日の記録・拠点の履歴）を前の世界のものとして使わず、「読み込み中」から始め直します。S1 の隊商・構造物・国家も、読んだ世界の記録だけを持ちます（失敗や NotFound のときに前の世界の内容を残しません）。世界の印のない状態は「世界なし」として扱います。
- 同じ世界の中の順序・間隔・「まだわからない」の出し方は変えません。

## 地図の範囲・環の一覧・環の概要も、読んだ世界の中だけで反映する（2026-11-17、Lane C）

実際の導線：`app.mjs` の `loadSeason`（固定）→ `controller.adoptPinnedWorld`。`controller.mjs` の `refreshOverviews`。`app.mjs` の `loadOverviews`。どちらの読み込みも、共有の読み込み列 `map/overviews.mjs` の `readOverviews` を通ります。

- `refreshOverviews` の処理（相乗り・キャッシュ・完了の印）は、ヘラルドと固定の世界（世代を含む）の両方が同じときだけ有効です。シーズンの記録の答えは、待ったあとも同じ世界のときだけ反映します（記録・範囲・環の一覧・`FS.season`）。
- 共有の読み込み列は、呼び出し側から今の世界（`source`）を受け取ります。各読み込みには、作ったときの世界が付きます。世界が変わったら、読み込み側が替わったときと同じく、待っている読み込みは false で終わります。世界がもう固定されていない読み込みは、始めず、答えを保存せず、false で終わります。`source` を渡さない呼び出し方は、これまでと同じです。
- 同じ世界の中は変えません。同時に四つまでの読み込み、優先の順、範囲が変わったときの読み直し、一部だけ読めたときに次の機会に読み直すことは、そのままです。
- 別の世界を固定した直後、その世界の記録を反映する前に、前の世界の読み込みを忘れます：
  - 環の概要（地図が同じ入れ物を持っているので、中身だけを空にします）
  - 概要を取ったときの州の数（新しい世界のすべての環を読み直すため）
  - 一部だけ読んだ環の一覧
  - 完了の印
  - 領土と S1 の状態

  最初の固定と、同じ世界の固定では、何も忘れません。
- 領土が無効の世界に移っても、前の世界の領土と S1 の状態は見せません。出来事の一覧・地図の効果・報告・調べる画面・S1 の歩みは、領土が有効かを確かめずにこれらを読みます。そのため `refreshConquest` は、有効かを確かめる前に、別の世界の状態を捨てます。

## シーズンの記録の答えは、尋ねた順に反映する（2026-11-17、Lane C）

実際の導線：シーズンの記録を読むのは二か所です。

- `app.mjs` の `loadSeason`：起動時に一度待ち、そのあとは `createPollLoop` で一度に一つずつ読みます。固定するのはここだけです。
- `controller.mjs` の `refreshOverviews`：プレイの読み込み・出撃の計画・帰還地の計画から呼ばれます。

二か所は同じヘラルドの `/h/season` を、互いを待たずに尋ねます。ヘラルドの読み込み側は、二つの要求を一つにまとめず、順番も付けません（`no-store`）。そのため、先に尋ねた答えが、あとに尋ねた答えより遅く届くことがあります。`loadSeason` 同士は重なりません。

- **番号**：尋ねるたびに番号を一つ進めます（`askSeason`）。答えは、それよりあとに尋ねた答えがまだ反映されていないとき（`seasonStale` が偽）だけ反映します。
- **反映済みの記し方**：反映済みとして番号を記すのは（`takeSeason`）、**すべてを書き終えたあと**だけです。古さの確認から書き込みと記しの終わりまでは、途中で一度も待ちません。そのため、確認と書き込みの間に別の答えが入ることはありません。
- **記さない場合**：次のときは、何も記しません。そのため、先に尋ねた有効な答えは、あとからでも反映されます。
  - 失敗
  - 固定の拒否（`PinMismatch`・`RulesetMismatch`）
  - 書き込み中の例外
  - `refreshOverviews` の中の例外（これまでどおり、最後の記録を残します）

  一部だけ書いたことを、成功として記すことはありません。（2026-11-17 訂正：最初の版は固定の確認より前に記していたため、固定が拒否されても番号が進み、先に尋ねた有効な答えを捨てていました。）
- **`loadSeason` に古い答えが届いたとき**：成功でも失敗でも、何も変えず、誤りとして数えません（`seasonStale`）。固定・記録・シーズン・時計・ビーコン・派生の読み込みは、あとの答えが決めたままです。新しい答えの失敗は、これまでどおりです。
- **`refreshOverviews` が反映する記録**：固定している世界のもの（クラスター・プログラム・シーズン・記録が名乗るならシーズンの口座）で、しかも最新の答えのときだけです。固定は `loadSeason` だけが行います。別の世界の記録は、次の `loadSeason` が固定します。
- **番号は増えるだけ**です。あとの読み込みを止めることはなく、世界の切り替えは、それが最新の答えになった時点で反映されます。同じ世界の通常の読み込みは変えません。

## 失敗のあとの読み直し・表示の回復・鎖の時計（2026-11-17、Lane C）

実際の導線：読み直しは三つの経路で起こります。いずれも `loadSeason` を呼び、一度に一つずつ読みます（`createPollLoop`）。

- シーズンの読み込みの繰り返し：30 秒ごと。速い時計ではもっと短い間隔です。
- 再読み込みのボタン（`onReread`）
- ページをもう一度表示したとき（`visibilitychange`・`pageshow`）

ここでの決まりは次のとおりです。

- **シーズンの読み込み自身の誤り**（記録を読めない・固定の拒否・ビーコンの不一致）は、シーズンの読み込みのものとして印を付けます。あとで読み込みに成功し、固定が受け入れられたら、その誤りは消します。ビーコンが合わなければ、また立てます。
- **別の操作の誤り**（ローカルプレイの接続先が変わった、など）は、シーズンの失敗で上書きしません。シーズンの成功でも消しません。
- **先に尋ねた答え**（成功でも失敗でも）は、誤りを立てることも消すこともしません。
- **鎖の時計**は、固定の世界が変わったときだけ、標本のない状態から始め直します。そのあと、その記録の標本をすぐに取ります。前の世界の標本（時刻・スロット・ずれ）を、新しい世界の時計として使いません。標本がない時計は「わからない」です（`behind()`・`now()` は null）。新しいとは言わず、遅れの表示も出しません。同じ世界の時計は、そのまま続けます。時計の意味とゲームの判定は変えません。

## 一部だけ反映した読み込み・起動時の失敗から、正常な表示に戻る（2026-11-17、Lane C）

- **鎖の時計**：時計は、その標本が属する世界（固定と世代。`FS.chainWorld`）を持ちます。その世界が今の固定と違うときだけ、時計を作り直します。前の読み込みが、固定と前の世界の忘却まで進んだところで例外になっても、次の成功で時計は新しい世界のものになります。最初の読み込みと同じ世界では、作り直しません。A → B → A は世代が違うので、三回とも作り直します。
- **シーズンが必要な開始は一度だけです**：プレイ・観戦・練習・環の概要・協力の掲示板がこれにあたります。最初に成功した読み込みのときに始めます。起動時でも、起動時に読めなかったときの、シーズンの読み込みの繰り返しの最初の成功でもかまいません。起動時の読み込みが例外になっても、起動は止まらず、繰り返しがまた読みます。読めない間の表示は、これまでどおりです（誤りの行、または「読み込み中…」。読み手の状態は `unreachable` または `pending`）。成功のふりはしません。

## 遅れた開始・途中の失敗のあとも、プレイは読み続ける（2026-11-17、Lane C）

- **最初の読み込みが失敗しても、開始は止まりません**：`startPlay` の最初の読み込みは次のものです。どれかが例外になっても、記録に残して開始を続けます。そのあとの手順も、これまでどおり行います（ローカルプレイの本人確認・ウォレットの出来事の追跡・二度目の同期・プレイの読み込みの繰り返し）。
  - 前回のウォレットへの静かな再接続と、セッションの復元
  - 規則のモジュール
  - ウォレットの同期
  - 最初の再読み込み

  読み直すのは、プレイの読み込みの繰り返しです。`startPlay` は値を返しません。ページの側で、終わったあとに `playReady` と `viewerMissed`、最後に `viewerKnown` を決める流れも、これまでどおりです。
- **答えを待っている間の読み手**：ウォレットがあり、その記録を尋ねていて（`meStatus` が `'loading'`）、まだ一度も答えがなく、市民も村もない間は、`pending` です。「未参加」（`known`）とは言いません。答えがなく失敗した場合の `unreachable` は、これまでどおり先に判断します。
- **シーズンが必要な開始の手順**：各手順は、実行し終えてから「済み」と記します。観戦・協力の掲示板・プレイは、繰り返しや時計や受け手を登録するので、一度しか実行しません。例外になった手順だけを、次の成功した読み込みで実行し直し、ほかの手順は二度実行しません。協力の掲示板が入れられなくても、プレイは止めません。全体を「済み」にするのは、すべての手順が済んだときだけです。
- **最初の地図**：これまでどおりです。地図は、本人がカメラを動かすまで毎回、開く位置を計画し直します。主題（本人の村）が変われば、そこへ向け直します。そのため、遅れて始まっても本人の村に届き、本人が動かしたカメラを奪うことはありません。

## 観戦の追従と戦いの場面は、一つの世界の中だけで（2026-11-17、Lane C）

実際の導線：`startSpectate` の繰り返し → `refresh` → `spectateBells` → `followBattles` → `playBattle`（カメラの移動、ない場合は代わりの位置へ）。地図が自分で見せる場面は `autoBattles`、報告は `openReport` です。

- **観戦の追従**：比べるのは、今の世界（世代を含む）のために読んだ記録（`FS.chronicleWorld`）の衝突だけです。その世界の記録がまだ読めていない間は、何も比べません。世界が変わったら、最初に見えた衝突を基準にします。前の世界の最後の衝突を基準にして「新しい戦い」と言うことはしません。読み込みに失敗した回は、何も追いません。
- **衝突の答えが届くまでの間**：その間に世界かヘラルド（その実体）が変わったら、`playBattle` は何もしません。場面も見せず、カメラも動かさず、**null**（取り消し）を返します。**false** は「場面なし」だけです。代わりの位置へ飛ぶのは false のときだけで、null のときは飛びません。
- **追従の条件**：上に加えて、その間に次のどれかが起きた場合も、場面を見せず、代わりの位置へも飛びません：
  - 観戦の自動の追従が切られた（`auto: false`）
  - 報告が開かれた
  - 地図が数えるカメラの移動があった（`map.moves`：ドラッグ・ホイール・ピンチ・キーやボタン・名前で頼む移動）

  飛んでいるカメラを指で止めるだけの操作は、この数には入りません。その代わり、地図が人の操作として記す `map.touchedAt`（指で触れた・ホイール・地図のキー）が変わったときも、追従を取り消します（次の節）。
- **地図が自分で見せる場面**：同じ州の、より新しいターンの場面が再生中なら、古い答えで上書きしません。名前で頼まれた場面（報告の「見る」）は、これまでどおりです。
- **地図が自分で見せる場面**：別の世界で見たものは忘れます。まだ残っている別の世界の州の記録は見ません。そのため、新しい世界で各州を最初に見たときは、「新しい」とは言いません。
- **変えていないもの**：同じ世界の中の正当な更新・カメラの移動・報告そのものの世界の確認は、これまでどおりです。

## 始まっている戦いの場面と、終わったあとのカメラの戻り（2026-11-17、Lane C）

- **場面の世界**：場面（`FS.battles` の一つひとつ）は、尋ねたときの世界（世代を含む）を持ちます。世界が変わったら、ほかの世界の場面を終えます：
  - 地図の描画から外し、`endBattle` で終えます。
  - 効果の層にも `battle:end` を送り、その場面の分だけを取り消します（暗くする効果・人物・題字・シートの人物）。同じ場所でも、別の場面は残します。
  - 世界の印のない場面には触れません。
- **戦いのためにとっておいたカメラの位置**：とっておいた世界のものです。
  - 別の世界でとっておいた位置は、その時計ごと手放してから、今の世界の位置をとっておきます。
  - 終わりの時計が戻るのは、同じ世界のままで、しかもとっておいてから人が地図に触れていない（`map.touchedAt` が同じ）ときだけです。そうでなければ、位置を手放し、カメラは動かしません。
  - `map.touchedAt` は、地図が人の操作として記すものです。指で触れたとき（飛んでいるカメラを止めるだけでも）、ホイール、地図のキーで変わります。
- **観戦の追従**：`map.touchedAt` が変わったときも、取り消します。
- **片付けの時点**：世界が変わったら、地図の人物の層が作り置きを返す・作るより前と、`playBattle` が場面を比べるより前に、戦いの状態をその世界のものにします（`syncBattleWorld`）。作り置き自体を、前の世界のまま返すことはありません。比べるのは、今の世界の場面だけです。
- **変えていないもの**：同じ世界の中の正当な終わりとカメラの戻り・明示の「見る」・最新の場面は、これまでどおりです。自動の追従をずっと止める仕様は採っていません。

## 報告の「戦いを再生」「見る」：読めるまで報告を残す（2026-11-17、Lane C）

実際の導線：「戦いを再生」「見る」のボタンは、次の場所にあります。どれも `battle-play` を送り、`app.mjs` の `playAsked` から `playBattle(focus)` に進みます。

- 報告
- 追跡の一覧
- お知らせ
- 調べる画面
- ターンの一覧

- **読む間**：押した報告は開いたままにし、ボタンの下に「戦いを読み込んでいます…」と出します。
- **場面を見せられたとき**（`playBattle` が true）：その報告だけを閉じます。
- **場面を見せられなかったとき**（false、または例外）：報告はそのまま残し、「戦いを読み込めませんでした。報告はそのまま残しています。もう一度押すと読み直します。」と出します。同じボタンを押せば、もう一度読みます。
- **取り消しは失敗ではありません**：世界やヘラルドが変わったことによる取り消し（null）では、何も言わず、何も戻しません（報告そのものの世界の扱いは、`openReport` と `loadSeason` のとおりです）。
- **押した順と本人の操作**：要求が有効なのは、次のすべてが成り立つ間だけです：
  - 最後に押したものである
  - 押したときの報告が今も開いている（報告なしで押したなら、今も報告がない）
  - 同じ世界である

  これは `playBattle` の中で、場面・効果・カメラ・地図の場面の一覧より前に確かめます（`asked`）。成り立たなければ、何も見せず（null）、新しい要求の状態にも触れません。
- **明示の再生を止めない**：`asked` は、自動の場面や追従の「新しいターンを優先」の決まりには入りません。本人が名前で頼んだ過去の戦いは見せます。
- **変えていないもの**：場面そのもの・カメラ・明示の要求であること（自動の場面や追従とは区別します）・ルールや結果は、これまでどおりです。

## 広い地図：読んでいない地域 → 選択 → くわしい表示 → 読み直し（2026-11-17、Lane C）

実際の導線：地図を動かして近づくと、見えている州の記録を読みます（`app.mjs` の地図の `provinceOf` → `controller.wantProvince` → `loadEnvelope`）。州や村を選ぶと、同じ読み込みを行い、`hud/inspect.mjs` の札に出します。環の村の一覧は `map/overviews.mjs` が読みます。

- **州の読み込みの結果を記します**（`FS.provinceReads`）。記すのは、固定している世界の読み込みで、しかもその州の記録をまだ持っていないときだけです。前に読めた記録があれば、それを見せ続けます。
  - 読み込み中（`loading`）
  - 読めなかった（`failed`。ヘラルドの符号つき）
  - ヘラルドに記録がない（`missing`。NotFound）
- **札の表示**：開いている土地について、次のものを、それぞれそのとおりに言います。「何もない州」「村がない」とは言いません。
  - 読み込み中
  - 読めなかった（符号つき）
  - 記録がまだ届いていない
  - まだ読み込んでいない
  - この環の村の一覧をまだ読めていない
- **「もう一度読み込む」**（`province-reread`）：読み込み中でないときに出します。その州の記録をすぐ読み直し（その州だけ、次に尋ねるまでの待ちを外します）、まだ読めていない環の一覧も読み直します。読むだけで、選択とカメラは動かしません。
- **世界が変わったら**：前の世界の州の記録・次に尋ねるまでの待ち・読み込みの結果を忘れます（州の記録の入れ物は、中身だけ空にします）。
- **変えていないもの**：同じ世界の通常の移動・拡大と、30 秒ごとの読み直しは、これまでどおりです。
- **読み込みの場所がすべて埋まっているとき**（同時に 12 件）：本人が選んだ州と、「もう一度読み込む」を押した州は、失いません。**一つだけの待つ場所**に入れ、どれかの読み込みが終わったときに始めます。待つのは一つだけで、列は作りません。あとから来たものが、その場所を取ります。始めるのは、同じ世界のままで、その州がまだ選ばれているときだけです。選択を変えたか、世界が変わったら、手放します。札には「順番を待っています」と出します。
- **「もう一度読み込む」の答え**：押した結果を必ず返します。始めた（`started`）、もう読み込み中（`loading`。二重には読みません）、待っている（`waiting`）のどれかです。
- **読み込みごとの印**：同じ州の古い読み込みが終わっても、新しい読み込みの場所は空けず、その表示も消しません。
- **場所の数え方**（訂正）：上限（同時に 12 件）は、**実際にまだ終わっていない要求**の数で数えます。尋ねた世界は問いません。世界が変わったら、前の世界の読み込みの意味（答え・「読み込み中」の表示）と、待っている要求は手放します。しかし、前の世界の要求がまだ使っている場所は、手放しません。要求を途中で止める手段はないので、止めたものとしては数えません。場所が空くのは、その要求が終わったときだけです（答えた・失敗した・捨てた、のどれでも）。そのため、世界が何度変わっても、同時に進む読み込みは 12 件を超えません。

## 行軍の入口：地図で選ぶ → 軍勢を知る → 計画の下書き → 行き先・道のりの確認 → 戻る（2026-11-17、Lane C）

実際の導線：地図のマスを選ぶと、`hud/inspect.mjs` の札に「進軍させる」（`compose`）が出ます。押すと、`controller.mjs` の `ACTIONS.compose`（下書き）→ 行き先（`dest-from-map`・`setDestination`）→ 行軍の札（道のり・着くターン・条件）と進みます。やめるには、しまう（`compose-close`）か、選び直します。**ここで扱うのは下書きと確認までです。** 送信の決まり・手数料・権限・行軍の実行そのものは変えません。

- **札の「進軍させる」**：そのマスにいる自分の軍勢なら、どの村のものにも出します。開いている村の軍勢に加えて、その州の記録から、自分のほかの村の軍勢も出します。ほかの村の軍勢には、「別の村の軍勢：その村から出します」と添えます。
- **下書きを開く村**：その軍勢の村です。開いていた村が別の村なら、まずその村に切り替えます（地図からの命令・「村へ戻す」・砦への進軍と同じです）。下書きが名乗る村も、その村です。
- **「村へ戻す」の行き先**：その軍勢自身の村です。印と行き先を書くのは、その要求が今開いた、その軍勢の下書きだけです。軍勢がもういなくて下書きを開けなかったときは、前から開いている別の軍勢の下書きを変えません。
- **ページの側の入口**（地図からの命令・行き先つきの下書き・札や一覧のボタン・「村へ戻す」）：先へ進むのは、その要求が開いた、その軍勢の下書きのときだけです。軍勢がもういなくて下書きが開かなかったときは、前から開いている別の軍勢の下書き・選択・カメラを変えません。道のりを待ったあとに断りを出したり、着くターンを動かしたりするのは、その要求のもののときだけです。要求のものかどうかは、**そのもの**で確かめます：その要求が開いた下書き、その要求が渡した行き先（座標が同じでも、選び直した行き先は別のものです）、そのときの世界（世代を含みます）。どれも、待つ前に取っておきます。同じ軍勢への二度目の要求、同じ場所の選び直し、取り消し、世界の変化のあとでは、前の要求は何も言わず、何も動かしません。
- **行き先を選んだあとの道のり**：下書きがまだ開いていて、その行き先を今も指しているときだけ書きます。しまった下書きや、別の行き先を選んだあとの下書きには、古い道のりを書きません。
- **世界が変わったら**：ただの下書きはしまい、手に取っていた軍勢は手放します。送信中・送信待ち・予約済みの下書きは、送信の側に任せます。選んだ場所はそのままです。

## 行軍の札：計画を読む → 判断する → 読めなければ調べ直す → やめて地図へ戻る（2026-11-17、Lane C）

実際の導線：行き先を選ぶと、`controller.setDestination` が道のりを求め、`hud/marchcard.mjs` の札に、道のり・着くターン・条件を出します。**扱うのは下書きまでです。** 送信・送信待ち・手数料・行軍の決まりは変えません。

- **道のりを読めなかったこと**（`routeUnread`）は、次の二つと分けて扱います：
  - 「道がない」という世界の答え（断りの符号）
  - 「探している途中」

  規則のモジュールを読めなかったときと、道のりを求める途中で失敗したときは、札に「道のりはまだわかっていません。行き先と設定はそのままです。着くターンは、道のりがわかってから決まります。」と出し、「道のりをもう一度調べる」（`dest-retry`）のボタンを出します。
- **調べ直し**：下書きが今指している行き先への、新しい要求です。前の要求の答えが遅れて届いても、書きません。構え・撤退・倍率・心づけ・「村へ戻す」の印は変えません。送信中は、調べ直しません。
- **着くターン**：道のり・いちばん早いターン・着くターンは、先に求めてから、まとめて書きます。札の着くターンは、いつも、そこに出ている道のりから求めたものです。
- **送信**：道のりがわからない間は、送信のボタンを押せません（これまでどおりです）。
- **やめる**（`compose-close`）：これまでどおりです。そのあとに届いた答えは、しまった下書きにも、新しい下書きにも書きません。

## 行軍の札の見込み：読めなければ「まだわからない」、同じ下書きから計算し直す（2026-11-17、Lane C）

実際の導線：`app.mjs` の `updateForecast`（毎秒）→ `hud/forecast.mjs`・`hud/forecastmodel.mjs` → `hud/marchcard.mjs` の見通し。**下書きまでです。** 送信・`pendingDriver`・行軍の決まり・視界の決まりは変えません。

- **見込みを出せなかった理由**は、次の三つに分けて扱います：
  - **読めなかった**（`unread`）：規則のモジュールを読めなかったとき、行き先の州の記録を持っていないとき（`NoRecord`）、計算の途中で失敗したとき。札には「見込みはまだわかりません（…を読めていません）。下書きはそのままです。」と出し、「見込みをもう一度計算する」（`forecast-retry`）のボタンを出します。行き先の州の記録は、通常の読み込みで頼みます。届いたら、自動で計算し直します。
  - **見えていない土地**（`OutOfSight`）：これまでどおり、見込みは出しません。最初に確かめ、頼み直すこともしません。視界は広げません。
  - **決まりによる断り**（柵が道にある、など）：答えです。読み直しのボタンは出しません。
- **要求の持ち主**：見込みの答え・失敗・後片付けは、どれも、その要求自身のものであるときだけ書きます。持ち主は、下書き・行き先（そのもの）・鍵・世界（世代を含む）で確かめます。次のあとでは、前の要求は何も書かず、新しい要求の場所も空けません：
  - 同じ鍵の別の下書き
  - 取り消し
  - 続けての計算し直し
  - 同じ座標の選び直し
  - 世界の変化
- **計算中のまま残った見込み**：前の要求が「計算中」のまま残していた見込みは、計算し直します。
- **地図を押して選んだ行き先の断り**：その押下が、その下書きに渡した行き先についてだけ出します。

## 報告の外から頼んだ「見る」「戦いを再生」：読み込みの結果を必ず言う（2026-11-17、Lane C）

実際の導線：お知らせの「見る」、追跡の一覧・調べる画面の「戦いを再生」は、どれも `battle-play` を送ります。`app.mjs` の `playAsked` から `playBattle(focus)` に進みます。報告が開いていないときは、その押下の状態（`FS.replayAsk`）を、地図のお知らせの積み重ねに一つだけ出します（`renderFeed`）。

- **読む間**：「戦いを読み込んでいます…」と出します。
- **場面を見せられたとき**：その表示を消します（再生の成功）。
- **読めなかったとき**（「場面なし」または例外。その間に何も変わっていない場合）：「戦いを読み込めませんでした（ターン N）。戦いがなかったという意味ではありません。記録はそのままです。」と出し、同じ要求をもう一度出すボタンを付けます。カメラは動かしません。
- **取り消し**（世界やヘラルドが変わった、本人が報告を開いた）：何も言わずに消します（失敗ではありません）。
- **押した順**：答えるのは、最後に押したものだけです。前の押下は、あとの押下の表示に触れません。
- **本人が表示を閉じたとき**：読む間に閉じたら、その要求は取り消しです。場面も見せず、カメラも動かしません。
- **世界が変わったら**：前の世界で頼んだ表示だけを消します。表示は、頼んだ世界（世代を含む）を持ちます。新しい世界で頼んだ表示は、地図の同期のあとも残り、あとから届く結果を受け取ります。
- **記録には触れません**：これは記録ではありません。お知らせの一覧の内容と、既読の印は変えません。送信の状態（`FS.notice`・「もう一度」）も使いません。報告の中で押したときは、報告の行に出します（これまでどおり）。

## 広い地図の上で、読めていない場所を知る（2026-11-17、Lane C）

実際の導線：読み込み側（`controller` の `FS.provinceReads`、`map/overviews.mjs`）→ `app.mjs` の `readMarksNow`（地図に渡す一覧）→ `map/fmap.mjs` の `topPass`（地図の上の文）→ 州を選ぶ → 札の「もう一度読み込む」。

- **記録のない土地は、空の土地ではありません。** 地図は、読めていない場所に、その場で文を出します。
  - **州**：地図か本人が読み込みを頼み、読めなかった州には、「読めていません（選ぶと読み直せます）」と出します。読み込みの場所が空くのを待っている州には、「読み込みの順番待ち」と出します。記録を持っていない間だけです。
  - **環**：村の一覧を頼んだのに届かなかった環には、その環の州の一つに、「この輪の村の一覧を読めていません（州を選ぶと読み直せます）」と出します。一覧が届いたら消します。
- **出さないもの**：次のものには、印を出しません。印は、頼んだ読み込みの結果だけを言います。視界は広げず、土地や敵は何も描きません。
  - 読み込み中の州（地図を動かすたびに、ちらつくため）
  - 記録を持っている州
  - 頼んでいない州（視界の外を含む）
  - 頼んでいない環
- **世界**：州の状態は、世界が変わると忘れます。環の「届かなかった」は、頼んだ世界（世代を含む）を持ち、別の世界のものとしては出しません。
- **戻り方**：州を選ぶと、札が読み込みの結果を言い、「もう一度読み込む」で読み直します。同時に 12 件の上限と、一つだけの待つ場所は、そのままです。

## 行軍の追跡：読めていないことを言い、一件ずつ読み直す（2026-11-17、Lane C）

実際の導線：`controller.readMarches`（行軍の一覧を作る既存の読み込み）→ `FS.marches` → `screens/tracker.mjs`。読み直しは `controller.rereadMarchFacts`（純粋な読み込み）です。

- **一覧をまだ読めていないこと**と、**進軍がないこと**を分けます。一覧を読んだら、`FS.marchesRead` を記します。読む前は、読み手に進軍がありうる間、「進軍の記録をまだ読めていません。進軍がないという意味ではありません。」と出します。読み手か世界が変わったら、一覧を空にして、「読めていない」に戻します。
- **一件の進軍の、到着先の記録を読めなかったこと**を、その進軍に付けます（`unread`）。対象は、到着のターンの州の記録と、そのターンの記録です。追跡の札は、「この進軍の到着先の記録を読めていません。上の進み具合は、読めたところまでです。結果がないという意味ではありません。」と出し、「記録をもう一度読む」のボタンを出します。
- **読み直しは、純粋な読み込みです。**
  - ヘラルドの同じ二つの記録を読み、その進軍の表示（進み具合・封が開いたか・`unread`）だけを書きます。
  - 帳簿の読み書き、封を開ける送信（self-reveal）、結果の受け取り（settle）は行いません。それらの判断のもとになる値（`slot`・`env`・`record`・`entry`・`transit`・`settleReady`）は変えません。条件・頻度・権限は、これまでどおり `readMarches` と送信の側のものです。
  - 到着のターンより前は、読みません。封をした行き先を、その前に尋ねることはありません。
- **書く条件**：答えを書くのは、ヘラルド・ローカルプレイ・村・帳簿の鍵・世界（世代を含む）・一覧・その進軍が同じで、最後に押した要求のときだけです。
