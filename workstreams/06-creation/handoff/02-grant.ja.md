## 1. ⑥が必要とすること

⑥は権利を作らず、移さず、写しません。定義には「どの種類の権利を、どの施設・倉に対して、何回分」と **書く** だけです。そのうえで、次の二つの問いに答えてほしいのです。

| 場面 | 問い | 求める性質 |
|---|---|---|
| 実行前の確認（助言） | 利用者 U は、発行元 S に対する種類 K の権利を、日 D に、N 回分、今使えるか。使えないなら、なぜか | 読み取りだけ。結果は保証にならなくてよい |
| 実行の各手順 | 同じ問いに「はい」なら、その N 回分を **同じ原子的な操作の中で** 消費する | 確認と消費の間に割り込みがないこと（二重使用の防止） |

```ts
// ⑥のアダプタが呼ぶ形（案。名前は②に合わせて変える）
grantProblem({ holder, kind, source, day }) -> null | { code, ...detail }   // 読み取り
runsLeft({ grant, source, day }) -> { onGrant, onFacility }                 // 読み取り
consumeRuns({ grant, source, day, runs }) -> ok | { code, ...detail }       // 実行時。原子的
```

## 4. 既知の不一致の候補（S2 の事実と⑥の仮置きの差）

| 項目 | S2（未統合ブランチ）の事実 | ⑥の仮置き | 影響 |
|---|---|---|---|
| 発行者による取り消し | 規則に見当たらない。設計22 §4 は「条件の変更は新しく出す札にだけ効く」 | 取り消し（`state: "revoked"`）を模擬し、実行を止める | ②が取り消しを持たないなら、⑥のこの経路は「施設を閉じる」「奪われる」だけになる |
| 権利の種類の表し方 | 数値（1 持ち分、2 受け取り、3 使用、4 配達） | 文字列。配達（4）は⑥では使っていない | アダプタで変換 |
| 持ち分・受け取りの札の実行 | `WithdrawShares`・`ClaimReceipt`/`WithdrawReceipt` | 定義の型の検査はあるが、⑥の模擬の実行は **工房と荷車だけ**（持ち分・受け取りの手順は実行で `EFFECT_UNKNOWN`） | ⑥の模擬の範囲の限界。②④が揃った後に足す |
| 預かりの中の束 | 使えない（`ESCROW` の印） | `GRANT_NOT_HELD`（預かりの中）として扱う | 理由の区別を②に合わせる |

## 5. ②に決めてほしいこと

1. 既に出した使用権を、発行者が取り消せるか。
2. 権利の確認を、スナップショットで行うか、ターンの始めにまとめて行うか（段階3の「ターン始めにまとめて判定」との関係）。
3. 準備の便宜として、候補の束を自動で選んでよいか。
4. ⑥の「確認（助言）」と「実行時の消費」を分ける形を、②の検証器の分け方として受け入れられるか。
