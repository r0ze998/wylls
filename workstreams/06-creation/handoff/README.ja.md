## 受け入れの確認に使えるもの

⑥のテスト（`node --test workstreams/06-creation/test/*.test.mjs`）は、模擬が契約を満たすことを確かめています。各担当の成果物にアダプタを差し替えたとき、同じテストが通るかで、⑥の必要とすることが満たされているかを確かめられます。各資料の最後に、関係するテストの名前を挙げました。

## ⑥から各担当への依頼（まとめ）

1. **②へ：** 既に出した使用権を発行者が取り消せるか。権利の確認を、スナップショットで行うか、ターンの始めで行うか。束ごと・工房ごとの回数の確認と加算を、実行の命令と同じ取引で行うこと（S2 の `UseRun` の形）を、接続の前提にしてよいか。
2. **③へ：** 命令の型を表として公開し、⑥の効果の表をそこから生成できるか。⑥の「効果」は複数の命令の組（例：荷車＝送る＋精算）だが、③の型の単位とどう対応させるか。
3. **④へ：** 実行の認可（採用・依頼の署名・使い捨て番号・1日の回数）をどこで記録するか。記録の id の決め方。配達で届いた物を押さえる「束」を、コアの仕組みとして持つか（持たない場合、C の二重消費の保証は弱くなる：[docs/07](../docs/07-guarantees.ja.md) §3）。
