# 共有UIへ：試作の画面とゲームの画面のつなぎ方（提案）

**状態：** 提案。共有 UI（`permutation-server/web/frontier/`）は変更していません。

## 1. 試作の画面にあるもの（`workstreams/06-creation/proto/`）

| 画面 | 中身 |
|---|---|
| 作る・確かめる | 見本から定義を作る、条件の確認、仕組みの紙（機械が書いたもの）と作者の説明を分けて表示、今の人の鍵で公開 |
| 一覧から選ぶ | 検索、紙、版の変わり方、使う準備、写して編集、作者の状態変更（作者以外が試すと拒否） |
| 使う準備 | 入力・札の名指し、実行前の確認、採用（版と内容ハッシュに固定）、採用済みの計画（実行の依頼・止める・更新の通知と確認） |
| 世界と台帳 | 場所・所持金・札・束（消費する権利）・完了記録（証明）・署名の記録 |

## 2. ゲームの画面に入れるなら（順番の案）

1. **一覧と紙だけ**：公開の一覧を配り、紙と作者の説明を分けて出す。
2. **使う準備と採用**：実行前の確認の結果を、今ある S1 の注文の欄（荷車・倉）の前に出す。足りない札は、S2 の画面（束の一覧・預かり）へ案内する。採用（固定）を明示の操作にする。
3. **採用済みの計画**：更新の通知と、利用者による更新の確認を分けて置く。説明だけの更新でも自動では移らないことを画面で示す。
4. **写して編集**：段階4の「テンプレート」と同じ入口。

⑥のモジュール（`src/`）は依存がなく、Node とブラウザの両方で動きます（WebCrypto の Ed25519）。

## 3. 本番に入れる前に要るもの（⑥の範囲外）

- 公開の一覧の置き場（チェーン・herald・別のサービス）。試作はブラウザの localStorage とメモリだけ。
- 署名の鍵：試作は固定の種から作った模擬の鍵。本番ではウォレット・セッション鍵の規則（他人あてはウォレット、S2 L7）と合わせる。
- 実行：④の Run（[04-run-receipt.ja.md](04-run-receipt.ja.md)）。
