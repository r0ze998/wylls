# 提案：②（Grant）へ — ⑥が権利について問うこと

**状態：** 提案。②の成果物は確認時点で repo にない。②の決定が優先し、⑥はそれに合わせて `src/world.mjs` を差し替える。

## ⑥が②に問うのは一つだけ

> 「利用者 U は、発行元 S に対する種類 K の権利を、日 D に、N 回（量）分、今使えるか。使えないなら、なぜか。」

⑥の定義は、この問いの **K・S・N を書く** だけで、権利を作らず、移さず、写さない。

```ts
// ⑥が呼ぶ形（案）
grantCheck({ holder, kind, source, day, need }) -> null | { code, ...detail }
grantCandidates({ holder, kind, source, day }) -> GrantId[]   // 準備の便宜。なくてもよい
```

## 理由の対応（⑥のコード ← S2 の規則）

| ⑥のコード | 意味 | S2 の根拠 |
|---|---|---|
| `GRANT_NOT_HELD` | 持ち手が違う、預かりの中にある | Lot の `HOLDER_*`、`ESCROW`（2a §2.2、2e） |
| `GRANT_WRONG` | 種類か発行元が違う | Issue の `KIND`・`SRC_*` |
| `GRANT_VOID` | 発行元が奪われた・建て直された・閉じた | `SRC_GEN`・`SRC_STAMP` の不一致（2a §1） |
| `GRANT_EXPIRED` | 期限切れ | `UNTIL_DAY` |
| `GRANT_INSUFFICIENT` | 今日の残り回数が足りない（束ごと／工房全体） | `AMOUNT × PER_UNIT`、工房の数×24（2d §1） |

②がこれと違う分け方を選ぶなら、⑥は②のコードをそのまま表示し、上の表は対応表として残す。

## ⑥の試作で確かめたこと（②が流用できるテスト）

- 写し（fork）は権利を持ち出さない：定義に束の id は入らない、元の作者の束を名指ししても `GRANT_NOT_HELD`（`test/required.test.mjs` 10）。
- 発行元の世代が上がると、その束はすべて無効（同 4）。
- 束の残りと工房全体の残りを別々に数える（同 2・7）。

## ②に決めてほしいこと

1. 権利の確認を「今のスナップショット」で行うか、「実行のターンの始め」で行うか（S3 の「ターン始めにまとめて判定」との関係）。⑥の実行前の確認はスナップショットで、実行時に変わりうることを前提にしている。
2. 準備の便宜として、候補の束を自動で選んでよいか（⑥の試作は、利用者が名指ししなければ自分の束から最初の一致を選ぶ）。
