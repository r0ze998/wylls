# 提案：③（命令型）へ — 組み合わせに要る欄

**状態：** 提案。③の成果物は確認時点で repo にない。

## 現状

⑥の `src/catalog.mjs` は、S1/S2 の既存命令を **⑥が手で写した表** です。命令のタグ・CU 予算は ABI（`frontier-abi/src/v2/tags.rs`・`budgets.rs`、S2 はブランチ）から、規則の数字（8+4→4、容量 5000、精算預け 50,000）は `permutation-rules` と契約文書から写しました。手で写したものは古くなります（MAINTENANCE の「どこが正本か」と同じ問題）。

## ③に持ってほしい欄（案）

⑥は、命令ごとに次の欄があれば、表を手で持たずに済みます。

| 欄 | 例（UseRun） | ⑥での使い道 |
|---|---|---|
| 識別子・タグ | `UseRun`, `0xC8` | 紙・エラー表示 |
| 引数の型 | `via: workshop (grant use)`, `vault: vault (own, same province, unshared)`, `runs: int 1..24` | 型の検査、場所の検査 |
| 出力の型 | `made: result:run at vault` | 依存（C）の型の照合 |
| 使う物・作る物（1回あたり） | `ore 8, wood 4 → arms 4` | 物の流れ、在庫・容量の空実行 |
| 取引数・CU | 1 件、20,000 CU | 処理量の上限 |
| 署名の規則 | セッション鍵でよい／他人あてはウォレット | 紙の「署名」、`WALLET_REQUIRED` |
| 失敗の仕方 | `UseLimit`, `Insufficient`, `BadData`, 世代の違い | 紙の「失敗するとき」 |
| ある場所（水準） | S2 から | `EFFECT_UNAVAILABLE` |

生成の流れの案：ABI の生成（`abi-vectors`）と同じく、③の表から ⑥の `catalog` を生成し、CI の `--check` で古さを検出する。

## ③に決めてほしいこと

2. 段階3の「決まり」を、命令の一種として③で型を付けるか、⑥の定義の `trigger` として持つか。
