# 8. 止める権限を分ける（利用者・施設所有者・運営）

**決定（2026-10-30）：**
- 利用者が自分の実行を止める権限、施設所有者が自分の施設への許可を取り消す権限、運営が脆弱性への対応で止める権限を分ける。
- 作者の公開停止だけで採用済みの計画を止めない方針は維持する。
- 運営の緊急停止は、権限者・対象範囲・再開条件・記録方法の **提案まで**。包括的な停止権は実装しない。
- 署名済み・送信済みの操作まで必ず止められるとは扱わない。

## 1. 三つの権限と作者の公開停止

| | 利用者 | 施設所有者 | 運営（緊急停止） | （参考）作者の公開停止 |
|---|---|---|---|---|
| 止められるもの | 自分の採用（計画）と、自分の実行の依頼 | 自分の施設・自分が出した許可（札） | 脆弱性の範囲（下の §3） | 自分の定義の新しい採用・新しい依存 |
| 止められないもの | 他人の計画 | 他人の施設、施設と無関係な計画 | 人単位の停止（特定の利用者を止める）。範囲外の計画 | **採用済みの計画** |
| 手段 | 自分の鍵の署名（`AdoptionBook.end`）。依頼を出さないこと | ②の規則の範囲（施設を閉じる。発行済みの札を取り消せるかは②の決定） | 複数の鍵の署名、期限つき（提案） | 作者の鍵の署名（状態の履歴の番号に結びつける） |
| 効く場所 | 実行の受理時と、実行中の各手順（次の手順から） | 実行中の各手順（権利の検査） | 実行の受理時と各手順（提案） | 新しい採用の確認時だけ |
| この試作 | **実装** | **模擬**（取り消しの状態 `revoked`。可否は②の決定待ち） | **未実装**（提案だけ） | **実装** |

## 2. 止まるまでの段階：署名済み・送信済みの操作は必ずは止まらない

止める操作が受理されても、その前に署名され・送られた操作がどうなるかは、実行の仕組み（④）とチェーン次第です。⑥は「止めれば必ず止まる」とは扱いません。

**④の報告（2026-10-30 の要約。資料は未受領・内容は未検証）：** 取消を三つの状態に分けている。
1. 新しい要求の停止
2. 署名済みの要求の照合待ち
3. 取消の完了

⑥の試作は、この三つのうち **1 だけ** を表しています。そこで、本番では次の対応を想定します（**提案、④の資料待ち**）。

| ⑥の操作 | ⑥の試作での効き方 | ④の段階との対応（想定） | 止まらない可能性があるもの |
|---|---|---|---|
| 利用者が計画を止める（`end`） | 以後の依頼は受理しない。実行中の回は次の手順の前に止まる | 1 → 2 → 3 | 既に送られ、チェーンの上で処理中の命令（荷車の出発など）。照合が済むまで、結果は「止まった」とは言えない |
| 施設所有者の取り消し | 次に権利を検査する手順から止まる | ②④の決定待ち | 取り消しの前に受理・送信された工房の実行 |
| 運営の緊急停止（提案） | ― | 1 → 2 → 3 | 同上。停止の記録の時刻より前に確定した手順は戻さない |

試作の模擬は一つのプロセスの中で動くため、「次の手順から止まる」はテストで確かめられます（`review2`「ending or superseding a plan stops a run already under way…」）。チェーンの上では、送信済みの命令の取り消しは保証されません。

## 3. 運営の緊急停止（提案。実装しない）

| 項目 | 案 |
|---|---|
| 権限者 | 運営の複数の鍵（例：3人中2人の署名）。鍵の持ち主と閾値は公開する。国の代表を含めるかは未決定 |
| 対象範囲 | 命令（例：`UseRun`）、⑥の効果（例：`workshop.run`）、定義の内容ハッシュのいずれか。**人（利用者）単位では止めない**。包括的な停止（すべての計画）は持たない |
| 効果 | 範囲に入る実行の **新しい受理** を止める。実行中の回は、次の手順の前に止める。既に確定した手順の結果は戻さない。送信済み・照合待ちの操作は §2 のとおり、必ずは止まらない |
| 期限 | 必ず期限を付ける（例：72時間）。延長は再署名。期限が切れると自動で解ける |
| 再開条件 | (a) 期限切れ、(b) 修正した版が出て、その版の内容ハッシュを範囲から外す、(c) 権限者の署名による解除、のいずれか。利用者は更新を確認して新しい版へ移る（自動では移らない） |
| 記録方法 | 理由・範囲・署名者・開始時刻・期限・解除を、公開の追記専用の記録に残す。範囲に入った実行の拒否も、理由のコードつきで記録する |
| 置き場所 | 実行を認可する場所（④の Run、またはプログラム）。⑥は受理の最初に停止の一覧を読む「受け口」だけを持つ案（`execute.mjs` の採用の検査の直後が候補）。**⑥の試作には入れていない** |

**本番のプログラム自体の停止**（命令の無効化など）は共通コアの決定です。シーズン制は廃止された（2026-10-31）ので、世界を終わらせる停止は前提にしません（docs/10）。

## 4. 作者の「注意の知らせ」（案、未実装）

作者は、公開停止に加えて、署名つきの注意（影響する版、重さ、文章）を出せる。利用者の確認と採用済み一覧に警告として出すが、実行は止めない（決定どおり）。AI の代理が計画を動かす場合、注意が出た計画は自動では動かさず、持ち主の確認を求めることを既定にする案。

## 5. 判断してほしいこと（あなたへ）

1. 緊急停止の権限者（運営の複数の鍵だけか、国の代表を含めるか）と閾値。
2. 停止の範囲に「定義の内容ハッシュ」を入れるか（運営が特定の作者の定義を止められることになる）。
3. 作者の注意の知らせを入れるか、AI の代理の既定の振る舞い。
4. ②：発行済みの許可を施設所有者が取り消せるか。
