# 8. 緊急停止：誰が何を止められるか（提案）

**状態：** 提案。この試作で実装したのは、表の「利用者」「施設の持ち主」「作者」の行の範囲だけです。緊急停止（運営・コア）の仕組みは実装していません。

**前提（決定 2026-10-30）：** 作者の公開停止は、新しい採用だけを止める。既存の採用済みの計画は止めない。脆弱性などへの緊急停止は、これと別の仕組みにする。

## 1. 止める力を分ける

| 誰が | 何を止められるか | 既存の採用済みの計画への効果 | 手段 | この試作 |
|---|---|---|---|---|
| **利用者** | 自分の計画（採用）。1回の実行を依頼しないこと | 止まる（自分のものだけ） | 自分の鍵の署名 | 実装（`AdoptionBook.end`） |
| **施設の持ち主** | 自分の施設・自分が出した札の範囲 | その施設に依存する計画が、実行時に止まる | S2 の規則の範囲（施設を閉じる、など）。既に出した札を取り消せるかは②の決定 | 模擬（`GRANT_REVOKED`。取り消しの可否は未決定） |
| **作者** | 自分の定義の公開（新しい採用、新しい依存） | **止めない**。注意を知らせることはできる（下の2） | 作者の鍵の署名（状態の履歴の番号に結びつける） | 実装（公開停止）。注意の知らせは未実装 |
| **国**（投票） | 国が持つ仕組み（C4）、国の倉・施設 | 国の施設の持ち主として止める | 国の投票の記録 | 未実装 |
| **緊急停止の権限者**（運営・コア） | 命令・効果・定義のハッシュの単位で、新しい実行の開始 | **止まる**（範囲に入る計画の実行時に） | 多重署名、期限つき、公開の記録 | **未実装（提案）** |
| ⑥の検証器 | 止める力なし。新しい定義の検証規則を厳しくできる | 及ばない（既存の採用は固定版のまま） | 検証器の版を上げる | ― |

## 2. 作者の「注意の知らせ」（案）

作者は、自分の定義に欠陥を見つけたとき、公開停止に加えて、署名つきの注意（影響する版、重さ、文章）を出せる。
- 利用者の確認（preflight）と採用済み一覧に、警告として表示する。
- 実行は止めない（決定どおり）。止めるかどうかは利用者が決める（自分の計画を止める、または更新を確認する）。
- AI の代理が計画を動かす場合、注意が出た計画は自動では動かさず、持ち主の確認を求める、を既定にする案。

## 3. 緊急停止（運営・コア）の条件（案）

脆弱性（例：ある命令の組み合わせで物が増える）に対して、作者の判断を待たずに止める仕組み。誰でも使えると、作者以外が他人の計画を止める道具になるので、条件を絞ります。

| 項目 | 案 |
|---|---|
| 範囲 | 命令（例：`UseRun`）、⑥の効果（例：`workshop.run`）、定義の内容ハッシュのいずれか。人（利用者）単位では止めない |
| 効果 | 範囲に入る実行の **開始** と **各手順** を拒否する。既に終わった手順の結果は戻さない |
| 権限 | 複数の鍵の署名（例：3人中2人）。鍵の持ち主と署名の閾値は公開する |
| 期限 | 必ず期限を付ける（例：72時間）。延長は再署名。期限が切れると自動で解ける |
| 記録 | 理由・範囲・署名者・期限を公開の記録に残す |
| 解除 | 修正の版が出たら、その版の内容ハッシュを範囲から外す。利用者は更新を確認して移る |
| 置き場所 | 実行を認可する場所（④の Run、またはプログラム）。⑥は実行の最初に「停止の一覧」を読む受け口を持つ（`execute.mjs` の採用の検査の直後が候補） |

**本番のプログラム自体の停止**（シーズンの停止・命令の無効化）は共通コアの決定です。⑥はこれを決めず、受け口だけを用意する案です。

## 4. 判断してほしいこと（あなたへ）

1. 緊急停止の権限者を誰にするか（運営の複数の鍵か、国の代表を含めるか）。
2. 停止の範囲に「定義の内容ハッシュ」を入れるか（⑥の定義ごとに止められるが、運営が特定の作者の定義を止められることになる）。
3. 作者の注意の知らせを入れるか。入れる場合、AI の代理の既定の振る舞いをどうするか。
