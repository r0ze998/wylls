# 5. 公開停止・固定版の継続・更新の確認

**決定（2026-10-30、あなたの判断）：**
1. 作者による公開停止と、既存利用者の実行停止を分ける。公開停止は新規利用・新規採用だけを止める。既に利用者が確認した固定版の計画は、作者の公開停止では止まらない。
2. ただし、実行に必要な施設所有者の権限取消・期限切れ・残高不足は、引き続き実行を止める。
3. 説明だけの patch でも、既存の計画を利用者の確認なしに新しい版へ移さない（AI が説明を読んで判断しうるため）。実行する定義は、確認済みの版と内容ハッシュに固定する。更新の通知と、利用者による更新の確認を分ける。
4. 脆弱性などへの緊急停止は別の仕組みとして整理する（[08](08-emergency-stop.ja.md)、提案）。

**追加の決定（2026-10-30、第2回報告の確認後）：** 1日の回数は「受理された開始」で数える案を暫定とする（§4）。停止の権限は利用者・施設所有者・運営で分ける（[08](08-emergency-stop.ja.md)）。束は新しいコア仕様としての採用を保留し、配送の完了の証拠＋実行時の在庫の原子的な検査・消費と比べる（[07](07-guarantees.ja.md) §4）。

**正本：** `src/adoption.mjs`（採用・置き換え・利用者の停止）、`src/execute.mjs`（実行時の検査）、`src/upgrade.mjs`（版の上げ方・通知）、`src/registry.mjs`（公開・状態）。テスト：`test/policy.test.mjs`、`test/runtime.test.mjs`、`test/upgrade.test.mjs`。

## 1. 三つの記録を分ける

| | 何か | 誰が署名するか | 何を決めるか |
|---|---|---|---|
| **公開**（一覧の状態） | 定義の版（書き換え不可）と、名前ごとの状態（一覧に出ている・停止・取り下げ） | 作者 | 新しく採用できるか。新しい定義がこれに依存できるか |
| **採用**（計画の確認） | 利用者が、ある版のある内容ハッシュに固定した計画を「これで動かす」と確認した記録 | 利用者（計画の署名） | その計画を動かしてよいか。更新で置き換わったか。利用者が止めたか |
| **実行の依頼** | 採用済みの計画を1回動かす依頼。使い捨ての番号（nonce）と、その回に消費する束を含む | 利用者 | その1回を始めてよいか |

採用は実行前の確認（preflight）を通ったときだけできます。確認は、そのときの模擬の世界で行う助言です。実行の許可でも、資源の確保でもありません（[07](07-guarantees.ja.md)）。

## 2. 何が何を止めるか（実装済み）

| 出来事 | 新しい採用 | 採用済みの計画の実行 | どこで検査するか | コード |
|---|---|---|---|---|
| 作者が公開を停止・取り下げ | **止まる** | **止まらない**（知らせだけ） | 採用時の preflight／実行時は見ない | `ENTRY_NOT_LISTED`／`ENTRY_DELISTED_PINNED` |
| 使う成果（C）の作り手の定義が停止 | **止まる**（公開時・採用時） | **止まらない**（記録は過去の事実の証明として有効） | 公開・採用時 | `DEPENDENCY_SUSPENDED`／`DEPENDENCY_DELISTED_PINNED` |
| 作者が新しい版を出す（patch を含む） | 新しい版で採用できる | **変わらない**。通知だけ | 実行時は固定のハッシュだけを使う | 通知：`updateNotices` |
| 利用者が更新を確認 | ― | 古い計画は置き換わって動かなくなり、新しい計画が動く | 採用時（`supersedes`） | `PLAN_SUPERSEDED` |
| 利用者が自分の計画を止める | ― | **止まる**（実行の途中でも次の手順から） | 実行時、各手順で | `PLAN_ENDED` |
| 施設の持ち主の取り消し（模擬） | 止まる | **止まる** | 実行時、各手順で | `GRANT_REVOKED` |
| 施設が奪われた・閉じた・工房がなくなった | 止まる | **止まる** | 同上 | `GRANT_VOID`・`DEPENDENCY_UNAVAILABLE` |
| 札の期限切れ・定義の利用期限切れ | 止まる | **止まる** | 同上 | `GRANT_EXPIRED`・`MANIFEST_EXPIRED` |
| 残高（荷車の精算預け）・物・容量・回数の不足 | 確認では警告・エラー | **止まる** | 同上 | `BALANCE_SHORT`・`STOCK_SHORT`・`CAPACITY`・`GRANT_INSUFFICIENT`・`RUNS_PER_DAY_EXCEEDED`（1日の回数は利用者×定義で数える。同じ定義の計画をいくつ採用しても合計で上限） |
| 実行の依頼がない・他人の署名・使い回し | ― | **始まらない** | 実行時 | `RUN_REQUEST_INVALID` |
| 世界の規則に効果がない（S2 の効果を main の S1 で） | 止まる | **始まらない** | 実行時 | `EFFECT_UNAVAILABLE` |

固定した定義の中身（`validUntilDay` を含む）は、作者が後から変えられません。期限は確認済みの内容の一部なので、期限切れは実行を止めます。

## 3. 版と更新

- 版は書き換えられない（`VERSION_EXISTS`）。新しい版は前より大きい（`VERSION_NOT_NEWER`）。変更の大きさに見合う上げ方を、公開時に機械で強制する（`VERSION_BUMP_TOO_SMALL`。patch＝機械の部分が同じ、minor＝追加だけ、major＝それ以外）。
- **上げ方は通知の情報であって、自動で移る条件ではない。** patch でも minor でも、計画は利用者が確認するまで元の版のまま動く。
- 利用者が更新を確認する手順：新しい版で計画を準備 → 実行前の確認 → `supersedes` に古い計画を書いて採用。古い計画はその時点で `PLAN_SUPERSEDED` になる。置き換えられるのは、同じ利用者・同じ定義名の、動いている採用だけ。
- 更新先の定義が公開停止中なら、新しい採用になるので移れない（古い計画は動き続ける）。

## 4. 1日の回数（暫定、2026-10-30）

**扱い：** 認可され、実行の依頼として受理された「開始」で数える案を暫定とする。本番の上限値と日付の規則は確定しない。

| 項目 | 試作での扱い（実装済み） | 本番で決めること |
|---|---|---|
| 数えるもの | 依頼が受理された時点（署名・宛先・使い捨て番号・採用の状態・その日の上限を通った後）で `started` を1増やす | ― |
| 数えないもの | 実行前の確認、採用、署名や宛先の不正な依頼、使い回し（再送）の依頼、受理前の拒否（採用されていない・停止・置き換え・上限超え・定義の効果が世界にない） | ― |
| 失敗の記録 | 受理後に手順で止まった回は `failed`、最後まで動いた回は `succeeded`。どちらも `started` に含まれ、成功回数とは分けて残る（`AdoptionBook.tally`） | 失敗の回を上限に含めるか（暫定は含める） |
| 上限の単位 | **利用者 × 定義（作者と名前）**。同じ定義のどの版・どの計画も合計する | ― |
| 日付の境界 | 模擬の世界の整数の「日」（`world.today`）。実行の回は開始した日に数える。日をまたいだ実行の各手順は、権利の回数をその手順の日で数える | 日の区切り（UTC の0時か、ゲームのターン・戦期の区切りか） |
| タイムゾーン | 模擬には時刻がない | 利用者の地域の時刻に依存させない（一つの基準時刻で切る）案 |
| 上限の値 | 定義の `limits.runsPerDay`（作者が書く。［フェーズ6］の上限 24 以下） | 値と、運営の上限 |

### 回避できるか

| やり方 | 結果 | テスト |
|---|---|---|
| 同じ定義の計画をもう一つ採用する | **回避できない**（利用者 × 定義で合計） | `review2`「runs per day hold per user and definition…」 |
| 同じ定義の別の版（patch を含む）を採用する | **回避できない**（版は単位に入らない） | `policy`「runs per day: another plan or another version…」 |
| 同じ依頼を再送する | **回避できない**（使い捨て番号。再送は数えないが、動きもしない） | `policy`「runs per day (provisional)…」 |
| 定義を写して（fork）別の定義として採用する | **別の上限になる。** 1日の回数は、作者が定義に書く上限であって、資源を守る仕組みではないため。資源の上限（札ごと・工房ごとの1日の回数、在庫、残高）は写しても変わらず、写しの実行も同じ札の残りで止まる | `policy`「…a fork does not」 |
| 別の利用者（別の鍵）として採用する | **⑥では防げない**（利用者ごとの上限のため）。資源の上限は同じく札で止まる | ― |

## 5. 残っている判断（あなたへ）


1. **1日の回数の本番の規則。** 上の §4 の「本番で決めること」（日の区切り・基準時刻・値・失敗の回を含めるか）。
2. **取り消しの是非。** S2 の発行者が、既に出した使用権を取り消せるかは S2 の規則で決まっていない（設計22 §4 は「条件の変更は新しく出す札にだけ効く」）。試作は取り消しを模擬し、実行を止める側に倒した。②の決定に合わせる。
3. **公開停止の範囲。** 状態は名前ごとで、版ごとではない。特定の版だけを止めたい場合（その版に欠陥がある）は、[08](08-emergency-stop.ja.md) の緊急停止の範囲で扱う案。
4. **国が持つ仕組み（C4）。** 作者の署名の代わりに国の投票で公開・停止する場合は、署名の検査を投票の記録の検査に置き換える拡張が要る（未実装）。
