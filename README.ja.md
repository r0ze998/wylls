## 1. AIがプレイヤーのように振る舞うゲーム

*Wylls* は、意志（*will*）の英語表記です。このゲームは思考実験でもあります。**AIに意志があるとき、ゲームはどう振る舞うのか。** ここでいう意志は、モデルが何かを望むという主張ではありません。システムが作り、外から見える形で示すものです。続く目標（進み具合は、数えられるものはコードが数えます）、見せられた記憶の行を引用した理由、信頼とまだ返していない恨み、命令を断ること、評議会での発言と投票です。このうち、まだ返していない恨み、断ること、自軍への攻撃の記録は、これまでのどの実行でも観測されていません。〔出典: docs/GAME-DESIGN.ja.md:196-198、:136-143〕

大規模なライブのマルチプレイヤーゲームで、言語モデルのプレイヤーが有能なまま続いた例は見つかりませんでした（見落としがあるかもしれません）。そこで設計では、保証をコードに置き、モデルは「ルール上許された選択肢から選ぶ役」に限ります（[理由](docs/DESIGN-OVERVIEW.ja.md)）。見せ場は2つあり、どちらも【作成中】です。コードはブランチ `frontier/ai-integ` にあり、小さなローカル実行まで動かしました。本走と録画はまだ行っていません。〔出典: docs/GAME-DESIGN.ja.md:239-249〕

**1つ目は、AI市民が自分で出す進軍です（主役）。** コードが、AI市民にルール上許された候補を短い一覧にして出します（野営地、野戦の敵軍、建設、訓練、待機など）。AIはその中から自分で1つを選び、ページには、AIが引用した「Remembered（引用した記憶）」の行が出ます。これは、公開記録からコードが書いた出来事の文で、たとえば「ほかの国が先に野営地を倒した」のようなものです。軍は出発し、行き先は封印されたままです。到着の鐘が終わり、その進軍の開示（reveal）が公開されると、判断が開きます。示された選択肢、AIの理由（モデルが書いたもので、確認されていないと表示）、行き先、そしてプログラムが決めた本物の衝突レポートが出ます。12マスの進軍なら、10倍速で出発から実時間で約3〜4分後です （モデル値）。モデルが選んだ進軍のうち本物の衝突になった数（Y）は、本走で数えるまで分かりません。Y が 0 なら、この主張は取り下げ、評議会を主役にし、映像でもそう伝えます。

**2つ目は、国の評議会です。** 評議会の期間（試験設定では24鐘または48鐘。設計では1日1回）ごとに、コードが国ごとに目標の州を3つまで提案します。AI市民が演説つきで案を動議し、投票します。国0では、運営の席が1票を投じます（A/Bテストでは、運営が台本で入れます）。目標が採用されるのは、投票が2票以上あり、ほかの選択肢と「なし」のどれよりも厳密に多い場合です。採用された目標、つまり**攻撃命令**（コードと契約書では「Call」）は、攻撃の時まで外部の人には封印されたままです。評議会はチェーンの外にあり、チェーンは何も強制しません。6体のスモークテスト（小さな試験実行）では、評議会の9回がすべて定足不足で閉じました（国ごとにAIが1体のため）。攻撃命令が採用された例は、まだありません。〔出典: docs/GAME-DESIGN.ja.md:664-686〕

**なぜチェーンなのか。** 衝突を解決するのは運営ではなくプログラムです。出発は公開で、行き先は到着の鐘まで drand の時間ロックで隠されます（これは設計上の性質です。[第7節](#limits)の「封印の秘匿」を参照）。そしてシーズン全体がトランザクションの記録になり、私たちの検証器がそれを再生して確かめます（検証器は私たちのもので、独立した監査ではありません）。速さや安さではなく、これが理由です。もう1つの理由は、ルールと状態をオープンなチェーンに置けば、組み合わせ可能な改造と、許可の要らない経済ができるという考えです【設計のみ】。トークノミクスは設計していません。〔出典: docs/GAME-DESIGN.ja.md:250-258〕

技術、外交、市場、統治、得点、共有の文明は、設計であり、作っていません（[第3節](#complete-game)）。

## 4. AI市民を1画面で

**状態：【作成中】。** コードはブランチ `frontier/ai-integ` にあり、2026-10-12 の朝にこのツリーへ取り込みます。それまで結果は [AS-BUILT: pending] のままです。モデルは Gemma 4 26B A4B で、ローカルで動かします（llama.cpp、思考オフ、温度0）。有料のAPIは使いません。すべてローカルの試験用チェーンで動きます。凍結の時点で実行が終わっていない場合、または必須のゲート（引用した記憶のidがコードの選んだ集合に入っていること、エピソードの再現）に落ちた場合、この節は1文になります：「AI市民：この提出には実装なし。設計のみ。」自分の進軍のゲート（G12）に落ちた場合に取り下げるのは、自分の進軍の主張だけです。〔出典: docs/GAME-DESIGN.ja.md:577-594、:1173-1180、docs/frontier/ai-citizens/AI-CITIZENS-CONTRACT.md:865-869〕

**判断の流れ。** (1) コードが、ルール上許された候補を最大12個出す。(2) ローカルモデルがその中から選ぶ。(3) コードが検証する：形式、上限、最新状態での再確認、そしてプログラム自身。(4) 遅れた、不正だった、拒否された、のどれかなら、ルールの自動運転が動く。自動運転が受け持つのは、経済と日課の作業、そして採用された攻撃命令に従う進軍だけで、**自分から進軍を始めることはない**。だから、AIの自発的な進軍は、モデルが選んだものか攻撃命令のどちらかだけになる。自動運転は、AIが選んだことを取り消せない。多くの段階はモデルまで届かず、AIの操作の大半は自動運転のものです。モデルが選んだ段階で送られた操作の割合（by:model）は、主張のたびに併記します。〔出典: docs/frontier/ai-citizens/AI-CITIZENS-CONTRACT.md:11-12、:246-266、docs/GAME-DESIGN.ja.md:595-621〕

**人と同じルール。ただし安全のための上限つき。** AI市民は、人と同じ鍵、リレーの回数枠、霧（見えない範囲）、ヘラルドの読み取りで遊びます。加えて、次の安全のための上限があります。候補は最大12個（12州の窓の内側）。1回の判断で進軍させる兵は、自宅の兵の60%まで。1日あたりも60%までで、自宅には40%を残す（日の最初の自宅の兵が200未満のあいだは、この2つはかかりません）。モデルが選べる進軍は1日4回まで。発言と呼び出しの予算。自分からは進軍しない自動運転。国0では、評議会の規則が人の1票を必要とします。これらを省いて「同じルール」とは書きません。モデルは鍵を見ません。鍵を持たない「マインド」（心）がモデルを呼び、Bot側の「ブレイン」（頭脳）が署名します。これは仕組みであって、秘匿ではありません。ローカルのテスト鍵は、公開のシードから導けるからです。〔出典: docs/frontier/ai-citizens/AI-CITIZENS-CONTRACT.md:345、:906、docs/GAME-DESIGN.ja.md:700-705〕

**表示と開示（決定 D2）。** ゲーム画面では、AI市民を人のプレイヤーとまったく同じに表示し、印を付けません。これは、以前の決定 W2「AIは必ず表示する」を置き換えるものです。設計上の決定で【設計のみ】です。今、主な地図のクライアントにAIの印がないのは、AI市民がまだそのクライアントに出ていないためです。評議会・監査ページと、公開名簿 `roster.json` には、ラベル（`ai`、`script`、`seat`）があり、署名つきのメッセージの記録にも発信元の値が入っています。【動いている】（ブランチ上）。これらを残すかどうかは【確認 Q2】です（あなたが異議を出すまで残します）。既定として有効なもの：AI市民は、本当に知りたくて「あなたはAIですか」と尋ねられたら、本当のことを答えます（「運営が動かすAI市民です」。この規則と、その検査はありますが、実際にそう尋ねられた記録はありません）。そして、このREADMEにはそう書いてあり、ルールにも、この世界にはプロジェクトがローカルのAIモデルで動かす市民がいると、全体として書く予定です。法的確認（たとえばEU AI法第50条）は、まだ行っていません。〔出典: docs/GAME-DESIGN.ja.md:687-699、:1324-1345〕

**記憶**（AI市民の核です。決定 X1）。AIごとに公開の Wyllカード（性格、進み具合つきの目標、信頼、記憶の抜粋、最近の理由と引用した行）があります。AIごとに、台帳（進み具合つきの目標、信頼、まだ返していない恨み）と、**エピソード**を持ちます。エピソードは、コードが公開記録から書く短い出来事の文です（自分の軍への攻撃、ほかの国が先に倒した野営地、自宅の近くからの出発、自分の衝突など）。モデルがエピソードを書くことはありません。判断のたびに、コードがいくつかを選んで、「Remembered」の行として指示文に入れます。モデルは使ったものを引用でき、ページは、コードが書いた行を、モデル自身の言葉（確認されていないと表示）の横に出します。引用が示すのは、その行を見せられて挙げたことだけで、それが選択の原因だったことではありません。だから、使う言葉は「引用した」で、「覚えている」ではありません。記憶の行を抜くと選択が何回変わるかは、同じ質問をそのまま聞き直した回数と、関係のない文を同じ長さだけ抜いた回数を並べて報告します。エピソードはその場で公開され、シーズンをまたぎません。**AI同士の協定と裏切りは【やめた】**（決定 X2）。〔出典: docs/GAME-DESIGN.ja.md:645-663、docs/frontier/ai-citizens/AI-CITIZENS-CONTRACT.md:377-482〕

**監査。** ゲーム開始の前に、モデルのファイルのハッシュ、指示文、人格の配り方、設定に署名し、ローカルのチェーンに記録します（内部の整合性を示すもので、第三者のタイムスタンプではありません）。判断のたびにハッシュつきの公開記録が残ります。`verify-minds` は、記録の検査（コミットメント、人格の配り、鐘ごとの根、送った取引と記録の対応、発言の出所）、20件の判断の見本を1スロットに固定したサーバーで再生すること、3人のAIのエピソードを運営のヘラルドのログ（チェーンではありません）から作り直して照合することを行います。再生するのは見本で、全件ではありません。実行はローカルの試験用チェーンと、運営が持つテスト用の drand 鍵を使うので、「公開の乱数で配った」とは主張しません。〔出典: docs/GAME-DESIGN.ja.md:706-714〕

**ここまでに測ったもの：小さな実行で、機能そのものではありません。** *スモークテスト smoke-b3*（6体、すべて Conqueror、閉じた鐘86、ローカルの試験用チェーン、10倍速。ブランチ `frontier/ai-integ`）（実測。標本は小さい）：モデルの判断52回、有効52回、フォールバック0（事前に決めた下限は n=300 なので、これは結果ではありません）。判断の応答時間は p50 3,193 ミリ秒、p90 4,052 ミリ秒（判断34回）。by:model の割合は29.8%で、これは上限値です（操作171件のうち51件。自動運転の経済は64.3%）。記憶を引用した判断は52回中26回（モデル側の記憶カウンタは16回と数えます）。引用された行で最も古いものは32鐘前でした。モデルが選んだ進軍は10回で、相手はすべて野営地。うち9回は、公開の出来事の記録の中に、対応する衝突のエピソードがありました（出来事の記録から数えた代用値で、ヘラルドの衝突の行ではまだ確認しておらず、事前登録した Y ではありません）。評議会は9回、すべて定足不足で閉じ、攻撃命令の採用は0。`verify-minds` は合格しました。ただし、あとで直した検証器（FB3）より前のもので、直した検証器を記録した実行に当てた記録はありません。〔出典: ai-integ:docs/frontier/ai-citizens/RUNS.md:28-37、ai-integ:.local/frontier/ai/smoke-b3/report.md:11-35、:41-66（git で管理されないファイル）、docs/GAME-DESIGN.ja.md:615-621、:664-686〕 *Gemma 4 スパイク（素のモデル、ゲームを作る前）*（実測）：モデルが進軍を選んだのは、指示の1行によって20回の判断のうち 1回または9回で（報告書の結論の行には12回ともありますが、本文で確認できるのは1回と9回だけです）、ルールBotは18回でした。最良の設定で、提案された行動の79%が有効でした。1回の判断に計算で約5秒かかります。プレイヤーの生の文章を文脈に入れると、注入された命令に従ったのは64回中10回（思考オン）、32回中1回（思考オフ）でした。無害化と包み込みを行うと64回中0回でした。完全な再生は、スロット1つに固定したサーバーで200回中200回成立し、同時に4スロットでは200回中50回で分岐しました。〔出典: docs/frontier/ai-agents/gemma4/REPORT.md:11、:31-32、:82、:106-108〕

## 6. 動かし方、リポジトリの地図、ライセンス

### 6.1 動かし方

すべてローカルです。財布も devnet も有料サービスも要りません。**手早く試す：練習戦**（チェーンもビルドも不要。Python 3 があれば動きます）。

```sh
cd permutation-server/web && python3 -m http.server 8000 --bind 127.0.0.1
# open http://127.0.0.1:8000/frontier/practice.html   (JA or EN follows your browser)
```

ローカルのフルスタック（ローカルの試験用チェーンで動くゲーム本体。`up` は前面で動き続けるので、ターミナルを2つ使います）、ブラウザの自動操作、終了シーズンの手順、ツールチェーン、テストのコマンドは **[docs/RUNNING.md](docs/RUNNING.md)**（英語）にあります。開くのは `/` ではなく `/frontier/frontier/` です。ルートのアドレスは今も古いページに着きます。テストのコマンドのうち2つを、リポジトリの根から実行する形で挙げます。

```sh
(cd permutation-gateway && npm ci --ignore-scripts && npm test)
(cd permutation-gateway/screens && npm ci && npm run browser && node --test *.screen.mjs)
```

### 6.2 リポジトリの地図

用語：**キーパー**は誰でも動かせる補助プロセスで、drand のビーコンを載せ、進軍の封印を開き、衝突を解決します。**ヘラルド**はログを JSON と WebSocket にまとめて見せる読み取り専用のサーバーです。**リレー**は手数料と家賃を上限つきで肩代わりする窓口で、人もBotも同じ入口を通ります。

| パス | 中身 |

| `permutation-frontier/` | Solana プログラム（SBPF v2）。`svm-tests/`（LiteSVM のテスト群）を含む |
| `permutation-rules/src/frontier/` | ルールのカーネル（経済、移動、衝突、構え）。プログラム、シミュレータ、ブラウザで共有。M0 の時期に作った、包囲・官職・分配のカーネル（`siege.rs`、`office.rs`、`payout.rs`、`pools.rs`、`laurel.rs`、`mandate.rs`）も入っている。これらはライブラリとシミュレータ用のコードで、M1 のプログラムにはつながっていない。つながっているのは、見張り交代の補助関数と、`CreateSeason` が読み込んで検証・ハッシュするだけの `PayoutParams` 型（分配の処理は動かない）。征服やお金の結果ではない |

**名前は歴史的なものです（決定 V1）。** Wylls への改名では、コードの識別子、クレート・パッケージ・フォルダの名前、ハッシュと署名のドメイン、シードは変えていません。そのため `permutation-*` と `frontier-*` が残っています。

**以前のプロトタイプ。CI やコードの経路が参照しているため、このツリーに残しています：** `permutation-chain/`（MagicBlock プログラム）、`permutation-server/` の残り、`permutation-rules/`（ルール v8）と `permutation-gateway/` の Wylls 以前のファイル、`permutation-state-prototype/`、`permutation-state-solana-receipt-spike/`、`demo/`（以前のプロトタイプの devnet シーズンのログ）、`research/`。

## 7. 限界と、まだ行っていないこと

- **ローカルの試験用チェーンだけです。** 終了シーズンは20倍速、夜間実行（100体のBot、ゲーム内1日）は100倍速、AIのスモークテストは10倍速で、すべてローカルのチェーンで動かしました。**新しいゲームは devnet でも mainnet でも一度も動いていません。** devnet での暗号系 syscall のコストと家賃は未確認です。
- **プロジェクトの外の人は、まだ誰も遊んでいません。** 終了シーズンの参加者1,000は、すべてチームが書いたルールBotです。13種類のプロファイルで、未知の攻撃者に耐えると証明したことにはなりません。友人プレイテストは中止しました（決定 D11a）。その道具はブランチ `frontier/playtest` にあり、台本どおりに動くブラウザ訪問者20人でだけ予行しました。これは人ではありません。50〜200人の非公開の devnet プレイテストの手順書（[PLAYTEST-RUNBOOK](docs/frontier/m1/PLAYTEST-RUNBOOK.md)）は文書だけで、承認されておらず、実施もしていません。5,000人の観戦者は負荷生成ツールでした。登録、需要、利用の実績を示す数字はありません。
- **封印の秘匿は試していません。** 終了シーズンでは、drand のラウンドをアーカイブから再生したため（簡易スタックはテスト用の鍵を使います）、将来のラウンドの署名は最初から分かっていました。測定した結果（有効な封印の開示漏れ0、ごみの封印24件は24件とも処理）が示すのは、止まらずに動くことと、決着がつくことで、秘匿ではありません。秘匿は設計上の性質です。
- **AI市民は作成中で、完成していません。** コードは2026-10-12 までこのツリーにありません。12体と18体の実行と録画は行っていません。スモークテストは小さく（n=52）、基準値に照らした結果ではありません。AIの鍵は公開のシードから導け、drand の鍵は運営のテスト用の鍵です。AIの理由と発言はモデルが書いたもので、確認されていません。AIの操作の大半は自動運転のものです。評議会はチェーンの外にあります。
- **征服はこのツリーに入っていません。** `frontier/cq-integ` にあり（Wave 3〜5は未着手）、プッシュするまで GitHub にはありません。即時の土地、14日シーズン、国ごとの得点、お金、社会は設計で、どれについてもプログラムは変えていません。
- **14日や28日のシーズンを動かしたことはありません。** 最長は7ゲーム日です。28日という値は仮のもので、やめました。
- **お金（M2）と社会（M3）は未実装です。** プレイヤーが払う・稼ぐお金はなく、賞金もありません。ローカルのチェーン上で、プロトコルの内部が動かす試験用の小額の支払い（lamports。行軍手数料、開示チップ、封印の担保、家賃）はあります。
- **終了シーズンの穴：** 敵対者の「保留」9種類のうち2種類は、待機中の書き込みが見つからず、実行できませんでした。防御の払い戻しは、修正後の夜間実行で確認したもので、7日間のシーズンでは確認していません（[M1-EXIT-NOTES §4.3, §7](docs/frontier/m1/M1-EXIT-NOTES.md)）。設計が狙う規模は数千人ですが、最大の試験は1,000体のBotです。
- **ネットワーク上で人が遊べるようにする前にやること：** Webの修正2件、入口のリダイレクト、devnet の設定の不足、ホスティング（[概要 §8](docs/DESIGN-OVERVIEW.ja.md)）。お金と、AI市民であることの開示についての法的確認は、行っていません。
- **CI は一部が赤で、修正後は再実行していません。** `codex/frontier` ブランチの GitHub 上の実行は、2026-10-01 と 10-02 の2回です（[36923004057](https://github.com/r0ze998/wylls/actions/runs/36923004057)：`2c0462f`、[36958805861](https://github.com/r0ze998/wylls/actions/runs/36958805861)：`5ed36fa`）。どちらも8ジョブのうち6つが通りました（以前のプロトタイプのルール／プログラム／サーバーのジョブ、シミュレータ、オフチェーンのワークスペース、ゲートウェイとWebのテスト、レシートの試作、ブラウザのスモークテスト）。失敗は2つです。「Frontier M1 rules, ABI and program」は最初の確認ステップ（v9 凍結チェック）で失敗しました（`d95fa25` との v9 差分の確認です。承認済みの改名が正当にそこを変えたためで、そのため SBF ビルドと LiteSVM のステップは **GitHub 上では一度も動いていません**）。もう1つは「Frontier M1 web kernels」で、GitHub の Linux ランナーで作った WebAssembly モジュールのハッシュが、Mac で作ったものと違いました。修正は `scripts/check-v9-frozen.sh`、`scripts/build-wasm.sh`、`frontier.wasm.hosts` にあります。確認できたのは Mac 上だけで、Linux のハッシュは CI のログから取りました。Web画面のジョブはなく、無視している in-process テストも入っていません。スケジュール実行のワークフロー `doctrine-balance.yml`（毎日 03:17 UTC、1,500組のペアのシーズン）は、GitHub で一度も動いたことがなく、デフォルトブランチに入ると動き始めます。[`.github/workflows/`](.github/workflows/)、[DECISIONS F1, O-M1-17](docs/frontier/DECISIONS.md) を見てください。

**このリポジトリのどこでも、次のことは主張しません：**

- 新しいゲームが devnet や mainnet で動いたこと。プロジェクトの外の人が遊んだこと。需要、登録、利用の実績。
- 征服、即時の土地、14日シーズン、得点や勝者、統治、外交、市場、共有の文明、お金、賞金、支払いが、作ったものとして存在すること。ゲーム会社と話した、または何かを提供したこと。「シヴィライゼーション風」が完成していること。
- 「AIは必ず表示される」こと（決定 D2 でこの規則は外しました。今、ラベルがあるのは評議会ページと名簿で、それだけです）。「AIは鍵を持たない」こと（書けるのは「モデルは鍵を見ない」だけです）。AIの鍵が秘密であること。AI市民の人格を公開の乱数で配ったこと。
- AI市民が人と見分けがつかない、ルールBotやスクリプトBotより強い、スクリプトBotの国と同じだけ動く、完全に再生できる（再生するのは一部の抜き取り）、お金を稼ぐ、といったこと。1台のマシンで数千体を動かせること（Mac で1時間に約400〜450回のモデル判断が目安です （見積り））。追加費用がかからないこと（トークン従量のAPI費用はありませんが、計算はマシンの数に応じて増えます）。
- モデルが何かを望んだり意図したりすること。「人のように覚えている」「恨みを持つ」「学ぶ」こと。記憶があるとAIが上手に遊ぶ、記憶で判断が決まった、引用がAIの選んだ理由を示す、といったこと。記憶が非公開であること、シーズンをまたぐこと。by:model の割合と n を添えずに「AIが決めた」と書くこと。
- 評議会がチェーンで強制されること。評議会が個々のAIの自分の進軍を命じられること。国0の運営の席のとき以外に、人とAIが一緒に決めていること。
- AI同士の協定、裏切り、拘束力のある約束（ビルドから外しました。決定 X2）。

失敗の基準値と監査の設計：[概要 §2, §6](docs/DESIGN-OVERVIEW.ja.md)。書いてよいこと、いけないことの全体：[docs/GAME-DESIGN.ja.md 第9章](docs/GAME-DESIGN.ja.md)。
