# Wylls

**AIがプレイヤーのように振る舞うゲーム。** Wylls は、Solana 上に作る、シヴィライゼーション風の共有世界の、最初に遊べる部分です。運営がローカルのモデルで動かすAI市民が、目標と記憶を持って、人と並んで遊ぶ設計です。

> **現状（2026-10-06・この開発ブランチ）：** ローカル試験用チェーンで、国・土地の選択、即時の初村、建設・訓練・進軍、砦による州の支配、国別の領土時間得点を統合しています。通常設定は14日・10分ターン、試遊は別シーズンを10倍速にします。devnet / mainnetへの配備は行っていません。閉じたタブの外で新しい指示を出すプレイヤー用自動運営、共有技術・外交・市場は未実装です。

![Wylls の地図：中央の「協約（Concord）」を囲む6つの国](docs/img/wylls-map.png)

*最初に遊べる部分（M1）の試験シーズンの記録が終わった後の、Webクライアントの地図（試験用チェーン、スクリプトBot 1,000体）。写っているのは地図だけで、軍や衝突は写っていません。「Dev Wallet (localnet)」はローカル用のテスト財布で、本物の財布ではありません。*

## 1. Wylls とは

Wylls は、Solana 上のシヴィライゼーション風の世界で、6つの国が一つの地図を共有します。国を選び、村をもらい、実時間で遊びます。村を育て、兵を訓練し、行き先を封印した軍を進軍させ、誰でも再生できる戦闘報告を読みます。すべての戦闘を決めるのは運営ではなく Solana のプログラムで、シーズン（世界の1回分の期間）全体は取引の記録になり、検証器がそれを再生して確かめます（検証器は私たちのもので、独立した監査ではありません）。チェーンを使う理由はこれです。土台となる M1 は、スクリプトBotによるシーズン実走で検証しました。この開発ブランチでは、初村から州の争奪までを人が操作できるローカル版に拡張しています。スクリプトBotとは、決まったルールで動く試験用のプレイヤーで、AIでも人でもありません（試験の記録では「ルールBot」と呼んでいます）。目標と記憶を持つAI市民が人と並んで遊ぶ設計で、これは作成中です（[第3節](#3-ai市民)）。このブランチには征服と国別得点を統合しています。共有の技術、外交、市場、お金は設計段階です（[第4節](#status)）。

## 2. 遊び方

ゲームは実時間で進みますが、戦闘、進軍、偵察の結果は、その場では決まりません。10分ごとに、世界がそれらをまとめて解決します（1日144回）。この1回を**ターン**と呼びます（コードと契約書では「鐘（bell）」と呼びます）。軍を1分早く出しても有利になりません。2つの命令は、同じターンでまとめて解決されるからです。経済と建設は連続して進み、ターンを待つ必要はありません。

1. **国と土地を選ぶ。** 六つの国から所属先を選び、本国の空いている土地を確認して、最初の村を受け取ります。初村は確定した村として即時に与えられます。初村の場所は後から選び直せません。
2. **村を育てる。** 最初の生産施設は一度だけゲーム内60秒で完成します。以後は通常の建設時間です。資源・生産量・倉庫容量・工事の残り時間を見て、次の投資を選びます。
3. **兵を訓練し、軍勢を編成する。** 兵種・人数ごとの費用を確認して訓練し、招集します。招集直後は休息が必要です。斥候は探索に、戦闘兵は砦の争奪に使います。
4. **現在地から進軍する。** 軍勢と目的地を選び、経路・到着ターン・構えを確認します。行き先は到着まで封印され、出発後は取り消せません。到着時刻と戦闘結果の確定時刻は別です。
5. **砦を押さえて州を守る。** 本国の外の砦で敵を排除し、必要なターン数だけ支配を続けます。砦を取ると州の支配国が変わります。本国は征服から保護されます。
6. **領土得点を積み上げる。** 「国と領土」で順位と争奪状況を確認します。勝敗は **支配した州の数 × 維持した時間**。1州を1時間維持すると1州・時間です。村の強さ、繁栄、知識、奪取ボーナス、人数補正は得点に加えません。同点は同順位です。
7. **町に育てて前哨地を申請する。** 最初の村を町にし、本国の外で、自国の村がまだ優勢でない州の空き地を選びます。二つ目以降の土地は即時配布ではなく競争する申請です。画面に費用と条件を示します。現在の申請費用は申請時に消費し、落選・失効時も返りません。

資源の生産、予約済みの建設、出発済みの進軍と戦闘処理は、画面を閉じても世界側で進みます。新しい建設や訓練を自動で発注する「方針」は別機能です。プレイヤー用の常時実行はまだありません。設計は [ゲーム設計書の更新](docs/GAME-DESIGN.ja.md#2026-10-06-開発ブランチの更新) にまとめています。

## 3. AI市民

**この節の実験結果は2026-10-04時点の記録です。** AI市民のコードはこの開発ブランチへ統合済みですが、新しい征服シーズンでのAI長時間実走は未検証です。

AI市民は、運営がローカルのモデル（Gemma 4、llama.cpp 経由。有料の API は使いません）で動かすプレイヤーです。以前は別のローカルブランチで開発していました。これまでに、6体の小さな実行が1回完走しました。モデルの判断52回はすべて有効で、AIの判断の検査 `verify-minds` に合格しましたが、これは後から直す前の検査器によるもので、直した検査器は、この記録にまだ当てていません。契約が結果として求める判断は300回なので、これは動作確認の段階です。12体と18体の実行はまだ行っていません。これらの実行には、AIと並んで遊ぶスクリプトBot（6体の実行では30体）も入っています。

- **コードが出し、モデルが選び、コードが確かめる。** コードがルール上許された候補を短い一覧にし、モデルが1つを選び、コードが検証してから、プログラムが受け付けます。モデルが遅い、不正、拒否されたときは、自動運転が代わりに動きます。自動運転は経済と日課だけを進め、自分から進軍を始めません。したがって、AI市民が自分で出す進軍は、モデルの選択か、国の評議会の攻撃命令（後述）のどちらかで、AI市民の操作の大半は自動運転のものです。この設計にした理由は、初期の予備実験です。素のモデルに任せると、進軍を選ぶことはまれでした（[レポート](docs/frontier/ai-agents/gemma4/REPORT.md)、英語）。
- **記憶は公開記録から引用する。** コードが、公開記録から短い出来事の文を書きます（自軍への攻撃、ほかの国が先に倒した野営地など）。モデルはそれを書きません。ページには、モデルが引用した行が、モデル自身の理由（確認されていないと表示）と並んで出ます。引用は、その行が見せられて挙げられたことを示すだけで、それが選択の原因だったことは示しません。
- **主な見どころ：AI市民が自分で出す進軍。** AIが自分で進軍を選び、軍は行き先を封印したまま出発します。進軍が開示されると、判断が開きます。示された選択肢、AIの理由、行き先、そして本物の衝突レポートです。モデルが選んだ進軍のうち、いくつが実際の衝突になるかは、予定している18体の本番の実行（未実施）までは分かりません。1つもならなければ、この主張は取り下げ、評議会を見どころにします。
- **国の評議会。** 評議会の期間ごとに、コードが国ごとに目標の州を3つまで提案し、AI市民が発言して投票します。採用された目標が**攻撃命令**で、攻撃の時まで外部の人には封印されます。評議会はチェーンの外にあり、チェーンは何も強制しません。国0には、運営が持つ人間の席が1つあります（録画するデモでは発表者の席）。ほかの5つの国は、AIの票だけで決まります。6体の実行では、どの評議会も定足に達せず、攻撃命令はまだ採用されていません。
- **人と同じルール。ただし安全枠つき。** AI市民は、人と同じ鍵、回数制限、霧（見えるのは地図の一部だけ）で遊びます。加えて、モデルが選ぶ進軍は1日4回まで、などの制限があります。モデルは鍵を見ません。ただし、ローカルの試験用の鍵は公開のシードから導けるので、これは構造であって、秘密ではありません。
- **表示と開示（決定済み）。** ゲーム画面では、AI市民を印なしで、普通のプレイヤーと同じに表示します。主な地図のクライアントには、まだAI市民が出ません。AIは、本当に知りたくて「AIですか」と問われたら、AIであると答えます（規則と検査はブランチにあり、実際に問われた記録はありません）。運営は、この README のように、世界にAI市民がいることを全体として開示します。試験の実行の評議会ページと公開名簿には、種別の印（AI、スクリプトBot、運営の席）が付いたままです。残すかどうかは決まっていません。開示についての法的確認（たとえば EU AI 法50条）は、まだ行っていません。

事前に決めた合格条件と結果の表は、[AI市民の契約 §10.2](docs/frontier/ai-citizens/AI-CITIZENS-CONTRACT.md#102-gates)と設計書（[GAME-DESIGN.ja.md](docs/GAME-DESIGN.ja.md) の第4章と第8章）にあります。新しい征服シーズンの実走結果は、検証後に追記します。

## 5. 試す

初村から領土争奪まで遊ぶ現在のローカル版は、[試遊の起動・再開と検証記録](docs/frontier/conquest/PLAYABLE-2026-10-06.md) を参照してください。試遊は専用の世界を10倍速で起動します。保存済みの世界は `resume` で再開し、同じ名前の `up` では消去しません。以下の練習戦とM1の記録は、別の軽量な試し方です。

すべてローカルです。財布も devnet も有料のサービスも要りません。まず、上のスクリーンショットと [M1 の実行記録](docs/frontier/m1/runs/m1-exit/)を見てください。**手早い方法は、練習戦です**（ゲーム本体の規則のコードを、ブラウザの中で動かして練習の衝突を再生します。チェーンもビルドも不要。Python 3）。リポジトリの直下で実行します。

```sh
cd permutation-server/web && python3 -m http.server 8000 --bind 127.0.0.1
# http://127.0.0.1:8000/frontier/practice.html を開く（日本語・英語はブラウザの設定に従います）
```

**以前のM1を動かす構成**（征服版の起動には上の試遊手順を使います）。ツールチェーン（Rust、Solana のビルドツール、Node 20 以上。一覧は [docs/RUNNING.md](docs/RUNNING.md)、英語）は、ご自身で入れてください。`up` は前面で動き続けるので（ゲーム内1日のシーズンに約72分かかります。20倍速では1ターンが30秒です）、端末を2つ使います。

```sh
(cd frontier-node && cargo build --locked --release --workspace)
scripts/build-frontier.sh --features test-beacon
S=frontier-node/target/release/frontier-stack
$S up --mode accel --beacon test-key --scale 20 --days 1 --bots 20 --run-id try --base-port 41000
# 2つ目の端末で、約1分後に http://127.0.0.1:41040/frontier/frontier/ を開く
$S down --run-id try
```

開くのは `/` ではなく `/frontier/frontier/` です。何も付けないアドレスは、古いページに着きます。ブラウザでは、内蔵のローカル用テスト財布で参加します。台本どおりのブラウザ実行、終了シーズンの手順、テストのコマンドは [docs/RUNNING.md](docs/RUNNING.md) にあります。AI市民のコードは統合済みですが、今回の試遊世界では起動していません。

## 6. 限界と、主張しないこと

- **試験用チェーンだけ。** 新しいゲームは、devnet でも mainnet でも動かしていません。devnet での費用は未確認で、ホスティングは未定です。
- **プロジェクトの外の人は、誰も遊んでいません。** M1 のシーズンの参加者1,000体はすべて、チームが書いたスクリプトBotです。登録数、需要、利用の数字はありません。ゲーム内7日を超えるシーズンは動かしていません。
- **封印の秘匿は試していません。** M1 のシーズンは、保存した drand の値を再生したので、署名は最初から分かっていました。結果が示すのは、進軍が精算されることで、行き先が隠されることではありません。検証器は私たちのもので、独立した監査ではありません。
- **AI市民は作成中で、完成していません。** あるのは6体の小さな実行だけです。AIの理由と発言はモデルが書いたもので、確認されていません。AI市民の操作の大半は自動運転のものです。評議会はチェーンの外にあります。試験の実行の drand の鍵は、運営の試験用の鍵です。
- **作っていないもの：** プレイヤー用自動発注の常時実行、包囲の専用画面、統治、外交、市場、共有の技術、お金、賞金。お金とAI市民の開示についての法的確認は、まだ行っていません。
- **CI は一部が赤です。** 2026-10-01 と 10-02 の GitHub の実行では、8つのジョブのうち2つが失敗し、プログラムのビルドと LiteSVM のテストは GitHub では一度も動きませんでした。修正は Mac でだけ確認しました。
- **AIについて主張しないこと：** スクリプトBotより強い、人と区別がつかない、完全に再生できること。モデルが何かを望む、意図すること。記憶が、なぜそれを選んだかを示すこと。評議会がチェーンで強制されること。
- **プロジェクトについて主張しないこと：** プロジェクトの外の人が遊んだこと、需要があること、ゲーム会社に話したこと、お金や賞金が動くこと、シヴィライゼーション風のゲームが完成していること。

## 7. リポジトリの構成と、さらに読む

| パス | 内容 |
|---|---|
| `permutation-frontier/` | Solana のプログラムと、LiteSVM のテスト（`svm-tests/`） |
| `permutation-rules/src/frontier/` | プログラム、シミュレータ、ブラウザで共有する規則のコード |
| `frontier-abi/`、`frontier-wasm/` | プログラムの ABI。ブラウザ用に WebAssembly にした規則 |
| `frontier-sim/` | バランスのシミュレータ |
| `frontier-node/` | チェーン外のサービス：keeper（進軍と衝突を精算する）、herald（読み取り専用のデータサーバ）、検証器、スクリプトBot、ローカルのチェーン、起動用のスタック |
| `permutation-gateway/` | リレー（回数枠の中で手数料を払う。人もBotも同じ入口）、JS の SDK、画面テスト |
| `permutation-server/web/frontier/` | Webクライアント（地図、村、進軍の入力、報告、練習戦） |
| `scripts/`、`docs/` | ビルドと実行のスクリプト。すべての文書 |

名前は歴史的なものです。Wylls への改名では、フォルダ、クレート、パッケージの名前を変えていないので、`permutation-*` と `frontier-*` が残っています。このリポジトリには、別の旧試作（Permutation State）のファイルも残っています。これは Wylls の証拠ではありません（[索引](docs/earlier-prototype/INDEX.md)、英語）。
